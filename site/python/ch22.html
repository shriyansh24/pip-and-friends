Part 1 · The alarm boardevery error belongs to a family, and families decide who answers

1

Pip's little shop program has grown. It reads settings, sells tea, takes coupons, writes files. Today the Professor hands Pip a new job title.

The Professor says: Congratulations, you're the safety officer. In Chapter 9 you learned to catch alarms. A safety officer designs them: which alarms exist, who answers each one, and what goes in the incident log.

Pip says: A badge! And a whistle? No whistle. OK. Where do I start?

An exception is Python's word for an error object that is raised (the alarm starts ringing) and travels up until something catches it (someone answers it). If nobody does, the program stops with a traceback.

2

First, the safety drill you already know. If any line feels shaky, Chapter 9 has the full story.

  1. try / except / else / finally. except runs if the try failed, else if it didn't, finally on every road.
  2. Catch what you expect. Name the error: except ValueError:. A bare except: catches everything, including your own typos.
  3. Keep the try small. Put only the risky line inside, so you know which line the net is for.
  4. EAFP or LBYL? "Easier to ask forgiveness than permission" (try it, catch the error) versus "look before you leap" (check first with if). Python code often prefers the first.
  5. raise and assert. raise rings an alarm on purpose. assert is a note-to-self check that can be switched off (the notebook shows how), so never use it to check user input.

    Under the hood: what with really does, and where the log is kept
    
      
      
      
      A with statement, written out by hand
      
      
      The language reference spells out what with means. Simplified: call __enter__ and bind its result to the as name; run the block inside a try; if anything at all is raised (even SystemExit), pass its details to __exit__ and re-raise unless it returns something true; if nothing is raised, call __exit__(None, None, None). Python looks up both methods on the class, like every socket in Chapter 20.
      
      
      
      
      Three attributes hold the incident log
      
      
      Every exception has __cause__ (set by from), __context__ (set automatically when it was raised while another was being handled) and __suppress_context__ (set to True by from, so the "during handling" part is not printed). from None sets the cause to None and hides the context. The traceback itself lives in __traceback__.
      
      
      
      
      except* always hands you a group
      
      
      Even when a single, ordinary exception is raised, except* wraps it, so the name after as is always an ExceptionGroup and you read eg.exceptions:
      
      
      
      
      Behind the scenes, each except* calls the group's split() method, which divides it into the matching part and the rest, keeping the tree shape:
      
      
      
      
      assert can be switched off
      
      
      Running Python with -O ("optimise") removes every assert statement before the program runs. That's why assert is for checking your own assumptions while developing, and raise is for problems that can really happen, such as bad input:
      
      
      
      
      
    
      
  
      

  
      
    In real programs: error hierarchies, logging and with everywhere
    
      
      
      Root exceptions in well-known libraries
      
      
        
        
      • The requests HTTP library raises everything from requests.RequestException, with children such as ConnectionError and Timeout.
        • 
        
      • The standard library's json.JSONDecodeError is a child of ValueError, so old code that catches ValueError still works. Inheriting from a matching built-in as well as your root is a common trick.
        • 
        
      • OSError has children for each operating-system problem: FileNotFoundError, PermissionError, IsADirectoryError, TimeoutError and more.
        • 
      
      
      
      Log the whole story at the top
      
      
      Inside an except block, logging.exception() logs your message and the full traceback. Many programs have exactly one broad except Exception, at the very top, that does this before stopping or moving on to the next request:
      
      
      
      
      
      
      Context managers you'll meet
      
      
        
        
      • Files (open), zip files (zipfile.ZipFile), network connections (socket, urllib.request.urlopen).
        • 
        
      • Databases: with sqlite3.connect(...) as conn: commits the changes if the block succeeds and rolls them back if it fails.
        • 
        
      • Locks (threading.Lock) and temporary files and folders (tempfile).
        • 
        
      • Settings for a moment: decimal.localcontext() changes the precision only inside the block; warnings.catch_warnings() changes warning filters only inside the block.
        • 
        
      • Tests: pytest.raises(ValueError) passes only if the block raises that error (Chapter 14; Chapter 26 goes further with testing).
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "except Exception is the safe choice." It hides your own bugs (Panel 5). Catch the specific errors you expect, close to where they happen.
        • 
        
      • "My errors should inherit from BaseException." Inherit from Exception. BaseException is for exit signals that should pass through ordinary handlers.
        • 
        
      • "The except clauses are tried to find the best match." They're tried top to bottom and the first match wins, so a parent class listed first steals its children's alarms (Exercise in Part 2).
        • 
        
      • "raise ... from e catches e again later." It only records e as the cause. Callers must catch the new class (Part 3's NAME THAT ERROR).
        • 
        
      • "Two tracebacks means two separate crashes." A chained traceback is one crash with its history, read bottom-up as usual.
        • 
        
      • "add_note changes the message." The message is unchanged; the notes print on extra lines underneath.
        • 
        
      • "Only one except* branch can run." Every branch that matches part of the group runs once.
        • 
        
      • "The name after as is the context manager." It's whatever __enter__ returns (Panel 36).
        • 
        
      • "with deletes the variable at the end." The name still exists; for a file, it now refers to a closed file (Panel 30).
        • 
        
      • "Code after yield always runs." Only if the block didn't raise, unless it's inside finally (Panel 38).
        • 
      
      
    
      
  
      

  
      
    Version notes: what is new, and since when
    
      
      
        
        
      • except A, B: without brackets (PEP 758): allowed since Python 3.14, when there's no as. 3.13.18 says SyntaxError: multiple exception types must be parenthesized (Panel 2).
        • 
        
      • return, break or continue in finally (PEP 765): a SyntaxWarning since 3.14. 3.13.18 prints nothing (Panel 8).
        • 
        
      • The contextlib.py line in Panel 40's traceback is line 203 in 3.15.2 and line 141 in 3.13.18, and the path is wherever Python is installed. The error itself is the same.
        • 
        
      • ExceptionGroup, except* and add_note() (PEPs 654 and 678): since 3.11.
        • 
        
      • Brackets around several managers in one with: officially supported since 3.10.
        • 
        
      • raise ... from and the chained traceback: since 3.0. contextlib.suppress since 3.4, redirect_stdout since 3.4, ExitStack since 3.3.
        • 
        
      • traceback.format_exception_only(e) with just the exception: since 3.10 (older versions need the type too).

    Words from this chapter
    
      
      
      
        
      exception
      An error object that is raised and travels up through the calling functions until something catches it.
      
        
      exception hierarchy
      The family tree of exception classes. Catching a class also catches all its descendants.
      
        
      BaseException
      The very top of the tree. Its direct children include Exception, SystemExit, KeyboardInterrupt and GeneratorExit.
      
        
      custom exception
      Your own exception class, made by inheriting from Exception (or a child of it).
      
        
      root exception
      One base class that every error of a package inherits from, so callers can catch them all at once.
      
        
      re-raise
      A bare raise inside an except block sends the same exception on its way.
      
        
      exception chaining
      Linking a new exception to an earlier one. Explicit with raise ... from e (__cause__); implicit when a handler fails (__context__).
      
        
      note
      An extra line of text attached with add_note(), printed under the message.
      
        
      traceback module
      Standard-library tools for formatting and printing exceptions and tracebacks.
      
        
      logging
      Recording messages with a level (such as ERROR) to a configurable place, instead of printing them.
      
        
      ExceptionGroup
      An exception that bundles several exceptions together, printed as a boxed tree.
      
        
      except*
      A handler that takes the matching part of an exception group; several can run for one group.
      
        
      SyntaxWarning
      A warning printed while Python reads your file, about code that's legal but probably wrong.
      
        
      context manager
      An object that works with with: it has __enter__ and __exit__.
      
        
      __enter__ / __exit__
      The methods with calls on the way in and on every way out. __exit__ gets the exception's class, the exception and the traceback (or three Nones).
      
        
      suppress (an exception)
      Stop it from spreading. __exit__ does this by returning True; contextlib.suppress does it for chosen classes.
      
        
      @contextmanager
      A decorator in contextlib that turns a generator with one yield into a context manager.
      
        
      teardown
      The cleanup step: closing, releasing, deleting, switching off.
      
        
      ExitStack
      A context manager that holds any number of others and exits them in reverse order.
      
        
      EAFP / LBYL
      "Easier to ask forgiveness than permission" (try, then catch) versus "look before you leap" (check first).
