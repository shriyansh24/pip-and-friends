CHAPTER 17

MACHINES AS PARCELS

Picture: a smiling cardboard parcel with a little yellow function machine peeking out over its flaps. A tag on a string says "shout".

A function is a thing, like a number or a list. You can hand it to someone, get one back, keep it in a cabinet, or write a tiny one on the spot. Then: stretchy slots, name-only slots, and a tip jar that remembers too much. About 60 minutes, with 28 hands-on checks.

  7. Boss level and recap

          What you learned in Chapter 17
          
    
            
      
          • NO BRACKETS HANDS IT OVER, BRACKETS RUN ITA function is a value: tag it, pass it, return it, keep it in a dict. key=len, never key=len().
            • 
      
          • A LAMBDA IS FOR HANDING OVER, A DEF IS FOR KEEPINGlambda params: expression, one expression, no return.
            • 
      
          • SORT BY THE STICKERThe key machine runs once per item; the stickers are compared; ties keep their order.
            • 
      
          • A STAR PACKS IN A DEF, AND UNPACKS IN A CALL*args is a tuple, **kwargs a dict; f(*xs) and f(**d) tip them out.
            • 
      
          • / AND * ARE WALLSBefore /: position only. After *: name only.

    Under the hood: function objects, stored defaults and how key sorting works
    
          
      
      
          What a function object carries
          
      
          A function is an object with attributes, like any other. callable(x) asks "can I put brackets after this?". The docstring (Chapter 6) lives in __doc__, and the compiled body lives in __code__, which knows the names of its local variables:
          
      
          
      
          Printing a function itself shows something like <function shout at 0x7f…>. The hex number is a memory address that changes on every run, which is why this chapter prints type() and __name__ instead.
          
      
          Where defaults live
          
      
          When a def runs, Python evaluates each default once and stores the results on the function: positional defaults in __defaults__ (a tuple), name-only ones in __kwdefaults__ (a dict). A call that leaves a slot empty simply ties that slot to the stored object. That's the whole tip-jar story. It also means a default captures the value a name had when the def ran; rebinding the name later changes nothing:
          
      
          
      
          How arguments find their slots
          
      
          For each call, Python fills the slots left to right with the positional values, then fills slots by name from the keyword arguments, then pours any leftovers into *args and **kwargs, and finally uses defaults for anything still empty. If a slot gets a value both ways, that is an error:
          
      
          
      
          How sorting with a key works
          
      
          sorted calls the key function exactly once per item, keeps the stickers beside the items, sorts by the stickers, then hands back the items. Python's sort is guaranteed to be stable: items with equal stickers keep their original order. That is what makes "sort by the second key first, then by the first key" work:
          
      
          
      
          Line 4 and line 5 agree: one tuple sticker (age, name) does the same job as two stable passes.

    Common wrong ideas
    
          
      
            
        
          • "key=len() means 'use len'." The brackets run len immediately, with nothing in it (Panel 22). Pass the machine: key=len.
            • 
        
          • "A lambda is faster or more advanced than a def." They make exactly the same kind of function object. A lambda is just shorter, nameless, and limited to one expression.
            • 
        
          • "name = lambda … is good style." It works, but every traceback then says <lambda> (Panel 18). PEP 8 asks for a def.
            • 
        
          • "Default values are made fresh on every call." They are made once, when the def runs (Panel 42). Lists, dicts and sets as defaults are shared.
            • 
        
          • "So I should never use a default." Immutable defaults are perfectly safe: numbers, strings, tuples, True, None. Only defaults you might change in place are a trap.
            • 
        
          • "*args has to be called args." Only the star matters. *nums, *toppings or *names say more.
            • 
        
          • "*args is a list." It is a tuple. Convert with list(args) if you need to change it.
            • 
        
          • "/ and * are parameters." They are markers, and they take no value. A bare * only puts up the name-only wall.
            • 
        
          • ".sort() gives back the sorted list." It sorts in place and returns None (Panel 30). sorted() gives back a new list.
            • 
        
          • "reduce is the clever way to do everything." For sums use sum, for products math.prod, for "any/all" use any/all. A loop is often the clearest of all.
            • 
      
          
    
          
  
          

  
          
    Version notes: what is new, and since when
    
          
      
            
        
          • The sentinel built-in (PEP 661): new in Python 3.15. Its signature is sentinel(name, /, *, repr=None). On older versions it is a NameError (Panel 44); use MISSING = object() there.
            • 
        
          • Positional-only parameters with / (PEP 570): you can write them since 3.8. Built-ins like len and sorted had them long before, which is why the docs used / early.
            • 
        
          • Keyword-only parameters with * (PEP 3102): since Python 3.0.
            • 
        
          • Several * and ** unpackings in one call or display, like f(*a, *b) and {**x, **y} (PEP 448): since 3.5.
            • 
        
          • reduce was a built-in in Python 2 and moved to functools in Python 3.
            • 
        
          • Everything else in this chapter works in every Python 3 you are likely to meet.

    Words from this chapter
    
          
      
          
        
          function object
          The machine itself, made by def or lambda. A value like any other.
          
        
          first-class
          Python's functions are "first-class": they can be tagged, passed, returned and stored, just like numbers and lists.
          
        
          callable
          Something you can run with brackets: functions, classes, and a few other objects. callable(x) checks.
          
        
          higher-order function
          A function that takes a function as an argument or returns one: sorted, map, twice.
          
        
          dispatch table
          A dict whose values are functions: look up a key, run what you find.
          
        
          callback
          A function handed over to be run later, when something happens.
          
        
          lambda
          lambda params: expression: a small nameless function whose body is one expression.
          
        
          expression
          Code that produces a value. A lambda's body must be one.
          
        
          statement
          A whole instruction such as return, x = 1 or if …:. Not allowed inside a lambda.
          
        
          key function
          The machine given as key=. It makes one sticker per item, and the stickers are compared.
          
        
          stable sort
          A sort that keeps items with equal keys in their original order. Python's is stable.
          
        
          itemgetter / attrgetter
          Ready-made key machines from operator: "item number n" and "attribute called x".
          
        
          reduce
          functools.reduce(f, items, start): combines a belt into one value, two at a time.
          
        
          partial
          functools.partial(f, ...): a new machine with some arguments preset.
          
        
          pure function
          Same inputs, same output, and nothing outside changes.
          
        
          side effect
          Anything a function changes outside itself: printing, changing a list it was given, changing a global.
          
        
          immutability
          Not changing objects after they're made; building new ones instead.
          
        
          *args
          A stretchy parameter that collects extra positional arguments into a tuple.
          
        
          **kwargs
          A parameter that collects extra keyword arguments into a dict.
          
        
          unpacking (in a call)
          f(*items) passes each item as a positional argument; f(**d) passes each pair as a keyword argument.
          
        
          positional-only
          Parameters before /: can't be passed by name.
          
        
          keyword-only
          Parameters after * (or after *args): must be passed by name.
          
        
          signature
          A function's name and parameters, with their markers and defaults.
          
        
          mutable default
          A default value that can be changed in place (list, dict, set). Made once and shared by every call.
          
        
          sentinel
          A special marker object that means "nothing was given". Usually None; Python 3.15 adds a sentinel built-in for when None is a real value.
