    Under the hood: where attributes and methods really live
    
        
      
        An instance is a small dict with a class attached
        
      
        Each object keeps its attributes in a dictionary of its own, called __dict__. The built-in vars() shows it. The methods are not in there: they live once, in the class's own dictionary, shared by every instance.
        
      
        
      
        Line 10 shows that you can stick a new attribute onto one object from outside the class. Python allows it, but it surprises readers: give every attribute a starting value in __init__, so all cookies from one cutter have the same set of attributes.
        
      
        How the dot looks things up
        
      
        Reading rex.something checks the instance's __dict__ first, then the class. Methods are found in the class. Assigning rex.something = ... always writes into the instance. Chapter 19 builds on this rule (class attributes, and the trap of one list shared by every instance).
        
      
        Bound methods
        
      
        rex.greet, without brackets, is a bound method: the function Pet.greet with rex already clipped into its self slot. Brackets call it. That's how rex.greet() becomes Pet.greet(rex).
        
      
        Is __init__ the constructor?
        
      
        Not quite. Calling Pet(...) first runs a method called __new__, which makes the blank object, then __init__, which decorates it. That's why __init__ must return None (Panel 20's fourth road). You'll almost never write __new__ yourself.
        
      
        What is the id, really?
        
      
        In CPython, the standard Python, id(x) is the object's address in memory: the same 0x… number you saw in <__main__.Pet object at 0x…>, written in hexadecimal. Addresses change from run to run, which is why this chapter's id and address runs are marked "one possible run". Other Pythons may use other numbers; the only promise is "unique while the object lives".
        
      
        self is only a name
        
      
        Python doesn't treat the word self specially; the first parameter gets the instance whatever you call it. But every Python programmer writes self, and the official tutorial (section 9.4) warns that other names make your code harder for other Python programmers to read. Do the same.
        
    
        
  
        

  
        
    Same or equal: the fine print
    
        
      
        Never use is to compare numbers or text
        
      
        Use is only to ask "same object?", and for None: if x is None:. For values, use ==. Python even warns you when you compare with is against a literal. The warning goes to stderr every time the file is compiled, and the program still runs:
        
      
        
      
        It printed found Rex here only because CPython happened to reuse one string object. Whether two equal strings or numbers are the same object is an implementation detail that changes between versions and situations. (Chapter 2's notebook mentioned one such speed trick: small whole numbers are kept alive and shared.)
        
      
        Ints never change
        
      
        "Adding 1" to an int builds a new int. The old tag keeps the old object:
        
      
        
      
        Why some kinds can't change
        
      
        Objects that can't change are called immutable; those that can are mutable. Immutable objects are safe to share: no one can change them behind your back. That's also why only immutable things can be dict keys (Chapter 8's unhashable-list error): a key that changed would end up in the wrong drawer.
        
      
        Python passes objects, not copies
        
      
        When you call a function, each parameter becomes a new name for the very object you passed. Nothing is copied. People argue about whether to call this "pass by reference" or "pass by value". The Python Tutorial says "call by value", where the value is always an object reference, and adds in a footnote that "call by object reference" would be a better description; the Programming FAQ says arguments are "passed by assignment". The tracer in Panel 7 is the whole story: a new tag, on the same object.
        
    
        
  
        

  
        
    In real programs: objects everywhere
    
        
      
        Everything really is an object, including functions and classes themselves. isinstance(x, object) is True for all of them, and type() names each one's class:
        
      
        
      
        A class's own class is type: the cutter was made by a cutter-maker. You've used many classes already without writing them:
        
      
          
        
        • Exceptions from Chapter 9 are classes. ValueError("bad") makes an instance, and raise throws it.
          • 
        
        • Files: open() in Chapter 10 handed back a file object, and f.write() and f.read() are its methods.
          • 
        
        • Modules from Chapter 13 hand you objects too: datetime.date(2026, 11, 7) is an instance with methods like .weekday(), and random.Random(1) is a random-number generator object with its own seed.
          • 
      
        
      
        When real programmers write a class
        
      
          
        
        • A record with fixed fields that moves around a program together: a Student, an Order, a Recipe.
          • 
        
        • Something with state that changes over time: a game character's health, a shopping cart, a bank account.
          • 
        
        • Not everything needs one. A handful of functions and a dict is often simpler. A common rule of thumb: a class with only __init__ and one other method is often clearer as a function.
          • 
      
        
      
        Chapter 20 shows Python's ready-made shortcut for record classes, dataclasses, which writes __init__ and __repr__ for you.
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "Passing a list to a function gives it a copy." It gives it the list itself (Panel 7).
          • 
        
        • "param = something inside a function changes the caller's variable." It only moves the function's own tag.
          • 
        
        • "Two objects with the same attributes are equal." Not for your own classes, yet: == falls back to is until you teach it otherwise (Chapter 20).
          
          • 
        
        • "self is a keyword." It's a naming convention for the first parameter (see "Under the hood").
          • 
        
        • "__init__ creates the object." The object already exists when __init__ runs; __init__ fills it in.
          • 
        
        • "Inside a method, I can use name for self.name." No: name means a local or global tag (Panel 35). Python never adds the self. for you.
          • 
        
        • "An attribute set from another attribute stays in sync." It's worked out once (the Badge exercise). Recompute it in a method if it must follow changes.
          • 
        
        • "Removing items in a for loop raises an error, like dicts do." For lists it fails silently (Panel 8). Sneak's favourite.
          • 
        
        • "Classes are only for big programs." Even a ten-line script can benefit when data and behaviour belong together. But a dict is fine when it's just data.

    Words from this chapter
    
        
      
        
        
        object
        Any thing in memory with a kind (its class) and a value. In Python, everything is one.
        
        
        identity
        Which object something is. is compares identities; id() gives a number for it.
        
        
        mutable / immutable
        Can change in place (lists, dicts, sets) / can never change (ints, floats, strings, tuples).
        
        
        iteration
        One pass of a loop over a collection; "during iteration" means "while a loop is walking it".
        
        
        method
        A function that belongs to a class, called with a dot: rex.feed(2).
        
        
        class
        A blueprint for a kind of object: the cookie cutter. Written with class Name:.
        
        
        instance
        One object made from a class: one cookie. rex is an instance of Pet.
        
        
        instantiate
        To make an instance by calling the class: Pet("Rex").
        
        
        attribute
        A name stuck onto an object, reached with a dot: rex.name. Methods are attributes too.
        
        
        self
        The first parameter of every method: the particular instance the method is working on.
        
        
        __init__
        The method Python runs automatically right after making a new instance, to set its attributes.
        
        
        dunder
        Short for "double underscore": names like __init__ that Python calls for you.
        
        
        __str__
        Returns the friendly text for an object; used by print, f-strings and str().
        
        
        __repr__
        Returns the programmer's text for an object; used in lists, by repr() and at the prompt.
        
        
        CapWords
        The PEP 8 naming style for classes: Pet, ShoppingList.
        
        
        pass
        A statement that does nothing; a placeholder where a block is required.
        
        
        bound method
        A method taken from an instance, with that instance already filled in as self.
