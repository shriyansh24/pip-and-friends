Python asks questions with comparison operators. Each one compares the value on its left with the value on its right.

  • ==is equal to?two equals signs
  • !=is not equal to?the ! means "not"
  • <is less than?the small end points at the smaller side
  • >is greater than?
  • <=less than, or equal?the < always comes first
  • >=greater than, or equal?there is no =>

Pip says: An operator is a symbol that does a job, like +. These six do the job of asking.

      PROFESSOR'S NOTEBOOK
      
    
      
      
      
      These pages go deeper than the comic. You don't need them to carry on, but they explain what Python is really doing. Open any page.
      
    
      
  
      

  
      
    Under the hood: and / or hand back a value, and stop early
    
      
      
      The comic treats and and or as lamp joiners. The full truth is slightly stranger. They don't always give back True or False: they give back one of their two sides.
      
      
        
        
      • x or y: if x is truthy, the answer is x; otherwise it is y.
        • 
        
      • x and y: if x is falsy, the answer is x; otherwise it is y.
        • 
        
      • not x always gives a real True or False.
        • 
      
      
      
      They also short-circuit: if the left side already decides the answer, the right side is never run. Line 7 below would divide by zero, but x != 0 is False, so and stops before the division. This is called a guard.
      
      
      
      
      That's also why name or "anonymous" is a common way to write "use the name, or a default if it's empty".
      
      
      Chains run the middle once
      
      
      a < b < c means a < b and b < c, except that b is worked out only once, and if a < b is False, c is never looked at.
      
      
      How Python sees blocks
      
      
      Before running anything, Python's tokenizer reads the spaces at the start of each line. When a line is indented more than the one before, it records an INDENT. When it moves back out, it records a DEDENT. The Proofreader checks those markers. That is why indentation mistakes are reported before line 1 runs, exactly like other SyntaxErrors.
      
    
      
  
      

  
      
    Under the hood: who goes first (precedence)
    
      
      
      When a condition mixes operators, Python works in this order: maths (+ - * / %), then comparisons (== != < > <= >= in), then not, then and, then or. Brackets change the order, just like in maths.
      
      
      
      
        
        
      • Line 1: and goes before or, so it means True or (False and False), which is True.
        • 
        
      • Line 2: brackets force the or first: True and False, which is False.
        • 
        
      • Line 3: comparisons go before not, so it means not (True == False), which is True.
        • 
        
      • Line 4: (not (3 > 5)) and (2 < 4), which is True.
        • 
      
      
      
      When in doubt, add brackets. They cost nothing, and the next reader will thank you.
      
    
      
  
      

  
      
    In real programs
    
      
      
        
        
      • Checking input. Programs check what people type before using it: "is it empty?" (if not name:), "is it in range?" (if 1 <= choice <= 5:).
        • 
        
      • Forgiving answers. .lower() (or .casefold(), which handles more languages) before comparing, so Yes and YES both work.
        • 
        
      • Searching text. if "error" in line: is how many log-reading scripts find the lines that matter.
        • 
        
      • Checking for None. Experienced Python programmers write is None rather than == None. is asks "is this the very same object?" There is only one None, so it is the clearest test.
          
        • 
        
      • Guard first. Put cheap or safety checks on the left of and, as in the short-circuit page, so the risky part only runs when it is safe.
        • 
        
      • Long ladders. When one value is compared against many fixed choices, Python 3.10 and newer also have a match statement (What's New in Python 3.10: structural pattern matching; tutorial: PEP 636). An if/elif ladder can always do the same job, and it is what you'll meet most often.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "= and == are the same." One gives a name, two ask a question.
        • 
        
      • "if x == 1 or 2: checks both numbers." It means (x == 1) or 2, and 2 is truthy, so it is always True. Write x == 1 or x == 2.
        • 
        
      • "Python reads all the elif rungs and picks the best one." It stops at the first True rung. Order is part of the meaning.
        • 
        
      • "else needs a condition." It never has one. It catches whatever is left over. else if is a SyntaxError; write elif.
        • 
        
      • "Indentation is just for neatness." In Python it decides which lines belong to which block. Move a line left and it leaves the block.
        • 
        
      • "Tabs and spaces are interchangeable." Mixing them can confuse Python and people. Use 4 spaces; most editors insert them when you press Tab in a .py file.
        • 
        
      • ""False" is False." It is a non-empty string, so it is truthy. So is "0".
        • 
        
      • ""10" < "9" compares numbers." It compares characters, so it is True. Convert with int() first.
        • 
        
      • "Comparing text with a number is an error." Only ordering is: "5" < 3 is a TypeError, but "5" == 5 is simply False.
        •

    Words from this chapter
    
      
      
      
        
      comparison operator
      One of == != < > <= >=. Compares two values and gives a bool.
      
        
      bool
      The type with exactly two values, True and False. The lamp.
      
        
      condition
      The question after if or elif. Anything with a truth value.
      
        
      logical operator
      and, or, not. Join or flip conditions.
      
        
      truth table
      A table of every input combination and the answer for each.
      
        
      keyword
      A word that is part of Python itself, like if, elif, else, and. You can't use it as a name.
      
        
      branch
      One road a program can take at a fork.
      
        
      block
      The indented lines after a colon. They run together, or not at all.
      
        
      indentation
      Spaces at the start of a line. In Python they mark blocks. Use 4.
      
        
      elif
      "else, if": the next rung of a ladder, tried only if every rung above was False.
      
        
      nested
      One thing inside another of the same kind, like an if inside an if.
      
        
      truthy / falsy
      Whether a value counts as True or False in a condition. The falsy values in this chapter: 0, 0.0, "", None and False. Every other value you have met here is truthy.
      
        
      chained comparison
      a < b < c: several comparisons joined, meaning each pair must hold.
      
        
      in
      Asks whether one string appears inside another. not in asks the opposite.
      
        
      .lower()
      Gives a lowercase copy of a string. The original is unchanged.
      
        
      short-circuit
      When and / or stop early because the left side already decides the answer.
      
        
      IndentationError
      A SyntaxError about indentation, such as a colon with no indented block after it.
      
        
      TypeError
      An operation used on the wrong kinds of value, such as "5" < 3.
