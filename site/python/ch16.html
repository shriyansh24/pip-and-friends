    Under the hood: the iterator protocol and frozen frames
    
      
      
      
      Two special method names
      
      
      The "packet and dispenser" agreement is called the iterator protocol. iter(x) really calls a method named __iter__ on x, and next(it) calls __next__ on the iterator. A for loop calls both for you. The double underscores mark names Python itself calls; Chapter 20 shows how to give your own classes these methods, which is how the Bag from Panel 29 could become loopable.
      
      
      An iterator is its own packet
      
      
      Calling iter() on an iterator gives back the very same iterator. That is why a for loop over a dispenser carries on from wherever the dispenser was, and why it empties it for everyone. A list, by contrast, loads a brand-new dispenser every time:
      
      
      
      
      What a paused generator keeps
      
      
      A normal function call gets a frame (Chapter 6) that is thrown away at return. A generator's frame is kept between calls to next(): its local names, and the exact spot to resume. That is the Storyteller's bookmark. When the body ends, Python raises StopIteration for you. If the generator has a return value, the value rides along on the exception:
      
      
      
      
      One safety rule (since Python 3.7): if a StopIteration escapes from inside a generator's body, for example from a stray next() call, Python turns it into a RuntimeError. Otherwise a bug could silently end someone else's loop early.
      
      
      Comprehensions have their own room
      
      
      A comprehension's loop variable lives in its own small scope. That is why k never leaked in Panel 19 and why the outer x survived in check 11. The first belt's source, though, is worked out in the surrounding code before the factory starts.
      
    
      
  
      

  
      
    In real programs: streams of records, grids and grouping

    Common wrong ideas
    
      
      
        
        
      • "Round brackets around a comprehension make a tuple." They make a generator expression. For a tuple, write tuple(x for x in xs).
        • 
        
      • "The if in a comprehension always goes at the end." Only a gate does. A choice of value goes in front, with an else (Panel 11).
        • 
        
      • "Calling a generator function runs it." It only builds the generator; the body waits for next() (Panel 36).
        • 
        
      • "Looping over it again will start from the beginning." True for lists, strings, ranges and dict views. False for zip, map, filter, reversed, enumerate, file objects and generators: they stay empty, silently.
        • 
        
      • "StopIteration is a crash." Only when you call next() yourself on an empty iterator. Inside a for loop it is the normal "that's all" signal. To avoid it, give a default: next(it, None) returns None instead of raising.
        • 
        
      • "Comprehensions are always faster and better." They are often a little faster than append in a loop, but clarity matters more. A comprehension built only for its side effects is a mistake (Panel 18).
        • 
        
      • "groupby works like a dict of groups." It only bundles neighbours (Panel 47). To group everything, sort first, or collect into a dict (Chapter 23 shows defaultdict).
        • 
        
      • "sum can join strings." It refuses (Panel 34). Use "".join(...).
        • 
      
      
    
      
  
      

  
      
    Version notes: what is new, and since when
    
      
      
        
        
      • Unpacking in comprehensions ([*L for L in lists], also {*s for s in sets} and {**d for d in dicts}): new in Python 3.15 (PEP 798). Panel 20 shows the real 3.13 SyntaxError.
        • 
        
      • itertools.batched: new in 3.12. Its strict=True option, which refuses a short last batch, arrived in 3.13:
        • 
      
      
      
      
      
        
        
      • zip(..., strict=True) and itertools.pairwise: new in 3.10.
        • 
        
      • StopIteration inside a generator becomes RuntimeError: the rule from PEP 479, on by default since 3.7.
        • 
        
      • Everything else in this chapter (comprehensions, yield, yield from, iter/next, the other itertools) works in every Python 3 you are likely to meet.

    Words from this chapter
    
      
      
      
        
      conditional expression
      a if test else b: a value that depends on a test. The "pocket fork". The else is required.
      
        
      expression
      A piece of code that produces a value, so it can go wherever a value can.
      
        
      comprehension
      A one-line factory that builds a new list, dict or set from an iterable: [stamp for x in belt if gate].
      
        
      filter / filtering
      Keeping only the items that pass a test (the gate, or the filter() built-in).
      
        
      map / mapping
      Turning every item into something else (the stamp, or the map() built-in).
      
        
      generator expression
      A comprehension in round brackets. It builds nothing up front and hands out items lazily.
      
        
      iterable
      Anything that can be gone through one item at a time: lists, strings, ranges, dicts, files. The packet.
      
        
      iterator
      The object that hands out the items and remembers its place. Single-use. The loaded dispenser.
      
        
      iter()
      Gets an iterator from an iterable: loads a dispenser.
      
        
      next()
      Asks an iterator for its next item: one click.
      
        
      StopIteration
      The signal an iterator raises when it is empty. for treats it as "done".
      
        
      lazy
      Works each item out only when it is asked for, instead of all at once.
      
        
      exhausted
      An iterator that has handed out everything. It stays empty.
      
        
      view
      d.keys(), d.values(), d.items(): live, reusable windows onto a dict.
      
        
      generator function
      A def whose body contains yield. Calling it returns a generator.
      
        
      generator
      An iterator made by a generator function or generator expression. The Storyteller.
      
        
      yield
      Hand a value to whoever asked, and pause right here until asked again.
      
        
      yield from
      Hand out every item of another iterable, one by one, before carrying on.
      
        
      pipeline
      Generators feeding each other, stage by stage; nothing moves until the last stage pulls.
      
        
      truthy
      Counts as True in a test (Chapter 4): non-zero numbers, non-empty strings and lists. any, all and filter(None, …) use it.
      
        
      key function
      A function passed with key= that tells sorted, min, max or groupby what to compare.
      
        
      itertools
      The standard-library module of ready-made iterator tools.
