    Under the hood: the drawer index (hashing)
    
      
      
      How does the cabinet open the right drawer instantly, without reading every label? It turns the key into a whole number called a hash, using the built-in hash(). The hash picks a slot in a hidden table, a bit like the index of a book. To look up a key later, Python hashes it again and jumps straight to that slot. On average a lookup takes about the same time whether the dictionary has ten keys or ten million. x in some_list is different: it checks the items one by one.
      
      nb_hash.py
      
      
      Two rules make this work. Equal things must have equal hashes, which is why hash(True) and hash(1) are both 1 (True == 1 in Python). And a key's hash must never change. A list can change after it is filed, so Python refuses to hash it at all:
      
      nb_hash_list.py
      
      
      Why a set of words changes order between runs
      
      
      Since Python 3.3, string hashes are mixed with a random "salt" chosen fresh each time Python starts. This stops attackers from sending a web server thousands of keys that all land in the same slot, which would slow it to a crawl. Run this twice and the number changes:
      
      nb_hash_str.py
      One possible run:
      
      
      That number is from one possible run. Yours will differ, which is exactly the point, so this program is never used as an answer in this book. Small whole numbers hash to themselves, which is why sets of small numbers often look sorted. That's a side effect of the slots, not a promise, so sort before you show.
      
      
      Why dicts keep their order and sets don't
      
      
      Since CPython 3.6 a dictionary keeps two things: a compact list of its entries in the order you added them, and a small table of hash slots that points into that list. A loop walks the entry list, so you get insertion order. Python 3.7 made this a promise of the language, not only of CPython. A set keeps only the slot table, so looping over it follows the slots, and their order depends on the hashes.
      
      
      keys(), values() and items() are live views
      
      
      They don't copy anything. They are windows onto the cabinet, so they show later changes too. Wrap one in list() when you need a real list.
      
      nb_view.py
      
    
      
  
      

  
      
    Dict comprehensions: build a cabinet in one line
    
      
      
      A comprehension builds a whole container in one line. Lists have them, and so do dictionaries. The dictionary shape is {key: value for item in things}, with an optional if at the end to filter.
      
      nb_comprehension.py
      
      
        
        
      • Line 1: each number becomes a key, and its square becomes the value.
        • 
        
      • Line 4: each word becomes a key, and its length becomes the value.
        • 
        
      • Line 7: loop over .items() and keep only the cheap pairs. That's a filter.
        • 
      
      
      
      Each one is the same as an empty {} followed by a for loop that fills it. Use a comprehension when the whole idea fits on one readable line, and the loop when it doesn't. Braces without a colon, {x for x in things}, make a set comprehension instead.
      
    
      
  
      

  
      
    In real programs
    
      
      
        
        
      • Data from the internet. Web services send JSON, which turns into nested dictionaries and lists in Python: user["address"]["city"].
        • 
        
      • Settings. Options like {"theme": "dark", "volume": 7}, read with .get(name, default) so a missing setting doesn't crash anything.
        • 
        
      • Counting and grouping. The standard library has ready-made helpers. A Counter counts for you. A defaultdict(list) builds an empty list the first time you use a new key.
        •

      • Remembering answers. Programs store results they have already worked out in a dictionary (a "cache") to avoid doing the work twice.
        • 
        
      • Sets in the wild. Removing duplicate email addresses, a seen set in a loop ("have I visited this page already?"), and comparing two lists of users with & and -.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "Dictionaries have no order." Older books, and even some recent ones, say this. Since Python 3.7 they keep insertion order. What's true is that == ignores order (see order.py in Panel 16).
        • 
        
      • "in checks the values." It checks the keys. Use value in d.values() for values.
        • 
        
      • "d[0] gives the first item." It looks for a key equal to 0, and that's usually a KeyError.
        • 
        
      • "{} is an empty set." It's an empty dict. Write set().
        • 
        
      • "A set keeps the order I typed." It doesn't, and with strings the order can change from run to run.
        • 
        
      • "I can delete drawers while I loop over the dict." Python stops you:
        • 
      
      
      nb_loop_change.py
      
      
      Loop over a copy of the keys instead. list(prices) makes one before the loop starts:
      
      nb_loop_fix.py
      
      
      • "b = a copies the dictionary." It doesn't. As with Chapter 7's lists, it makes a second name tag for the same cabinet. Use .copy() for a real copy:
      
      nb_alias.py

    Words from this chapter
    
      
      
      
        
      dict
      Short for dictionary: a collection of key: value pairs. You look values up by key.
      
        
      key
      The label you look up by. Keys are unique within one dictionary and must be unchangeable.
      
        
      value
      What's stored under a key. It can be anything, including a list or another dictionary.
      
        
      item
      Also called a pair: one key together with its value. .items() gives them as (key, value) tuples.
      
        
      KeyError
      You asked for a key that isn't in the dictionary.
      
        
      default
      The spare answer .get() or .pop() gives back when the key is missing.
      
        
      insertion
      order
      The order keys were first added. Dictionaries keep it (Python 3.7 and later).
      
        
      counting
      pattern
      counts[x] = counts.get(x, 0) + 1 inside a loop.
      
        
      nesting
      Putting one container inside another, like a list inside a dictionary.
      
        
      immutable
      Can't be changed after it's made: strings, numbers, tuples. Lists, dicts and sets are mutable.
      
        
      hash
      A hash is the whole number Python computes from a key to find its slot. Hashable means it has a hash that can never change, so it can be a key or a set item.
      
        
      TypeError
      The wrong kind of thing for the job, like a list used as a key.
      
        
      AttributeError
      That kind of thing has no such method or attribute, like .add on a dict.
      
        
      set
      An unordered collection with no duplicates. Made with set() or {1, 2, 3}.
      
        
      deduplication
      Removing repeats, for example with set(my_list).
      
        
      set operations
      Union | (in either), intersection & (in both), difference - (in the first only), symmetric difference ^ (in exactly one).

      Version notes
      
      
      Every program here was run with CPython 3.15.2 and 3.13.18. Three of them print different error text: for a list used as a dict key or set item, 3.15 (like 3.14) says cannot use 'list' as a dict key (unhashable type: 'list'), while 3.13 says only unhashable type: 'list'. Everything else matched exactly.
