A program is a list of instructions that a computer follows, one after another, top to bottom.

YOU WRITEinstructions, as plain text
→
A FILEthe recipe card, like hello.js
→
IT RUNSstep by step; results appear on the screen

Kit says: Computers are fast and obedient, with zero imagination. They do exactly what the list says. Nothing more, nothing less.

3

Two words you will hear all the time.

SOURCE CODEthe recipe card

The text you write and save in a file. It just sits there. A recipe card in a drawer cooks nothing.

A RUNNING PROGRAMthe cooking, happening now

What happens while the computer follows that text, step by step. It starts, does things, and ends.

    PART 2 · ONE RECIPE, TWO KITCHENSThe language, the engine, and the host it runs in
    

  
    
    8
    
    Here is the big idea of this chapter. JavaScript is a recipe language. The same recipe can be cooked in different kitchens.
    
    
    
      
    
        
    THE BROWSER KITCHENChrome, Firefox, Safari, Edge
    
        
        
    • document
    • alert()
    • prompt()
    • console
    
      
    
      
    
        
        
    ECMAScript
    • let
    • if … else
    • Math.max()
    • "text"
    
        
    ← SAME →↑ SAME RECIPE ↓
    
      
    
      
    
        
    THE NODE KITCHENNode (also Deno and Bun)
    
        
        
    • fs (files)
    • process
    • console
    
      
    
    
    
    
    
      
    THE RECIPE is the language: JavaScript, officially called ECMAScript. Its words (let, if, Math…) mean the same thing in every kitchen.
    
      
    THE COOK is the engine: the program that reads JavaScript and carries it out.
    
      
    THE KITCHEN is the host: the place the engine works in. Each kitchen adds its own tools, like a page to draw on or a pantry of files.
    
    
    
    
    Picture: three parts. The browser kitchen card: a web page standing on a counter, a pop-up bell and a question card; its tools are document, alert, prompt and console. The cook, between the two kitchens, holds one recipe card titled ECMAScript, listing let, if else, Math.max and "text", and the words "same recipe" point to both kitchens. The Node kitchen card: a pantry with shelves of files, tins, folders and a little terminal; its tools are fs for files, process, and console.

    So what is JavaScript, exactly?
    
    
    
      
      
    
        
    Kit says: JavaScript is a programming language: a set of words and rules for writing instructions. Its official name is ECMAScript.
    
        
    Kit says: And no, it is not Java! Two different languages. The name was picked in 1995, when Java was famous. Like "car" and "carpet".
    
      
    
    
    
    
    The rules are written down in a standard published by Ecma International, by a committee called TC39. A new edition comes out every year, named after the year.

      2. 
      
    2. 2009ES5

      4. 
      
    4. 2016 →one edition

      5.

      the 17th edition
      6. 
    
    
    
    
      
    The Professor says: When someone says "ES6", they mean ES2015. Since then, editions are named by year. ES2026 was approved in June 2026.

    16
    
    Your first real error message. Read it like a detective, clue by clue.
    
    
    
    
      
      
    1. ReferenceError: alert is not defined
      Start here: the line with the error's name and message. A ReferenceError means "I don't know that name". Node has no alert.
      2. 
      
    2. file:///home/you/javascript-ch1/alert.js:1
      Where: the file, written as a file:/// address, then a colon and the line number, 1.
      3. 
      
    3. alert("Dinner is ready!"); and ^
      The line that broke, copied for you. The caret ^ points at the exact spot: the name alert.
      4. 
      
    4. at file:///…/alert.js:1:1
      A trail of footprints: line 1, column 1. The lines after it mention node:internal: they are Node's own machinery, folded here into one note (the full text is just below the terminal). Skip them for now.
      5. 
      
    5. Node.js v26.13.0
      Which Node ran it. Then the exit code: 1 means "failed".

    PART 3 · SET UP YOUR KITCHENInstall Node, open a terminal, find your folder
    

  
    
    18
    
    To cook in the Node kitchen, install Node from nodejs.org. The download page offers two kinds of version.
    
    
    
      
    
        PICK THIS ONE
        
    LTSLong-Term Support
    
        
    The steady version. It gets safety fixes for about three years. This book uses Node 26 LTS.
    
      
    
      
    
        
    CURRENTthe newest
    
        
    The very latest features. It changes often. Great for trying new things, not for learning on.
    
      
    
    
    
    
    
      
      
    Kit says: Installing Node also installs npm, a helper for adding other people's code to your projects. You'll meet it in Chapter 14. The lab in the Professor's notebook has steps for Windows, macOS and Linux.
    
    
    
  
    

  
    
  

  
    
    19
    
    You'll talk to Node through a terminal: a text window where you type commands.
    
    
    
      
      
    
        
    You speak: type a command and press Enter.
    
        
    The computer answers: it does the job and replies with text.
    
        
    Then it waits for your next command, after the $ sign (the prompt).
    
      
    
    
    
    
    
      
      
    Kit says: Like my headset! "Lights, go." Lights come up. Over. Windows calls it Terminal or PowerShell; macOS and Linux call it Terminal.
    
    
    
  
    

  
    
    20
    
    Your first two commands: "Node, which version are you?" and "npm, which version are you?"
    
    
    
    
      
      
    1. you@laptop:~/javascript-ch1$
      The prompt. It shows who and where you are, then waits. You type only what comes after the $.
      2. 
      
    2. node --version
      Asks the Node program for its version. Two dashes, then version. A v and three numbers come back.
      3. 
      
    3. npm --version
      npm came along with Node. It answers with its own, separate version number.
      4. 
    
    
    
    
      
      
    Kit says: If the terminal says it can't find the command node, Node isn't installed yet, or the terminal was opened before the install finished. Close it, open a new one, try again.

    PART 5 · THE REPLA calculator with memory, for trying one line at a time
    

  
    
    32
    
    Type node with no file name, and Node opens the REPL: you type one line, it answers at once.
    
    
    
      
      
    
        
    Read: it reads the line you type.
    
        
    Eval: it works it out ("evaluates" it).
    
        
    Print: it shows you the result.
    
        
    Loop: it waits for the next line, and remembers what you did before, like a calculator's memory key.
    
      
    
    
    
  
    

  
    
    33
    
    A real REPL session. Node's prompt is >. After each > comes what was typed; the line below is Node's answer.
    
    
    
    
    How this run was really made: the capture typed node -i, not node. Its keyboard was a recording, and -i tells Node "open the REPL anyway". In your own terminal, plain node opens exactly this REPL.
    
    
      
      
    1. Welcome to Node.js v26.13.0.
      The banner: which Node you're talking to.
      2. 
      
    2. > let a = 1 then undefined
      This line ties a name tag, a, to the value 1 (Chapter 3 is all about this). Tying a tag has no result to show, so the REPL says undefined: "nothing to show". Not an error.
      3. 
      
    3. > a + 2 then 3
      The REPL remembered a and shows the result. No console.log needed: the REPL echoes every result.
      4. 
      
    4. > console.log(…) then two lines
      First the text that console.log printed, then undefined: console.log itself has no result to give back.
      5. 
      
    5. > .help and > .exit
      Commands that start with a dot talk to the REPL itself. .exit leaves (so does Ctrl+D, or Ctrl+C twice).
      6. 
    
    
  
    

  
    
    34
    
    
      
      
    
        
    Kit says: When the REPL answers undefined, it's like me saying "Copy that. Nothing to report." Not a problem!
    
        
    Kit says: Real errors look different: they have a name like ReferenceError and a message.
    
      
    
    
    
    
    Remember the difference: the REPL echoes every result on its own. A file run with node file.js stays quiet and shows only what you console.log.
    
  
    

  
    
  

  
    
    35
    
    
    Mix-up alert: typing terminal commands at the REPL's >.
    
    
    
    
    How this run was really made: as in panel 33, the capture started the REPL with node -i because its typing was a recording. Plain node gives you the same REPL.
    
    
    
      
      
    Kit says: At > you're talking to JavaScript, not to the terminal. To JavaScript, node hello.js is gibberish and ls is an unknown name. Leave with .exit first, then type terminal commands at the $.
    
    
    
    
    Look at the prompt before you type. $ means the terminal is listening. > means the JavaScript REPL is.

    • Check what something gives back.
    • Do a quick sum.
    • Nothing is saved when you leave.
    
      
    
      
    
        
    A .js FILEa recipe you keep

    • Programs you change and run again.
    • Every program in this book.
    
      
    
    
    
    
    
      
    A SECOND REPL: THE BROWSER CONSOLEevery browser has one

It's a REPL in the browser kitchen: document and alert work there, and the output of console.log lands there too. In Safari, first turn on the developer features in Settings, Advanced.
    
    
    
  
    

  
    
  

  
  
    PART 6 · DETECTIVE SCHOOLRead any Node error, then ask for help like a pro
    

  
    
    37
    
    Every Node error message is a set of clues. Read them in this order:
    
    
      
      
    1. Find the Name: message line. It's in the middle, just after a blank line. The name says what kind of trouble; the message says what happened.
      2. 
      
    2. Find your file and line number. At the very top: file:///…/alert.js:1. Line 1.
      3. 
      
    3. Look at the copied line and its caret ^: the exact spot.
      4. 
      
    4. Skip Node's machinery. Lines with node:internal are Node's own code. The last line just names the Node version.
      5. 
    
    
    
    
      
    The Professor says: The list of at … lines is called a stack trace: the trail of footprints that led to the error. In Chapter 12 you'll follow longer trails.

    Under the hood: what happens when you type node hello.js
    
    
      
      
        
    1. The terminal finds the node program on your computer (it searches a list of folders called the PATH) and starts it, handing it the word hello.js.
      2. 
        
    2. Node finds the file, relative to the folder the terminal is standing in. If it is not there, you get MODULE_NOT_FOUND and nothing else happens.
      3. 
        
    3. Node decides what kind of file it is. This chapter's folder has a package.json file containing "type": "module", so every .js file here is an ES module, the modern style. That is why the error messages show file:/// addresses. (Modules get their own chapter, Chapter 14.)
      4. 
        
    4. V8 parses the text: it checks the grammar of the whole file and builds a tree of what each part means. A grammar mistake stops everything here, before any line runs: a SyntaxError (Chapter 2).
      5. 
        
    5. V8 turns the tree into bytecode, a compact list of simple steps, and its interpreter (named Ignition) runs them one by one.
      6. 
        
    6. Hot code gets compiled. If some code runs many times, V8 translates it into the CPU's own machine code while the program is running, so it gets faster. Doing this "just in time" is called JIT compilation. V8 has several compilers for this (Sparkplug, Maglev and TurboFan), from quick-and-simple to slow-and-very-fast.
      7. 
        
    7. When the last line is done and nothing is left waiting, Node exits with code 0. An uncaught error exits with code 1.
      8.

    Where does a name like alert come from?
    
      
    Every running JavaScript program has a global object, the kitchen's big shelf of ready-made tools. The language puts its own things on it (Math, JSON), and the host adds the rest (document in browsers, process in Node). The language gives this shelf the same name everywhere, globalThis, which is what kitchen_check.js looks inside. When a line uses a name that is neither on the shelf nor made by your program, the engine throws a ReferenceError.
    
    
    
  
    

  
    
    In real programs: why one language runs everywhere
    
    
      
      
        
    • In browsers, JavaScript is the only programming language every browser runs natively (alongside WebAssembly, a low-level format), which is why every interactive website uses it.
      • 
        
    • On servers. In 2009 Node took the V8 engine out of the browser and gave it a new kitchen with files, networking and processes. Suddenly the same language could run a web server.
      • 
        
    • In tools. Much of the software developers use every day is written in JavaScript or TypeScript and runs on Node, for example npm itself and many build tools. VS Code is built on Electron, which combines a browser engine with Node.
      • 
        
    • Other kitchens. Deno (V8) and Bun (JavaScriptCore) are newer server-side hosts. They run the same language, but some of their own tools differ from Node's.
      • 
      
    
      
    Output streams and exit codes
    
      
    A running program has two output streams. Normal output goes to standard output (stdout); error messages go to standard error (stderr), shown in red in this book's terminals. Every program also ends with an exit code: 0 for success, anything else for failure. Scripts and tools read it to decide what to do next.
    
      
    
    
    
  
    

  
    
    Common wrong ideas
    
    
      
      
        
    • "JavaScript is a kind of Java." No. Different languages, different designs. The similar name is a piece of 1995 marketing history.
      • 
        
    • "console.log is part of the language." It is a host tool. Browsers and Node each provide one; it is described by the WHATWG Console Standard, not by ECMAScript.
      • 
        
    • "Node is a programming language." Node is a host, a kitchen. The language it runs is JavaScript.
      • 
        
    • "If it works in my browser, it works in Node" (or the other way round). Only the language part is shared. document, alert and prompt give a ReferenceError in Node; fs and process do not exist in a web page.
      • 
        
    • "undefined at the REPL means something failed." It means "this line has no result to show". Errors have a name and a message.
      • 
        
    • "ES6 is the newest JavaScript." ES6 is ES2015. New editions arrive every year; ES2026 is the 17th.
      • 
        
    • "Node runs what's in my editor." Node runs what's saved on the disk.
      • 
        
    • "Every ES2026 feature works in Node 26." Not quite: engines add features one at a time. For example, Math.sumPrecise is one of ES2026's additions (InfoWorld's report on the ES2026 approval lists it), but this book's Node 26.13 doesn't have it yet: asking for its type gives undefined, "no such thing" (run below). Check a feature before you rely on it (MDN's compatibility tables are the usual place).
      • 
        
    • "The top line of an error is the most important." In Node, look for the Name: message line first. In a "Cannot find module" error, the top lines even point into Node's own code.

    Lab: run it yourself (Windows, macOS, Linux)
    
    
      
    1. Install Node 26 LTS
    
      
      
        
    • Windows: download the LTS installer (.msi) from nodejs.org and run it. Or, in a terminal: winget install OpenJS.NodeJS.LTS.
      • 
        
    • macOS: download the LTS installer (.pkg) from nodejs.org.
      • 
        
    • Linux: use the binaries from nodejs.org, or the instructions on its download page for your distribution. The version in your system's package manager may be older than 26.
      • 
        
    • Any system: a version manager lets you install and switch Node versions, for example nvm (macOS, Linux: nvm install 26), nvm-windows, or fnm (fnm install 26).
      • 
      
    
      
    2. Open a terminal and check
    
      
      
        
    • Windows: Terminal (PowerShell) from the Start menu. macOS: Terminal, in Applications, Utilities. Linux: your desktop's Terminal app.
      • 
        
    • Type node --version and npm --version. If either one says the command can't be found or isn't recognized, close the terminal, open a new one, and try again; if it still fails, re-run the installer.
      • 
        
    • On Windows, if PowerShell refuses to run npm with a message about running scripts being disabled, use npm.cmd --version or run it from Command Prompt; this is a PowerShell security setting, not a Node problem.
      • 
      
    
      
    3. Write and run
    
      
      
        
    1. Make a folder, for example javascript-ch1, and open it in VS Code (File, Open Folder).
      2. 
        
    2. Create hello.js containing console.log("Hello, world!");. Save it.
      3. 
        
    3. In the terminal, go to the folder: cd javascript-ch1 (use pwd and ls to check). VS Code also has a built-in terminal (Terminal, New Terminal) that opens in your folder already.
      4. 
        
    4. Run node hello.js. Expected: Hello, world!
      5. 
        
    5. Change the text, run again without saving. Then save and run. See the difference.
      6. 
        
    6. Add a line alert("Hi"); after the first. Run it. Read the ReferenceError like a detective, then delete the line.
      7. 
        
    7. Try node --watch hello.js. Change and save the file a few times. Press Ctrl+C to stop.
      8. 
      
    
      
    4. Try both REPLs
    
      
      
        
    1. Type node alone. Try 1 + 2, let a = 1, then a + 2. Type .help, then .exit.
      2. 
        
    2. Open any web page, press F12, and choose Console. Type alert("Hi from the browser kitchen"). It works there!
      3. 
        
    3. Save the three lines of hello.html from panel 11 next to hello.js, open the page in a browser, and find Hello, world! in its console.
      4.

    Version notes: Node 26 and Node 22
    
    
      
    Every program in this chapter was also run on Node 22.23.4, an older LTS line that is still supported. Apart from version numbers, every program prints the same normal output on both. The differences are all in the details:
    
      
      
        
    • The REPL banner names the version (Welcome to Node.js v22.23.4. there).
      • 
        
    • node --version, npm --version and the V8 version are different numbers (npm 10 comes with Node 22).
      • 
        
    • In error messages, the lines inside Node's own code (node:internal/…) point to different line numbers, and the last line names the other version. Your own file's line and column, the error's name and its message are identical.
      • 
      
    
      
    Deno and Bun would also run every successful program here. Their error messages are laid out differently, so the clue-reading habits matter more than the exact text.
    
    
    
  
    

  
    
    Words from this chapter
    
    
      
    
        
    program
    A list of instructions a computer follows, in order.
    
        
    source code
    The text of a program, as you write and save it.
    
        
    running program
    What happens while the computer follows the source code.
    
        
    output
    What a running program shows, for example lines on the screen.
    
        
    JavaScript
    A programming language for browsers, servers and tools.
    
        
    ECMAScript
    The official name of the JavaScript language standard. Editions are named by year (ES2015, also called ES6; ES2026).
    
        
    edition
    One yearly version of the ECMAScript standard.
    
        
    engine
    The program that reads and runs JavaScript: V8, SpiderMonkey, JavaScriptCore.
    
        
    host
    The environment an engine runs in (a browser, Node, Deno, Bun). It adds its own tools.
    
        
    host tool (host API)
    A ready-made tool that comes from the host, not from the language: document, alert, fs, process, console.
    
        
    Node (Node.js)
    A host that runs JavaScript outside the browser, with the V8 engine.
    
        
    LTS
    Long-Term Support: a version that gets fixes for a long time. This book uses Node 26 LTS.
    
        
    npm
    A tool that comes with Node for adding other people's code to a project.
    
        
    terminal
    A text window where you type commands.
    
        
    prompt
    The sign that says "your turn": $ in the terminal, > in the Node REPL.
    
        
    folder (directory)
    A container for files and other folders.
    
        
    path
    The address of a file or folder, like /home/you/javascript-ch1/hello.js.
    
        
    pwd / ls / cd
    Terminal commands: where am I, what's here, go into a folder.
    
        
    code editor
    A program for writing code, such as VS Code.
    
        
    file extension
    The end of a file name, like .js, that says what kind of file it is.
    
        
    console.log
    The print instruction: writes a line to the console (the screen in Node).
    
        
    string
    Text in quotes, like "Hello, world!".
    
        
    REPL
    Read, Eval, Print, Loop: type one line, see its result at once. Start it with node.
    
        
    undefined
    JavaScript's word for "no value here". At the REPL it means "nothing to show". Not an error.
    
        
    module
    Node's word for a JavaScript file it loads.
    
        
    ReferenceError
    An error meaning "I don't know that name", like alert in Node.
    
        
    MODULE_NOT_FOUND
    The code for "Cannot find module": Node could not find the file you asked it to run.
    
        
    stack trace
    The list of at … lines in an error: the trail that led to it.
    
        
    caret
    The ^ mark under a copied line, pointing at the trouble.
    
        
    exit code
    A number a program ends with: 0 for success, anything else for failure.
    
        
    JIT compilation
    Translating code into machine code while the program runs, to make busy parts faster.
    
        
    global object
    The shelf of ready-made tools every program can use; called globalThis in every host.
