CHAPTER 9

CRATES AND CONVEYOR BELTS

Picture: Kit, the stage manager in a pink hoodie and headset, waves hello next to the crate creature: a row of three boxes holding 'hat', 'cape' and 'mask', numbered 0, 1 and 2 underneath.

One value per name gets clumsy fast. Today you learn the array: a crate of numbered boxes that can carry as many values as you like. You'll add and remove boxes at both ends, copy and cut, and then send whole crates down a factory conveyor belt that repaints boxes, drops some through a trapdoor and tips all of them into one bucket. About 120 minutes, with 29 hands-on checks.

  1. Open the crate: boxes numbered from 0
  2. Back door, front door: push, pop, shift, unshift
  3. Search, cut and glue: slice, splice, grids and holes
  4. The conveyor belt: forEach, map, filter, find
  5. One bucket catches them all: reduce and chains
  6. Sorting the boxes
  7. Boss level and recap

    26
    
        Down in the scenery workshop, a conveyor belt carries boxes past machines.
        
    
        
      
      
        
        
        Kit says: You already know how to loop over a crate with for...of. But most loops do one of a few jobs: change every box, keep some boxes, find one box, or add everything up.

          Remember the mystery from Chapter 5? ["1", "2", "3"].map(parseInt) gave a strange answer. You now have every clue.
          
    parseint_map.js
    
          
    
          
    
            
      
          1. map calls the card with two things: the box and its index (panel 28's forEach did the same).
            2. 
      
          2. parseInt takes an optional second value: the radix, the number base to read in (10 for ordinary numbers, 2 for binary).
            3. 
      
          3. So the boxes are read as parseInt("1", 0), parseInt("2", 1), parseInt("3", 2). Radix 0 means "work it out", which gives 1. Base 1 doesn't exist: NaN. In base 2 there's no digit 3: NaN. Lines 2–4 print exactly that.

          What you learned in Chapter 9
          
    
            
      
          • COUNT BOXES FROM ZEROAn array is a crate: [a, b, c], read with arr[0], last at length - 1 or .at(-1). Past the end you get undefined, not an error. <= in a loop is the classic off-by-one.

            •

    Under the hood: what an array really is
    
          
      
          An object with number-named properties
          
      
          In the specification, an array is an object whose property names include the indexes "0", "1", "2"… plus a special length property that always stays one more than the highest index. That's why typeof says "object", why writing to index 4 of a short array makes length jump (panel 22), and why setting length smaller deletes the boxes at the back (panel 23).
          
      
          Why the front is slow
          
      
          Engines such as V8 store most arrays as a compact block of memory, one slot after another. Adding or removing at the end touches one slot. Adding or removing at the front means moving every other element along by one, so the work grows with the length of the array. For small arrays you won't notice; for very long queues, it's a reason to prefer push/pop.
          
      
          Holes are expensive too
          
      
          Sparse arrays (panel 22) may be stored differently, like a dictionary of index to value, which is slower. Methods also disagree about holes. In this real run, forEach visits only the two real boxes, map skips the hole and keeps it, filter drops it, while for...of, find and includes treat it as undefined. MDN's array reference lists which methods do what.
          
      holes_methods.js
      
          
      
          
      
          How sort compares
          
      
          MDN: without a comparator, elements are converted to strings and compared by their UTF-16 code units, and undefined elements go to the end. Since ECMAScript 2019, sort is stable: elements that compare equal keep their original order. Your comparator should be consistent (always the same answer for the same pair); a random one gives a biased shuffle.
          
      
          includes versus indexOf
          
      
          indexOf uses strict equality (===). includes uses "SameValueZero", which is the same except that NaN equals NaN. That single difference is panel 47.
          
    
          
  
          

  
          
    In real programs
    
          
      
            
        
          • Data from servers arrives as arrays of records (lists of users, products, messages). filter, map, find and reduce are how most JavaScript code shapes that data for the screen.
            • 
        
          • User interfaces build lists with map. In React, for example, a list of items on screen is usually made with items.map(item => …).
            • 
        
          • Prefer the copying methods in shared code. A function that sorts or splices its argument surprises the caller (Boss 2). Many teams use toSorted, slice and spread copies so functions don't change what they're given.
            • 
        
          • Stacks and queues: push+pop makes a stack (last in, first out), as in an "undo" history. push+shift makes a queue (first in, first out), as in Boss 3.
            • 
        
          • Linters help: ESLint's array-callback-return rule flags a map or filter card that forgets to return (panel 32). TypeScript (Chapter 26) checks the kinds of values before the program runs, so mistakes like cast = cast.push(…) can be reported while you type.
            • 
        
          • Sorting text for people: real apps sort names with a.localeCompare(b), which follows a language's alphabet instead of code units. In this real run (with LANG=en_US.UTF-8) it puts "apple" and "Apple" together:
          locale_sort.js

    Common wrong ideas
    
          
      
            
        
          • "The first element is number 1." It's 0. The last is length - 1.
            • 
        
          • "Reading past the end is an error." In JavaScript it's undefined. The crash comes later, when you use it.
            • 
        
          • "arr[-1] is the last element." Only arr.at(-1) counts from the back.
            • 
        
          • "push hands back the array." It hands back the new length.
            • 
        
          • "const arrays can't change." Their contents can. Only the tag is fixed.
            • 
        
          • "slice and splice are the same thing." One copies, one cuts.
            • 
        
          • "forEach makes a new array." It hands back undefined. Use map.
            • 
        
          • "filter hands back undefined when nothing matches." It hands back []. find is the one that gives undefined.
            • 
        
          • "sort() sorts numbers." It sorts text. Bring a comparator.
            • 
        
          • "sort makes a sorted copy." It changes the original. toSorted copies.
            • 
        
          • "An empty array is falsy." It's truthy. Test length === 0.
            • 
        
          • "Two arrays with the same contents are ===." They're two different arrays (Chapter 10).
            • 
        
          • "new Array(3) is [3]." It's three empty slots.

    Words from this chapter
    
          
      
          
        
          array
          An ordered list of values under one name, written [a, b, c].
          
        
          element
          One value in an array: the cargo of one box.
          
        
          index
          An element's position number, counted from 0.
          
        
          array literal
          Writing an array directly with square brackets.
          
        
          length
          How many elements; one more than the last index. You can also set it.
          
        
          off-by-one error
          A loop or index that goes one step too far or stops one step short.
          
        
          push / pop
          Add to / remove from the back.
          
        
          unshift / shift
          Add to / remove from the front; every other element is renumbered.
          
        
          mutate
          Change an existing array in place, rather than making a new one.
          
        
          slice
          Copy part of an array into a new array; the end index is not included.
          
        
          splice
          Remove, insert or replace elements in the array itself; hands back the removed ones.
          
        
          concat
          Join arrays into a new, longer array.
          
        
          join
          Glue all elements into one string with a separator.
          
        
          nested array / grid
          An array whose elements are arrays; read with grid[row][col].
          
        
          hole / sparse array
          An index with no element at all, shown as <1 empty item>.
          
        
          Array.isArray
          The reliable test for "is this an array?".
          
        
          RangeError
          An error for a number outside the allowed range, such as an array length of -1.
          
        
          callback
          A function handed to another function, which calls it (Chapter 7).
          
        
          iteration method
          An array method that calls your callback for each element: forEach, map, filter…
          
        
          forEach
          Call a function for each element; hands back undefined.
          
        
          map
          A new array of the callback's return values, same length.
          
        
          filter
          A new array of the elements the callback says true to.
          
        
          find / findIndex / findLast
          The first (or last) element that passes, or its index.
          
        
          some / every
          Does at least one / do all elements pass?
          
        
          reduce
          Combine all elements into one value, carrying an accumulator.
          
        
          accumulator
          The running value reduce carries from call to call: the bucket.
          
        
          initial value
          The accumulator's starting value, given after the callback.
          
        
          method chaining
          Calling a method on the result of another: .filter(…).map(…).
          
        
          comparator
          A function (a, b) => number that tells sort which comes first.
          
        
          stable sort
          A sort that keeps equal elements in their original order.
          
        
          toSorted / toReversed
          Sorted / reversed copies; the original is unchanged.
          
        
          flat
          A new array with nested arrays unpacked one level (or more).
          
        
          Array.from
          Build an array from a string, a length, or another list-like thing.
          
        
          radix
          The number base parseInt reads in: 10, 2, 16…
          
        
          vacuous truth
          "Every element passes" being true for an empty array.
