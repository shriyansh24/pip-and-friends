CHAPTER 4

NECKLACES AND SCISSORS

Picture: Kit, the stage manager in a pink hoodie with a headset and a clipboard, waves hello.

Text in JavaScript is a string: a necklace of characters, sealed in glass. You'll write strings three ways, fill them in with templates, count their beads from 0, search them, cut them with scissors, glue them back together, tidy them, chain tools into a production line, and find out why "10" comes before "9". About 90 minutes, with 31 hands-on checks.

  1. Necklaces in glass: quotes, beads and the sealed case
  2. Glue and stencils: + and template literals
  3. Finding beads: searching a string
  4. Scissors and glue: slice, split and join
  5. Tidy up and chain
  6. Who comes first? Comparing strings, and two traps
  7. Boss level and recap

    5
    
The backslash \ is a wink: "the next character isn't what it looks like". The pair is called an escape sequence, and it stands for one character in the string.

    

      
\'a single quote that doesn't end the string

      
\"a double quote that doesn't end the string

      
\\one real backslash

      
\nnew line: the text carries on on the next line

      
\ttab: a jump to the next tab stop

    

    

      
      
The Professor says: Because the backslash winks, writing one plain backslash takes two: \\. Forget that, and a Windows folder like C:\new turns into C:, a new line, and ew. You'll see it in a moment.

    Under the hood: code units, borrowed methods and sealed glass
    
      
      
      What a string really is
      
      
      The ECMAScript standard defines a string as an ordered list of 16-bit numbers called UTF-16 code units. That is all a string is. length counts code units; s[i] and s.at(i) read one code unit and hand it back as a new one-unit string; < compares code units one by one. For the letters, digits and punctuation on an English keyboard, one character is exactly one code unit, so "bead" and "character" mean the same thing.
      
      
      Characters outside the first 65,536 codes, like most emoji, are stored as two code units, called a surrogate pair. That's why "😀".length is 2. Chapter 22 shows the tools that count what you see: [...s], for...of and Intl.Segmenter.
      
      
      How can a primitive have methods?
      
      
      Chapter 2 said strings are primitives, not objects. Yet "kit".toUpperCase() works. When you put a dot after a string, the engine looks the name up on String.prototype, a shared object holding every string method. The method runs with your string as its input and returns a new string. Your string itself never becomes an object and never changes. (The standard describes this as briefly wrapping the string in a String object; engines like V8 skip the wrapper in practice.)
      
      
      Why immutable?
      
      
      Because strings can't change, the engine can share them safely: two names can point at one string, and no one can surprise the other. V8 also stores many strings cleverly behind the scenes: gluing with + may first build a "rope" that points at both pieces, and a slice may point into its parent. You never see any of this, which is the point: sealed glass lets the engine cheat safely.
      
      
      The exact rules of slice and substring
      
      
        
        
      • slice(start, end): a negative number has the length added to it; then both are clamped to 0..length. If start ≥ end, the result is "".
        • 
        
      • substring(start, end): negatives and NaN become 0; both are clamped to 0..length; then the smaller one is used as the start.
        • 
        
      • Leaving out end means "to the end" for both.
        • 
        
      • An old third cousin, substr(start, length), is listed in the standard's "legacy" annex. Don't use it in new code.
        • 
      
      
      
      Why a strict-mode TypeError for s[0] = "H"?
      
      
      Each bead of a string behaves like a property that is not writable. Assigning to a non-writable property is silently ignored under the old rules, and throws a TypeError in strict code. Every ES module is strict, which is why this book's .js files throw and the .cjs file doesn't.
      
    
      
  
      

  
      
    In real programs
    
      
      
        
        
      • Cleaning what people type. Forms almost always trim() input before saving or comparing it, and compare e-mail addresses after toLowerCase().
        • 
        
      • Slugs. The chain from Part 5 is how blog and shop addresses like /people/ada-lovelace are made. Real slug makers also remove accents and punctuation, usually with regular expressions (Chapter 22).
        • 
        
      • Padding. padStart(2, "0") turns 7 into 07 for clocks and dates; padEnd lines up columns in terminal tools.
        • 
        
      • Templates everywhere. Modern code builds messages, file paths and HTML with template literals. Careful with HTML: a name like <b> typed by a user becomes real markup if you glue it into a page, so web frameworks "escape" values before inserting them.
        • 
        
      • Splitting data. split(",") is fine for simple lists. Real CSV files can have commas inside quoted values, so programs use a CSV library instead of a plain split.
        • 
        
      • Line endings. Text files made on Windows end lines with "\r\n", others with "\n". Splitting a Windows file at "\n" leaves a stray "\r" on each line; trimEnd() removes it.
        • 
        
      • Sorting names. Lists of names are sorted with localeCompare (or the faster Intl.Collator), never with plain <, so adam and Zoe land where people expect. Sorting lists is Chapter 9.
        • 
        
      • Linters help. ESLint's prefer-template rule suggests templates instead of long + chains, and no-template-curly-in-string warns about "${name}" in ordinary quotes, the bug from panel 19.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "Single and double quotes mean different things." They make exactly the same strings. Only backticks add something: holes and line breaks.
        • 
        
      • "The first character is s[1]." It's s[0]. The last is s[s.length - 1], or s.at(-1).
        • 
        
      • "s[-1] is the last character." In JavaScript it's undefined. Only at() and slice() count backwards.
        • 
        
      • "Reading past the end is an error." It's undefined, silently. That's why off-by-one bugs hide so well.
        • 
        
      • "toUpperCase() changes my string." No method can change a string. Keep the result: s = s.toUpperCase().
        • 
        
      • "const is why I can't change a bead." A let string is just as sealed. let lets the tag move to a new string; nothing lets you change the old one.
        • 
        
      • "replace replaces every match." Only the first. Use replaceAll.
        • 
        
      • "indexOf gives false when it finds nothing." It gives -1, and a match at the front gives 0. Use includes for yes-or-no questions.
        • 
        
      • "slice(2, 5) includes bead 5." The end is not included. Think of the numbers as gaps.
        • 
        
      • "length is a method." It's a number: s.length, no brackets.
        • 
        
      • "Strings are arrays of characters." They share indexes and length, but strings have no push, map or other list tools. s.split("") makes a real list when you need one.
        • 
        
      • ""10" < "9" is false, obviously." It's true. Strings compare character codes, not amounts. Convert to numbers first (Chapter 5), or use localeCompare with { numeric: true }.
        • 
        
      • ".length counts the characters I see." It counts UTF-16 code units, so many emoji count as 2.

    Words from this chapter
    
      
      
      
        
      string
      A value made of text: an ordered row of characters, written in quotes or backticks.
      
        
      template literal
      A string in backticks. It can span lines and has ${ } holes to fill.
      
        
      interpolation
      Dropping the value of an expression into a template's ${ } hole.
      
        
      escape sequence
      A backslash and a character that together stand for one special character, like \n.
      
        
      concatenation
      Gluing strings together, with +.
      
        
      index
      A bead's number, counted from 0.
      
        
      length
      How many code units (beads) a string has. A number, not a method.
      
        
      off-by-one
      A mistake where a count is one too many or too few, like reading s[s.length].
      
        
      immutable
      Cannot be changed once made. Strings are immutable.
      
        
      method
      A tool that belongs to a value, called with a dot and brackets: s.trim().
      
        
      empty string
      "": a string with no beads. Its length is 0.
      
        
      separator
      The mark split cuts at, or the glue join puts between pieces.
      
        
      array
      A list of values in square brackets, like the pieces split returns (Chapter 9).
      
        
      whitespace
      Invisible characters: spaces, tabs, line breaks.
      
        
      padding
      Adding characters to the front or back of a string until it is long enough.
      
        
      method chain
      Several methods in a row, each called on the result of the one before.
      
        
      slug
      A tidy, lower-case, dash-joined version of a title, for use in web addresses.
      
        
      character code
      The number a character is stored as; charCodeAt reads it.
      
        
      UTF-16 code unit
      The 16-bit number JavaScript stores each piece of a string as. Most characters use one; many emoji use two.
      
        
      locale
      A language and region's rules, such as dictionary order. "en" is English.
      
        
      identifier
      A name in code, like s or word.
      
        
      RangeError
      An error meaning "the value is the right kind but outside the allowed range", like repeat(-1).
      
        
      logic bug
      A mistake that produces wrong results without any error message. Sneak's speciality.
