TOGGLES AND INVISIBLE INK

Picture: Kit, the stage manager in a pink hoodie and headset, waves hello. Objects have been drawers with labels since Chapter 10. Today you open the back panel. Every drawer has three little toggles that decide whether it can be changed, whether it shows up when someone lists the drawers, and whether it can be removed. You'll lock a whole object with Object.freeze (and find out why the lock only reaches the top layer), and pick up a toolbox of object helpers. Then come symbols, keys written in invisible ink, and the question that has hung over this book since Chapter 5: why is [] + {} the text [object Object]? About 130 minutes, with 26 hands-on checks.

PART 2 · FREEZE, SEAL, AND THE TOP LAYERLocking a whole object, and where the lock stops


  

    11
    
Setting toggles one drawer at a time is fiddly. Three built-in tools lock a whole object at once, each a bit tighter than the last.

    

      
preventExtensionsno new drawers
Object.preventExtensions(obj): nothing can be added. Existing drawers keep their toggles, so they can still be changed and deleted.

      
sealno new, no removing
Object.seal(obj): no new drawers, and every drawer's C goes OFF. Values can still change.

      
freezenothing at all
Object.freeze(obj): no new drawers, every C OFF and every W OFF. Read-only from top to bottom… of the top layer.

    

    

      
      
    

    
Picture: two control panels. The sealed object's seats row has W ON, E ON, C OFF. The frozen object's panel has a FROZEN badge and a dashed outline; its seats row has W OFF, E ON, C OFF.

    What you learned in Chapter 19
    
    
      
      
    • EVERY DRAWER HAS THREE TOGGLESwritable (can it change?), enumerable (is it listed by Object.keys, for...in, JSON and spreading?) and configurable (can it be deleted or rewired? turning it off is a one-way door). Read them with Object.getOwnPropertyDescriptor; set them with Object.defineProperty, whose toggles start OFF for new drawers. Getters and setters are drawers that run code.
      • 
      
    • STRICT SHOUTS, SLOPPY SHRUGSA write to a read-only drawer throws TypeError: Cannot assign to read only property 'seats' of object '#<Object>' in strict code (every ES module) and is silently ignored in sloppy code. Built-in methods like push throw either way. defineProperty on a primitive throws Object.defineProperty called on non-object.
      • 
      
    • FREEZE ONLY LOCKS THE TOP LAYERpreventExtensions stops new drawers, seal also stops deleting, freeze also stops changing. Inner objects stay open unless you deep-freeze them. const glues the tag; freeze locks the drawers. The toolbox: entries out, array tools, fromEntries back; index keys first, then insertion order; Object.assign and spreading copy values shallowly; Object.hasOwn; Object.groupBy and Map.groupBy.
      • 
      
    • ONLY THE EXACT KEY OPENS THE INK DRAWEREvery Symbol() is new and unique; the description is just a label. Symbol keys are hidden from Object.keys and JSON but not secret. Symbol.for shares keys through a registry. Symbols refuse quiet conversion: Cannot convert a Symbol value to a string. Well-known symbols are the language's hooks.
      • 
      
    • THE HINT COMES FROM THE OPERATORObjects become primitives by Symbol.toPrimitive if present, otherwise toString then valueOf for "string", and valueOf then toString for "number" and "default".     Under the hood: attributes, integrity levels and ToPrimitive
    
    
      
    Property attributes
    
      
    The ECMAScript standard stores each property as a record of attributes, written in double square brackets. A data property has [[Value]], [[Writable]], [[Enumerable]] and [[Configurable]]. An accessor property has [[Get]], [[Set]], [[Enumerable]] and [[Configurable]]. A descriptor object is just how JavaScript lets you read and write that record. The standard forbids passing both value and get to defineProperty, because no property can be both kinds (not run here).
    
      
    The configurable rules, exactly
    
      
    When [[Configurable]] is false, the standard's ValidateAndApplyPropertyDescriptor allows only two changes: [[Writable]] from true to false, and a new [[Value]] if the property is still writable. Everything else, including deleting, flipping E, or turning a data property into an accessor, is refused. That's the one-way door in locked.js.
    
      
    Integrity levels
    
      
    Every object has an internal [[Extensible]] flag. preventExtensions clears it. seal clears it and sets every own property's [[Configurable]] to false. freeze does that and sets [[Writable]] to false on every data property (accessors keep their setters: a frozen object's setter still runs, and may change some other object). isFrozen checks that the object isn't extensible and every own property is locked. None of this reaches private #fields, which aren't properties, so a frozen class instance can still change its private state.
    
      
    Silent failure, explained
    
      
    Assignment calls the object's internal [[Set]], which returns true or false. In strict code a false result throws a TypeError; in sloppy code it's thrown away. Built-in methods such as Array.prototype.push are specified to throw whenever a write fails, which is why fz_push.cjs throws in sloppy mode.
    
      
    Key order
    
      
    The standard's OrdinaryOwnPropertyKeys lists array-index keys (canonical numeric strings from 0 up to 232 − 2) in ascending order, then other string keys in creation order, then symbols in creation order. Object.keys, for...in (for the object's own keys), JSON.stringify and Object.entries all follow it.
    
      
    ToPrimitive and OrdinaryToPrimitive
    
      
    ToPrimitive(input, hint) first looks up input[Symbol.toPrimitive]. If it exists, it is called with the hint and must return a non-object, or a TypeError is thrown. Otherwise the standard runs OrdinaryToPrimitive, which calls toString then valueOf for "string" and the reverse for "number", skipping any that are missing or return an object, and throws if neither gives a primitive. A missing hint means "default", which OrdinaryToPrimitive treats as "number". Date.prototype[Symbol.toPrimitive] maps "default" to "string", and Symbol.prototype[Symbol.toPrimitive] returns the symbol itself, which is why a Symbol wrapper object converts back to a symbol.
    
      
    Symbols
    
      
    A symbol is a primitive whose only property is its identity, plus an optional [[Description]]. Property keys are either strings or symbols, nothing else: a number key is turned into a string first (ToPropertyKey, which asks objects with the hint "string"). Symbol() can't be called with new. The global registry is shared by every realm in the process (for example, every iframe on a page). The well-known symbols are the same values in every realm.
    
      
    Template objects
    
      
    The strings array a tag receives is frozen, has a frozen raw array, and is created once per place in the source code: calling the same tagged template in a loop passes the very same array every time. That lets libraries cache work per template. Invalid escapes such as \unicode are allowed in tagged templates (the cooked piece becomes undefined, the raw piece keeps the text), which is why String.raw`C:\users` works.
    
    
    
  
    

  
    
    In real programs
    
    
      
      
        
    • Configuration and constants: apps often Object.freeze their settings or lookup tables (a list of HTTP status codes, a colour palette) so nothing changes them by accident. Teams that freeze nested data use a deep-freeze helper or a library.
      • 
        
    • State management: UI frameworks expect state to be treated as immutable: you make a changed copy (with spreading or Object.assign) instead of editing. Some libraries freeze state in development builds to catch accidental edits, and the strict-mode TypeError then points straight at the culprit.
      • 
        
    • Hidden helpers: libraries use enumerable: false for internal bookkeeping on objects they hand you, so it doesn't appear in your loops or JSON. Built-in methods are non-enumerable for the same reason.
      • 
        
    • Getters and setters validate input, compute values on demand (a full name from first and last), or keep a cached value fresh. Many front-end frameworks use getters or Proxies to notice when data is read and changed.
      • 
        
    • Symbols appear as private-ish markers in libraries (a symbol key that tags objects the library made), as registry keys shared between separately loaded scripts, and above all as the well-known hooks: every iterable in Chapter 20 has a Symbol.iterator method.
      • 
        
    • Object.groupBy replaces many hand-written reduce loops for reports: orders by status, log lines by level, students by grade. Older code used Lodash's groupBy.
      • 
        
    • Tagged templates are everywhere in modern web code: html`…` in lit, css`…` and styled.div`…` in CSS-in-JS libraries, sql`…` query builders that turn every value into a safe database parameter, gql`…` for GraphQL, and translation helpers.
      • 
        
    • Custom conversions: date, money and unit libraries define toString, toJSON and sometimes Symbol.toPrimitive so their objects print nicely. Many deliberately throw from valueOf (the Temporal API does) to stop accidental < and + on objects that shouldn't be compared that way.
      • 
      
    
    
    
  
    

  
    
    Common wrong ideas
    
    
      
      
        
    • "const makes an object read-only." It glues the name to the object. Freezing is a separate step (panel 18).
      • 
        
    • "Object.freeze freezes everything inside." Only the object's own drawers. Inner objects and arrays stay open (panel 16).
      • 
        
    • "Freeze returns a frozen copy." It freezes the object you pass, and returns the same object.
      • 
        
    • "If the write didn't throw, it worked." In sloppy code, writes to read-only drawers fail silently. Check with a strict file, or read the value back.
      • 
        
    • "Non-enumerable means private." It only means "not listed". Anyone can read it by name, and Object.getOwnPropertyNames lists it.
      • 
        
    • "defineProperty with just a value makes a normal property." It makes a read-only, unlisted, permanent one, because missing toggles default to off.
      • 
        
    • "Symbols are secret." They avoid clashes. Object.getOwnPropertySymbols, Reflect.ownKeys and console.log all reveal them.
      • 
        
    • "Symbol(\"id\") gives me back the key I made earlier." Every call makes a new one. Keep the symbol in a variable, or use Symbol.for.
      • 
        
    • "valueOf is used for everything." Templates and String() try toString first.
      • 
        
    • "obj + \"\" and `${obj}` are the same." The first sends "default", the second "string" (panel 36, roads two and three).
      • 
        
    • "The number hint means I'll get a number back." The method may return any primitive; the hint is only a wish.
      • 
        
    • "Two objects that convert to the same value are ==." Object versus object is always an identity check.
      • 
        
    • "A tag function receives a finished string." It receives the pieces and the raw values, and returns whatever it likes, not necessarily a string.

    BigInt: the other new primitive

    Words from this chapter
    
    
      
    
        
    property descriptor
    A small object describing one property: its value (or get/set) and its toggles.
    
        
    writable
    The toggle that decides whether a property's value can be changed.
    
        
    enumerable
    The toggle that decides whether a property is listed by Object.keys, for...in, JSON and spreading. To enumerate is to count things off one by one.
    
        
    configurable
    The toggle that decides whether a property can be deleted or have its toggles changed.
    
        
    Object.defineProperty
    Makes or changes a property with chosen toggles; missing toggles start off for new properties.
    
        
    accessor property, getter, setter
    A property that runs a function when read (getter) or written (setter) instead of holding a value.
    
        
    extensible
    Able to get new properties. preventExtensions turns it off.
    
        
    seal, freeze
    Lock a whole object: seal stops adding and deleting; freeze also stops changing values.
    
        
    shallow, deep
    Shallow affects only the object's own properties; deep also reaches every object inside.
    
        
    recursion
    A function calling itself to handle a smaller part of the job (Chapter 21).
    
        
    entries
    [key, value] pairs, made by Object.entries and turned back into an object by Object.fromEntries.
    
        
    grouping
    Sorting items into named piles by a callback's answer: Object.groupBy, Map.groupBy.
    
        
    symbol
    A primitive value that is unique, made by Symbol(). Used as clash-free property keys.
    
        
    description (of a symbol)
    The label given to Symbol("…"), for printouts only.
    
        
    global symbol registry
    A shared cupboard of symbols, used by Symbol.for and Symbol.keyFor.
    
        
    well-known symbol
    A built-in symbol such as Symbol.iterator or Symbol.toPrimitive that the language looks for to change how it treats your object.
    
        
    primitive
    A simple value that isn't an object: number, string, boolean, undefined, null, bigint or symbol.
    
        
    ToPrimitive, hint
    The standard's name for turning an object into a primitive, and the operator's wish ("string", "number" or "default") that goes with it.
    
        
    valueOf, toString
    The two methods an object without Symbol.toPrimitive uses to answer, in an order set by the hint.
    
        
    tagged template, tag
    A template literal with a function in front; the function (the tag) receives the text pieces and the values.
    
        
    String.raw
    A built-in tag that keeps backslashes exactly as typed.
    
        
    BigInt
    A primitive for whole numbers of any size, written with an n.
