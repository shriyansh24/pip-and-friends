CHAPTER 22

STENCILS AND EMOJI

Picture: Kit, the stage manager in a pink hoodie and headset, waves hello. On one side is a short bookshelf for the text "Hi😀": the books H and i take one slot each, and the smiley is a fat book spread over two slots, marked 2 SLOTS. Under the slots are the numbers 0048, 0069, D83D and DE00, and the slot indexes 0 to 3. On the other side is a yellow stencil card with the pattern [A-Z]\d+ cut into it, and a row of eight dials under it labelled g, i, m, s, u, v, y and d; only g is ON.

Chapter 4 said, in a hurry, that an emoji "counts double". Today you find out why. Text in JavaScript is a library shelf where most letters take one slot and some books, like emoji, need two; and what you see as one picture can be five books glued together. Then you pick up the most powerful text tool there is: the regular expression, a stencil you slide along the text to find every piece of a certain shape, like "a capital letter followed by digits". About 140 minutes, with 27 hands-on checks.

Picture a string as a library shelf with numbered slots. Each slot holds one small number between 0 and 65,535, called a code unit. Every character has an official number in a worldwide list called Unicode; that number is its code point, written like U+1F600. Small code points fit in one slot. Big ones, like most emoji, don't, so they are stored as a pair of slots.

    

      
    

    
Picture: a shelf for the text "Hi😀!". Book H sits in slot 0 (code unit 0048), book i in slot 1 (0069), the smiley book spans slots 2 and 3 (code units D83D and DE00) and is marked 2 SLOTS, and book ! sits in slot 4 (0021).

    

      
      
Kit says: The two slots of a fat book are called a surrogate pair: two stand-in numbers that only mean something together. Alone, half a book is nonsense. Chapter 4's "beads on a necklace" were code units all along.

Kit wants just the first bold name out of a scrap of web page. .* means "anything, any number of times". What could go wrong?

    greedy.js
    

    

    
    
      
  1. Line 3: the whole line! Quantifiers are greedy: .* first swallows everything to the end, then gives back characters one at a time only until the rest of the stencil, </b>, fits. The last </b> fits first.
    2.

    3.

    4.

    2. 
      
  2. Lines 6 to 8: cat appears 4 times (inside "category" and "bobcat" too). \bcat\b fits only the 2 whole words, so only those become DOG.

    What you learned in Chapter 22
    
    
      
      
    • LENGTH COUNTS SLOTS, NOT PICTURESA string is a shelf of 16-bit code units. Characters past U+FFFF, like most emoji, take two slots (a surrogate pair). .length, indexes, slice and at work on slots, so they can cut a book in half and leave �. codePointAt and String.fromCodePoint read and write whole code points.
      • 
      
    • THREE RULERS: SLOTS, BOOKS, PICTURESSpreading, Array.from and for...of count code points. Intl.Segmenter counts graphemes, what people see, because a ZWJ family or a skin tone is several code points. Reverse and truncate by graphemes. normalize() before comparing text that may be composed or decomposed; sort names with localeCompare.
      • 
      
    • A REGEX IS A STENCIL YOU SLIDE ALONG THE TEXTCharacter classes (\d \w \s . [A-Z] [^…]), quantifiers (+ * ? {n,m}, greedy unless followed by ?), anchors (^ $ \b), groups and named groups, |, backreferences and lookarounds. new RegExp builds one from a string (double your backslashes); a broken pattern is a SyntaxError: Invalid regular expression.
      • 
      
    • NAME YOUR POCKETStest, search, match (with or without g), matchAll, exec, replace with $1, $<name> or a function, and split. replaceAll with a regex needs g, or it throws called with a non-global RegExp argument.
      • 
      
    • A g REGEX REMEMBERS WHERE IT STOPPEDFlags g i m s u v y d are the machine's dials. lastIndex makes a reused g regex answer yes, no, yes. Escape user input with RegExp.escape (ES2025: in Node 26, not in Node 22), beware nested repeats, and prefer plain string methods when you know the exact text.

    Under the hood: UTF-16, graphemes and the regex engine
    
    
      
    Why two slots?
    
      
    Unicode has room for 1,114,112 code points, from U+0000 to U+10FFFF. JavaScript strings were designed in the 1990s, when 65,536 seemed enough, so the standard defines a string as a sequence of 16-bit code units: the encoding called UTF-16. Code points up to U+FFFF (the "Basic Multilingual Plane": most living scripts) fit in one unit. Bigger ones are split: subtract 0x10000, put the top 10 bits on 0xD800 (the "high surrogate") and the bottom 10 bits on 0xDC00 (the "low surrogate"). For U+1F600: 0x1F600 − 0x10000 = 0xF600; its top ten bits are 0x3D, giving 0xD83D, and its bottom ten bits are 0x200, giving 0xDE00. The range D800–DFFF is reserved, so no real character is ever mistaken for half a pair.
    
      
    Lone surrogates and well-formed strings
    
      
    Nothing stops a JavaScript string holding half a pair, as cut.js showed. Such a string isn't valid Unicode, and printing or encoding it turns each lone half into U+FFFD (�). ES2024 added s.isWellFormed() to check for lone halves and s.toWellFormed() to replace them with U+FFFD yourself, which is useful before sending text to a server. Files and the web mostly use UTF-8, which stores the same code points in 1 to 4 bytes; Node converts between UTF-8 and UTF-16 whenever it reads or prints text.
    
      
    Grapheme clusters
    
      
    Unicode Standard Annex #29 defines "extended grapheme clusters": rules that keep together a base letter and its combining marks, emoji with skin-tone modifiers, ZWJ sequences, pairs of regional indicator letters (which draw as flags), and Korean syllables built from parts. Intl.Segmenter implements those rules using the ICU library that ships inside Node and browsers, so the answer can change slightly when a new Unicode version adds emoji. The same segmenter can split into "word" and "sentence" pieces too, which works even for languages written without spaces, such as Japanese and Thai.
    
      
    Normalization forms
    
      
    There are four: NFC and NFD (composed and decomposed) and NFKC and NFKD, the "compatibility" forms, which also fold look-alikes such as ﬁ (one ligature character) into fi and full-width digits into ordinary ones. NFC is the usual choice for storing and comparing; NFKC is common for search and user names.
    
      
    How the regex engine slides
    
      
    V8's regex engine, Irregexp, compiles each pattern to bytecode or machine code the first time it's used. It's a backtracking engine: it tries alternatives in order, and on a dead end it returns to the last choice point and tries the next option, which is why the order of | branches and greediness decide which fit you get. V8 also has an experimental non-backtracking engine (behind the --enable-experimental-regexp-engine flag, with an l flag for "linear"), which can't run backreferences or lookarounds but never blows up. Backreferences make the general matching problem far harder than plain patterns; that's the price of their power.
    
      
    Who owns lastIndex
    
      
    The standard's RegExpBuiltinExec reads lastIndex only when the regex is global or sticky, and writes it back after each attempt. String.prototype.match, matchAll, replace and split work through hooks on the regex (Symbol.match, Symbol.replace, Symbol.split, well-known symbols from Chapter 19); the global versions reset lastIndex to 0 first, and matchAll and split work on an internal copy, so only direct calls to test and exec leak state between uses, and match or replace with a sticky regex that has no g, which read and move lastIndex too:
    
      sticky_match.js
      
    
      
    
      
    The first match fits B1 at slot 0 and leaves lastIndex at 2. The same call again starts at slot 2, a space, and sticky won't slide: null, back to 0. replace moves it to 2 again.
    
    
    
  
    

  
    
    In real programs
    
    
      
      
        
    • Form validation: HTML's <input pattern="…"> attribute takes a regex (compiled with the v flag in current browsers), anchored to the whole value automatically. Server code checks again, because browser checks can be skipped.
      • 
        
    • Search and replace in editors: VS Code's find box has a .* button that switches to JavaScript-style regexes, with $1 in the replacement.
      • 
        
    • Log processing: pulling timestamps, levels and request ids out of log lines with named groups is a daily job in operations.
      • 
        
    • Routers: web frameworks turn paths like /shows/:id into regexes behind the scenes. Browsers now have URLPattern for this.
      • 
        
    • Tokenizers: syntax highlighters (including the one on this page) and template engines walk through text with sticky or global regexes, one token at a time.
      • 
        
    • Text limits: social sites count graphemes, or their own rules close to them, for character limits. Databases often limit bytes or code units instead, which is why an emoji-heavy name can be "too long" for one and fine for the other.
      • 
        
    • Slugs and search: making /shows/les-misérables into les-miserables uses normalize("NFD") to split off the accents, then replace(/\p{M}/gu, "") to delete the marks.
      • 
        
    • Security: "ReDoS" (regex denial of service) is a known category of vulnerability: a pattern with catastrophic backtracking, fed a crafted input, freezes a server. Linters such as eslint-plugin-regexp warn about risky patterns.

    Common wrong ideas
    
    
      
      
        
    • ".length is the number of characters." It's the number of UTF-16 code units (panel 2).
      • 
        
    • "Spreading a string gives me what people see." It gives code points. Families, skin tones and flags still come apart (panel 11).
      • 
        
    • "Two strings that look the same are ===." Not if one is composed and the other decomposed (panel 12).
      • 
        
    • "split(\"\").reverse().join(\"\") reverses any text." Only text with no surrogate pairs or combining marks.
      • 
        
    • "sort() sorts alphabetically." It sorts by code unit numbers. Use localeCompare with a language.
      • 
        
    • "A dot in a pattern means a dot." It means any character. Escape it: \.
      • 
        
    • "new RegExp(\"\\d\") is the same as /\d/." The string loses its backslash first. Double it.
      • 
        
    • "/\d{4}/ checks that the input is four digits." It checks that four digits appear somewhere. Anchor with ^ and $.
      • 
        
    • ".* takes the shortest match." It's greedy: it takes the longest, then gives back as little as needed.
      • 
        
    • "replace with a regex changes everything." Only with g.
      • 
        
    • "test has no side effects." With g or y it moves lastIndex.
      • 
        
    • "A regex that checks the date's shape checks that it's a real date." 2026-13-45 has the right shape. Check the numbers separately (Chapter 23 has the date tools).

    Words from this chapter
    
    
      
    
        
    Unicode
    The worldwide list that gives every character a number.
    
        
    code point
    A character's Unicode number, written like U+1F600. A "book" in this chapter.
    
        
    code unit
    One 16-bit number in a JavaScript string; a "slot". .length counts these.
    
        
    UTF-16
    The way JavaScript stores code points as one or two code units.
    
        
    surrogate pair
    Two code units that together store one code point above U+FFFF.
    
        
    hexadecimal
    Writing numbers in base 16, with digits 0–9 and a–f. 0x1f600 in JavaScript.
    
        
    zero width joiner (ZWJ)
    U+200D, an invisible character that asks for its neighbours to be drawn as one emoji.
    
        
    grapheme
    What a person sees as one character, which may be several code points.
    
        
    Intl.Segmenter
    A built-in tool that cuts text into graphemes, words or sentences.
    
        
    combining mark
    A code point, like an accent, that attaches to the character before it.
    
        
    normalization, NFC, NFD
    Rewriting text in one standard form (composed or decomposed) so equal-looking strings compare equal.
    
        
    regular expression, regex
    A pattern describing the shape of text; a stencil.
    
        
    metacharacter
    A character with a special job in a pattern, such as . * + ? ( ) [ ] { } ^ $ | \.
    
        
    escape
    A backslash in front of a metacharacter, so it matches itself.
    
        
    character class
    A hole that fits any one character from a group: \d, [A-Z], [^…].
    
        
    quantifier
    How many times a hole may fit: + * ? {n} {n,m}.
    
        
    greedy, lazy
    Greedy quantifiers take as much as they can; lazy ones (with an extra ?) as little as they can.
    
        
    anchor, word boundary
    Holes that fit a position: ^, $, \b.
    
        
    capture group, named group
    Brackets that keep the text they fit, by number or by name ((?<name>…)).
    
        
    alternation
    |, meaning "this or that".
    
        
    backreference
    \1 or \k<name>: the same text a group caught, again.
    
        
    lookahead, lookbehind
    Checks for text after or before the fit, without including it.
    
        
    flag
    A dial after the closing slash: g i m s u v y d.
    
        
    lastIndex
    Where a global or sticky regex starts its next search.
    
        
    sticky
    The y flag: fit only exactly at lastIndex.
    
        
    backtracking
    The engine backing up to try another way after a dead end.
    
        
    catastrophic backtracking
    So many ways to try that a match effectively never finishes.
