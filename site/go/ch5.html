CHAPTER 5

FORKS AND DOORS

Picture: Scoot, the bike courier, points at a signpost. One arm of the signpost says true, the other says false.

Every program that does something useful has to decide. Ask yes-or-no questions with == and <, join them with && and || like switches in a circuit, take a fork with if and else, and walk down a corridor of doors with switch. The Compiler will catch a whole row of classic mistakes on the way. About 80 minutes, with 26 hands-on checks.

  1. Yes or no: true, false and the six comparisons
  2. Lamp circuits: &&, || and !, and why Go stops early
  3. Forks: if, else and the else-if ladder
  4. The backpack: the short statement, scope and early return
  5. Doors: switch, default and fallthrough
  6. Boss level and recap

PART 1 · YES OR NObool, true, false and the six comparisons

1

Scoot's programs so far run every line, top to bottom, every time. Real deliveries aren't like that.

Scoot says: Heavy parcel? Take the van. Light one? Take the bike. Nobody home? Leave a note.

Scoot says: Every one of those choices starts with a question that has only two answers: yes or no.

Picture: Scoot shrugs, holding a letter, thinking about which way to go.

2

Go has a type just for yes-or-no answers: bool (short for boolean). A bool box holds exactly one of two values, true or false. Nothing else, ever. In this book it's the lamp: lit or not lit.

Scoot says: true and false are written in small letters and without quotes. "true" in quotes is a string, a train of four letters, not a lamp.

    7
    
Strings can be compared too. == asks "exactly the same letters?". < asks "does this one come first?" Go walks both trains carriage by carriage and stops at the first carriage that differs.

    

      
      
    

    
Each letter is stored as a number code. The capitals A to Z have smaller codes (65 to 90) than the small letters a to z (97 to 122). So every capital comes before every small letter, and "Zebra" < "apple" is true. It's not a dictionary: it's a code order, and it is case-sensitive.

    strings_cmp.go
    

    

    
    
      
  1. "10" < "9" is true (line 11)
    These are strings, not numbers! Carriage 0 is 1 versus 9, and 1 has the smaller code. Go stops right there.
    2. 
      
  2. "ant" < "anteater" is true (line 12)
    The first three carriages match, then "ant" runs out. A shorter train that matches the start of a longer one comes first.

    9
    
Scoot's rule for handing over a parcel: "I know the address and someone is home."

    

      
      

        
Scoot says: Two questions, one answer. Go joins lamps with three logical operators: && (and), || (or) and ! (not).

        
Scoot says: Picture each lamp as a switch in an electric circuit. Closed switch: true. Open switch: false. If current reaches the bulb, the answer is true.

Notice the fence in panel 10? Go is a lazy, clever checker. It stops as soon as it knows the answer.

    
    

      
      
Scoot says: With &&, if the left side is false, the whole answer is false already, so Go skips the right side. With ||, if the left side is true, the answer is true already: skip. This is called short-circuit evaluation. Memory hook: why knock if there's no parcel?

      PART 5 · DOORSswitch, default and fallthrough
      

  
      
    33
    
      When one value decides between many roads, an else-if ladder gets long. switch is a corridor of labelled doors. Scoot walks along with a value, reads each label in turn, goes through the first door that matches, and leaves by the exit at the end.
      
    
    
      
      
      
      Scoot says: Each door is a case. A door can carry several labels. The dashed door, default, is for when nothing else matched. And that red slide? That's fallthrough, coming up soon. Memory hook: one door, one room.
      
    
      
  
      

  
      
    34

    days.go

        2.

      If you've seen switch in C, Java or JavaScript, here's a surprise.

    Under the hood: lamps, jumps and the order of operators
    
      
      
      A bool is one byte
      
      
      A bool box takes one byte of memory. All-zero bits mean false, which is why false is the zero value. The machine has no "if" in the way you write it: the Compiler turns your fork into a compare instruction followed by a conditional jump, "if the last comparison said no, jump to the instruction at address X". The else block is simply the code at X. Skipped lines are lines the processor jumps over.
      
      
      Short-circuit is a jump too
      
      
      The Go specification says the right operand of && and || "is evaluated conditionally". In machine terms, a && b becomes: work out a; if it's false, jump straight to the "answer is false" code; otherwise work out b. That's why circuit.go could prove which side ran: a call on the skipped side is never reached.
      
      
      Which operator goes first?
      
      
      Go groups operators into five precedence levels. From strongest to weakest: * / % << >> & …; then + - | ^; then the comparisons == != < <= > >=; then &&; then ||. The ! in front of a value is applied before all of them. So raining || parcels > 5 compares first and joins last, exactly what you want. And && binds tighter than ||:
      
      
      
        
      precedence.go
      
        
      Line 6 is read as true || (false && false). When you mix && and ||, add brackets anyway: the next reader will thank you.
      
      
      
      
      Why must { be on the same line?
      
      
      Go's grammar uses semicolons to end statements, but you almost never type them. The lexer (the part that chops your text into words) inserts one automatically at the end of a line that ends in a name, a number, a string, ), ] or }, among others. if weight > 20 ends in 20, so it becomes if weight > 20; and the { on the next line is an orphan. The same rule turns a } at the end of a line into };, which is why else can't start the next line. This single rule is the reason every Go program uses the same brace style.
      
      
      Strings compare byte by byte
      
      
      The specification says strings are ordered "lexically byte-wise". Go compares the bytes of the two strings one pair at a time; the first pair that differs decides, and if one string runs out first, the shorter one is smaller. For English letters each byte is the letter's ASCII code. Letters outside English (é, ß, 日) take several bytes each in UTF-8, so their order follows those bytes, not any language's alphabet. Chapter 11 opens up strings and runes; for human-friendly sorting there's the golang.org/x/text/collate package.
      
      
      How a switch is matched
      
      
      For switch x { … }, Go works out x once, then compares it with each label using ==, left to right inside a case, cases top to bottom, and stops at the first match. Labels don't have to be constants: case limit * 2: is fine. Only constant labels are checked for duplicates, because only those the Compiler can compare before the run. A tagless switch { is the same as switch true {.
      
    
      
  
      

  
      
    In real programs: where you'll see these every day
    
      
      
        
        
      • if err != nil { return err }. The most common three lines in Go. A function hands back an error value, and the caller checks it with a guard clause straight away (chapter 8). It's panel 31's shape, thousands of times a day.
        • 
        
      • The short statement with two values. if n, err := strconv.Atoi(text); err != nil { … } (chapter 8) and if v, ok := prices["tea"]; ok { … } (chapter 12) pack a backpack, then ask about it. The backpack keeps n, err, v and ok from cluttering the rest of the function.
        • 
        
      • Nil guards. if p != nil && p.Name == "Ana" relies on short-circuit evaluation: if p points at nothing, Go never tries to read p.Name, which would crash. Same idea as guard.go.
        • 
        
      • Switches on strings and numbers. Command-line tools often do switch os.Args[1] { case "add": … case "list": … default: … }. HTTP servers switch on the method: case "GET":, case "POST":.
        • 
        
      • Tagless switches for ranges. Shipping prices, tax bands, grade boundaries: switch { case weight < 1: … case weight < 5: … } reads better than a long ladder.
        • 
        
      • fallthrough is rare. Search large Go codebases and you'll find it far less often than break. Most people prefer comma-separated labels or a small helper function.
        • 
        
      • go vet flags a few of this chapter's slips that still compile. In vet_slips.go below, x != 1 || x != 2 is always true (vet calls it a "suspect or"), and x > 5 && x > 5 asks the same question twice (a "redundant and"). vet is not a mind-reader: it says nothing about x == x on line 9. Run go vet before you share code.

    Common wrong ideas
    
      
      
        
        
      • "= and == are interchangeable." = fills a box; == asks. In a condition, = is a compile error (panel 22).
        • 
        
      • "0 means false and 1 means true." Not in Go. Numbers, strings and everything else are never conditions; only bools are (panel 23).
        • 
        
      • ""Zebra" < "apple" is false, because Z comes after a." Capitals have smaller codes, so it is true. String order is code order, not dictionary order.
        • 
        
      • ""10" < "9" compares numbers." It compares text, carriage by carriage: true. Convert to numbers first (chapter 7) if you mean numbers.
        • 
        
      • "Go always works out both sides of &&." It stops as soon as the answer is known (panel 13).
        • 
        
      • "x == 1 || 2 checks two values." Each side must be a full question; Go refuses this (panel 16).
        • 
        
      • "1 <= n <= 10 works like in maths." It's a compile error. Write n >= 1 && n <= 10.
        • 
        
      • "Brackets are required around the condition." if (x > 5) { compiles, but the formatter removes the brackets. Braces, on the other hand, are required.
        • 
        
      • "In an else-if ladder, every true condition runs." Only the first true one does (panel 24).
        • 
        
      • "A variable from if v := …; is available after the if." It lives in the if and its else blocks only (panel 30).
        • 
        
      • "Every case needs a break." That's C, Java and JavaScript. Go cases end by themselves (panel 35).
        • 
        
      • "fallthrough checks the next case." It runs the next room's code without reading its label (Boss 1 and 4).
        • 
        
      • "default must come last." It can sit anywhere in the switch and still runs only when nothing matches. Putting it last is the custom, because that's where readers look.
        • 
        
      • "break inside a switch inside a loop stops the loop." It only leaves the switch (chapter 6 shows the trap).

    Words from this chapter
    
      
      
      
        
      boolean, bool
      The type for yes-or-no values. Only two values exist: true and false. Zero value: false.
      
        
      comparison operator
      ==, !=, <, <=, > or >=. Asks a question about two values of the same type and hands back a bool.
      
        
      operator
      A symbol that works on values: +, ==, &&…
      
        
      case-sensitive
      Treating capital and small letters as different. Go's string comparisons are case-sensitive.
      
        
      lexical (byte-wise) order
      Ordering strings by comparing their bytes one by one; the first difference decides.
      
        
      strings.EqualFold
      Compares two strings ignoring the difference between capital and small letters.
      
        
      logical operator
      && (and: both must be true), || (or: at least one true), ! (not: flips).
      
        
      truth table
      A table listing every combination of inputs and the result, like the one under the circuit.
      
        
      short-circuit evaluation
      Stopping as soon as the answer is known: false && x and true || x never work out x.
      
        
      guard
      A check placed first so the risky part only runs when it's safe.
      
        
      panic
      A crash while the program runs, with a report. Exit status 2.
      
        
      precedence
      Which operator is applied first when several appear together. && before ||.
      
        
      condition
      The bool expression an if (or a switch case) checks.
      
        
      if / else
      A fork: run one block when the condition is true, the other when it's false.
      
        
      block
      The lines between { and }.
      
        
      branch
      One road of a fork: the if block or the else block.
      
        
      else-if ladder
      A chain of else if questions asked top to bottom; the first true one runs.
      
        
      nested if
      An if inside another if's block.
      
        
      logic bug
      A mistake that compiles and runs but gives a wrong answer.
      
        
      short statement
      A small statement before the condition, if v := f(); v > 0 {. Its names live only in that if (and its else) or switch.
      
        
      scope
      The part of the program where a name can be used.
      
        
      return
      Leave the current function now (and hand back a value, if the function promises one).
      
        
      early return, guard clause
      Handling a problem with an if that returns, so the normal path continues without an else.
      
        
      missing return
      The Compiler's error when a function that promises a value could reach its end without one.
      
        
      switch
      A corridor of doors: compare one value with labels and run the first matching case.
      
        
      case
      One door of a switch, with one or more comma-separated labels.
      
        
      default
      The switch's room for "nothing matched".
      
        
      fallthrough
      As the last line of a case: also run the next case's code, without checking its label.
      
        
      tagless switch
      switch { … } with a full question on each case; same as switch true.
      
        
      expression switch
      A switch on a value, like switch day { … }.
      
        
      break
      Leave the nearest switch (or loop) right now.
      
        
      duplicate case
      The Compiler's error when the same constant label appears twice in one switch.
