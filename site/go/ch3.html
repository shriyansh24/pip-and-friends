CHAPTER 3

BOXES AND STONE

Picture: Scoot, the bike courier in a red cap and green jacket, waves hello.

Programs need to remember things. In Go, they keep them in labelled boxes called variables. Build boxes with var and :=, refill them with =, learn the Compiler's house rules, swap two boxes in one move, and meet constants: values carved in stone before the program even runs. About 75 minutes, with 30 hands-on checks.

  1. Labelled boxes: var, := and =
  2. No empty boxes, and the Compiler's house rules
  3. Many boxes at once: swaps, the blank box, names and scope
  4. Carved in stone: constants and iota
  5. Boss level and recap

A variable is a box in the computer's memory. It has a name on its label, a type sticker that says what kind of thing fits inside, and one value inside.

Scoot says: One box, one name, one kind of thing, one value at a time. The sticker never changes: an int box only ever holds whole numbers.

There are four moves to learn. Three build a box. One refills a box that already exists.

    

      

        
var x intbuild, with a sticker

        
        
You choose the type. The box starts with that type's starting value: 0 for int.

      

      

        
var x = 5build, Go reads the sticker

        
        
No type written. Go looks at 5, sees a whole number, and sticks on int for you. This is called type inference.

      

      

        
x := 5build and fill, in one move

        
        
The short declaration. Same as var x = 5, with less typing. The favourite move inside functions.

      

      

        
x = 9refill a box that exists

        
        
No new box. The old value is tossed out and the new one goes in. The box keeps its name and its sticker.

      The Compiler keeps a tidy warehouse. Four house rules for boxes:
      
    
        
      
      1. Every box you build inside a function must be used. Built a box and never looked inside? That's an error, not a warning. (Boxes built outside functions are let off; the notebook shows one.)
        2.

        3. 
      
      3. A name must exist before you use it. No box, no reading, no refilling.
        4. 
      
      4. Loose statements stay inside functions. := is a statement, so it can't sit outside func main. var can.
        5.

    Under the hood: boxes, addresses and carved values
    
        
      
        A variable really is a place in memory
        
      
        Memory is a long row of numbered slots, each holding one byte (8 bits). A variable is a run of slots with a name: on a 64-bit computer an int takes 8 bytes. The slot number where it starts is its address. When you write var coins int, Go sets aside 8 bytes and sets every bit to 0. That is why the zero value of int is 0, of bool is false, and of float64 is 0.0: all-zero bits mean exactly those values. (A string is a little two-part record, a pointer to the letters plus a length; all zeros means "no letters, length 0", which is "".)
        
      
        Copying is real copying. bonus := coins reads the bytes in coins and writes the same bytes into bonus's own slots. Afterwards the two have nothing to do with each other, which is what the tracer in panel 5 shows. (Later chapters meet slices, maps and pointers, where the thing copied is a reference to shared data. The box rule still holds; what's inside the box is different.)
        
      
        := is exactly var with an initial value
        
      
        The Go specification calls x := 5 a short variable declaration and defines it as shorthand for var x = 5. The one extra power: in a list like a, c := 3, 4, a name that already exists in the same block is simply assigned, as long as at least one name is new. That is why Boss 1 compiled. A name from an outer block doesn't count as "already here", so := builds a fresh inner box instead, which is the shadowing in Boss 2.
        
      
        Why "neither addressable nor a map index expression"?
        
      
        The left side of = must name somewhere to store a value: an addressable box, or an entry in a map (chapter 12). A constant is neither. It has no slots at all: the Compiler copies its value into the machine code everywhere it's used, like letters carved into the program. Nothing to overwrite, so nothing to assign.
        
      
        How big can a constant be?
        
      
        The specification says numeric constants "represent exact values of arbitrary precision and do not overflow", and requires every Go compiler to handle integer constants of at least 256 bits. 1 << 100 needs 101 bits, so it's fine. Only when a constant is used as a value of some type (put in a box, passed to a function) must it fit that type, and the Compiler checks it right there.
        
      
        
        
        big.go
        
        
        << shifts the bits left: each step doubles. >> shifts right: each step halves, dropping any remainder.
        
      
        
      
        What type does an untyped constant become?
        
      
        If the box or function says what it needs, the constant takes that type. If nothing says (as in fmt.Println(lucky / 2)), it takes its default type: int for whole numbers, float64 for numbers with a point, string for text, bool for true/false. And x := 5 uses the default too, so x is an int.
        
    
        
  
        

  
        
    In real programs: where you'll see these every day
    
        
      
          
        
        • := everywhere inside functions. Most Go code builds its boxes with :=. var x T appears when the zero value is the right start (var total int before adding things up) or when the type matters more than a starting value.
          • 
        
        • Package-level boxes need var. Outside functions only declarations are allowed, so you'll see var and const blocks at the top of files. House rule 1 doesn't apply out here: in pkgvar.go, line 6's spare is never used, and the program still compiles and runs.
          • 
      
        
      
        pkgvar.go
        
      
          
        
        • The err pattern. Real Go code is full of lines like n, err := strconv.Atoi(text) followed later by m, err := strconv.Atoi(other). The second line compiles because m is new; err is just refilled. You now know the rule that makes it work (chapters 7 and 8 show it in action).
          • 
        
        • _ to ignore what you don't need. Functions often hand back two values. _, err := … keeps only the error. The Go team's advice: never throw away an error with _ unless you really mean it.
          • 
        
        • Constants for settings. const maxRetries = 3, const defaultPort = 8080. Named constants make a program easier to read and to change: one edit, every use updated.
          • 
        
        • iota in the standard library. The time package numbers the weekdays with iota, starting with Sunday as 0. Chapter 18 builds your own.
          • 
        
        • Capital first letter = shared. fmt.Println starts with a capital, which is why your program can use it. Names that start lowercase stay private to their own package.
          • 
        
        • Short names for short lives. Go style prefers short names when a box lives for a few lines (i, n, s) and longer, clearer names when it lives long or far away (retryDelay).
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "var x int leaves x empty, or full of junk." It holds 0. Every Go box starts at its zero value.
          • 
        
        • ":= and = are the same thing." := builds a new box; = refills one that exists. Mix them up and the Compiler stops you (panels 15 and 16).
          • 
        
        • "I can use := again to change a value." Only if a new name is on the left too. Otherwise: no new variables on left side of :=.
          • 
        
        • "An unused variable is only a warning." In Go it is a compile error. Nothing runs until you use it or delete it.
          • 
        
        • "b := a ties b to a." It copies the value. Changing a later doesn't change b (panel 5).
          • 
        
        • "x = x + 1 is false maths." = is not "equals" here; it means "put the right side into the box". The right side is worked out first.
          • 
        
        • "Swapping always needs a spare box." In Go, a, b = b, a does it in one line.
          • 
        
        • "my_box is illegal." It's legal, just not Go style. my-box is the one that breaks, because - means minus.
          • 
        
        • "Score and score are the same name." Capitals matter; they are two different boxes.
          • 
        
        • "A constant is a variable I promise not to change." It's stronger: the Compiler works it out before the run, it has no box, and changing it is impossible.
          • 
        
        • "Constants must fit in an int." Untyped constants can be enormous. Only the value you finally put into a box has to fit.
          • 
        
        • "Go's const works for anything." Only numbers, strings, runes and booleans can be constants, and only if the Compiler can work out the value itself.

    Words from this chapter
    
        
      
        
        
        variable
        A named box in memory that holds one value of one type. Its value can change.
        
        
        declare / declaration
        Building a box (or a constant) and giving it a name, like var x int.
        
        
        var
        The keyword that declares variables: var x int, var x = 5, var ( … ).
        
        
        type
        What kind of value a box can hold, like int or string. Fixed when the box is built.
        
        
        int
        The type for whole numbers.
        
        
        float64
        The type for numbers with a decimal point.
        
        
        string
        The type for text.
        
        
        bool
        The type for true or false.
        
        
        type inference
        Go choosing a box's type from its starting value, as in var x = 5 or x := 5.
        
        
        statically typed
        Every box's type is known and checked by the Compiler before the program runs.
        
        
        zero value
        The value a box holds before you fill it: 0, 0.0, "", false or nil.
        
        
        nil
        The zero value for some kinds you'll meet later (pointers, slices, maps…).
        
        
        short variable declaration
        x := value: declare and fill in one move. Only inside functions.
        
        
        assignment
        x = value: put a new value into an existing box.
        
        
        multiple assignment
        Filling several boxes in one statement: a, b = 1, 2. All right-side values are worked out first.
        
        
        swap
        Exchanging two boxes' values: a, b = b, a.
        
        
        logic bug
        A mistake that compiles and runs but gives the wrong result.
        
        
        blank identifier _
        A write-only "box with no bottom" that throws its value away.
        
        
        identifier
        Any name you give to something: a variable, a constant, a function.
        
        
        keyword
        A word Go reserves for itself (var, const, func…). It can't be a name.
        
        
        MixedCaps
        Go's naming style: join words, capitalise each new word (parcelCount).
        
        
        block
        The code between a pair of braces { }.
        
        
        scope
        The part of the program where a name can be used: from its declaration to the end of its block.
        
        
        shadowing
        An inner box with the same name as an outer one, hiding it inside the inner block.
        
        
        constant
        A named value fixed at compile time that can never change.
        
        
        const
        The keyword that declares constants.
        
        
        untyped constant
        A constant with no type yet (const n = 7); it takes the type its use needs.
        
        
        typed constant
        A constant with a type written in (const n int = 7).
        
        
        compile time
        When the Compiler checks and translates the program. Constants are worked out here.
        
        
        overflow
        A value too big (or too small) for the box it's meant to go into.
        
        
        uint8
        A tiny box for whole numbers from 0 to 255 (chapter 4).
        
        
        addressable
        Having a real place in memory, so a value can be stored there. Variables are; constants aren't.
        
        
        iota
        A counter inside a const ( … ) group: 0 on the first line, then 1, 2, 3…
