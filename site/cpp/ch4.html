    18
    
              Write these on the inside of your toolbox lid.
              
    
              
      
              1 · ZEROthe failed box
              The read that fails puts 0 in its variable. (The very first C++ standard left the old value there, so old books may say so.)
              
      
              2 · STUCKthe bad character
              The character that caused the jam stays in the tray. Nothing removes it by itself.
              
      
              3 · SILENTevery read after
              Every later read does nothing: no waiting, no change, no message. Until someone calls clear().
              
    
              
    
              
      
      
              Wren says: A jam stops everything. Some languages would stop the program with an error message; C++ just goes quiet. That is why checking input matters so much in C++. Chapter 15 builds proper checking loops.
              
    
              
    
              Picture: the Taster, the critter for a bad value, pulls a face.

    Under the hood: streams, buffers, states and conversions
    
                
      
                Two trays, not one
                
      
                When a program reads the keyboard, the text passes through two holding areas. First the terminal keeps your line while you edit it (that's why Backspace works) and hands it over only when you press Enter. This is the terminal's "line mode". Then std::cin keeps its own buffer: the tray in this chapter. A read takes from the buffer; only when the buffer is empty does the program ask the system for more, and that is the moment it waits.
                
      
                Why the prompt appears without \n
                
      
                std::cin is tied to std::cout: before every read, std::cin flushes std::cout. So a prompt sitting in the output buffer reaches the screen just before the program waits.
                
      
                Formatted and unformatted input
                
      
                >> is formatted input: it skips leading whitespace, then reads characters only as long as they can still be part of the type (digits and a sign for an int; digits, one point and an exponent like e5 for a double; anything but whitespace for a string). std::getline and ignore are unformatted: they skip nothing and look at raw characters. std::ws is a manipulator, a small helper function that you "read into"; it eats whitespace and stops at the first other character.
                
      
                The four state flags
                
      
                Every stream carries flags. failbit is set when a read can't produce a value (the jam). eofbit is set when the input ran out: the end of a file, a pipe that closed, or Ctrl+D on Linux and macOS (Ctrl+Z then Enter on Windows). badbit means something broke underneath, which is rare. goodbit means none of the others. fail() is true when failbit or badbit is set, and clear() resets them all. While any flag is set, formatted reads do nothing.
                
      
                What a failed read writes
                
      
                Today a failed number read stores 0. If the digits are fine but the number is too big for the type (say 99999999999 into an int), the read stores the largest value the type can hold (or the most negative one) and still sets failbit. The 1998 standard left the variable untouched; a later correction to the standard (library issue LWG 696) changed that, which is why some older tutorials disagree with this chapter.
                
      
                The conversion rules, a little more precisely
                
      
                  
        
                • Integral promotion: before arithmetic, bool, char and short are converted to int. That's why 'A' + 1 is an int and true + true is 2.
                  • 
        
                • The usual arithmetic conversions: when the two sides of an operator have different types, the "smaller" one is converted to the "bigger" one. Any floating type beats any integer type, so int ⚬ double happens in double.
                  • 
        
                • Floating to integer: the fraction is discarded (toward zero). If the whole part doesn't fit the integer type at all, for example 1e20 into an int, the result is undefined behaviour: anything may happen.
                  • 
        
                • Number to bool: zero becomes false, everything else true. Bool to number: false is 0 and true is 1.
                  • 
      
                
      
                Why 3.7 is really 3.7000000000000002
                
      
                A double stores a binary fraction, and 3.7, like 0.1, has no exact binary form; the nearest double is a hair above it. std::cout normally rounds to 6 significant digits, so you see 3.7. g++'s narrowing message prints the stored value at full precision in scientific notation instead, which is honest but surprising.

                • Narrowing from a variable. The standard says int cup{jug}; is ill-formed. clang++ makes it an error; g++ makes it a warning, keeps going and the program prints 2. -Werror makes g++ strict (panel 32 shows that run).
                  • 
        
                • Silent conversions. clang++ warns about int bolts = 3.7; and bool d = 0.5; by default (-Wliteral-conversion). g++ needs -Wconversion, which also warns about many other narrowing = assignments, such as int small = big;.
                  • 
        
                • Fix-its. clang++ suggests the exact repair, static_cast<int>( ), and also tells you what the value would have become (300 to 44).
                  • 
        
                • Quotes. g++ prints curly quotes ‘ ’ because this capture ran with a UTF-8 language setting; clang++ always uses straight quotes.

    In real programs: input you can trust
    
                
      
                  
        
                • Check every read. A read can be tested directly: if (std::cin >> age) is true only when it worked. Real programs loop until the input is good, then clear() and ignore() on failure. Chapter 15 builds those loops, and handles the end of input properly.
                  • 
        
                • Read lines, then convert. Many programmers read every answer with std::getline and convert the text afterwards with std::stoi or std::stod (Chapter 5). One way of reading means no leftover envelopes, and bad input can be reported nicely.
                  • 
        
                • The big ignore. Code you will meet in the wild writes std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n'); (with #include <limits>). It means "ignore as many characters as it takes, up to the newline", where this chapter's 1000 is a fixed limit.
                  • 
        
                • Test files. Saving inputs in files and running ./prog < case1.txt is how programming-contest judges and many test scripts check programs. Pipes chain programs: sort names.txt | ./greet.
                  • 
        
                • Warnings as policy. Serious projects often compile with -Wconversion (and -Wsign-conversion, Chapter 20) to catch silent spills, and treat warnings as errors in their test builds.
                  • 
        
                • Searchable casts. Because every named cast contains the word _cast, a team can search a whole codebase for conversions to review. A C-style (int) hides among ordinary parentheses.

    Common wrong ideas
    
                
      
                  
        
                • "std::cin >> name reads what I typed." It reads one word. Use std::getline for a line.
                  • 
        
                • "getline waits for me to type." Only if the tray is empty. After a >>, the leftover envelope is enough for it.
                  • 
        
                • "Typing letters for a number crashes the program." Nothing crashes: the variable becomes 0, the stream jams, and later reads silently do nothing.
                  • 
        
                • "clear() removes the bad input." It only resets the state. The bad characters are still in the tray until you ignore() them.
                  • 
        
                • "Converting a double to an int rounds it." It chops toward zero: 3.99 → 3, -3.99 → -3.
                  • 
        
                • "Storing the result in a double makes the division exact." The division happens first. double avg = 9 / 2; is 4.
                  • 
        
                • "static_cast<double>(a / b) fixes it." Too late: cast one side, static_cast<double>(a) / b.
                  • 
        
                • "Braces always stop narrowing in g++." For values written in the code, yes. For variables, g++ only warns by default.
                  • 
        
                • "std::cout << jug printed 7, so jug is an int." A double with no fraction prints without a decimal point.
                  • 
        
                • "(int)"42" turns text into 42." It's an error (the run is below), and (long)"42" compiles into a memory address. Text-to-number is std::stoi.
                  • 
        
                • "bool b = 2; stores 2." A bool holds only true or false; 2 becomes true, and adding it gives 1.

    Words from this chapter
    
                
      
                
        
                std::cin
                The standard input stream: the keyboard (or a pipe or file), sorted by Cindy.
                
        
                input
                Data a program receives while it runs, such as what you type.
                
        
                prompt
                Text printed to tell the user what to type.
                
        
                >> (extraction operator)
                Takes one item from an input stream, converts it to the variable's type and stores it.
                
        
                whitespace
                Spaces, tabs and newlines. >> skips it before each item.
                
        
                input buffer
                The tray: characters that have arrived but haven't been read yet.
                
        
                newline character
                '\n', the envelope that Enter adds at the end of each typed line.
                
        
                std::getline
                Reads every character up to the next newline into a string, then discards the newline.
                
        
                std::ws
                A manipulator that discards whitespace: std::cin >> std::ws.
                
        
                fail state
                The jammed state a stream enters after a failed read. Reads do nothing until clear().
                
        
                fail()
                Asks whether the stream is in the fail state (true or false, printed as 1 or 0).
                
        
                clear()
                Resets a stream's state flags so it works again.
                
        
                ignore(n, '\n')
                Discards up to n characters, stopping after the first newline.
                
        
                pipe |
                Sends one command's output into the next command's input.
                
        
                redirect <
                Feeds a file into a program's input.
                
        
                conversion
                Turning a value of one type into another type.
                
        
                implicit conversion
                A conversion C++ does by itself, for example in double d = 7;.
                
        
                promotion
                A safe automatic conversion to a bigger type before arithmetic, like char to int.
                
        
                truncation
                Chopping off the fraction, toward zero.
                
        
                narrowing conversion
                A conversion that may lose information, like double to int or int to char.
                
        
                brace initialisation
                int x{5};. It refuses narrowing conversions.
                
        
                cast
                An explicit conversion written in the code.
                
        
                static_cast<T>(x)
                The named cast for ordinary conversions: convert x to type T.
                
        
                long
                A whole-number type like int, but bigger here, so it can hold much larger numbers, even a memory address.
                
        
                C-style cast
                (T)x. Tries several kinds of conversion, including unsafe ones. Avoid it.
                
        
                character code
                The number a char really stores; A is 65.
                
        
                std::boolalpha
                Makes std::cout print bools as true/false instead of 1/0.
                
        
                scientific notation
                Writing a number as digits times a power of 10: 3.7e+0 = 3.7 × 100.
