C++ · CHAPTER 7

MACHINES IN MANY ROOMS

Picture: Wren, the mechanic in orange coveralls, waves hello next to her red toolbox.

Time to build your own machines. A function is a named machine: you drop values in, it works in private, and one result drops out. You'll build machines, press their buttons, hand them photocopies, stack them on top of each other and give two machines the same name. Then the house: which names are known in which room, when a box is thrown away, and how namespaces keep two things called count apart. About 90 minutes, with 23 hands-on checks.

  1. The workbench: defining, calling, parameters, return
  2. Who knows whom: declarations, definitions, every road returns
  3. Photocopies: pass by value, the call stack, main's return value
  4. One name, several machines: default arguments and overloading
  5. Rooms in a house: scope, lifetime, shadowing, globals, static
  6. Surnames: namespaces, ::, using
  7. Boss level and recap

    21

    28
    
        You can build machines now. Here's how good engineers build them, adapted from the C++ Core Guidelines.
        
    
          
      
        1. One job per machine. If you need "and" to describe it ("reads the age and prices the ticket and prints it"), split it (F.2).
          2. 
      
        2. Short. A function you can see on one screen is a function you can check (F.3).
          3. 
      
        3. Name it for what it does. Verbs for actions (print_box, add_bonus), nouns for answers (ticket_price, sign_of). The name should make a comment unnecessary (F.1).
          4. 
      
        4. Inputs in, result out. Take small values by value, return the answer (F.16, F.20). Prefer a chute to a loudspeaker.
          5. 
      
        5. Defaults before twins. If two versions would differ only in a preset, use one machine with a default argument (F.51).

        PART 5 · ROOMS IN A HOUSEScope, lifetime, shadowing, globals and static locals
        

  
        
    29
    
        Every pair of curly braces makes a room, called a block. A name made inside a room is known only from where it's made to that room's closing brace. That stretch of code is the name's scope. And when the room's closing brace is reached, the boxes made in it are destroyed: that's their lifetime.
        
    
        
    
        
      
      
        Wren says: From the kitchen you can see into the hall around it: apples is known there. From the hall you can't see into the kitchen. And the garden is a different house altogether: a function only knows its own parameters and locals, never the caller's. What's made in a room stays in the room.

          PART 6 · SURNAMESNamespaces, ::, and using
          

  
          
    36
    
          Big programs, and the libraries they use, have thousands of names. Two of them are bound to clash: two things called count. A namespace is a family surname for names. kitchen::count and garden::count are different things, like two people with the same first name in different families.
          
    
          
    
          
      
      
          Wren says: You've written a surname since Chapter 1! std is the standard library's family name, and :: joins surname to first name: std::cout, std::string. Surname first, then the name.
          
    
          
  
          

  
          
    37
    
          Making a family is easy: namespace kitchen { ... }. Everything declared inside gets the surname. Inside the family you can use first names alone (line 6 says just count); from outside you use the full name.
          
    namespaces.cpp
    
          
      
          
      
          
    
          
    
          
      
      
          Wren says: Two counts and two report machines, and no clash. On line 6, the kitchen's report finds its own family's count first. Notice no semicolon after a namespace's closing brace.
          
    
          
  
          

  
          
    38
    
          Tired of typing surnames? A using-declaration brings one name into the current room: after line 11, cout means std::cout until main's closing brace.
          
    using.cpp
    
          
      
          
      
          
    
          
    
          
      
          USING ONE NAMEusing std::cout;
          You choose exactly which names come in. Fine in a .cpp file, best inside the function that needs it.
          
      
          USING A WHOLE FAMILYusing namespace std;
          Brings in every name from std, hundreds of them, including ones you've never heard of. Seen in many tutorials. Next panel shows the trouble.
          
    
          
  
          

  
          
    39
    
    
          Mistake eight. A perfectly reasonable global called count, plus using namespace std;. But <algorithm> has a machine called std::count too, and line 3 just invited the whole std family in.

    42
    
          What you learned in Chapter 7
          
    
            
      
          • BUILD IT ONCE, PRESS IT OFTENA function is a named machine: return type, name, parameters, body. Calling it jumps in; return jumps back with one value. void means no value comes out. Programs start at main.
            • 
      
          • SLOTS IN THE BLUEPRINT, COINS IN THE CALLParameters are the slots; arguments are the values, matched by position. Printing isn't returning: a void result can't be stored.
            • 
      
          • EVERY ROAD NEEDS AN EXITDeclare before you call (or define first). A declaration is a promise; a missing definition is a link error. Every path through a non-void function must return.
            • 
      
          • THE MACHINE GETS A PHOTOCOPYPass by value copies the argument. Changes stay inside. Return the new value instead. Each call gets a frame on the call stack, destroyed at its return.
            • 
      
          • WHAT'S MADE IN A ROOM STAYS IN THE ROOMA name lives from its declaration to its block's }. Watch for shadowing (-Wshadow); avoid non-const globals; a static local remembers between calls.
            • 
      
          • SURNAME FIRST, THEN THE NAMENamespaces keep names apart: kitchen::count, std::cout. Prefer std:: or a single using std::x; over using namespace std;.

    Under the hood: frames, return addresses and mangled names
    
          
      
          The stack is real memory
          
      
          The call stack isn't only a picture. Each running program gets a region of memory called the stack. A call reserves a slice of it, the stack frame, for the function's parameters and locals, plus the return address: where to continue in the caller when the function returns. Returning releases the slice, which is why locals "die" at the closing brace: their memory is simply reused by the next call. That's also why a function must never hand back a reference to one of its locals, or its address (Chapter 8 shows the warning g++ gives for the reference).
          
      
          How arguments and results travel
          
      
          The exact rules are the platform's calling convention. On x86-64 Linux and Intel Macs (the System V convention), the first six whole-number arguments travel in processor registers rather than in memory, and an int result comes back in eax (the low half of the register rax). ARM64 machines, such as Apple Silicon Macs, use eight argument registers instead, and 64-bit Windows uses a different convention with four. Compilers also inline small functions, pasting the body in place of the call, so with optimisation turned on a tiny function may cost nothing at all. Write clear small functions; let the compiler worry about speed.
          
      
          How can two machines share a name?
          
      
          The Linker needs a unique name for every function. So the compiler quietly mangles each name with its parameter types. Here are the two biggest machines, compiled to an object file, and the names inside it listed by the nm tool. -C turns them back into readable C++:
          
      mangle.cpp
      
          
      
          
      
          _Z7biggestii means "a 7-letter name, biggest, taking int, int"; dd is two doubles. The return type is not part of the mangled name: C++ never chooses an overload by return type (overloads must differ in their parameters), so the name doesn't need it. The T means "defined in this file's code". The scheme shown is the Itanium C++ ABI used by g++ and clang on Linux and macOS: the same commands with clang++ 18 listed the same two names (only the offset of the second, 30 instead of 20, differed). Microsoft's compiler mangles differently.
          
      
          Why must a name be declared first?
          
      
          C++ inherited from C the idea that a compiler can check each call as it reads, top to bottom, knowing only what came earlier. That kept compilers small when C was young, and it is what lets separate files be compiled on their own, sharing declarations through header files (Chapter 10). Inside a class, the rule is relaxed: member functions can use members declared further down.
          
      
          Where do globals and statics live?
          
      
          Not on the stack. Global variables and static locals live in a separate area set up before main starts (or, for a static local, made the first time its line runs) and released after main ends. That's why the static bell remembered its count: its box was never on the stack at all. Since C++11, making a static local is safe even if several threads reach that line at once.
          
    
          
  
          

  
          
    In real programs
    
          
      
            
        
          • Small functions everywhere. Real code bases are mostly functions of a few to a few dozen lines, each with one job, named so that main reads like a table of contents. A good rule: if you're tempted to write a comment explaining what a block does, make it a function with that name instead.
            • 
        
          • The standard library is a toolbox of machines. std::max, std::min and std::abs already exist (std::max({3, 9, 4}) does max-of-three in <algorithm>). Learning a language is partly learning which machines it already has.
            • 
        
          • Exit codes drive automation. Build tools, test runners and shell scripts check whether each program returned 0. <cstdlib> names them EXIT_SUCCESS and EXIT_FAILURE.
            • 
        
          • Namespaces in the wild. Libraries put everything in their own namespace: std::, boost::, fmt::, absl::. Companies often use one per project. Long names get a short namespace alias: namespace fs = std::filesystem;.
            • 
        
          • Warnings as policy. Many teams build with -Wall -Wextra -Wshadow -Werror, so a shadowed name or a missing return can never reach users. Some go further and treat -Wreturn-type as an error by itself: -Werror=return-type.
            • 
        
          • Debuggers show the call stack. When a program stops in a debugger (Chapter 10), the "call stack" or "backtrace" window lists exactly the frames you stepped through in panel 22, and you can click each one to see its locals.
            • 
      
          
    
          
  
          

  
          
    Common wrong ideas
    
          
      
            
        
          • "The program runs from the top of the file." It starts at main. Function definitions only build machines.
            • 
        
          • "A function changes the variable I pass in." Not with pass by value: it gets a photocopy. Panels 18 to 20.
            • 
        
          • "Printing a value returns it." Printing shows it; only return hands it back to the caller.
            • 
        
          • "Parameter names must match the caller's variable names." Arguments match slots by position. print_box(height, width) puts height in the width slot (Boss 2).
            • 
        
          • "The Compiler will find my function further down." It reads top to bottom; declare first, or define first.
            • 
        
          • "A missing return is just a warning, so it's fine." Reaching the end of a non-void function is undefined behaviour. Treat that warning as an error.
            • 
        
          • "A variable made inside an if exists afterwards if the if ran." Scope is about where the code is written, not what ran.
            • 
        
          • "int total = ... inside a block updates total." The int makes a new, shadowing box.
            • 
        
          • "Globals save typing, so they're good." Non-const globals let any function change state invisibly. Pass values in and return results.
            • 
        
          • "using namespace std; is required." It's optional, and risky in big programs. Write std::.
            • 
        
          • "Two functions can differ only by return type." Overloads must differ in their parameters. The return type isn't used to choose.
            • 
        
          • "void main() is fine." Standard C++ requires int main(); g++ rejects void main (the lab's step 7 has the real run).

    Words from this chapter
    
          
      
          
        
          function
          A named group of steps that can be run (called) from elsewhere, taking inputs and optionally returning one value.
          
        
          call
          Running a function by writing its name and brackets: square(4).
          
        
          definition
          The signature plus the body in { }: how the function works. Exactly one per program.
          
        
          declaration (prototype)
          The signature followed by ;: tells the Compiler a function's name, parameters and return type.
          
        
          forward declaration
          A declaration placed before the definition so earlier code can call it.
          
        
          signature
          A function's name and parameter types (people often include the return type when they say it).
          
        
          parameter
          A named input slot in a function's definition: int n.
          
        
          argument
          The actual value given in a call: the 4 in square(4).
          
        
          return type
          The type of the value a function hands back, written before its name.
          
        
          return value
          The value a function hands back with return.
          
        
          void
          "No value": a void function returns nothing.
          
        
          pass by value
          Giving a function a copy of the argument. Changes to the copy don't affect the caller.
          
        
          stack frame
          The memory for one running call: its parameters, locals and return address.
          
        
          call stack
          The pile of frames for every call that hasn't finished, newest on top (drawn at the bottom in this book's tracer).
          
        
          stack trace
          The call stack written out, as in a sanitizer report or a debugger.
          
        
          exit code
          The number main returns to the shell; 0 means success.
          
        
          default argument
          A preset value for a parameter, used when the call leaves it out.
          
        
          overloading
          Several functions with the same name and different parameter lists.
          
        
          ambiguous call
          A call that two or more overloads fit equally well; a compile error.
          
        
          name mangling
          How the compiler encodes parameter types into a function's name for the Linker.
          
        
          undefined reference
          The Linker's error for a function that is called but never defined.
          
        
          block
          Statements inside { }; a room for names.
          
        
          scope
          The part of the code where a name can be used: from its declaration to the end of its block.
          
        
          lifetime
          When an object exists while the program runs. A local's lifetime ends at its block's closing brace.
          
        
          local variable
          A variable made inside a function or block.
          
        
          shadowing
          A name in an inner block hiding the same name from an outer block (or a global).
          
        
          global variable
          A variable made outside every function; known in the whole file and alive for the whole run.
          
        
          static local
          A local marked static: made once and kept between calls, but still named only inside its function.
          
        
          namespace
          A named family for declarations: namespace kitchen { ... }.
          
        
          scope resolution operator
          ::, joining a namespace to a name (std::cout), or alone in front of a name for the global one (::level).
          
        
          using-declaration
          using std::cout;: brings one name into the current scope.
          
        
          using-directive
          using namespace std;: brings every name of a namespace into the current scope.
          
        
          undefined behaviour
          Something the C++ rules give no meaning to, such as falling off the end of a non-void function. Anything may happen.
