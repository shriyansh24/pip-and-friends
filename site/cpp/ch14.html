C++ · CHAPTER 14

COAT CHECKS AND GADGETS

Picture: Wren, the mechanic in orange coveralls, waves hello next to her red toolbox.

Wren's crew is throwing a party, and the coats are piling up on one chair. Time for a coat check: hand over a ticket, get your coat back. In C++ that's a map, which files every value under a key. You'll learn the polite ways to ask a map a question (and the one way that quietly changes it), maps that keep order and maps that don't, sets that never hold anything twice, and how to count words. Then Wren opens her toolbox: the standard algorithms, ready-made gadgets for sorting, finding, counting and adding up, and lambdas, the clip-on attachments that tell a gadget what to do. About 120 minutes, with 25 hands-on checks.

  1. The coat check: std::map, [] and sorted order
  2. Asking without touching: at, find, contains, count, insert and erase
  3. Bins and badges: unordered_map, set, counting words, choosing a container
  4. The gadget drawer: iterators and the standard algorithms
  5. Clip-on attachments: first lambdas and captures
  6. Boss level and recap

    PART 3 · BINS AND BADGESunordered_map, std::set, counting words, and choosing the right container
    

  
    
    16
    
    C++ has a second coat check next door. A std::map keeps its hooks in sorted order. A std::unordered_map skips the sorting: a quick rule called a hash function turns each ticket into a bin number, and the coat goes straight into that bin. Fast to file, fast to find, but there's no "first" or "last" coat.

    22
    
      The gadgets don't take a whole vector. They take a range: two positions, where to start and where to stop. v.begin() is the position of the first box. v.end() is the position just past the last box: a "stop here" line, not a box.
      
    
    positions.cpp
    
      
      
      
      
      
    
      
    
      
      
      
      The crate says: An iterator is a position in me, like a finger on a box. * reads the box under the finger, as with a pointer. The last real box is end() - 1; reading *end() would read past my last box, which is never allowed. "From begin up to, but not including, end" is how every gadget walks me.

    35
    
      [lim] copies a value into the attachment. But sometimes the attachment must write into main's variables, like keeping a running total. [&] means "use main's own variables, by reference": the attachment writes straight into total and big. Here std::ranges::for_each runs the attachment once for each tip.
      
    capture_ref.cpp
    
      
      
      
      
      
    
      
    
      
      
      [lim]a copy inside the attachment
      The lambda gets its own copy of lim, made when the lambda is written. Good for reading a setting.

    Under the hood: trees, hash bins, pairs with a const key, and what a lambda really is
    
      
      
      A std::map is a sorted tree
      
      
      The standard doesn't say how to build a std::map, but it does set the speed: finding, inserting and erasing a key take time that grows with the logarithm of the size. Doubling the map adds roughly one more step. Every major library meets that with a balanced binary search tree (libstdc++ uses a red-black tree): each node holds one key and value, smaller keys go left, bigger keys go right, and the tree keeps itself roughly balanced. Walking it left to right visits the keys in sorted order, which is why the range-for loop always prints them sorted. That's also why a key type needs <: the map compares keys with std::less unless you give it a different rule.
      
      
      An unordered_map is an array of bins
      
      
      A std::unordered_map keeps an array of buckets. A hash function, std::hash, turns a key into a big number, and that number picks the bucket. Finding a key means hashing it and looking in one bucket, so it takes about the same time whatever the size (on average). When the buckets get crowded, the table rehashes: it builds more buckets and redistributes every element. That's why one extra key can change the whole printing order, and why the order is left unspecified. Keys need std::hash and ==; strings and numbers have both. Hashing your own struct is a later topic.
      
      
      Every element is a pair with a const key
      
      
      The element type of std::map<std::string, int> is std::pair<const std::string, int>. That's why a loop can write [name, n], and why a map's iterator has ->first and ->second. The key is const: changing a key in place would put it in the wrong spot in the tree. To "rename" a key, erase the old one and insert the new one.
      
      
      Why [] has to build a drawer
      
      
      m[k] returns a reference to the value (Chapter 8), so you can write m[k] = 5 or ++m[k]. A reference must refer to something, so when the key is missing the map has to create a value first. It uses a value-initialised one: 0 for numbers, false for bool, an empty string for std::string. Because it may change the map, operator[] can't be const, which is exactly the "discards qualifiers" error. (For the same reason, the value type needs a default constructor to be used with [].)
      
      
      Why std::remove can't remove
      
      
      An algorithm receives two iterators, not the container. Through a pair of positions it can read and overwrite elements, but it has no way to make the vector shorter. So std::remove moves the keepers forward and returns the position of the new logical end. The classic two-step, called the erase-remove idiom, hands that position to the vector's own erase: v.erase(std::remove(v.begin(), v.end(), 0), v.end());. C++20 wrapped both steps into std::erase(v, 0) and std::erase_if(v, pred). Chapter 25 returns to it.
      
      
      A lambda is an object
      
      
      For each lambda, the Compiler invents a small unnamed class with a function-call operator, and the lambda expression creates one object of it. Captured variables become its data members: [lim] gives it a member holding a copy of lim; [&] gives it references to the originals. That's why auto rule = [](int x) { return x > 5; }; works: rule holds the object, and rule(7) calls it. It's also why a lambda captured by reference must not outlive the variables it refers to, a danger Chapter 24 explores along with mutable and std::function.
      
      
      Algorithms and iterator kinds
      
      
      Not every container's iterators can do everything. A vector's iterators can jump (it + 5, end() - begin()): they are random-access. A list's can only step one element at a time. std::sort needs jumps, which is why panel 29 failed. The ranges versions state these needs as concepts (random_access_range, sortable), so the Compiler can say "constraints not satisfied" at your call instead of deep inside the library. Chapter 25 maps out every iterator category.
      
    
      
  
      

  
      
    In real programs
    
      
      
        
        
      • Counting is everywhere. Word frequencies, votes, page views, how many errors of each kind appeared in a log: a std::map<std::string, int> with ++counts[key] is the standard trick.
        • 
        
      • Configuration and lookups. Settings files become maps from option name to value; a program asks with contains or find and falls back to a default when an option is missing.
        • 
        
      • Caches. Programs remember answers they've already worked out in an std::unordered_map from question to answer, so they never compute the same thing twice.
        • 
        
      • Sets for "seen before?". Crawlers, games and puzzle solvers keep a set of visited places so they never go round in circles.
        • 
        
      • Algorithms in code review. Many teams ask "is there an algorithm for this?" when they see a raw loop. A named algorithm tells the reader the intent at once and has been tested by millions of programs.
        • 
        
      • Lambdas with sort. Sorting records by one field, highest first, is one of the most common lambdas you'll write: leaderboards, file lists by date, products by price.
        • 
        
      • The default choice. Real code uses std::vector most, then the maps. A sorted std::map is the safe first pick when you need a key; profile before swapping to unordered_map for speed.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "Reading m[k] can't change anything." It adds a drawer when k is missing (panels 6 and 7).
        • 
        
      • "A map remembers the order I added things." A std::map sorts by key; an unordered_map has no promised order at all.
        • 
        
      • "The unordered order I saw is the order." It's one library's result on one run. Another library, or one more key, can change it.
        • 
        
      • "Map keys are like vector indexes." They're labels. There's no element 0 unless you put a key 0 in.
        • 
        
      • "insert updates an existing key." It does nothing if the key exists. Use m[k] = v (or insert_or_assign) to overwrite.
        • 
        
      • "count can return 2." Not for std::map or std::set: keys are unique, so it's 0 or 1. (std::multimap allows repeats.)
        • 
        
      • "std::remove makes the vector shorter." It can't (panel 28). Use std::erase.
        • 
        
      • "end() is the last element." It's one past the last; reading through it is never allowed.
        • 
        
      • "max_element returns the biggest value." It returns a position; read it with *, after checking it isn't end().
        • 
        
      • "accumulate(v.begin(), v.end(), 0) works for doubles." The starting value's type decides the arithmetic: use 0.0.
        • 
        
      • "A lambda can use any variable it can see in the code." Only its parameters, globals, and what it captures.
        • 
        
      • ">= is fine in a sort comparison." It must be a strict "comes before": < or >.

    Words from this chapter
    
      
      
      
        
      map (std::map)
      A container of key and value pairs, each key unique, kept in sorted key order. From <map>.
      
        
      key
      The label you look things up by: the ticket.
      
        
      value (mapped value)
      What's filed under a key: the coat.
      
        
      operator[] (subscript)
      m[k]: the value for k, created with a value-initialised 0 if the key was missing. Not const.
      
        
      at
      m.at(k): the value for k, or a thrown std::out_of_range if it's missing.
      
        
      find
      Returns an iterator to the element with that key, or end().
      
        
      contains
      true if the key is present (C++20).
      
        
      count
      How many elements have that key: 0 or 1 for a map or set.
      
        
      insert
      Adds an element if its key is new; returns a pair whose .second says whether it did.
      
        
      erase
      m.erase(k) removes the element with key k and returns how many were removed.
      
        
      unordered_map
      A map that files keys into hash buckets; fast lookups, unspecified order. From <unordered_map>.
      
        
      hash function
      A rule that turns a key into a number used to pick a bucket.
      
        
      unspecified
      Allowed to differ between libraries or runs; the standard doesn't promise one result. Never rely on it.
      
        
      set (std::set)
      A sorted collection of unique keys with no values. From <set>. unordered_set is the hashed version.
      
        
      exception
      An emergency signal a function throws when it can't do its job; if nothing catches it, the program stops (Chapter 15).
      
        
      std::out_of_range
      The standard exception thrown by at for a missing key or position.
      
        
      algorithm
      A ready-made standard function for a common job, from <algorithm> or <numeric>.
      
        
      iterator
      A position in a container. *it reads the element; ++it moves to the next one.
      
        
      begin / end
      The position of the first element, and the position just past the last one.
      
        
      range
      A sequence given by a begin and an end position, or a whole container.
      
        
      std::ranges
      The C++20 versions of the algorithms, which take a whole container: std::ranges::sort(v).
      
        
      accumulate
      Adds up a range, starting from the value you give; the starting value's type decides the arithmetic.
      
        
      lambda
      A small unnamed function written where it's used: [](int x) { return x > 5; }.
      
        
      predicate
      A function that answers yes or no (returns bool), like the attachment handed to count_if.
      
        
      capture list
      The [...] at the start of a lambda: which outside variables it may use.
      
        
      capture by value / by reference
      [x] copies x into the lambda; [&] lets it use the original variables.
      
        
      comparator
      A two-parameter predicate telling sort whether a comes before b.
