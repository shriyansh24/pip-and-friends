C++ · CHAPTER 21

NEW WORDS, SPARE KEYS

Picture: Wren, the mechanic in orange coveralls, waves hello with her wrench.

C++ already knows what + means for two ints and what << means for a std::string. It has never heard of your types. This chapter has two halves. First, Wren teaches the old language new words: + for fractions, << for points, < for version numbers, [] and () for her own gadgets. Then she looks at what happens when an object is born, copied, overwritten and thrown away: the six special member functions. Copying an object that holds a key to the heap is like copying a house key. Get it wrong and two keys open one house, which then gets demolished twice. About 130 minutes, with 23 hands-on checks.

  1. New words: operator<<, operators as functions, Fraction arithmetic, member or non-member, the rules, this and chaining
  2. Comparing, converting, sharing: == and <=>, const operators, [] and (), explicit, conversion operators, friends, static members
  3. The six special members: who gets called when, what the Compiler writes, = default and = delete
  4. Spare keys: shallow and deep copies, the double free, and the rule of zero, three and five
  5. Boss level and recap

Every type comes with a little phrasebook: the operators it understands. An int's phrasebook is full: +, -, <, <<, everything. A brand-new struct knows almost nothing (just =, to copy it, and &, to take its address). Operator overloading means writing new entries in your type's phrasebook. "Overloading" means one name, several meanings: + keeps its old meanings and gains yours.

    

    

      
      
Wren says: Here's the whole secret: an operator is just a function with a funny name. The name of + is operator+; the name of << is operator<<. When the Compiler sees a + b and a is your type, it looks for a function called operator+ that takes an a and a b. Write that function, and the word exists.

    7
    
You may add entries to a phrasebook. You may not rewrite the language. The rules:

    
    
      
  1. Only existing operators. There's no ** for powers in C++, and you can't invent one.
    2. 
      
  2. Same shape. + between two things stays between two things, and * still happens before +. You can't change how many operands an operator takes or its precedence (Chapter 3's order of operations).
    3. 
      
  3. At least one side must be yours. int + int is built in and stays built in: try it below.
    4. 
      
  4. A few are off-limits: . (member access), ::, ?: and sizeof can't be overloaded.
    5. 
      
  5. Keep the meaning. + should add, == should compare and change nothing. The Compiler can't check this one. Your readers will.
    6.

Since C++20, line 10 does the lot. <=> is the three-way comparison operator, nicknamed the spaceship: it answers "less, equal or greater?" in one go. = default asks the Compiler to write it for you, and you need #include <compare> (line 2).

    PART 3 · THE SIX SPECIAL MEMBERSWho gets called when, temporaries, what the Compiler writes for you, = default and = delete
    

  
    
    19
    
    Every object goes through the same workshop. It is made, maybe copied, maybe overwritten, and finally thrown away. Each of those moments runs a member function with a fixed name and shape, and C++ calls them by itself. They're called the special member functions, and there are six.
    
    
      
      
    1. 1 · DEFAULT CONSTRUCTORGadget()
      Makes an object from nothing: Gadget a;
      2. 
      
    2. 2 · COPY CONSTRUCTORGadget(const Gadget&)
      Makes a new object as a copy of an old one: Gadget b{a};
      3. 
      
    3. 3 · COPY ASSIGNMENTGadget& operator=(const Gadget&)
      Overwrites an object that already exists with a copy: b = a;
      4. 
      
    4. 4 · MOVE CONSTRUCTORGadget(Gadget&&)
      Makes a new object by taking over an old one's insides. Chapter 22.
      5. 
      
    5. 5 · MOVE ASSIGNMENTGadget& operator=(Gadget&&)
      Overwrites by taking over. Chapter 22.
      6. 
      
    6. 6 · DESTRUCTOR~Gadget()
      Cleans up when the object's life ends (Chapter 12).
      7. 
    
    
    
    
      
      
    Wren says: Today is about stations 1, 2, 3 and 6. The two dashed ones, the moves, get a whole chapter next time; you'll see their names here because the Compiler uses them. The && in their signatures is a new kind of reference. For now: "a move takes over, a copy duplicates".
    
    
    
  
    

  
    
    20
    
    To see which station runs, Wren writes a Gadget that prints from every special member. Each new gadget gets the next id number from next_id (line 3), so you can tell them apart. main prints each statement before running it.
    
    noisy.cpp
    
    
      
    
      
    
    
    
    
      
      
    1. Statement 3, Gadget c = a;: there's an =, but it says copy, not copy-assign. c is being born on this line, so this is construction. The = here is just another way to write an initial value.
      2. 
      
    2. Statement 4, b = c;: b already exists. Now it's assignment: copy-assign #2 = #3. No new id: no new object.
      3. 
      
    3. Statement 5, c = Gadget{};: Gadget{} makes a temporary object, #4, with no name. It is moved into c (a temporary is about to die anyway, so taking over its insides is safe), and then it's destroyed at the semicolon, the end of the statement.
      4. 
      
    4. The end of main: the named gadgets die in reverse order of birth: #3, #2, #1. Last made, first destroyed, like plates on a stack.
      5. 
    
    
  
    

  
    
    21
    
    The one question that tells copy construction from copy assignment: is the object on the left being born on this line? If it has a type in front of it, it's being born.
    
    
    
    
    
      
      
    Wren says: Building a new house on an empty plot is easy. Making an existing house match its neighbour means dealing with what's already inside it first. That's why assignment is the harder one to write by hand, as Part 4 will show. Passing by value (void use(Gadget g)) is construction too: the parameter is a brand-new object born from the argument.

In principle that's a copy (or a move) out of the function. First, the normal build. Then the same source, built with -fno-elide-constructors, a g++ switch that turns off the optional shortcut.
    
    elision.cpp

    The Professor says: Skipping a copy or move like this is called copy elision. Returning a temporary (return Gadget{};) is elided by a rule since C++17, on every compiler, with or without the switch: that's statement 5 of the trace.     deleted_copy.cpp

      3.

    The Compiler's copy constructor copies each member. Usually that's perfect: copying a std::string member copies the text. But Chapter 13's raw pointer is just an address, a key to a block in the heap. Copying the key does not copy the house.

Twenty-seven lines became nineteen, and there's nothing left to get wrong. That's the rule of zero: let the members do the cleaning (Core Guideline C.20).

          Three rules, one idea. If your class directly manages something (a raw new, a file handle from a C library), it needs a destructor to give it back, and then the copies must be thought about too.

          What you learned in Chapter 21
          
    
            
      
          • AN OPERATOR IS A FUNCTION WITH A FUNNY NAMEa + b means operator+(a, b) (or a.operator+(b)). Teach your type a new word by writing that function. operator<< takes the stream and a const&, and returns the stream so chains keep going. Only existing operators, same shape, at least one side yours.
            • 
      
          • SYMMETRIC? SET IT FREEWrite +, ==, < and << as free functions, so both sides convert alike (1 + half). Write =, +=, [] and () as members, and return *this by reference to allow chaining. friend lets a free function read private members, when it really must.
            • 
      
          • LOOKING? SAY CONSTComparison operators only look, so they're const, or the call on a const object discards qualifiers. auto operator<=>(const T&) const = default; gives all six comparisons, member by member in declared order: right for versions, wrong for fractions.
            • 
      
          • ONE ARGUMENT? MAKE IT EXPLICITA one-argument constructor converts silently unless it's explicit (C.46). Conversion operators should be explicit too (C.164); explicit operator bool still works in if.
            • 
      
          • A PHOTOCOPIED KEY OPENS THE SAME HOUSEThe Compiler's copies copy member by member. For a raw owning pointer that's a shallow copy: shared data, then a double free. A deep copy builds a second house. Gadget c = a; is construction; b = a; is assignment.
            • 
      
          • LET THE MEMBERS DO THE CLEANINGRule of zero: use members that manage themselves and write no special members (C.20). If you write one of destructor, copy or move, write or = delete them all (C.21): the rule of three, or five. = delete makes a type non-copyable on purpose.

    Under the hood: how operators are found, what C++20 rewrites, and exactly when the Compiler writes each special member
    
          
      
          How the Compiler finds your operator
          
      
          For a + b with a class on either side, the Compiler gathers candidates from three places: member functions a.operator+(b), free functions named operator+ visible where the expression is, and free functions in the namespaces of the argument types. That last rule is argument-dependent lookup (ADL). It's why std::cout << s finds std::operator<< for std::string without you writing std:: in front of the operator. Put your type's operators in the same namespace as the type, and they'll always be found. Then overload resolution picks the best fit, preferring exact matches over conversions, exactly as for ordinary overloaded functions (Chapter 7). A friend defined inside the class (a hidden friend, Boss 4) can only be found by ADL, which keeps it out of unrelated searches and makes error lists shorter.
          
      
          What C++20 rewrites
          
      
            
        
          • a != b may be rewritten as !(a == b), so you write only ==.
            • 
        
          • a == b may also be tried as b == a (a "reversed candidate"). That's the "ambiguous, even though the second is reversed" warning in panel 12: two equally poor fits.
            • 
        
          • a < b, <=, >, >= may be rewritten as (a <=> b) < 0 and so on, in either order.
            • 
        
          • A defaulted <=> also declares a defaulted ==. A hand-written <=> does not, because equality can often be checked faster than ordering (compare lengths first).
            • 
        
          • <=> returns an ordering type from <compare>: std::strong_ordering for integers and for structs made of them, std::partial_ordering when some values can't be compared (a double NaN, Chapter 20), and std::weak_ordering for "equivalent but not identical", such as case-insensitive text.
            • 
      
          
      
          When the special members are written for you
          
      
          
        
          you declare...default ctorcopy ctor / copy =move ctor / move =destructor
          
        
          
          nothingwrittenwrittenwrittenwritten
          
          
          any constructornot writtenwrittenwrittenwritten
          
          
          a destructorwrittenwritten, but deprecatednot written: moves fall back to copiesyours
          
          
          a copy ctor or copy =(copy ctor counts as a constructor)yours, and the other written but deprecatednot writtenwritten
          
          
          a move ctor or move =(move ctor counts as a constructor)deletedyours (the other not written)written
          
                  
      
          
      
          "Written" always means "written if every member can do it": a unique_ptr member makes the copies deleted (panel 24), a const or reference member makes the assignments deleted. "Deprecated" means the standard keeps it only for old code and may remove it; g++'s -Wdeprecated-copy-dtor and clang's -Wdeprecated warn about it.
          
      
          Copy elision in one paragraph
          
      
          Since C++17, a prvalue (a temporary that hasn't been given a name, like Gadget{} or a function's return Gadget{};) is never copied or moved into the object it initialises: it's built in place. That's guaranteed, and it even works for types with deleted copy and move constructors. Returning a named local (return g;) may also be elided (NRVO), and in practice usually is, but it isn't guaranteed. When it isn't, the return uses the move constructor if there is one. Panel 22's -fno-elide-constructors only switches off the optional kind. The trace exercise's program, built with that switch, still shows statement 5 as a single default:
          
      
          
      
          trace_eight_noelide.cpp is a byte-for-byte copy of trace_eight.cpp, built with -fno-elide-constructors. 
          
      
          Copy-and-swap, the idiom
          
      
          Boss 3's careful order is easy to get wrong. The copy-and-swap idiom gets it right with less code: take the parameter by value (Scores& operator=(Scores other)), so the copy constructor builds the new block; then swap your pointer with the parameter's (std::swap(data_, other.data_);) and return *this;. The parameter dies at the end of the function and takes your old block with it. Self-assignment is safe, a failed copy leaves you untouched, and the same function serves as move assignment once moves exist. The price is an extra allocation even when the sizes already match.
          
    
          
  
          

  
          
    In real programs
    
          
      
            
        
          • The standard library is full of overloaded operators. std::string's + and ==, std::vector's [], iterators' * and ++ (Chapter 14), std::chrono's 2h + 30min, std::complex's arithmetic, and the streams' << and >>. Every one is a function like the ones in this chapter.
            • 
        
          • Maths libraries. Vector and matrix types in game engines and graphics code (position + velocity * dt) are the classic good use: the operators mean exactly what they mean on paper.
            • 
        
          • Function objects everywhere. Comparators for std::sort and std::map, hash functions for std::unordered_map, and every lambda are objects with an operator().
            • 
        
          • Non-copyable handles. std::unique_ptr, std::thread, std::mutex and file streams delete their copy operations: copying a running thread or an open file has no sensible meaning.
            • 
        
          • Rule of zero as house style. Many code bases forbid raw new and delete outside a few low-level classes, so that nearly every class follows the rule of zero and the few resource-owning ones are reviewed carefully.
            • 
        
          • Defaulted comparisons. Since C++20, one = default line replaces six hand-written comparison functions in record-like types: versions, dates, keys in a std::map.
            • 
        
          • Static members. Counters, shared configuration, and "named constructors" (Fraction::from_string("3/4")), which are static member functions that build an object.
            • 
      
          
    
          
  
          

  
          
    Common wrong ideas
    
          
      
            
        
          • "Operators are magic built into the language." For your types they're ordinary functions with special names (panel 2).
            • 
        
          • "I can make up new operators, like ** for powers." Only existing ones, with their usual number of operands and precedence (panel 7).
            • 
        
          • "Member or free makes no difference." A member never converts its left side, so 1 + half fails (panel 6).
            • 
        
          • "operator<< should return void." Then the chain stops after one link. Return the stream (panel 3).
            • 
        
          • "A defaulted <=> knows what my members mean." It compares them in declaration order, nothing more (panel 11).
            • 
        
          • "If it compiles, the conversion was intended." Non-explicit constructors convert silently (panel 14). Mark them explicit.
            • 
        
          • "Gadget c = a; calls operator=." c is born there: copy constructor (panel 20).
            • 
        
          • "The copy constructor always runs when I return an object." Copy elision skips it; since C++17 it's guaranteed for temporaries (panel 22).
            • 
        
          • "The Compiler's copy constructor copies everything deeply." It copies each member. For a raw pointer that's the address, not the block (panel 26).
            • 
        
          • "If I wrote a destructor, I'm done." Then the copies are wrong. Rule of three/five, or better, zero (panel 30).
            • 
        
          • "A class with a unique_ptr member is broken because it can't be copied." That's the Compiler protecting you. Decide what a copy should mean (panel 24).

    Words from this chapter
    
          
      
          
        
          operator overloading
          Giving an existing operator a meaning for your own type, by writing a function named operator+, operator<< and so on.
          
        
          operand
          One of the things an operator works on: in a + b, a and b.
          
        
          member operator / free (non-member) operator
          An operator written inside the class (the left operand is *this) or outside it (both operands are parameters).
          
        
          symmetric operator
          One whose two sides play the same role, like + and ==; best written as a free function.
          
        
          compound assignment
          +=, -= and friends: change the left side and return it.
          
        
          this / *this
          Inside a member function: a pointer to the object it was called on / that object itself.
          
        
          chaining
          Calling one function on the result of another, r.add(...).add(...), made possible by returning *this by reference.
          
        
          three-way comparison, spaceship
          <=> (C++20): answers less, equal or greater in one go.
          
        
          defaulted comparison
          = default on == or <=>: compare member by member, in declaration order.
          
        
          subscript operator
          operator[]: lets an object be indexed like a vector.
          
        
          call operator, function object, functor
          operator(): lets an object be called like a function; such an object is a function object.
          
        
          converting constructor
          A constructor callable with one argument and not explicit: the Compiler may use it to convert silently.
          
        
          explicit
          On a constructor or conversion operator: never use it for silent conversions.
          
        
          conversion operator
          A member like operator bool() that turns your type into another.
          
        
          friend
          A function (or class) that a class allows to read its private members. Named inside the class.
          
        
          hidden friend
          A friend function defined inside the class body; found only through argument-dependent lookup.
          
        
          static data member / static member function
          Belongs to the class, not to one object: one shared copy; called as Class::f(), with no this.
          
        
          nested type
          A type declared inside a class, like Ticket::Kind.
          
        
          temporary object
          An unnamed object such as Gadget{}; it dies at the end of the full statement (the semicolon).
          
        
          special member functions
          Default constructor, copy constructor, copy assignment, move constructor, move assignment and destructor.
          
        
          copy constructor / copy assignment
          Make a new object as a copy / overwrite an existing object with a copy.
          
        
          = default / = delete
          "Write the usual version" / "this function must not exist".
          
        
          non-copyable
          A type whose copy operations are deleted, like std::unique_ptr.
          
        
          copy elision
          Skipping a copy or move by building the object in its final place; guaranteed for temporaries since C++17.
          
        
          shallow copy / deep copy
          Copying a pointer (two keys, one house) / copying what it points to (a second house).
          
        
          double free
          Returning the same heap block twice: undefined behaviour.
          
        
          self-assignment
          x = x; an assignment operator must survive it.
          
        
          rule of zero / three / five
          Write no special members / if you write one of destructor, copy constructor, copy assignment, write all three / the same, with the two moves.
          
        
          copy-and-swap
          An idiom for writing assignment safely: copy into a by-value parameter, then swap.
