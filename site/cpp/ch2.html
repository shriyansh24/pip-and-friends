Line 3: int main() {. A function is a named group of instructions. main is the one every program must have: the front door.

    

      
intwhat comes back
When main finishes it hands back a whole number (an integer) to whoever started it. 0 means "all good".

      
main()the name, then parentheses
The name must be exactly main, lower case. The empty () say "this function needs no inputs".

      
{ ... }a block
The braces open and close main's body. Every { needs its }, like a lid and a base.

    12
    
    Three ways to end a line. "\n" inside the text, '\n' as its own box, or std::endl.
    
    endl.cpp
    
    
    
    
    
    
      
    '\n'the new-line box
    Moves to the next line. The text waits in a holding tray, called a buffer, and is shipped to the screen in batches. Batches are fast.
    
      
    std::endlnew line + ship now
    Moves to the next line and forces the tray to be shipped this instant. That is called flushing. Extra work, every time.
    
    
    
    
    
      
      
    Wren says: Same output, as you can see. So this book uses '\n'. Save std::endl for when you truly need the text out now. Everything still in the tray is shipped when the program ends normally anyway.

    Comments are notes for humans. The Compiler skips them completely. Two kinds:
    
    
    
      
    // ...to the end of the line
    Everything from // to the end of that line is ignored. Code before it on the same line still counts.

    PART 5 · TURN UP THE ALARMSWarning flags, -Werror, and asking for help
    

  
    
    30
    
    Warnings are optional extras. You switch groups of them on with flags in the compile command. This book always uses -Wall -Wextra.
    
    
    
      
    -Wall
    The common warnings. Despite the name, not all of them.
    
      
    -Wextra
    More warnings that -Wall leaves out.
    
      
    -Wpedantic
    Warns when you use a compiler extra the official standard forbids.
    
      
    -Wshadow
    Warns when one name hides another. (Useful from Chapter 3 on.)
    
      
    -Wconversion
    Warns when a value silently changes, like 3.7 becoming 3.
    
      
    -Werror
    Turns every warning into an error: the gate stays down.
    
    
    
    
    Pictures: six dials. -Wall and -Wextra are drawn turned on and filled yellow; -Wpedantic, -Wshadow, -Wconversion and -Werror are drawn with dashed outlines, off in this book's standard command.

      2.

    Under the hood: what each line of Hello, World really is
    
    
      
    #include is copy and paste
    
      
    The preprocessor runs first. It obeys every line that starts with # and then hands the result to the compiler proper. #include <iostream> is replaced by the entire text of the iostream header, which itself includes other headers, and so on. Panel 4 counted the result: 6 lines in, tens of thousands out. Angle brackets search the system's include folders (here /usr/include/c++/13/); quotes, as in #include "mine.h", search your own folder first. Headers are covered properly in Chapter 10.
    
      
    std::cout is an object, << is an operator
    
      
    std::cout is an object: a thing the library has already made for you, of the type std::ostream ("output stream"). << is an operator, like +. Applied to an output stream it means "insert into", and it hands back the same stream, so the next << can use it. That is why std::cout << "a" << "b" works: it is read as (std::cout << "a") << "b". The same symbol means "shift bits left" between two whole numbers, which you'll meet much later.
    
      
    Buffers and flushing
    
      
    Talking to the screen is slow compared with copying characters in memory, so output streams collect characters in a buffer and send them in batches. std::endl writes '\n' and then calls flush(). Some things flush on their own: reading from std::cin flushes std::cout first (so prompts appear before you type), and a program that ends normally flushes everything. A program that crashes may lose what was still in the buffer, which is the one good reason to flush on purpose. std::cerr, the error stream, ships every piece of output immediately.
    
      
    Why the missing return was fine
    
      
    The C++ standard says that reaching the closing brace of main has the same effect as return 0;. This applies to main only. Any other function that promises to return a value must actually do so. (Falling off the end of one is undefined behaviour; Chapter 7 shows it.)
    
      
    What main may look like
    
      
    The standard allows int main() and int main(int argc, char* argv[]) (the second receives command-line words; Chapter 16 uses it). It must return int. void main(), seen in some old books, is not valid C++: g++ rejects it with an error.
    
    
    
  
    

  
    
    g++ versus clang++: the same mistakes, two styles
    
    
      
    Both compilers follow the same standard and both read the same files, but they word their reports differently. Every program on this page was compiled with both. Every program that built printed the same thing with both; only the messages differed. (The one count that differs is pasted.cpp's: clang's preprocessor writes 44150 lines where g++'s writes 44652.) A few comparisons, all real runs:
    
      
    
        
    Missing }, g++
    
        
    Missing }, clang++
    
      
    
      
    
        
    Unclosed comment, g++
    
        
    Unclosed comment, clang++
    
      
    
      
      
        
    • The heading. g++ opens with an In function ‘int main()’: line; clang++ does not.
      • 
        
    • Quotes. g++ uses curly quotes ‘ ’ when the terminal's language setting allows it (this capture used UTF-8) and straight quotes otherwise. clang++ always uses straight quotes.
      • 
        
    • The count. clang++ ends with a total, like 2 errors generated.
      • 
        
    • Cascades. clang++ tends to recover from a mistake better: panel 28 showed one missing quote costing a few lines in clang++ and hundreds in g++. It is not always shorter, though: nobrace.cpp gave 4 errors in g++ and 5 in clang++.
      • 
        
    • Defaults. clang++ warns about int bolts = 3.7; with no extra flags; g++ needs -Wconversion.
      • 
      
    
      
    Reading both is a superpower: when one message confuses you, the other compiler's wording often makes it click. Compiler Explorer (godbolt.org) shows several compilers side by side in the browser.
    
    
    
  
    

  
    
    In real programs: warnings, errors and streams at work
    
    
      
      
        
    • Warnings as policy. Most teams compile with at least -Wall -Wextra, often -Wpedantic and -Wshadow too, and fix every warning. Many turn on -Werror on their test machines so a warning can never sneak in. Code shipped for other people to compile usually leaves -Werror off, because a newer compiler may invent new warnings.
      • 
        
    • Taming cascades. -fmax-errors=5 makes g++ stop after five errors; clang's matching flag is -ferror-limit=5. Fixing from the top and recompiling often is still the best tool.
      • 
        
    • Two output streams. Real programs send results to std::cout and problems to std::cerr, so a user can save the results to a file and still see the complaints. Compilers do the same: every message on this page went to the error stream, which is why the terminals show it in red.
      • 
        
    • Editors read the reports too. The file:line:col format is a convention that editors and IDEs understand: they turn each message into a squiggle and let you jump to the address with a click.
      • 
        
    • Style guides. The C++ Core Guidelines, written by experts including the creator of C++, include the rule SL.io.50: "Avoid endl". Same reason as panel 12.
      • 
      
    
    
    
  
    

  
    
    Common wrong ideas
    
    
      
      
        
    • "The program starts at line 1." It starts at main. Line 1 was for the preprocessor.
      • 
        
    • "Each std::cout starts a new line." Only a new-line box does: '\n', "\n" or std::endl.
      • 
        
    • "std::endl is the proper way; '\n' is a shortcut." '\n' is the normal way. endl adds a flush you rarely need.
      • 
        
    • "Single and double quotes are the same." Single quotes hold one character; double quotes hold text. 'Hello!' builds, warns, and prints a number.
      • 
        
    • "Indentation matters to the Compiler." Not in C++. Semicolons and braces do the work; indentation is for people.
      • 
        
    • "The error is exactly at the address." The address is where the Compiler noticed. A missing ; or { is usually just before it.
      • 
        
    • "Fix the error at the bottom of the screen." Fix the first one. The rest are often echoes.
      • 
        
    • "No error means the program is right." Warnings can still matter, and even a silent build can do the wrong thing (3.7 became 3).
      • 
        
    • "I should fix the file in /usr/include that the note points to." Never. Notes there are witnesses describing the library. The mistake is in your file.
      • 
        
    • "undefined reference is a typo on that line." It is the linker saying a piece doesn't exist anywhere. Look for something declared but never written, or a misspelled function name.
      • 
        
    • "using namespace std; is required." It's optional: it lets you drop std::, at the cost of possible name clashes. This book writes std:: every time, as many style guides recommend.

    Words from this chapter
    
    
      
    
        
    preprocessor
    The step before compiling that obeys # lines, such as pasting in headers.
    
        
    directive
    A line starting with #, like #include: an order for the preprocessor. It has no semicolon.
    
        
    header
    A file of declarations you #include, like <iostream>.
    
        
    standard library
    The toolbox of ready-made parts that comes with every C++ compiler.
    
        
    namespace
    A labelled group of names. The standard library's is std.
    
        
    ::
    "Inside": std::cout is the cout inside std.
    
        
    function
    A named group of instructions.
    
        
    main
    The function where every C++ program starts running.
    
        
    block
    Statements grouped by braces { }.
    
        
    statement
    One instruction, ended by a semicolon.
    
        
    whitespace
    Spaces, tabs and line breaks. Between parts of code, the Compiler ignores how much there is.
    
        
    std::cout
    The standard output stream: the belt to the screen.
    
        
    <<
    The insertion operator: drops a value onto an output stream.
    
        
    string literal
    Text in double quotes, like "Hello".
    
        
    character literal
    One character in single quotes, like 'A' or '\n'.
    
        
    escape sequence
    A backslash code for a special character: \n, \t, \", \\.
    
        
    buffer
    A holding tray where output waits before being shipped to the screen.
    
        
    flush
    Ship everything in the buffer now. std::endl does it after a new line.
    
        
    comment
    A note for humans, ignored by the Compiler: // ... or /* ... */.
    
        
    exit code
    The number a program hands back when it ends; 0 means success.
    
        
    diagnostic
    Any message from the compiler: an error, a warning or a note.
    
        
    error
    A broken rule. No program is made.
    
        
    fatal error
    An error so bad that compiling stops at once, like a missing header.
    
        
    warning
    Legal but suspicious code. A program is still made.
    
        
    note
    An extra clue attached to an error or warning: the witness.
    
        
    address
    The file:line:column at the start of a message.
    
        
    caret
    The ^ under the code that points at the exact column.
    
        
    fix-it
    A suggested repair printed under the caret.
    
        
    cascade
    Many errors caused by one mistake.
    
        
    linker
    The tool (ld) that joins compiled pieces into a program.
    
        
    undefined reference
    The linker's message for a piece that was promised but never built.
    
        
    object file
    A compiled piece of a program (.o), waiting to be linked.
    
        
    flag
    An option in a command, like -Wall.
    
        
    -Werror
    The flag that turns warnings into errors.
