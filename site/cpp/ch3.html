    PART 2 · SHELF RULESAssignment, names, sealed boxes and the empty-box trap
    

  
    
    7
    
    Two different moments in a box's life. They can look alike, so learn to tell them apart.
    
    
    
      
    
        
    INITIALISATIONfilled as it's made: once
    
        
    
        
    A type comes first: int score{10}; or int score = 10;. The box is born full.
    
      
    
      
    
        
    ASSIGNMENTcontents swapped later: any time
    
        
    
        
    No type in front: score = 15;. The box already exists; its old value is thrown out.
    
      
    
    
    
    
    
      
      
    Wren says: And = doesn't mean "equals" like in maths. It means "put the right side into the box on the left". That's why score = score + 5; makes sense: work out the right side first, then store it.

    16
    
    Wren's shelf rules. They come from the C++ Core Guidelines, written by the language's creator and many experts.
    
    
      
      
    1. Always initialise. Every box filled when it's made. Guideline ES.20
      2. 
      
    2. Prefer braces {}. One style for everything, and braces catch values that don't fit. Guideline ES.23
      3. 
      
    3. Seal by default. Write const unless the value really needs to change. Guideline Con.1
      4. 
      
    4. One box per line. int a, b = 5; fills only b! Guideline ES.10
      5. 
      
    5. Make it near where you use it. A box declared just before it's needed is easy to check. Guideline ES.21
      6. 
    
    
    
    
      
      
    Wren says: Tidy shelves, fewer surprises. Measure twice, compile once.
    
    
    
  
    

  
  
    PART 3 · WHAT KIND OF BOX?int, double, bool, char, sizeof, literals and auto
    

  
    
    17
    
    Four kinds of box come built into C++. They're called fundamental types. Meet the creatures who live in them:
    
    
    
      
    BRICKint
    Whole numbers. Solid, countable: 12, 0, −7. No fractions, ever.
    
      
    JELLYdouble
    Numbers with a point: 2.49, 0.5. Handy, but a tiny bit wobbly.
    
      
    LAMPbool
    Only two values: true (on) or false (off).
    
      
    TILEchar
    One character in single quotes: 'A'. Secretly a small number.
    
    
    
    
    Picture: four creatures. Brick, an orange block labelled 12, is int. Jelly, a green wobbly blob labelled 2.49, is double. Lamp, a lit lamp, is bool. A letter tile showing A with a small 65 in the corner is char.

    Under the hood: what a box really is
    
        
      
        Objects, addresses and names
        
      
        The C++ rules call a piece of memory that holds a value an object, and a named object a variable. Memory is numbered byte by byte; each object sits at an address and covers as many bytes as its type needs (panel 20). The names exist only for you and the Compiler: after compiling, the machine code just says "the 4 bytes at this spot". That's why a typo in a name is caught at build time, never at run time.
        
      
        Where do local boxes live?
        
      
        Boxes made inside main live in an area called the stack. When main starts, it grabs a chunk of stack; when it ends, the chunk is handed back. Nobody wipes that memory between users, which is exactly why an unfilled box contains leftovers. Filling it costs one tiny instruction.
        
      
        How an int is stored
        
      
        A 4-byte int has 32 bits. Half the patterns are used for negative numbers (a scheme called two's complement), so the range runs from −2147483648 to 2147483647, the two numbers limits.cpp printed. 2147483647 is 231 − 1. The standard library also offers std::numeric_limits<int>::max() from <limits>, the C++-style way to ask the same question.
        
      
        How a double is stored
        
      
        A double uses 64 bits in the IEEE 754 format: a sign, an exponent and about 53 bits of binary digits. Binary fractions are made of halves, quarters, eighths… so 0.5 and 0.75 fit exactly, but 0.1 is a repeating fraction in binary, like 1/3 in decimal. The nearest double to 0.1 is very slightly more than 0.1, and the same for 0.2; their sum lands a hair above the nearest double to 0.3. A double gives about 15 to 17 significant decimal digits, which is why setprecision(17) reveals the wobble.
        
      
        A char is a 1-byte number
        
      
        sizeof(char) is 1 by definition. The letter codes come from ASCII (A = 65, a = 97, the digit 0 = 48). Whether a plain char counts as signed or unsigned depends on the platform; it doesn't matter for letters.
        
    
        
  
        

  
        
    Undefined behaviour, a first look
    
        
      
        Three things in this chapter have undefined behaviour (UB): reading an unfilled box, overflowing a signed integer, and dividing a whole number by zero. "Undefined" means the C++ standard sets no rules at all for what happens. It is not "a random number": the compiler is allowed to assume UB never happens and to build the program around that assumption. Results can change with the compiler, the optimisation level (-O2) or the surrounding code.
        
      
        Why this book never shows UB output
        
      
        Any number we printed from such a run would be a coincidence of this machine, this compiler and this day, and you might learn it as a fact. So for overflow and divide by zero we show only the sanitizer report: a build with extra checks (-fsanitize=address,undefined) that catches the mistake at the exact line. -fno-sanitize-recover=all stops the program at the first report instead of letting it carry on.
        
      
        Not every UB is caught
        
      
          
        
        • AddressSanitizer and UndefinedBehaviorSanitizer don't detect reads of unfilled boxes. Your guards are -Wall (it turns on -Wuninitialized) and the habit of always initialising. clang offers a separate MemorySanitizer for this, and Valgrind can also find it; both are beyond this chapter.
          • 
        
        • g++'s -Wuninitialized works best with optimisation on; some cases are only reported at -O1 or higher. Don't treat "no warning" as "no problem".
          • 
        
        • Unsigned integers (Chapter 20) don't overflow in the UB sense: they wrap around by rule. Floating-point division by zero is also different: on IEEE 754 machines it gives infinity or "not a number".
          • 
      
        
      
        A change on the way
        
      
        The C++26 draft (finished by the committee in March 2026 and sent to the national bodies for their vote; as of November 2026 it is not an official ISO standard yet, so C++23 remains the current standard) reclassifies reading an unfilled local variable as erroneous behaviour: still a bug, but with limits on what can happen. The advice doesn't change: fill the box. (Status as of 8 November 2026; sources in "Go deeper".)
        
      
        Chapter 11 is all about UB and the full sanitizer toolkit.
        
    
        
  
        

  
        
    In real programs
    
        
      
          
        
        • const everywhere. Many code bases make every local variable const unless it must change. Reviewers then know which boxes to watch.
          • 
        
        • Money in cents. Banks and shops store amounts as whole numbers of the smallest unit (cents, pence), often in a 64-bit integer, so sums stay exact. Rounding to two decimals happens only when printing.
          • 
        
        • Overflow bugs are real. Counters that run for a long time, sizes multiplied together and timestamps can all outgrow an int. Programmers pick bigger types (long long, 8 bytes here), check before adding, and run tests with sanitizers.
          • 
        
        • Digit separators such as 1'000'000 arrived in C++14 and make big constants readable at a glance.
          • 
        
        • Naming styles vary by team: the standard library uses snake_case; many companies use camelCase. Be consistent within a project.
          • 
        
        • Warnings as errors. Teams add -Werror so that an unused or unfilled variable stops the build instead of scrolling past.
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "int x; starts at 0." Only int x{}; does. Without an initialiser a local box holds junk. Panel 14.
          • 
        
        • "= means equals." It means "store". Testing equality is ==, in Chapter 5.
          • 
        
        • "Putting the result in a double keeps the fraction." Not if the division was already done with two ints. Panel 37.
          • 
        
        • "Integer division rounds." It chops toward zero: 7 / 2 is 3, and −7 / 2 is −3.
          • 
        
        • "^ means power." It's XOR. Use std::pow or multiply.
          • 
        
        • "0.1 + 0.2 is exactly 0.3 because the screen says so." The screen rounds to 6 digits. Panel 33.
          • 
        
        • "Overflow wraps around to the smallest number." For signed int it's undefined behaviour; a wrapped number you might see once is not a rule.
          • 
        
        • "A char holds text." It holds one character, which is really a small number. Text is std::string, in Chapter 5.
          • 
        
        • "const and constexpr are the same." Both seal the box; constexpr also demands the value be known while compiling.
          • 
        
        • "auto means the box can hold anything." The kind is decided once, from the starting value, and never changes.

    Words from this chapter
    
        
      
        
        
        variable
        A named box in memory that holds one value of one type.
        
        
        object
        The C++ word for a piece of memory holding a value. A variable is a named object.
        
        
        memory
        Where a running program keeps its values: a long shelf of numbered bytes.
        
        
        type
        The kind of a box: what it may hold and how big it is, like int or double.
        
        
        declaration
        A line that introduces a name and its type, like int apples{5}; (Chapter 7 shows declarations that only promise).
        
        
        initialisation
        Filling a box at the moment it's made. Brace ({5}), copy (= 5) or value ({}, which gives zero).
        
        
        initialiser
        The value written in a declaration, such as the {5} in int apples{5};.
        
        
        assignment
        Replacing the value in an existing box: score = 15;.
        
        
        identifier
        The official word for a name you choose.
        
        
        keyword
        A word C++ keeps for itself, like int, class or return.
        
        
        case-sensitive
        Capital and small letters count as different: score is not Score.
        
        
        const
        Makes a box read-only after it's filled.
        
        
        constexpr
        Read-only, and the value must be known while compiling.
        
        
        indeterminate value
        The junk in a box that was never filled.
        
        
        undefined behaviour
        Code the C++ rules give no meaning to, such as reading junk, overflow, or dividing an int by zero.
        
        
        fundamental types
        The kinds built into C++, like int, double, bool and char.
        
        
        int / double / bool / char
        Whole number (brick) / number with a point (jelly) / true or false (lamp) / one character (tile).
        
        
        byte
        8 bits. Memory is measured in bytes.
        
        
        sizeof
        Asks how many bytes a type or box takes, on this machine.
        
        
        literal
        A value typed straight into the code, like 42, 3.5 or 'A'.
        
        
        digit separator
        The ' in 1'000'000; ignored by the Compiler.
        
        
        ASCII
        The table of character codes: A is 65, a is 97.
        
        
        auto
        Lets the Compiler choose a box's type from its starting value.
        
        
        operator / operand
        A symbol that computes, like + / the values it works on.
        
        
        integer division
        / with two ints: the fraction is chopped off, toward zero.
        
        
        remainder (modulo)
        %: what's left over after integer division.
        
        
        precedence
        The order operators are worked out in: parentheses, then * / %, then + -.
        
        
        compound assignment
        Shortcuts like x += 3, meaning x = x + 3.
        
        
        increment / decrement
        ++x adds 1 / --x subtracts 1.
        
        
        <cmath>
        The standard library part with maths functions like std::pow and std::sqrt.
        
        
        overflow
        A result too big for its type. For signed ints, undefined behaviour.
        
        
        sanitizer
        A build option that adds checks and reports problems like overflow while the program runs.
