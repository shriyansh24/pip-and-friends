C++ · CHAPTER 8

NICKNAMES AND EGG CARTONS

Picture: Wren the mechanic waves hello. Beside her is the Crate, a row of three numbered boxes holding 62, 58 and 65, and the Sanitizer in night-vision goggles, smiling.

Two new tools for Wren's toolbox. A reference is a nickname: a second name for a box that already exists, so a function can change your variable or read a big one without copying it. A std::vector is an egg carton that grows when you add eggs, and a std::array is a carton moulded to an exact size. Along the way: names that dangle, cartons that move, and the Sanitizer catching every egg that isn't there. About 110 minutes, with 27 hands-on checks.

    16
    
        Three ways to hand something to a machine. Ask two questions: will it change it? and is it cheap to copy?
        
    
        
      
        A PHOTOCOPYpass by value
        void f(int n)
        Only reads it, and it's small: int, double, char, bool.
        Copying a number is as cheap as pointing at it, and the function can scribble on its copy safely.
        
      
        A VISITOR BADGEpass by const&
        void f(const std::string& s)
        Only reads it, and it may be big: std::string, std::vector, your own types later.
        No copy, and no way to change it by accident. Takes variables and temporaries.
        
      
        A NICKNAMEpass by reference
        void f(int& n)
        Must change the caller's variable.
        The & in the signature warns every reader: "this may change your box". Use it on purpose, not out of habit.
        
    
        
    
        
      
      
        The Professor says: This is straight from the C++ Core Guidelines, rules F.16 and F.17: cheap "in" parameters by value, other "in" parameters by const&, "in-out" parameters by &. And rule F.20: when a function produces a value, prefer returning it over changing a parameter.

              Three member functions people mix up, because they all sound like "make room".
              
    reserve_resize.cpp
    
              
    
              
    
              
      
              reserve(10)buy a bigger carton
              Capacity becomes at least 10. Size stays 0: no eggs. Handy when you know how many are coming: no moves while you push.

              Size becomes 3. New eggs are 0 (for numbers). Making it smaller throws eggs away from the back.

              Size becomes 0. The carton itself is kept: capacity is still 3.

    Under the hood: references, frames and how a vector stores its eggs
    
              
      
              What a reference compiles to
              
      
              The language says a reference is not an object: it has no size of its own you can ask for, and you can't make a reference to a reference or a vector of references. Underneath, when a reference has to be stored or passed (a parameter like int& x), the compiler almost always passes the address of the box. That's why the stack-and-heap picture in panel 37 draws it as a ticket. Inside one function, a reference like bob usually costs nothing at all: the compiler just uses robert's box wherever you wrote bob.
              
      
              Why a plain int& refuses 40
              
      
              Every expression has a value category. An lvalue names a box that outlives the expression (robert, eggs[0]). A prvalue like 40 or a + b is just a value. Binding a non-const int& to a value would let the function change something nobody can see, so it's forbidden. A const int& may bind to a value: C++ creates a temporary box and keeps it alive as long as that reference lives. That rule is why greet("Bob") works with const std::string&.
              
      
              C++23 made one mistake an error
              
      
              Since C++23 (the "simpler implicit move" rule), a local variable named in a return statement is treated as something about to expire (an xvalue), which a plain int& can't bind to. So the non-const version of panel 17's mistake doesn't even compile with -std=c++23:
              
      return_local_ref.cpp
      
              
      
              
      
              The const& version in panel 17 still compiles, with the warning. Under -std=c++20 the non-const version compiles too, with only the warning:
              
      return_local_ref20.cpp (same source as return_local_ref.cpp)
      
              
      
              
      
              A vector is three numbers on the stack
              
      
              A std::vector<int> object itself is small: in libstdc++ it holds three pointers, to the first egg, one past the last egg, and one past the last cup. size() and capacity() are worked out from them. The eggs live in one block on the heap, side by side with no gaps, which is why eggs[i] is fast: start address plus i times the size of an int.
              
      
              Why doubling?
              
      
              Moving every egg is expensive, so libstdc++ multiplies the capacity by 2 each time it runs out (panel 34: 1, 2, 4, 8); other libraries use 1.5. Either way, the total work spread over many push_backs stays small: on average each push costs a constant amount ("amortised constant time"). The standard only promises that; the exact factor is up to each library.
              
      
              Returning a whole vector is cheap
              
      
              In panel 33, doubled returns a vector by value. The compiler usually builds result directly in the caller's variable (copy elision); if it can't, the vector is moved: the three pointers are handed over and the eggs stay where they are. Either way no egg is copied. Chapter 22 covers moves properly.
              
      
              std::array lives right on the plate
              
      
              A std::array<int, 7> has no heap block. Its seven ints are stored inside the object itself, so it sits wherever the variable sits (on main's plate here). That's why its size must be known while compiling.
              
    
              
  
              

  
              
    In real programs
    
              
      
                
        
              • const& is everywhere. Open almost any modern C++ code base and most function parameters that are strings, vectors or bigger types are const T&. Seeing a plain T& is a signal to readers: "this function changes what you pass".
                • 
        
              • Vector is the default container. Stroustrup and the Core Guidelines (SL.con.2) say: use std::vector unless you have a reason not to. Microsoft's "Welcome back to C++" page gives the same advice. Its eggs sit side by side in memory, which modern processors read very fast.
                • 
        
              • reserve in hot loops. When a program knows it will push a million items, a reserve(1'000'000) first avoids about twenty carton moves. Measure before assuming it matters (Core Guideline Per.6).
                • 
        
              • Checked builds. Many teams test with -D_GLIBCXX_ASSERTIONS (or the sanitizers), so that an out-of-range [] stops the program in testing instead of quietly reading a wrong value in production. Some projects turn the assertions on in release builds too.
                • 
        
              • Grids. A vector of vectors is the simplest grid, good for small boards and puzzles. Programs that need speed often use one flat vector of rows * cols cells and compute row * cols + col themselves, so the whole grid is one block.
                • 
        
              • Dangling references are a classic security bug. "Use after free" is a whole category in vulnerability databases. It's one reason sanitizers exist, and one reason newer languages (Rust's borrow checker) refuse such programs at compile time.
                • 
      
              
    
              
  
              

  
              
    Common wrong ideas
    
              
      
                
        
              • "int& r = x; copies x." No box is made; r is x. Panel 5.
                • 
        
              • "r = y; makes r refer to y." It copies y's value into x. A reference is never reseated. Panel 7.
                • 
        
              • "References are always faster." For small types like int a copy is just as cheap, and clearer. Use const& for big things. Panel 16.
                • 
        
              • "A const& parameter can't take a literal." It can: greet("Bob") works. It's a plain T& that can't. Panels 12 and 14.
                • 
        
              • "Returning a reference avoids a copy, so it's better." Only when the box outlives the function. Returning a reference to a local is a dangling reference. Panel 17.
                • 
        
              • "for (auto x : v) x *= 2; doubles the vector." It doubles copies. Use auto&. Panel 29.
                • 
        
              • "v[i] and v.at(i) are the same." Same result when i is valid. Out of range, .at throws std::out_of_range; [] is undefined behaviour. Panels 25 and 26.
                • 
        
              • "The last element is v[v.size()]." It's v[v.size() - 1], or v.back().
                • 
        
              • "empty() empties the vector." It only asks. clear() empties. Panel 24.
                • 
        
              • "reserve(10) gives me 10 elements." It gives room for 10 and zero elements; v[0] is still past the end. resize(10) makes 10 elements. Panel 39.
                • 
        
              • "std::vector<int> v{10}; makes 10 elements." Braces list elements: one element, 10. Use v(10) for a count. Panel 39.
                • 
        
              • "A reference into a vector stays valid as long as the vector exists." Not after anything that can grow it. Panels 35 to 37.
                • 
        
              • "std::array is the old C array." It's a safer wrapper around one: it knows its size, has .at(), and can be copied and passed like any value.

    Words from this chapter
    
              
      
              
        
              reference
              Another name for an existing object: int& bob{robert};. A nickname.
              
        
              reseat
              To make a reference name a different object. C++ references can't be reseated.
              
        
              pass by value
              The parameter is a new box holding a copy of the argument.
              
        
              pass by reference
              The parameter is a nickname for the caller's variable (int& x).
              
        
              reference to const (const&)
              A nickname you may only read through. Can also hold a temporary.
              
        
              lvalue
              An expression that names a box you could point at, like robert or eggs[0].
              
        
              rvalue
              A temporary value with no box of its own, like 40 or a + b.
              
        
              temporary
              An unnamed object C++ makes for a moment, such as a std::string made from "Bob".
              
        
              dangling reference
              A reference whose object no longer exists. Using it is undefined behaviour.
              
        
              stack
              The memory where function frames (plates) and their local variables live.
              
        
              heap
              The memory a program asks for while running, where a vector keeps its elements.
              
        
              std::vector
              A sequence that can grow and shrink: the stretchy egg carton. #include <vector>.
              
        
              element
              One item in a container: one egg.
              
        
              index
              An element's position number, starting at 0.
              
        
              template
              One design for many types, filled in with angle brackets: std::vector<int>.
              
        
              member function
              A function called with a dot on an object: eggs.size().
              
        
              push_back / pop_back
              Add an element at the end / remove the last element.
              
        
              front / back
              The first / last element.
              
        
              size / empty
              How many elements / whether there are none.
              
        
              .at()
              Element access that checks the index and throws std::out_of_range if it's wrong.
              
        
              exception
              A signal that something went wrong, thrown by code like .at(). Uncaught, it stops the program (exit 134 here).
              
        
              auto
              "Compiler, work out this type for me."
              
        
              std::ssize
              C++20: a container's size as a signed number, for index loops with int.
              
        
              capacity
              How many elements fit before the vector must get a bigger block (cups in the carton).
              
        
              reserve / resize / clear
              Make room without elements / change the number of elements / remove every element.
              
        
              std::erase
              C++20: remove every element equal to a value; returns how many went.
              
        
              std::array
              A fixed-size sequence whose size is part of its type: std::array<int, 7>. #include <array>.
              
        
              vector of vectors
              A vector whose elements are vectors: a grid, read as g[row][col].
              
        
              running maximum
              A variable holding the biggest value seen so far in a loop.
              
        
              heap-buffer-overflow / heap-use-after-free
              AddressSanitizer's names for reading past a heap block / reading a block already freed.
