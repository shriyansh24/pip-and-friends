    Under the hood: what a std::string really is
    
      
      
      A small object that points at the carriages
      
      
      A std::string object is a little control box: where the characters live, how many there are (the size), and how many fit before it must find more room (the capacity). Long text lives in memory the string borrows from the heap, the program's big pool of spare memory; when the string grows past its capacity it moves to a bigger piece. That borrowed memory is what the Sanitizer watched in panel 12.
      
      
      Short strings live inside the box
      
      
      With this toolchain's library (libstdc++, used by both g++ and clang++ here), a string object takes 32 bytes, and up to 15 characters fit inside those bytes without borrowing anything. This is the small string optimisation. It's why "hello"'s capacity is 15, and why the goggles missed seat 10 of "hello": that spot is inside the string object, not past a borrowed block. Other libraries choose other sizes; the C++ rules don't fix them.
      
      string_inside.cpp
      
      
      
      
      
      Seat numbers are unsigned
      
      
      .size() and .find() give a std::size_t: a whole number that can't be negative (unsigned), 8 bytes here. npos is its largest value, 264 − 1, which is the giant number in panel 13. One trap to remember for later: with an empty string, size() - 1 does not give −1; it wraps around to that same giant number. Chapter 20 covers unsigned numbers properly.
      
      
      Why const char [4]?
      
      
      A string literal is stored as an array of characters followed by a null character, '\0' (code 0), which marks the end. That's the C language's way of doing text, and C++ kept it for literals. Arrays of characters have no +, which is the whole story of panel 6. The suffix s (as in "Hi "s, after using namespace std::literals;) makes a literal a real std::string; this book sticks with std::string{"..."} because it's easier to read at first.
      
      
      How if becomes machine code
      
      
      The processor has no "if". The Compiler turns a condition into a compare instruction and a jump: "if the answer is false, jump past the true block". else adds one more jump over the false block. Short-circuiting falls out naturally: after the left side of &&, there is simply a jump straight past the right side.
      
    
      
  
      

  
      
    Exceptions, a first look
    
      
      
      When .at(), std::stoi or std::stod can't do their job, they don't return a made-up answer: they throw an exception, an object describing the problem. Its type names the kind of problem:
      
      
        
        
      • std::out_of_range: a position or value outside what's allowed. .at() with a bad seat; .substr() with a start past the end; std::stoi with digits too big for an int.
        • 
        
      • std::invalid_argument: input that can't be converted at all, like std::stoi("abc").
        • 
      
      
      
      If no part of the program catches the exception, C++ calls std::terminate. With g++'s library that prints terminate called after throwing an instance of '...' plus the exception's what() message, then aborts. Exit code 134 is 128 + 6, where 6 is the number of the "abort" signal on Linux and macOS.
      
      
      An exception is not undefined behaviour: it is defined, predictable and the same every run. That's why this book shows those runs as plain output, but never shows [] past the end without a sanitizer. Chapter 15 teaches try and catch, so a program can recover, ask again or explain politely.
      
      
      What std::stoi accepts
      
      
      It skips spaces at the start, accepts an optional + or -, then reads as many digits as it can and stops at the first character that isn't one. So "12 apples" gives 12 and " -7" gives −7. Only "no digits at all" throws invalid_argument. To check that the whole text was a number, std::stoi can report where it stopped (an optional second argument); Chapter 18 shows the stricter std::from_chars, which always reports where it stopped.
      
    
      
  
      

  
      
    In real programs
    
      
      
        
        
      • Parsing is everywhere. Splitting "Ada King" at the space is the same move as splitting a date at its dashes, a web address at its slashes, or a line of a spreadsheet file at its commas. find plus substr is the starter kit.
        • 
        
      • .at() or []? Code that has just checked i < s.size() often uses [] for speed. Code handling positions from outside (users, files, networks) checks first or uses .at(). Many teams also build test versions with sanitizers or with the library's checking mode, so an unchecked [] mistake is still caught before release.
        • 
        
      • Warnings as guards. -Wall already turns on -Wparentheses, -Wdangling-else and -Wmisleading-indentation; -Wextra adds -Wempty-body. Teams add -Werror so none of these can scroll past unnoticed. Some style guides go further and require braces on every if.
        • 
        
      • Yoda conditions. Some older code writes if (0 == lives), so that a missing = becomes a compile error. With modern warnings it's not needed, and most people find it harder to read.
        • 
        
      • Floating-point tolerances in real code are chosen to match the data: a fixed tolerance for values near 1, or a tolerance relative to the size of the numbers for big or tiny values.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "Seats start at 1." At 0. The last seat is size() - 1.
        • 
        
      • "Anything in double quotes is a std::string." It's a literal (const char[N]) until it meets a std::string. Panel 6.
        • 
        
      • "s = 65; stores the text 65." It stores the character with code 65: A. Use std::to_string.
        • 
        
      • ""10" < "9" is false." Strings compare character by character, and '1' comes before '9'. Convert with std::stoi to compare as numbers.
        • 
        
      • "find returns −1 when it fails." It returns std::string::npos. Compare with npos.
        • 
        
      • "[] past the end gives an error." It gives undefined behaviour, and maybe no visible symptom at all. Only .at() promises a check.
        • 
        
      • "stoi checks the whole text." It reads digits until it can't; "12 apples" gives 12.
        • 
        
      • "x == 1 || 2 means x is 1 or 2." It's always true. Write x == 1 || x == 2.
        • 
        
      • "Indentation decides which if owns an else." The nearest unmatched if owns it. Use braces.
        • 
        
      • "if (x = 5) is a compile error." It builds, with a warning, and stores 5 in x.
        • 
        
      • "Both sides of && are always worked out." The right side runs only if the left side is true (and for ||, only if the left side is false).

      After a run, echo $? (Linux, macOS, Git Bash) or $LASTEXITCODE (PowerShell) shows the exit code. Expect 134 after an uncaught exception on Linux and macOS. On Windows a crash like this usually reports a different code, often 3, and may show a dialog box.

    Words from this chapter
    
      
      
      
        
      string
      A piece of text. In C++, usually a std::string from <string>.
      
        
      character
      One letter, digit, space or symbol; a char.
      
        
      member function
      A function you call on an object with a dot: word.size().
      
        
      empty string
      A string with no characters: "" or std::string{}. Its size is 0.
      
        
      concatenation
      Joining strings end to end with + or +=.
      
        
      string literal
      Text written in double quotes in the code. Its type is const char[N], not std::string.
      
        
      null character
      '\0', the hidden end marker after every string literal.
      
        
      index
      A seat number. The first is 0.
      
        
      indexing
      Reaching one character with s[i] (unchecked) or s.at(i) (checked).
      
        
      substring
      A piece cut out of a string, made by .substr(start, count).
      
        
      npos
      std::string::npos, "no position": what find returns when there's no match.
      
        
      std::size_t
      The unsigned whole-number type used for sizes and seat numbers.
      
        
      exception
      A "something went wrong" signal that a function throws. Uncaught, it ends the program.
      
        
      escape sequence
      A backslash plus a character meaning one special character, like \n or \".
      
        
      raw string
      R"(...)": text where backslashes and quotes are not special.
      
        
      std::format
      Builds a string from a template with {} holes, from <format>.
      
        
      condition
      An expression whose value is true or false, which steers an if.
      
        
      relational operator
      < > <= >= == !=: compare two values and give a bool.
      
        
      logical operator
      && (and), || (or), ! (not).
      
        
      short-circuit
      && and || skip their right side when the left side already decides the answer.
      
        
      tolerance
      The tiny gap you accept when asking whether two doubles are "close enough".
      
        
      if / else
      Run one block when a condition is true, and (optionally) another when it is false.
      
        
      else if
      A further question tried only when everything above it was false; chained into a ladder.
      
        
      block
      Statements grouped in { } that run together.
      
        
      nested if
      An if inside another if's block.
      
        
      dangling else
      An else without braces belongs to the nearest if that has none, whatever the indentation says.
      
        
      empty statement
      A lone ;. After if (...) it becomes the whole body.
      
        
      conditional operator
      c ? a : b: the value a if c is true, otherwise b.
