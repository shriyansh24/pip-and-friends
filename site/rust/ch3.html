PART 1 · NUMBERS COME IN SIZESInteger types, their ranges, the default, and how to write numbers

1

Last chapter you made labelled boxes with let. Today: what goes inside them.

Mabel says: In my library every book has a shelf size. In Rust every value has a type: what kind of thing it is, and how much room it takes.

Mabel says: The Compiler knows the type of every box before the program runs. That's how it catches mix-ups early.

Picture: Mabel points ahead, ready to explain.

2

Think of a car's odometer: the little wheels of digits that count kilometres. More wheels, bigger numbers.

Mabel says: Rust's whole-number types are odometers with a fixed number of wheels. Inside the computer the wheels are bits: tiny switches that are 0 or 1. u8 has 8 bits, so it counts from 0 to 255.

3

A whole number is an integer. Every integer type's name is a letter and a size in bits.

i · SIGNEDi8 i16 i32 i64 i128

Can be negative. Half the room goes below zero. Use it for temperatures, scores that can drop, a change up or down.

u · UNSIGNEDu8 u16 u32 u64 u128

Never negative ("no sign"). All the room is zero and up. Use it for counts, ages, sizes, colours.

Mabel says: Same 8 bits, same 256 positions. i8 spends half of them on negatives, so it only reaches 127. The number after the letter is always the count of bits: 8, 16, 32, 64 or 128.

Pictures: two number lines. The i8 line runs from -128 through 0 in the middle to 127. The u8 line starts at 0 and runs to 255. Below, Mabel explains.

4

    Under the hood: bits, wrapping, floats and chars
    
        
      
        How a signed integer stores negatives
        
      
        An i8 and a u8 both have 8 bits, so both have 2⁸ = 256 patterns. A u8 reads them as 0 to 255. An i8 uses two's complement: the patterns from 0000 0000 to 0111 1111 mean 0 to 127, and the ones starting with a 1 mean the negatives, from 1000 0000 (−128) to 1111 1111 (−1). The point of this trick is that the CPU can add signed and unsigned numbers with the very same circuit. That's also why wrapping looks the way it does: add 1 to 1111 1111 and every bit flips to 0, with the carry falling off the end. For a u8 that's 255 → 0; for an i8 it's −1 → 0, and 127 + 1 wraps to −128.
        
      
        Why i32 is the default
        
      
        It's big enough for most everyday counting (about ±2.1 billion) and fast on every common CPU. The Rust book's advice: start with i32 unless you have a reason, and use usize for positions and lengths of things in memory.
        
      
        Why overflow checks are only in debug builds
        
      
        Checking every + costs a little time. Debug builds pay it to catch bugs while you test; release builds skip it for speed. You can switch the checks on for release builds too by adding overflow-checks = true under [profile.release] in Cargo.toml. Either way, Rust's rules say a plain + that overflows is a bug in your program. The explicit methods (checked_, wrapping_, saturating_, and overflowing_, which returns the wrapped value plus a bool) are how you say what you really want.
        
      
        Floats are binary fractions
        
      
        An f64 follows the IEEE 754 standard, like almost every language: 1 bit for the sign, 11 bits for a power of two, and 52 bits of digits. That's about 15 to 17 correct decimal digits. Numbers like 0.5 and 0.25 are exact; 0.1 and 0.2 are not, which is where 0.30000000000000004 came from. Floats also have special values. Dividing a float by zero doesn't panic:
        
      
        
      
        inf is infinity; NaN means "not a number", and it isn't even equal to itself.
        
      
        A char is not a byte
        
      
        A char holds one Unicode scalar value, a code number from 0 to 0x10FFFF (except a small reserved block), so it needs 4 bytes. Text (strings) stores characters more compactly in UTF-8, using 1 to 4 bytes each, which is why .len() on text counts bytes. One more surprise for later: what a person calls one character (like a flag emoji) can be several chars.
        
      
        The format string is checked at compile time
        
      
        println! is a macro, so the Compiler reads the format string before the program runs. That's how it could count the holes in spot_fmt.rs, and why a missing Display is a compile error rather than a crash.
        
    
        
  
        

  
        
    In real programs: choosing types, money, and printing
    
        
      
          
        
        • Counts, lengths and positions: usize. It's what .len() gives and what lists use for their positions (Chapter 5).
          • 
        
        • Bytes, colour channels, small codes: u8. Files and network data arrive as bytes.
          • 
        
        • Money: never a float. 0.1 + 0.2 shows why. Store whole cents in an integer (i64 allows a balance to go negative), or use a decimal library.
          • 
        
        • Measurements and science: f64. Use f32 only when memory or speed really matters, as in graphics and games.
          • 
        
        • Comparing floats: check whether the difference is tiny instead of using ==, for example (a - b).abs() < 1e-9.
          • 
        
        • Untrusted numbers (anything a user or a file gives you): use checked_add and friends, so overflow becomes something you handle, not a panic or a silent wrong answer.
          • 
        
        • stderr for problems: command-line tools print results with println! and warnings with eprintln!, so someone can save the results to a file (cargo run > out.txt) and still see the warnings on screen.
          • 
        
        • dbg! is temporary: remove it before you share code. Many teams' checks flag it.
          • 
        
        • Hex in real life: colours on the web (0xff8800), memory addresses and file formats. {:x} prints a number in hex, {:b} in binary.
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "7 / 2 is 3.5." Not for integers: it's 3, and % gives the 1 left over. Use 7.0 / 2.0 for 3.5.
          • 
        
        • "Integer division rounds." It cuts off toward zero: 7 / 2 is 3 and −7 / 2 is −3. 7.9 as i32 is also 7.
          • 
        
        • "Rust will convert my i32 to an f64 when it needs to." Never automatically. You write as f64.
          • 
        
        • "A u8 that overflows always panics." Only in a debug build. A release build wraps silently, unless you turn the checks on.
          • 
        
        • "Overflow wrapping is fine because it's what release does." A plain + that overflows is still a bug. If you want wrapping, write wrapping_add.
          • 
        
        • "A bigger type is always better." It works, but it takes more memory. Pick the odometer that fits the trip, with some room to grow.
          • 
        
        • "\"a\" and 'a' are the same." One is text, one is a char. E0308 if you swap them.
          • 
        
        • "0.1 + 0.2 printing 0.30000000000000004 is a Rust bug." Every language with binary floats gets the same number; some just print fewer digits.
          • 
        
        • "{} can print anything." Only types with Display. {:?} works for many more.
          • 
        
        • "format! prints." It only builds the text. Print it, or store it.
          • 
        
        • "Every help: line is the right fix." Usually it is. But as_text.rs's help suggested a "raw pointer", an expert tool that's wrong for a beginner's problem. Read help lines as suggestions, and think.

    Words from this chapter
    
        
      
        
        
        type
        What kind of value something is, and how much room it takes. The Compiler knows every value's type.
        
        
        bit
        A binary digit: 0 or 1. The smallest piece of computer memory.
        
        
        byte
        8 bits.
        
        
        integer
        A whole number, like 7 or −40.
        
        
        signed / unsigned
        Can / can't be negative: i8…i128 and u8…u128.
        
        
        usize / isize
        Integers the size of the computer's memory addresses (64 bits on most laptops), used for lengths and positions.
        
        
        float
        A number with a decimal point: f64 (default) or f32.
        
        
        bool
        A value that is true or false.
        
        
        char
        One Unicode character in single quotes, 4 bytes.
        
        
        Unicode
        The world's numbered list of characters from every writing system, plus emoji.
        
        
        literal
        A value written straight into the code, like 42, 0xff, 'M' or "hi".
        
        
        hexadecimal / octal / binary
        Base 16 (0x), base 8 (0o) and base 2 (0b) ways to write a number.
        
        
        byte literal
        b'a': a character's byte value as a u8.
        
        
        suffix
        A type written on the end of a literal: 5u8, 0.5f32.
        
        
        default type
        The type the Compiler picks when you don't say: i32 and f64.
        
        
        lint
        An automatic check on your code. deny makes it an error; warn a warning.
        
        
        operator
        A symbol that works on values: + - * / %, == != < > <= >=.
        
        
        remainder
        What's left after whole-number division: 7 % 2 is 1.
        
        
        casting
        Converting a value to another type on purpose with as.
        
        
        overflow
        A result too big (or too small) for its type.
        
        
        wrap
        Overflow that rolls round to the other end, like an odometer going 255 → 0.
        
        
        saturate
        Overflow that stops at the top or bottom of the range.
        
        
        build profile
        Debug (cargo run: checks, quick to build) or release (--release: optimized, no overflow checks).
        
        
        method
        A tool called with a dot after a value: odometer.checked_add(3).
        
        
        Some / None
        "Here is some answer" / "no answer", as given by checked_add. More in Chapter 11.
        
        
        format string
        The text in quotes given to println! and friends, with {} holes.
        
        
        Display / Debug
        The polite voice {} and the programmer's X-ray voice {:?} ({:#?} is pretty Debug).
        
        
        width / alignment / precision
        {:5} total cells, < ^ > left/centre/right, {:.2} digits after the point.
        
        
        stdout / stderr
        The normal output stream and the error stream. eprintln! and dbg! use stderr.
        
        
        tuple
        A few values grouped in brackets, like (3, 4). Chapter 5.
