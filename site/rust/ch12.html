Mabel says: Later is today. A librarian keeps her promises, and her overdue notices.

Mabel says: In my library there are two kinds of writing. Notebooks, which belong to someone and can be written in. And pages you're allowed to look at, but never write on. Rust has exactly the same two.

2

A notebook that you own, and two kinds of page you may look at: a handout printed with the program, and someone's notebook held open at a page for you.

THE NOTEBOOKString

You own it. You can write more in it, change it, or hand it to someone else. It keeps its letters on the heap (Chapter 7), so it can grow. When its owner leaves, it is dropped.

A PAGE TO LOOK AT&str, said "string slice"

You may read it. You never own it and you can't write on it. It is either a handout printed into the program (every "text in quotes") or a window onto part of someone's notebook (Chapter 9's slices).

Mabel says: Catchphrase: own the notebook, borrow the page. Looking at a page never copies anything; only to_string and friends run the photocopier.

      PART 3 · SQUARES ARE NOT LETTERSUTF-8, len() counts bytes, why s[0] is refused (E0277), chars(), bytes(), char_indices(), and safe slicing
      

  
      
    17
    
      Mabel opens a notebook and finds it is made of graph paper. Each square holds one byte. A plain letter like h fits in one square, but é needs two, 日 needs three, and an owl emoji needs four.
      
    
    
    
      
      
      UTF-8how Rust writes text down
      Every Rust String and &str is stored in UTF-8: a code that can write every alphabet in the world. Each character takes 1 to 4 bytes. Plain English letters, digits and punctuation take 1, so for them you never notice.
      
      
      CHARone Unicode character
      A char (Chapter 3) is one character: 'h', 'é', '日'. Alone in a variable it always takes 4 bytes. Written into a String it takes only as many squares as UTF-8 needs.
      
    
      
  
      

  
      
    18
    
      So what does len() count, squares or letters?
      
    len_bytes.rs
    
      
    
      
    
        
      
      1. word.len() counts bytes: squares of graph paper. That's what the String stores, and Rust can answer instantly.
        2. 
      
      2. word.chars().count() counts chars: letters. To answer, Rust has to walk through every byte and see where each letter starts.
        3. 
      
      3. For hello the two numbers agree. For héllo, 日本 and hi🦉 they don't.
        4. 
    
      
  
      

  
      
    19

      • ▲ thick line: a slice may start or stop here
      • dotted line: inside a letter, never cut here

    21
    
      Why so strict? Ask what word[1] should even mean for héllo. There are three honest answers, and Rust makes you pick one.
      
    
      
      
      BYTESword.bytes()
      6 of them for héllo. Byte 1 is 195: the first half of é. True, but rarely what you meant.
      
      
      CHARSword.chars()
      5 of them. Char 1 is é. Usually what you meant, but finding it means walking from the start.
      
      
      WHAT YOU SEEnot in the standard library
      Some "letters" on screen are built from two chars, like an e plus a separate accent mark. Counting those needs an extra crate: see the Professor's notebook.
      
    
      
    
      
      
      
      Mabel says: If word[1] handed you half a letter, you'd get nonsense. If it walked to the first letter, square brackets would look fast and secretly be slow. So Rust refuses, and asks you to say which you want.
      
    
      
    
      
      
      
      The Professor says: Catchphrase: squares aren't letters. len() and slice ranges count squares. chars() counts letters.

      What you learned in Chapter 12
      
    
        
      
      • OWN THE NOTEBOOK, BORROW THE PAGEString is owned, growable text on the heap (pointer, length, capacity). &str is a borrowed view (pointer, length) of a literal baked into the program or of part of a String. Make Strings with String::from, .to_string(), .to_owned() or String::new(). A literal where a String is expected: E0308, fix with .to_string().

      • WRITE ON THE LEFT, READ ON THE RIGHTpush_str("text") and push('c') write at the end. s1 + &s2 takes s1 (E0382 afterwards) and must have a page on the right (E0308) and a notebook on the left (E0369). format! borrows everything.
        • 
      
      • SQUARES AREN'T LETTERSText is UTF-8: 1 to 4 bytes per char. len() counts bytes; chars().count() counts letters. No s[0] (E0277): use chars(), bytes(), char_indices() or chars().nth(i). Slices must start and stop on char boundaries, or the program panics.
        • 
      
      • TAKE A PAGE, GIVE BACK A NOTEBOOKParameters that only read are &str; deref coercion turns &String into &str. Functions that make new text return String. Tools: trim, split, split_whitespace, lines, to_uppercase, replace, contains, starts_with, parse.
        • 
      
      • A BACKSLASH MEANS "SPECIAL"\n, \t, \", \\, \u{e9}. Unknown escapes are compile errors; real ones can hide in paths. Raw strings r"..." and r#"..."# take every character as typed.

    Under the hood: a String is a vector of bytes, and how UTF-8 works
    
      
      
      
        
        
      The Professor says: A String is a Vec<u8> with one promise attached: its bytes are always valid UTF-8. Every String rule in this chapter comes from keeping that promise cheaply.
      
      
      
      
      Sizes, and bytes you can see
      
      sizes.rs
      
      
      A String is three 8-byte numbers (pointer, capacity, length), so 24 bytes on the stack wherever it lives; a &str is two (pointer and length), 16 bytes. Neither number includes the text itself. A lone char is 4 bytes, enough for any Unicode character, which is why a Vec<char> takes up to four times the memory of the same text in a String. (These sizes are for this 64-bit Linux machine.)
      
      
      as_bytes() gives a look-only view of the raw bytes. String::from_utf8 goes the other way: it checks a vector of bytes and returns Ok only if they are valid UTF-8. [104, 195] ends in the middle of a letter, so it is refused. That check is how Rust keeps its promise when bytes come from outside, for example from a file or the network.
      
      
      How a byte says how wide its letter is
      
      
      UTF-8 marks every byte. A byte below 128 (binary 0xxxxxxx) is a whole 1-byte letter: plain ASCII. A byte starting with binary 110 starts a 2-byte letter, 1110 a 3-byte one, 11110 a 4-byte one. Every following byte starts with 10. So é (Unicode number 233) is written 11000011 10101001: 195 and 169, exactly the ruler's squares. 240 (11110000) starts the owl's four bytes. This design means you can land on any byte and tell at once whether it starts a letter, which is how is_char_boundary answers instantly.
      
      
      Where the baked-in text lives
      
      
      String literals are stored in a read-only part of the executable file, loaded into memory when the program starts. Their type is really &'static str (Chapter 9): 'static because the text exists for the whole run. That's one reason literals can never change. More generally, a &str is only a pointer and a length, with no room to grow, and it's a shared loan. So it has no push_str whether it points at a literal or into a String: Card C's error, method not found in `&str`, names the type, not where the page points.
      
      
      What + and format! cost
      
      
      s1 + &s2 reuses s1's heap block, growing it only if needed (panel 10), so it's cheap. format! always makes a new String. Both are fine for everyday code. In a loop that builds a long text, start with String::with_capacity(n) or just push_str into one notebook, rather than making a new String every lap.
      
      
      Why deref coercion works
      
      
      String implements a trait called Deref whose target is str. Whenever you offer a &String where a &str is wanted, the Compiler inserts the conversion for you. The same mechanism lets &Vec<i32> become &[i32] (Chapter 9) and &Box<T> become &T. Traits come in Chapter 17; Deref itself in Chapter 23.
      
    
      
  
      

  
      
    In real programs: how professionals handle text
    
      
      
        
        
      • Functions take &str. Look at the standard library: str::contains, str::starts_with and friends all borrow. Structs that must keep text store a String (Chapter 10).
        • 
        
      • Parse line by line. Configuration files, logs and CSV data are read with lines(), trim(), split and parse. Here is a tiny settings reader. split_once cuts at the first = only, and hands back a gift box (Chapter 11) holding both halves:
        • 
      
      
      in_real.rs
      
      
        
        
      • Compare without caring about capitals with a.eq_ignore_ascii_case(b) for plain English text, or by lowercasing both sides with to_lowercase() for any language.
        • 
        
      • Grapheme clusters. To count what a reader sees as letters (an emoji family, a letter with a separate accent mark), professionals use the unicode-segmentation crate. Chapter 22 returns to this.
        • 
        
      • User-facing text is never sliced by bytes unless the boundary came from a search (find, char_indices, split). Fixed byte offsets are for formats known to be plain ASCII.
        • 
        
      • Big text, shared: when a program reads a large file once and many parts look at it, they pass around &str windows into one String, instead of copying pieces. That's the borrow checker letting you be fast and safe at the same time.

    Common wrong ideas
    
      
      
        
        
      • "A &str is a copy of the text." It's a pointer and a length: a view. Only to_string, to_owned, String::from, format! and friends copy letters (panel 4).
        • 
        
      • "let mut s = "hi"; makes the text changeable." It makes the name able to point at a different page. The page itself is still read-only (Card C).
        • 
        
      • "len() is the number of letters." It's the number of bytes. They agree only for plain ASCII text (panel 18).
        • 
        
      • "chars().count() is the number of letters on screen." Usually, but not always: some letters are two chars, and many emoji are several chars joined together. That needs grapheme clusters.
        • 
        
      • "s[0] works for English text, so it's fine." It doesn't compile for any text (E0277). Use s.chars().next(), or &s[..1] when you know the first letter is ASCII.
        • 
        
      • "+ makes a new String." It reuses the left String, which is why the left side is moved (panel 13).
        • 
        
      • "push("x") and push('x') are the same." push takes a char in single quotes; push_str takes text in double quotes (panel 9).
        • 
        
      • "Functions should take &String to borrow a String." Take &str: it accepts Strings and literals and windows (panel 33).
        • 
        
      • "trim changes my String." It returns a page of the middle; the original is untouched (panel 26). The same goes for to_uppercase and replace, which return new Strings.
        • 
        
      • "A Windows path in quotes is fine." \n and \t hide inside paths (panel 35). Use raw strings, or forward slashes, which Windows also accepts in most places.
        • 
        
      • "The capacity numbers are part of Rust." How much a String grows by is an internal detail of this version (panel 10). Only the length is exact.

    Words from this chapter
    
      
      
      
        
      String
      Owned, growable UTF-8 text. On the stack: pointer, length, capacity. The letters are on the heap.
      
        
      &str, string slice
      A borrowed view of UTF-8 text: a pointer and a length. Points at a literal or into a String.
      
        
      str
      The text itself, without the &. You almost always meet it behind a reference.
      
        
      string literal
      Text in double quotes in your code. Baked into the program; its type is &'static str.
      
        
      to_string / to_owned / String::from
      Three ways to copy a &str's letters into a new String.
      
        
      push_str / push
      Write a &str / a single char at the end of a String.
      
        
      capacity
      How many bytes a String has room for before it must find a bigger block. At least its length.
      
        
      concatenation
      Joining text end to end, with +, push_str or format!.
      
        
      format!
      Like println!, but returns the text as a new String instead of printing it.
      
        
      UTF-8
      The way Rust stores text: every Unicode character in 1 to 4 bytes.
      
        
      Unicode
      The world's catalogue of characters, giving each a number (é is 233, written \u{e9}).
      
        
      byte
      One square of the graph paper: a number from 0 to 255 (u8).
      
        
      char boundary
      A byte index where a letter starts (or the end of the text). The only places a slice may begin or end.
      
        
      chars() / bytes() / char_indices()
      Walk text letter by letter / byte by byte / letter by letter with each letter's starting byte index.
      
        
      grapheme cluster
      What a reader sees as one letter, which may be several chars. Not handled by the standard library.
      
        
      deref coercion
      Rust's automatic conversion of &String into &str (and &Vec<T> into &[T]) where needed.
      
        
      turbofish
      The ::<T> that names a type for a method, as in parse::<i32>().
      
        
      escape
      A backslash plus a character that stands for something special, like \n.
      
        
      raw string
      r"..." or r#"..."#: text with no escapes, every character as typed.
      
        
      case-sensitive
      Treating capital and small letters as different (contains, starts_with, ==).
      
        
      E0308 / E0277
      Mismatched types (String vs &str, char vs &str); a String indexed with a number.
      
        
      E0369 / E0599
      + with no String on the left; a method a &str doesn't have, such as push_str.
