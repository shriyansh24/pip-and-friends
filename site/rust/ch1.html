3

A program is a list of instructions saved in a file. Like a recipe card.

Recipe: good morning

  1. Say "Good morning!"
  2. Say "Rust runs main from top to bottom."
  3. Say "The end."

Mabel says: This card is in English, for people. You'll see the same recipe in Rust soon. The computer follows the steps in order, exactly as written.

Picture: Mabel points at a hand-drawn recipe card with three numbered steps.

4

There's a catch. People and CPUs speak different languages.

SOURCE CODEwhat you write

Text in a programming language, such as Rust. Words like fn and println!. People can read it, change it and share it.

MACHINE CODEwhat the CPU runs

Long patterns of 0s and 1s: tiny steps like "add these two numbers". Each kind of CPU has its own. Almost nobody writes it by hand.

The Professor says: So something must translate source code into machine code. There are two ways to do it.

Pictures: in the source code card, a cream page with lines of text; in the machine code card, a blue page full of 0s and 1s. The Professor, in a white coat and round glasses, explains.

5

Two ways to translate a program.

AN INTERPRETERtranslates while it runs

Like a live interpreter at a meeting: hears a sentence, translates it, then the next. An interpreter translates and runs your program as it goes, every time you run it.

A COMPILERtranslates everything first

Like translating a whole book before anyone reads it. It checks and translates the entire program ahead of time into a finished file. Then that file runs on its own, as often as you like. Rust works this way.

The interpreter picture: a page goes into a person who translates out loud, sentence by sentence. The compiler picture: a whole page becomes a finished blue booklet of 0s and 1s.

6

Rust's translator is a robot: the Compiler. Its program name is rustc.

RECIPE CARDyour source code, src/main.rs
→
THE COMPILERreads the whole program, checks every step, translates
→
PHRASEBOOKthe executable: machine code in a file
→
THE CPUruns it, fast, again and again
REFUSED!A step the robot can't understand, or a dangerous one? It hands the recipe back with the problem circled in red, and builds nothing.

The Compiler says: NOTHING RUNS UNTIL EVERYTHING CHECKS OUT.

The Compiler says: And when I refuse, I always say: here's the problem, here's where, and here's a fix.

Picture: the Compiler robot, its beacon red and its gate down, holds up a red marker.

7

So every Rust program lives two lives: compile time, then run time.

COMPILE TIMEThe Compiler checks every line and translates.Your program is not running yet.It catches: writing mistakes, like a missing ; (and later, much more).
EXECUTABLE BUILT
RUN TIMEThe executable runs on the CPU.The Compiler has gone home.Can still go wrong: a file that isn't there, a surprise from the user.

Mabel says: The Compiler checks the recipe. It can't check the kitchen: what's on the computer when the program finally runs.

8

The classic wrong idea about compilers…

The Professor says: "It compiled, so it must be correct!"

Mabel says: Not quite. It compiled, so it is written correctly. It can still stop with an error while it runs. Rust calls that a panic. You'll see a real one in Part 5.

Picture: the Professor makes a confident claim; Mabel shrugs and corrects him kindly.

PART 2 · WHY RUST?Fast, safe, used everywhere, and the edition you'll write

9

People pick Rust when they want two things at once.

FASTlike C and C++

  • Compiled ahead of time, straight to machine code.
  • No translator while it runs.
  • No garbage collector (a helper some languages run alongside your program, pausing now and then to tidy up memory).

SAFEchecked before it runs

  • The Compiler checks how your program uses memory.
  • Whole families of crashes and security holes that C and C++ allow are refused at compile time.
  • Rare jobs that need to skip a check use a word, unsafe, that you won't need for a long time.

Mabel says: The memory rules are my department. Every value has exactly one owner, like every book in my library. You'll meet my rules in Chapter 7.

Picture: a speedometer with its needle far to the right for FAST; a green shield with a tick for SAFE.

10

Rust grew up at Mozilla, the makers of Firefox, and reached version 1.0 in 2015. Today it's in places like these:

  • OPERATING SYSTEMSparts of Linux, Android and Windows
  • WEB BROWSERSparts of Firefox
  • COMMAND LINEsmall, quick tools you run in a terminal
  • SERVERSthe computers behind websites and apps
  • TINY DEVICESchips inside gadgets, often with no operating system
  • GAMES AND MOREgame engines, data tools, and code that runs inside web pages

Six small pictures: a window for operating systems, a globe for web browsers, a black terminal for command-line tools, a stack of boxes for servers, a chip for tiny devices, and a game piece for games.

PART 3 · THE TOOLBOXrustup, rustc and cargo: installing and checking

12

Installing Rust gives you a toolbox with three main tools.

RUSTUPthe toolbox

Installs Rust, keeps it up to date, and adds extra tools. rustup update fetches the newest version.

RUSTCthe hammer

The Compiler itself: the robot from Part 1. It does the checking and translating.

CARGOthe foreman

Makes projects, calls rustc for you with the right settings, runs your program, and fetches helper code. You'll use it every day.

Mabel says: You could swing the hammer yourself. But the foreman knows the plans, so let cargo swing it.

Pictures: a red toolbox for rustup, a hammer for rustc, and a yellow hard hat with a clipboard for cargo.

      Exactly where: the caret sits under the spot, with the fix next to it.
      4. 
      
    4. ------- unexpected token
      A second marker, under line 3: where the Compiler got surprised. The cause is just before it.
      5.

      What you learned in Chapter 1
      
    
        
      
      • NOTHING RUNS UNTIL EVERYTHING CHECKS OUTRust is compiled: the Compiler checks and translates the whole program into an executable before it runs. Compile time first, then run time.
        • 
      
      • THE RECIPE, NOT THE KITCHENA clean build means "written correctly". A program can still panic at run time, for example when a file is missing. Exit code 101 for a failed build or a panic; 0 for success.
        •

    Under the hood: what cargo run really does
    
      
      
      cargo run is three jobs in a row. Cargo reads Cargo.toml, works out what has changed, and calls rustc with the right settings (the edition, the profile, where to put files). Then rustc does the real work, in stages:
      
      
        
        
      1. Reading. It splits your text into words and symbols, then into a tree of the program's structure. A missing ; or { is caught here.
        2. 
        
      2. Expanding macros. println! is replaced by the longer code it stands for. That's why the bang matters: the Compiler treats macros differently from functions.
        3. 
        
      3. Checking. Names, types, and the memory rules you'll meet in later chapters.
        4. 
        
      4. Translating. Rust hands the checked program to LLVM, a code generator also used by other languages, which writes machine code for your CPU.
        5. 
        
      5. Linking. The linker joins your machine code with the parts of Rust's standard library you used, into one executable file.
        6. 
      
      
      
      Finally cargo starts that executable. The executable contains no Rust source at all, only machine code.
      
      
      Two output streams
      
      
      A running program has two output streams: standard output (stdout) for its normal text, and standard error (stderr) for messages about what's happening. Cargo prints its progress lines on stderr and your program prints on stdout. A terminal shows both mixed together, which is why the comic's cargo sessions look the way they do. You can throw one stream away to see the other on its own (2> means "stream 2, stderr, goes to…", and /dev/null is a bin that swallows everything):
      
      
      
      
      One possible run: the build time in the Finished line changes every time.
      
      
      How this run was really made
      As in panel 20, the cd hello step also made a brand-new project and let cargo build inside it: bash stage.sh fresh streams.rs && unset CARGO_TARGET_DIR && cd hello. The two cargo run commands ran exactly as shown.
      
      
      In this book's terminals, stderr text is drawn in red, whether or not it is an error. That is also why panel 20 types 2>&1: it sends stream 2 into stream 1, so the recording catches both in the order they happened.
      
      
      Block comments nest
      
      
      Unlike in C, a block comment inside a block comment is fine in Rust: each /* needs its own */.
      
      
      
      
      Comments that start with /// are documentation comments: tools turn them into web pages about your code. They come much later.
      
      
      Strings can hold any text
      
      
      A string literal can hold letters from any language. To put a double quote inside one, put a backslash before it: \".
      
      
      
    
      
  
      

  
      
    In real programs: git, Cargo.lock, release builds, tools
    
      
      
      cargo new also starts a git repository and writes a .gitignore file. It tells git not to keep a history of target/, because everything in there can be rebuilt from your source:
      
      
      
      
      How this run was really made
      The cd hello step also made a brand-new project first: bash stage.sh fresh gitignore.rs && cd hello. Then cat .gitignore ran exactly as shown.
      
      
      That also means deleting target/ is safe. cargo clean does it for you, and the next build makes it again. Never delete src/!
      
      
        
        
      • Cargo.lock records the exact versions of every helper library (called a crate) your program uses. For programs, keep it with your code, so everyone builds exactly the same thing.
        • 
        
      • Release builds are what you ship to users and what you time when you compare speed. Debug builds are for working: they build faster, and in a later chapter you'll see they also check extra things while running.
        • 
        
      • Exit codes let scripts and other programs react: 0 means success, anything else means failure. Automated build servers run cargo check, tests and cargo clippy on every change and stop at the first non-zero exit code.
        • 
        
      • Formatting and advice: cargo fmt lays out your code in the standard Rust style, and cargo clippy suggests improvements. Most Rust teams use both.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "If it compiles, it's correct." It's written correctly. It can still panic at run time, as missing_file.rs did.
        • 
        
      • "println is a function." It's a macro, which is why it needs the bang. Without it you get E0423.
        • 
        
      • "Every line needs a semicolon." Statements end with ;, but the very last line of a block may leave it off. Here it makes no difference:
          
        
          Chapter 4 explains when a missing last semicolon does change the meaning. Until then, end every statement with ;.
        • 
        
      • "The line number is always where the mistake is." It's where the Compiler noticed. Bosses 1 and 6 show two cases where the slip is earlier. Check the line above, especially for quotes and braces.
        • 
        
      • "rustc main.rs and cargo run are the same." Plain rustc uses edition 2015 unless told otherwise, and it doesn't run the program.
        • 
        
      • "The target folder is my program." It's build output. Your program is src/ plus Cargo.toml.
        • 
        
      • "The Playground shows exactly what my computer will." It may run another version and edition. Check its menu.
        • 
        
      • "The (1) after thread 'main' is an error count." It's a thread id. This book's runs happen in a fresh, isolated space where the main thread really is number 1; on your computer it will be some other number. Rust added the number to panic messages in version 1.91, so older tutorials don't show it.
        • 
      
      
    
      
  
      

  
      
    Lab: run it yourself (Windows, macOS, Linux)
    
      
      
      1. Install
      
      
        
        
      • Windows: download rustup-init.exe from rust-lang.org/tools/install and run it. Accept the offer to install Visual Studio's C++ tools (they include the linker). Use PowerShell or Windows Terminal afterwards.
        • 
        
      • macOS: run xcode-select --install once (for the linker), then curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh in Terminal.
        • 
        
      • Linux: install a C toolchain if you don't have one (Ubuntu: sudo apt install build-essential), then run the same curl line.
        • 
      
      
      
      Open a new terminal and check: rustc --version and cargo --version.
      
      
      2. An editor
      
      
      Any plain-text code editor works. A popular free choice is VS Code with the rust-analyzer extension, which underlines mistakes as you type. Never use a word processor: it changes straight quotes into curly ones, which Rust rejects.
      
      
      3. Your first project
      
      
        
        
      1. Make a folder for this book's work and open a terminal there.
        2. 
        
      2. cargo new hello, then cd hello.
        3. 
        
      3. cargo run. Expected last line: Hello, world!
        4. 
        
      4. Open src/main.rs. Add two more println! lines and a comment. Predict the output, then cargo run.
        5. 
        
      5. Delete one ; between two statements. Run it. Find the first line, the --> line and the caret. Put it back.
        6. 
        
      6. Delete a !. Read the help:. Put it back.
        7. 
        
      7. Try cargo check, cargo build, then run the executable directly: ./target/debug/hello on macOS and Linux, .\target\debug\hello.exe on Windows.
        8. 
        
      8. cargo build --release and find the second executable in target/release.
        9. 
      
      
      
      4. Optional: the edition trap
      
      
      In an empty folder, save main.rs from panel 29 and run rustc main.rs, then rustc --edition 2024 main.rs. On Windows the executable is main.exe.
      
      
      5. Offline reading
      
      
      rustup doc --book opens the official Rust book in your browser, even without internet.
