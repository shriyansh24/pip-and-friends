So when do you take the lift, and when the ladder?

    

      
TAKE THE LIFTswitch
  • One value, compared with exact constants
  • The value is an int, a char or an enum
  • Several values share a floor
The C++ Core Guidelines say it: prefer a switch when you have the choice (rule ES.70). It's easier to read, and the Compiler can check it for you.

      
TAKE THE LADDERif, else if, else
  • Ranges: score >= 90
  • Text: name == "Ada"
  • double values
  • Questions about different variables, joined with && and ||
A case can't say "90 or more". It can only say "exactly this".

      RANGE-FORevery item, in order
      for (char c : word)

    Under the hood: how a switch and a loop become machine code
    
      
      
      A switch is a jump
      
      
      The processor has no "switch" instruction. It has jumps: "continue at that address". A switch compiles to code that works out which address to jump to. With a few cases the compiler emits a short chain of comparisons. With many cases packed close together (1, 2, 3, … 20) it often builds a jump table: a list of addresses, indexed by the value, so finding the floor costs the same for floor 2 as for floor 20. Either way, the case labels are just addresses inside one block of code. That's why execution runs straight on from one case into the next when there's no break: nothing in the machine code separates them. break compiles to one more jump, to the end of the switch.
      
      
      Why the labels must be constants
      
      
      The compiler has to lay out the jump table or comparison chain while compiling. That's why case needs a value known at compile time (a literal, a constexpr, an enumerator) and why two labels can't share a value. It's also why a switch only takes whole-number-like types: integers, char, bool and enums. A std::string is an object in memory, not a number the processor can index with.
      
      
      Jumping over a variable
      
      
      "Jump to case label … crosses initialization" (panel 11) comes from a general rule: C++ never lets a jump skip over the line that initialises a variable and land somewhere that variable is still in scope. The case braces end the scope before the next label, so nothing is crossed.
      
      
      A loop is a jump backwards
      
      
      A while loop becomes: test the condition; if false, jump past the loop; run the body; jump back to the test. A for loop is the same, with the start before it and the change just before the jump back. continue jumps to the change part (for) or to the test (while); break jumps past the loop. Compilers often rearrange this so the test sits at the bottom, which saves one jump per lap, but the behaviour is exactly what the comic showed.
      
      
      Unsigned wrap-around
      
      
      Unsigned arithmetic is defined to wrap: 0 − 1 gives the largest value of the type, 18446744073709551615 for a 64-bit std::size_t. That's not undefined behaviour (signed overflow is, Chapter 3). The wrapping itself is legal; what panel 35's loop then does with that huge seat number is not. Chapter 20 covers unsigned types in depth.
      
    
      
  
      

  
      
    In real programs
    
      
      
        
        
      • Event loops. Games, editors and servers are built around one big loop: wait for something to happen (a key, a click, a network message), switch on what kind of thing it was, handle it, go round again. menu.cpp is a tiny version of that shape.
        • 
        
      • State machines. A traffic light, a vending machine or a network protocol is often an enum class State plus a switch inside a loop: each lap, look at the current state, act, and move to the next state.
        • 
        
      • Warnings as guard rails. Many teams build with -Wall -Wextra -Werror, so a missing break (-Wimplicit-fallthrough) or a forgotten enumerator (-Wswitch) stops the build instead of scrolling past. Some also add -Wswitch-enum, which warns about a missing enumerator even when there's a default.         • 
        
      • Linux kernel style. The Linux kernel replaced its old /* fall through */ comments with a fallthrough marker, so the compiler can check every intentional fall-through. Same idea as [[fallthrough]].
        • 
        
      • Index loops are fading. Modern code uses range-for and the standard algorithms (Chapter 14) wherever it can. The fewer seat numbers you write by hand, the fewer off-by-one bugs you can make.

    Common wrong ideas
    
      
      
        
        
      • "A case ends at the next case label." It ends at a break (or return). Labels only mark where to start. Panel 7.
        • 
        
      • "break leaves every loop I'm in." It leaves only the innermost loop or switch. Inside a switch inside a loop, it leaves the switch. Panel 40.
        • 
        
      • "default must come last." It can go anywhere; it's just conventional to put it last. If it isn't last, it can be fallen into like any other label. Boss 2.
        • 
        
      • "A comment saying fall through silences the warning." In g++ some comment spellings do count, but that's a compiler habit, not the language. [[fallthrough]]; is the standard way.
        • 
        
      • "I can switch on a string if I put the cases in double quotes." No: switch only takes integer-like values. Panel 13.
        • 
        
      • "Enum class values are strings, so I can print them." They're named numbers in disguise. You print a number with static_cast<int>, or a word with your own switch. Panel 18.
        • 
        
      • "A while loop runs at least once." That's do-while. A while may run zero times. Panel 26.
        • 
        
      • "The loop condition is checked all the time, so the loop stops the moment it becomes false." It's only checked at the gate, before each lap. The rest of the current lap always finishes. The purse in the trace exercise overshot to 81.
        • 
        
      • "for (int i{1}; i <= n; ++i) and for (int i{0}; i < n; ++i) visit the same seats." Both run n laps, but one counts 1 to n and the other 0 to n − 1. Seat numbers start at 0. Panel 34.
        • 
        
      • "An infinite loop will crash by itself eventually." Not necessarily: it can spin until you stop it with Ctrl+C or close the terminal.

    Words from this chapter
    
      
      
      
        
      switch statement
      Reads one value and jumps to the matching case label.
      
        
      case label
      case 3:: a place where the switch may start. Its value must be a compile-time constant.
      
        
      default
      The label used when no case matches.
      
        
      break
      Leaves the innermost switch or loop at once.
      
        
      fall through
      Running on into the next case because there was no break.
      
        
      [[fallthrough]]
      An attribute that marks a fall-through as intentional (C++17).
      
        
      attribute
      A note to the compiler in double square brackets, like [[fallthrough]].
      
        
      magic number
      A bare number in code whose meaning is a secret, like case 2: meaning "green".
      
        
      enumeration
      A type whose values are a list of names you choose.
      
        
      enum class
      A scoped enumeration: names live inside the type (Light::red) and never turn into numbers by themselves.
      
        
      enumerator
      One name in an enumeration's list.
      
        
      plain enum
      The older enum without class: its names spill into the surrounding scope and convert to int silently.
      
        
      static_cast
      A named, deliberate conversion, such as an enum class value to int.
      
        
      loop
      Code that runs again and again while a condition holds.
      
        
      iteration
      One trip round a loop: one lap.
      
        
      while loop
      Checks its condition before each lap; may run zero times.
      
        
      do-while loop
      Checks its condition after each lap; always runs at least once.
      
        
      for loop
      A loop with its start, check and change written on one line.
      
        
      loop variable
      The counter a for loop makes in its first part.
      
        
      scope
      The stretch of code where a name can be used.
      
        
      infinite loop
      A loop whose condition never becomes false.
      
        
      Ctrl-C
      The key combination that stops a running program in a terminal.
      
        
      continue
      Skips the rest of the current lap and goes on to the next check.
      
        
      sentinel
      A special input value that means "stop", like 0 or −1.
      
        
      accumulator
      A variable that collects a running total with +=.
      
        
      counter
      A variable that tallies how many times something happened with ++.
      
        
      flag
      A bool that a loop checks, like running.
      
        
      nested loop
      A loop inside another loop's body.
      
        
      off-by-one error
      Doing one lap too many or too few, often <= instead of <.
      
        
      signed / unsigned
      A whole-number type that can / can't be negative.
      
        
      std::size_t
      The unsigned type used for sizes, such as what .size() returns.
      
        
      trace table
      A table with one row per lap and one column per variable, for checking a loop by hand.
      
        
      range-for
      for (char c : word): visits every item in order, with no counter.
