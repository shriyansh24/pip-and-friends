C++ · CHAPTER 20

GIFT BOXES, CLOCK FACES

Picture: Wren, the mechanic in orange coveralls, waves hello. Next to her: a gift box with its lid up, and a clock face counting from 0 to 255.

Two kinds of box today. A gift box that might be empty, for answers that might not exist (std::optional). A box with a dial on the front, which tells you which one of several toys is inside (std::variant). Then we open the number drawers and look at what's really in them: exact-size integers, the clock face that unsigned numbers live on, the cliff that signed numbers fall off, switches you flip one bit at a time, and the wobbly jelly that is double. About 130 minutes, with 28 hands-on checks.

  1. Gift boxes: std::optional
  2. Boxes with a dial: std::variant and std::visit
  3. Named settings: enum class in depth
  4. Clock faces and cliffs: integers in depth
  5. Switchboards: bits and masks
  6. Wobbly jelly: floating point
  7. Boss level and recap

1

Wren asks her toolbox a question: which slot holds the saw? Sometimes there's a good answer (slot 2). Sometimes there isn't one at all, because there is no saw.

Wren says: So far we've had three ways to say "no answer". Return a fake number like -1 and hope the caller checks (Chapter 15 showed how that goes). Throw an alarm, which is loud and right for real errors. But "no saw today" isn't an error. It's just an ordinary maybe.

Gift box says: That's me. I'm a gift box. Open me and there's either one thing inside, or nothing. And my label says so on the outside, so nobody forgets to look.

    3
    
Four ways to look inside. Solid cards are safe on an empty box. Dashed cards need something inside first.

    

      
IS ANYTHING IN?
box.has_value()if (box)
Both give true when there's a value. They mean exactly the same.

      
OR USE A SPARE
box.value_or(0)
The value if there is one, otherwise the spare you hand it. Never fails.

      
CHECKED OPEN
box.value()
The value, or, on an empty box, an alarm: std::bad_optional_access (panel 5).

      
JUST GRAB IT
*box
The value, no checking. On an empty box this is undefined behaviour (panel 6). Only after a check.

    

    
Four cards. Solid border, safe on an empty box: has_value() or if (box) asks whether there is a value; value_or(0) gives the value or the spare. Dashed border, needs a value: value() throws bad_optional_access on an empty box; *box is undefined behaviour on an empty box.

    PART 3 · NAMED SETTINGSenum class in depth: underlying types, names in and out, warnings that save you
    

  
    
    17
    
    Chapter 6 gave you enum class: a type whose values are a short list of names, like the settings on a workshop lamp. Two more tools today: choosing the underlying type (the kind of integer each name is stored as), and turning names into text and back.
    
    
    
    
      
      
    Wren says: enum class Light : std::uint8_t { off, dim, bright }; The part after the colon is the underlying type. Without it you get int (4 bytes here).     PART 4 · CLOCK FACES AND CLIFFSIntegers in depth: exact sizes, limits, wrapping, overflow and mixing signed with unsigned
    

  
    
    21
    
    Back to the brick, our int creature. Integers come in several sizes. The plain names (short, int, long) have sizes that differ from machine to machine. The names from <cstdint> say their size out loud: std::int32_t is exactly 32 bits on every machine that has it. A bit is one on/off switch; a byte is 8 bits.
    
    
    
      
      
    
    
    
    Two brick creatures, one labelled int32_t and one labelled uint8_t.
    
    sizes.cpp
    
    
      
    
      
    
    
    
    
    
      
      
    Wren says: These sizes are on this machine (64-bit Linux). On 64-bit Windows (not run for this book), long is 4 bytes, not 8. That's exactly why the fixed-width names exist: when the size matters (a file format, a network message, a pixel), say it. std::size_t is the type of sizes and counts, like v.size(); it's unsigned and as wide as the machine's addresses.
    
    
    
  
    

  
    
    22
    
    std::numeric_limits<T> (from <limits>) knows each type's smallest and biggest value. Line 7 is a shortcut so we can write numeric_limits without std:: in front.

      2. 
      
    2. The negative side is always one bigger: there's a −2147483648 but no +2147483648. Chapter 3's odometer showed what happens past the top; the clock face in panel 25 shows it properly.
      3.

    24
    
    Big idea: an unsigned number lives on a clock face. Go past the top and you come round to 0 again; go below 0 and you come round to the top. This isn't a mistake in C++: it's the rule for unsigned types, so it's well defined. ("Modulo 2N" arithmetic, if you like the maths words.)
    
    
    
      
      
    Wren says: A 12-hour clock does it every day: 3 hours after 11 o'clock is 2 o'clock, not 14. A std::uint8_t clock has 256 marks, 0 to 255. Unsigned numbers go round the clock.

    PART 5 · SWITCHBOARDSBinary and hex literals, bitwise operators, masks, std::bitset and std::popcount
    

  
    
    31
    
    Inside the machine, a std::uint8_t is a row of 8 switches. Starting from bit 0, the last switch, each switch is worth double the one before it: 1, 2, 4, 8, 16, 32, 64, 128. Add up the switches that are on and you get the number.
    
    
    
      
    1. bit 70off128
    2. bit 60off64
    3. bit 50off32
    4. bit 40off16
    5. bit 30off8
    6. bit 21ON4
    7. bit 10off2
    8. bit 01ON1
    
      
    00000101 = 4 + 1 = 5
    
    
    
    literals.cpp
    
    
      
    
      
    
    
    
    
    
      
      
    Wren says: You can write numbers the way the machine sees them. 0b starts a binary literal (only 0s and 1s); 0x starts a hexadecimal one, base 16, where A to F mean 10 to 15 and each hex digit is exactly 4 switches. The ' marks are digit separators: the compiler ignores them; they're there for your eyes. std::format's {:08b} prints 8 binary digits, and {:#x} prints hex with 0x in front.
    
    
    
  
    

  
    
    32
    
    Bitwise operators work on every switch at once, column by column. Read the run with the code: each line lines up its 8 bits under a and b.
    
    bitops.cpp
    
    
    
    
    
    
      
    OperatorNameA column is 1 when…
    
      
        
    a & bANDboth are 1
    
        
    a | bORat least one is 1
    
        
    a ^ bXOR, "exclusive or"exactly one is 1 (they differ)
    
        
    ~aNOTa's switch was 0 (every switch flips)
    
        
    a << n, a >> nshift left, rightit was n places to the right (left); zeros slide in
    
          
    
    
    
    
      
      
    Wren says: Watch the last line: ~a on its own is -203! Promotion again: a became a 32-bit int first, so ~ flipped 32 switches, including the sign. That's why lines 13 and 14 cast back to std::uint8_t. Don't mix up & and &&, or | and ||: the doubled ones are Chapter 5's true/false logic.
    
    
    
  
    

  
    
    33
    
    A mask is a number with just the switches you care about turned on. 1 << 3 is a mask for bit 3 (00001000). Four moves cover almost everything you'll ever do with flags.
    
    
    
      
    SET (turn on)
    flags |= 1 << n;
    OR with the mask: bit n becomes 1, the others stay as they were.
    
      
    CLEAR (turn off)
    flags &= ~(1 << n);
    AND with the flipped mask: every bit is kept except bit n, which becomes 0.
    
      
    TOGGLE (flip)
    flags ^= 1 << n;
    XOR with the mask: bit n flips; the others stay.
    
      
    TEST (is it on?)
    (flags & (1 << n)) != 0
    AND keeps only bit n; anything left over means it was on. Mind the brackets.
    
    
    
    
    Four cards. Set: flags OR-equals 1 shifted left by n. Clear: flags AND-equals NOT of 1 shifted by n. Toggle: flags XOR-equals 1 shifted by n. Test: flags AND the mask, not equal to 0.
    
  
    

  
    
    34

    If you'd rather not juggle masks, std::bitset<8> (from <bitset>) is a row of 8 switches with names for every move: set, reset, flip, test, count. And <bit> (C++20) has tools for plain unsigned numbers, like std::popcount, which counts the switches that are on.
    
    bitset_pop.cpp

After set(0) and reset(7) you get 00110011, which is 51. std::has_single_bit asks "is exactly one switch on?" (is it a power of 2?).

    perms.cpp

    PART 6 · WOBBLY JELLYdouble in depth: rounding, comparing, infinity, NaN and std::midpoint

    The jelly creature is our double: wobbly, a little imprecise. A double stores numbers as binary fractions, in 64 switches (the IEEE 754 standard). Halves, quarters and eighths fit exactly. A tenth doesn't: in binary, 0.1 goes on forever, like 1/3 = 0.3333… does in decimal. So the jelly stores the nearest number it can.
    
    
    
      
      
    
    
    
    Two jelly creatures, labelled 0.1 and 0.2.
    
    float_sum.cpp

They're different numbers, so == says 0. Never ask jelly if it's exactly equal.

    Instead of "equal?", ask "close enough?". nearly_equal (lines 6 to 8) allows a difference of one part in a billion of the bigger number. epsilon is the gap between 1.0 and the next double above it: the jelly's finest wobble near 1.
    
    nearly.cpp
    
    
      
    
      
    
    
    
    
    
      
      
    Wren says: Ten tenths don't add up to exactly 1.0, because each step rounds a little. "Close enough" depends on the job: a billionth suits measurements like these; a game might use a thousandth. A tolerance that scales with the numbers (rel * max(...)) works for big and small values alike. And for money, use whole cents in an integer, not jelly.

      3.

    Under the hood: how the boxes are built, two's complement, and the 64 switches of a double
    
    
      
    Where an optional keeps its value
    
      
    A std::optional<T> is not a pointer and uses no heap memory. It holds room for one T plus a flag that says whether the room is in use, right inside the variable. An empty optional has no T in it at all: no constructor ran, and none will run until you assign. That's why *box on an empty box is undefined behaviour rather than "zero": there is memory there, but no object. The standard library is allowed to skip checks in operator*, and libstdc++ only checks it when built with -D_GLIBCXX_ASSERTIONS (panel 6). The sanitizers watch memory and arithmetic, not library promises, so they saw nothing (panel 6 has that sanitizer run).
    
      
    The same program built by clang++ 18 (same library) trips the same assertion; the function names are just printed in clang's style:
    
      
    
      
    Where a variant keeps its alternatives
    
      
    A std::variant is a tagged union: one block of memory big enough for its largest alternative, plus the dial (the index). Assigning a different kind destroys the old object and builds the new one in the same place. std::visit uses the index to jump straight to the right road, usually through a small table the compiler builds, so it's about as fast as a switch. If building the new alternative throws an exception halfway, a variant can be left "valueless" (valueless_by_exception() is true, and index() returns std::variant_npos). It's rare, and the C++ Core Guidelines' advice (C.181: avoid "naked" unions) is exactly to use std::variant instead of hand-made unions.
    
      
    Why the visit with a missing string road fails so loudly
    
      
    The spot-the-bug after panel 14 had a missing double road, which compiled because a double converts to int. A missing string road can't convert to anything, so the Compiler refuses. The message is long because the failure is found deep inside the library's template code. Read it like a detective: search for the first error:, then look for your own file name in the required from lines.
    
      
    The full g++ message (50 lines)
    
      
    Two's complement
    
      
    Since C++20, signed integers must be stored in two's complement, which is what every common processor already did. In 8 bits, 0 to 127 look like ordinary binary; −1 is 11111111, −2 is 11111110, and −128 is 10000000. That's why converting −1 to an unsigned type gives the all-ones pattern, the top of the clock (panel 28). Knowing the bit pattern does not make overflow defined: C++20 kept signed overflow undefined, so compilers may assume x + 1 > x is always true for a signed x and optimise on that basis.
    
      
    Shifts
    
      
    Shifting by a negative amount, or by at least the width of the (promoted) type, is undefined: 1 << 32 on a 32-bit int is not 0. Since C++20, shifting a signed number left is defined (it wraps like unsigned arithmetic), and shifting a negative number right copies the sign bit in. Use unsigned types for bit patterns anyway; it avoids every one of these questions.
    
      
    The 64 switches of a double
    
      
    An IEEE 754 double has 1 sign bit, 11 exponent bits and 52 fraction bits. The value is roughly 1.fraction × 2exponent, so it keeps about 15 to 17 significant decimal digits whatever the size of the number. epsilon is 2−52, the 2.22045e-16 printed in panel 39. The all-ones exponent is reserved for infinity (fraction zero) and NaN (fraction non-zero); the sign bit still exists for both, which is how -nan happens. Printing 17 significant digits ({:.17g}) is always enough to tell two different doubles apart.

    In real programs
    
    
      
      
        
    • Lookups and parsing. Functions that search, parse or read settings commonly return std::optional: "the value for this key, if there is one". C++23 added and_then, transform and or_else to chain such steps without nested ifs.
      • 
        
    • Messages and events. Programs that handle several kinds of message (a click, a key press, a network packet) often store them as a std::variant and handle them with std::visit. Adding a new kind then makes every visit without a matching road fail to compile, if no conversion sneaks in (the spot-the-bug after panel 14).
      • 
        
    • Errors as values. C++23's std::expected<T, E> is like an optional that carries a reason when it's empty. It's available here with g++ only; Chapter 27 compares it with optional and exceptions.
      • 
        
    • File formats and networks. Image, audio and network formats specify exact sizes, so the code uses std::uint8_t, std::uint16_t, std::uint32_t. Bytes in a file may also come in a different order (big-endian or little-endian); C++20's std::endian and C++23's std::byteswap help.
      • 
        
    • Flags everywhere. File permissions on Linux (read, write, execute for owner, group and others) are 9 bits; the 0755 you may have seen is an octal number. Graphics APIs, game engines and operating systems pass options as OR-ed masks.
      • 
        
    • Hashing and checksums deliberately use unsigned wrap-around and XOR, because both are well defined and fast.
      • 
        
    • Money is stored in whole cents (or smaller units) as integers, or with decimal libraries, never in double. Scientific and graphics code uses double and float freely, with tolerances.
      • 
      
    
    
    
  
    

  
    
    Common wrong ideas
    
    
      
      
        
    • "An empty optional holds 0." It holds nothing at all. value_or(0) gives 0; *box gives undefined behaviour.
      • 
        
    • "*box throws if the box is empty, like value()." It doesn't check. Only value() throws.
      • 
        
    • "A variant can be empty." It always holds one alternative; a new one holds a default-made first alternative. Use std::monostate for "nothing yet".
      • 
        
    • "If I forget a road in std::visit, the compiler always tells me." Only if the value can't convert to another road (the spot-the-bug after panel 14).
      • 
        
    • "std::any is a better variant." It's a box without a list of kinds; mistakes show up only when the program runs.
      • 
        
    • "int is always 4 bytes and long is always 8." Only the minimums are guaranteed. long is 4 bytes on 64-bit Windows.
      • 
        
    • "std::uint8_t is a small number type, so it prints as a number." It's unsigned char here, and prints as a character.
      • 
        
    • "Unsigned is safer for things that can't be negative." One subtraction (2u - 3u) and you're at 4294967295. Prefer signed for counts and maths.
      • 
        
    • "Signed overflow just wraps, like unsigned." It's undefined. It may seem to wrap in a quick test, and then behave differently with optimisation turned on.
      • 
        
    • "-1 < 1u is obviously true." It's false: −1 becomes 4294967295 first.
      • 
        
    • "~a on a std::uint8_t gives a std::uint8_t." It gives an int (promotion), here −203.
      • 
        
    • "0.1 + 0.2 == 0.3 is a C++ bug." It's how binary floating point works in every mainstream language.
      • 
        
    • "Comparing with epsilon fixes float comparisons." epsilon is the gap near 1.0. For numbers like 1000000.0 the gaps are far bigger; scale the tolerance with the numbers.
      • 
        
    • "NaN == NaN is true." NaN is unequal to everything, itself included.
