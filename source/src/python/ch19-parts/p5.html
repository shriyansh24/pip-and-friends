Python's attitude has a name: duck typing. "If it walks like a duck and quacks like a duck, treat it as a duck." What matters is what an object can do, not which family it's from.

Any object with a speak() method can join the choir. No shared parent needed. Python checks at the moment of the call.

      mixin.py

The Professor's checklist before writing class A(B):

    
    
      
  1. Say it out loud. "An A is a B." If it sounds silly ("a Robot is a Battery"), use composition.
    2. 
      
  2. Could an A be used anywhere a B is expected? Every method of B should still make sense for an A.
    3. 
      
  3. Would you ever want two, or swap one? Two engines, a new battery: that's a part, so has-a.
    4. 
      
  4. Count the floors. More than two or three levels deep is a warning sign.
    5. 
      
  5. Just want one shared method? A plain function, a part, or a small mixin is often simpler than a parent.
