Under the hood: notebooks are dicts, methods are bound, properties are objects, and how the MRO is built

The notebook really is a dict

Most objects keep their own attributes in a dict called __dict__, and vars(obj) shows it. The class has one too. Shadowing is just a key appearing in the object's dict, and del removes it so the whiteboard shows through again:


      
Where self comes from

      
A method is a plain function stored on the class. Reading it through an object, rex.speak, gives a bound method: the function with rex already clipped into the first slot. That's all self is. So rex.speak() and Pet.speak(rex) do the same thing:

      

      
@classmethod clips in the class instead, and @staticmethod clips in nothing.

      
A property is an object on the class

      
@property builds a property object and stores it on the class under the method's name. Because properties sit on the class and have a "set" handler, Python checks them before the object's notebook. That's why oven.celsius = … reaches the setter instead of simply writing the notebook. Written without the @:

      

      
How the MRO is worked out

      
Python builds every class's climbing order with an algorithm called C3 linearization. Its promises: a class comes before its parents, parents keep the left-to-right order you wrote, and each class appears once. In a diamond (two parents sharing a grandparent), the grandparent waits until both parents are done. super() means "the next class in this object's MRO", not "my parent", which is why every hello below runs exactly once:

      

      
If no order can keep all the promises, Python refuses to create the class at all:

    In real programs: where these tools show up
    

      
    
        
  • Alternative constructors are everywhere in the standard library: dict.fromkeys(…), int.from_bytes(…), datetime.fromisoformat("2026-11-07") and datetime.now() are all class methods.
    • 
        
  • Properties let a library start with a plain attribute and add checks later without changing a single caller. That's why Python programmers rarely write get_x() and set_x() methods.
    • 
        
  • Inheritance from framework classes: test frameworks (unittest.TestCase, Chapter 26), web frameworks and GUI toolkits give you a base class; you subclass it and override a few methods. The framework calls them.
    • 
        
  • Abstract base classes define plug-in points: "every storage backend must have save and load". Exceptions form a family tree too; Chapter 22 builds your own.
    • 
        
  • Composition is the default in most well-designed code: a game holds a board and players, a web app holds a database connection, a car holds an engine. Design books summarise this as "favour composition over inheritance".
    • 
        
  • Duck typing: print and json.dump accept anything with a write method, not only real files.
    • 
      

    

  


  

    Common wrong ideas
    

      
    
        
  • "self.count += 1 updates the class counter." It reads the class attribute but writes a new instance attribute (the boss-level bug). Write ClassName.count += 1.
    • 
        
  • "Class attributes are like defaults that get copied into each object." Nothing is copied. Objects without their own entry keep looking at the one shared value, which is exactly why a shared list leaks between them.
    • 
        
  • "Inside a setter I store the value with self.age = value." That calls the setter again, and again… Store it under a different name, self._age. The same mistake in a getter:

  • "One underscore makes it private." Nothing is enforced; it's a convention. Two underscores rename the attribute, which is still not a lock.
    • 
        
  • "super() means my parent class." It means the next class in the object's MRO. With one parent that is the parent; with several, it may be a sibling (see the diamond).
    • 
        
  • "A subclass's __init__ runs the parent's automatically." Only if the child doesn't define one. Once it does, it must call super().__init__(…) itself (Panel 28).
    • 
        
  • "Check types with type(x) == Pet." That rejects every subclass. Use isinstance(x, Pet), or better, duck typing: just call the method.
    • 
        
  • "Every shared method calls for a parent class." Inheritance glues two classes together for good. Prefer composition unless it's a true is-a.
    • 
        
  • "A static method is just a worse class method." They do different jobs: a classmethod needs the class (to build objects), a staticmethod needs nothing. If a staticmethod never mentions the class's idea, it may belong outside the class as a plain function.
    • 
      

    

  


  

    Version notes: what is new, and since when
    

      
    
        
  • The abstract-class message "Can't instantiate abstract class Shape without an implementation for abstract method 'area'" has this wording since Python 3.12. Older versions said "…with abstract method area".
    • 
        
  • The read-only property message "property 'fahrenheit' of 'Oven' object has no setter" names the property and class since 3.11; older versions said only "can't set attribute".
    • 
        
  • The __slots__ message "…and no __dict__ for setting new attributes" is recent; 3.15.2 and 3.13.18 both print it.
    • 
        
  • super() with no arguments works since Python 3.0. Very old code writes super(Dog, self).__init__(name), which means the same.
    • 
        
  • abc.ABC exists since 3.4; before that you wrote metaclass=ABCMeta.
    •

    Words from this chapter
    

      

        
class attribute
A value stored on the class (written in the class body), shared by all its objects. The whiteboard.

        
instance attribute
A value stored on one object, usually set with self.x = …. The notebook.

        
shadowing
An instance attribute with the same name as a class attribute hides it for that object.

        
__dict__ / vars()
The dict where an object (or class) keeps its own attributes.

        
property
A method read and written like an attribute, made with @property.

        
getter / setter
The methods a property runs when it is read / assigned.

        
read-only
A property with a getter but no setter: assigning it is an AttributeError.

        
validation
Checking a value before accepting it, and raising an error if it's wrong.

        
encapsulation
Keeping an object's inner details behind its methods and properties.

        
name mangling
Python renaming __name inside a class to _ClassName__name.

        
class method
A method that receives the class (cls), made with @classmethod.

        
alternative constructor
A class method that builds an object another way, such as from_string.

        
static method
A plain function kept in a class, made with @staticmethod; gets no self or cls.

        
__slots__
A fixed list of allowed attributes; the object gets no __dict__.

        
inheritance
Making a class from another one, so it gets all the parent's attributes and methods.

        
subclass / base class
The child / the parent in class Child(Parent).

        
override
Defining a method in the child with the same name as one in the parent; the child's wins.

        
super()
Reaches the next class up the MRO, usually to call the parent's version of a method.

        
MRO
Method resolution order: the order Python climbs the classes when looking up a name. C.__mro__ shows it.

        
object
The root class that every class inherits from.

        
multiple inheritance
A class with more than one parent.

        
polymorphism
One call, such as s.speak(), doing the right thing for many kinds of object.

        
duck typing
Using an object for what it can do, not what class it is.

        
abstract base class
A class that only promises methods (@abstractmethod) and can't be built itself.

        
composition
Building an object out of parts kept as attributes: "has-a".

        
delegation
An object passing a job on to one of its parts.

        
mixin
A small class that adds one skill when mixed in as an extra parent.
