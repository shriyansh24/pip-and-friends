CHAPTER 7

VENDING MACHINES AND RECIPE CARDS

Picture: Kit, the stage manager in a pink hoodie and headset, waves hello next to a machine creature labelled vend(), with an input hopper on top and an output chute at the bottom.

Write a few lines once, give them a name, and run them whenever you like. That's a function. Today you build them like vending machines (coins in, snack out), learn the difference between shouting a result and handing it over, and then discover that a function can be handed around like a recipe card. About 100 minutes, with 27 hands-on checks.

  1. Build it once: declaring and calling
  2. Coins in, snack out: parameters and return
  3. Shouting isn't handing over
  4. Empty slots and spare coins
  5. A function is a value
  6. Arrows and recipe cards
  7. Boss level and recap

    Under the hood: frames, the call stack, and what a function really is
    
        
      
        The call stack
        
      
        The engine keeps a pile of frames called the call stack. A call pushes a frame (holding the parameters and local variables); return, or reaching the closing }, pops it. A stack trace is a printout of that pile at the moment of an error, newest frame on top, which is why the trace in panel 26 lists shout first and the line that called it second. The stack has a size limit: a function that calls itself forever runs out of room and throws a RangeError, which Chapter 12 shows in a real run. Functions calling themselves on purpose (recursion) come in Chapter 21.
        
      
        How arguments travel
        
      
        When you call greet(guest), the parameter name gets the value that guest holds. Giving name a new value inside the function never changes guest outside. For lists and objects the value is a reference to the same object, so changing the object's contents inside a function is visible outside (Chapter 9's Boss 2 shows it with sort, and Chapter 10 draws it with the memory tracer).
        
      
        A function is an object
        
      
        In the specification, a function is an object with an internal "call" ability. Because it's an object, it has properties: name (the name you see in [Function: greet], inferred from the tag for anonymous expressions) and length (the number of parameters before the first one with a default). typeof reports "function" for it as a special case, even though it is an object.
        
      
        Declarations and expressions
        
      
          
        
        • A declaration (function name() {} as a statement of its own) is created when its surrounding scope starts, so it can be called earlier in that scope.
          • 
        
        • An expression (a function on the right of =, or passed as an argument) is created when that expression runs. Its tag follows the rules of var, let or const. Chapter 8 explains those rules in full.
          • 
      
        
      
        How arrows differ
        
      
        Arrow functions are not just shorter. According to MDN, they have no arguments object, no this of their own (they use the surrounding one, which matters in Chapter 17), and they can't be used with new to build objects. For everything in this chapter, an arrow and an expression behave the same.
        
    
        
  
        

  
        
    In real programs
    
        
      
          
        
        • Small, named, single-job functions are the main tool for keeping code readable. A common rule of thumb: if you scroll to read one function, it's doing too much.
          • 
        
        • Callbacks are everywhere: list methods (items.map(fn), items.filter(fn), Chapter 9), browser events (button.addEventListener("click", fn)), timers (setTimeout(fn, ms)), and many Node APIs. The "card, not the cake" bug (save() instead of save) is one of the most frequent beginner bugs in all of them.
          • 
        
        • Arrow functions are the usual choice for short callbacks. Many teams use declarations for top-level, named functions so they read like a table of contents.
          • 
        
        • Linters help: ESLint's no-unreachable rule flags code after return (panel 19), and consistent-return flags functions that return a value on some paths and nothing on others.
          • 
        
        • TypeScript (Chapter 26) checks the number and kind of arguments before the program runs, so shout() with no argument would be caught as a mistake while you type.
          • 
        
        • Documentation comments: many projects describe each function's parameters and return value in a /** … */ comment above it (the JSDoc style). Editors show that text when you hover over a call.
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "Declaring a function runs it." Only a call runs it.
          • 
        
        • "console.log inside a function returns the value." It only prints. The caller gets undefined.
          • 
        
        • "If the screen shows the number, my variable has it." The screen shows what was shouted. Check what was returned (panel 18).
          • 
        
        • "Calling with too few arguments is an error." Not in JavaScript: the missing ones are undefined, and the error (if any) comes later, somewhere else.
          • 
        
        • "A default is used whenever the argument is falsy." Only when it is undefined. 0, "" and null are kept.
          • 
        
        • "return can go on its own line, with the value below." Automatic semicolon insertion ends the statement right after return.
          • 
        
        • "greet and greet() are the same thing." One is the machine, the other is what it hands back.
          • 
        
        • "() => { name: \"Ada\" } returns an object." The braces are a body. Write () => ({ name: "Ada" }).
          • 
        
        • "Arrow functions are just a shorter syntax." Mostly, but they differ around this, arguments and new.
          • 
        
        • "Parameters and arguments are the same word." Parameters are the slots in the declaration, arguments are the values in the call.
          • 
        
        • "Any function can be called before its line." Only declarations. Function expressions follow the rules of their var, let or const.

    Words from this chapter
    
        
      
        
        
        function
        A named, reusable set of lines; a machine you build once and use many times.
        
        
        function declaration
        function name(params) { body } as a statement of its own. Can be called before its line.
        
        
        call
        Running a function: its name (or any expression holding it) followed by ( ).
        
        
        body
        The lines between the function's { and }.
        
        
        parameter
        A slot's name in the declaration. Inside the body it works like a variable.
        
        
        argument
        The actual value you pass in a call. Arguments fill parameters by position.
        
        
        return
        The keyword that hands a value back to the caller and ends the function immediately.
        
        
        return value
        The value a call hands back; undefined if there is no return value.
        
        
        undefined
        JavaScript's "no value here": the result of a call without a return value, and the value of a missing argument.
        
        
        guard clause
        An early return at the top of a function that turns away special cases.
        
        
        unreachable code
        Lines no path can reach, such as lines after a return.
        
        
        frame
        A call's private workspace, holding its parameters and local variables.
        
        
        call stack
        The pile of frames for the calls in progress, newest on top.
        
        
        local variable
        A variable made inside a function; it exists only during that call.
        
        
        scope
        Where in the program a name can be seen (Chapter 8).
        
        
        pure function
        A function whose result depends only on its arguments and which changes nothing outside itself.
        
        
        side effect
        Anything a function does besides returning a value: printing, changing an outside variable.
        
        
        default parameter
        slot = value: used when the argument is missing or undefined.
        
        
        function expression
        A function made as a value, usually on the right of =.
        
        
        anonymous function
        A function written without its own name.
        
        
        arrow function
        The short form (params) => ….
        
        
        concise body
        An arrow body without braces; its value is returned automatically.
        
        
        label
        A name followed by : in front of a statement. Rare, but it's why () => { id: 1 } returns undefined.
        
        
        callback
        A function handed to another function, to be called later by it.
        
        
        higher-order function
        A function that takes a function as an argument or returns one, like twice or makeGreeter.
        
        
        closure
        A function that remembers the variables around where it was made (Chapter 17).
        
        
        rest parameter
        ...name as the last parameter: collects the remaining arguments into a list.
        
        
        arguments
        An older, list-like object holding all the arguments of a non-arrow function.
        
        
        hoisting
        Names being set up before the code runs; declared functions are fully ready (Chapter 8).
        
        
        setTimeout
        A built-in helper that calls a function after a number of milliseconds.
