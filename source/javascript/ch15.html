When the browser reads HTML, it builds a tree of objects in memory, one object per piece of the page. That tree is the DOM (Document Object Model). JavaScript never edits the HTML file; it changes this tree, and the screen follows.

    

      

      
    
        
  • Node: any box in the tree. Every piece of the page is a node.
    • 
        
  • Element node (blue boxes): made from a tag, such as <ul>. Elements can have children.
    • 
        
  • Text node (rounded cream boxes): the words inside an element. Text nodes are always leaves: no children.
    • 
        
  • document (yellow): the root, the great-grandparent of everything. It's the object you start every search from.
    • 
        
  • Parent, child, sibling: ul is the parent of both lis; they are its children, and siblings of each other. body is an ancestor of "Ada".
    •

PART 3 · CHANGING THE PAGEWords, HTML, attributes, classes, style, and new elements


  

    11
    
Two ways to change what an element says. textContent swaps the words painted on a sign. innerHTML rebuilds the sign: it reads your string as HTML and builds new nodes from it.

    

      
      
    

  


  

    12
    
The same string, given to two signs.

    signs.html
    

    

    
    
      
  1. Sign a got its string through textContent, so its words are exactly Tonight: <b>Hamlet</b>, angle brackets and all. The visitor sees the brackets. To store them safely, the HTML spells them &lt; and &gt;, and it has 0 child elements.
    2. 
      
  2. Sign b got it through innerHTML, so the browser built a real <b> element: 1 child element. Its words read Tonight: Hamlet, with Hamlet in bold.
    3. 
      
  3. Reading works both ways too: textContent gives back all the text inside, tags left out; innerHTML gives back the HTML as a string.
    4. 
    

  


  

    13
    
    
The lobby gets a guestbook: visitors type their name and the page welcomes them. One visitor types something that isn't a name.

    guestbook.html
    

    
The test script typed this into the box, then clicked both buttons: <img src="nope.png" onerror="console.log('A stranger ran code on your page!')">

    

    
    
      
  1. The innerHTML sign built a real <img> element out of the visitor's text. The picture nope.png doesn't exist, so the browser fired the image's onerror, and the visitor's code ran on your page. Here it only logs a line. A real attacker would read what other visitors type, or act as them.
    2. 
      
  2. This attack is called cross-site scripting (XSS). Browsers refuse to run a <script> tag inserted with innerHTML, but as you just saw, there are other ways in.
    3. 
      
  3. The textContent sign shows the visitor's text as harmless letters, brackets included: 0 elements inside.
    4. 
      
  4. The red line is the browser reporting the missing picture. It sits where it happened: right after the innerHTML sign was built, and just before the stranger's code ran in the picture's onerror.

STRANGERS' TEXT GOES IN textContent.

An attribute is what the HTML says. A property is a key on the element object in the tree. Usually they're linked, but not always. The script typed 5 into the box after the page loaded.

    props.html
    

    

    
    
      
  1. Typing changes the property, not the attribute. After the visitor typed 5, seats.value is 5 but getAttribute("value") still says 2: the attribute is the starting value from the HTML, and .value is what's in the box now. For form boxes, always read .value.
    2. 
      
  2. Same attribute, different property: the HTML says map.html; the .href property is the full address the browser worked out from it.
    3. 
      
  3. Many properties write through to their attribute: setting map.id changed the id attribute (line 14). setAttribute(name, value) writes an attribute directly.
    4. 
      
  4. Notice the order: the "after typing" line is last, even though it's written on line 8. Lines 7 to 9 only wire up a listener; it ran later, when the typing happened.
    5. 
    

  


  

    15
    
To change how something looks, add or remove a class and let the stylesheet do the work. classList is the element's set of team badges.

    classes.html
    

    

    
    
      
  1. classList.add pins on a badge; remove takes one off; toggle flips it: on if it was off, off if it was on. contains asks "wearing it?" and gives true or false. className is the whole badge list as one string.
    2. 
      
  2. element.style.something sets one style on that one element. CSS names with dashes become camelCase: font-size is style.fontSize. The result lands in the element's style attribute (last line).
    3. 
      
  3. Prefer classes. A class keeps the look in the stylesheet, where designers expect it, and one toggle can change many styles at once.
    4.

    PART 5 · DOORBELLSaddEventListener, the event object, typing, and forms
    

  
    
    22
    
    An event is something that happens on the page: a click, a key press, a form being sent. element.addEventListener(type, handler) is like wiring a doorbell to a speaker. Wiring it makes no sound. The speaker plays only when someone presses the bell, every time they press it.
    
    
    
    
    
      
      
        
    • "click": the event type, a string. Others: "input", "change", "keydown", "submit".
      • 
        
    • ring: the handler (or listener), a function you hand over without calling it. The browser calls it for you, later, once per event. A function given to someone else to call later is a callback.
      • 
        
    • An element can have many listeners, even for the same type. They run in the order they were added.
      • 
      
    
      
    
        
        
    Kit says: It's how I run a show. "Lights, stand by..." means get ready and wait. "...GO!" is the moment it happens. addEventListener is the stand-by; the click is the GO.

    Under the hood: how a page becomes a tree, and how an event travels
    
      
      
      From text to tree
      
      
      The browser downloads the HTML as text and feeds it to its HTML parser, which reads from the top and builds nodes as it goes. The parser is forgiving: if you leave out <html>, <head> or <body> (as most of this chapter's small examples do), it creates those elements anyway, so every page ends up with the same basic shape. When the parser meets a plain <script>, it pauses, runs the script, then carries on. That pause is exactly why a script in the head can't see the body: the body hasn't been parsed yet. defer and module scripts run after parsing finishes, in the order they appear, just before the DOMContentLoaded event fires.
      
      
      Node types
      
      
      Every node has a nodeType number and a nodeName. The ones you met: the document (type 9, name #document), the doctype (10), elements (1, name in capitals such as LI) and text (3, name #text). Comments in HTML become comment nodes (8). The tree helper in Panel 6 checks these types to decide how to print each node.
      
      
      The invisible whitespace
      
      
      The spaces and line breaks between tags are real text nodes. ul.childNodes.length counts them (a text node before each li and one after the last), while ul.children.length counts only elements. Here is a three-name list, counted in the real browser:
      
      whitespace.html
      
      
      
      
      Seven child nodes for three elements: four of them are text nodes holding only a line break and spaces. That's why this book uses children for counting, and why the helper skipped blank text nodes.
      
      
      Live and static lists
      
      
      querySelectorAll returns a static NodeList: a snapshot taken at that moment, which doesn't change when the page does. element.children and the older getElementsByClassName return a live HTMLCollection that updates itself as elements come and go. Live lists surprise people who remove items inside a loop over them.
      
      
      An event's journey
      
      
      When you click, the browser works out the target (the deepest element under the pointer) and dispatches the event along the path from window down to the target and back up. On the way down is the capture phase, which listeners only join if they ask for it with { capture: true }; on the way back up is the bubble phase, where ordinary listeners run. Chapter 28 covers capture and stopPropagation. A few events don't bubble at all, such as focus and blur; most of the ones in this chapter do. Some events have a default action the browser performs after all the listeners have run (sending a form, following a link, typing a character); preventDefault() cancels it, which is why it doesn't matter where in the handler you call it, as long as the handler gets there.
      
      
      Why innerHTML is expensive
      
      
      Setting innerHTML runs the HTML parser on your string and replaces every child node. Reading it does the reverse: it serialises the children back into text. innerHTML += does both, on everything inside, every time. Besides losing listeners, it also loses what the visitor typed into any boxes inside, and it gets slower as the content grows.
      
    
      
  
      

  
      
    In real programs
    
      
      
        
        
      • Frameworks build the tree for you. Libraries like React, Vue and Svelte let you describe what the page should look like, then make the DOM changes themselves. Underneath they call the same createElement, append and addEventListener you used here, and React attaches its listeners at the root and delegates, much like Panel 31.
        • 
        
      • Delegation everywhere. Long lists, tables, chat windows and anything that grows while the page is open use one listener on a container.
        • 
        
      • Escaping text. Frameworks escape text by default, the way textContent does. Their "dangerous" escape hatches (React's dangerouslySetInnerHTML, for one) are named to make you stop and think. When a site truly needs to show HTML from users, it runs it through a sanitiser library first.
        • 
        
      • Forms. Many forms are still sent the old way, with a reload, and that's fine when the server builds the next page. Interactive apps use preventDefault and send the data themselves with fetch (Chapters 16 and 28).
        • 
        
      • Accessibility testing. Teams try their pages with only a keyboard (Tab, Shift+Tab, Enter, Space) and with a screen reader, and run automatic checkers such as the one built into Chrome's Lighthouse panel.
        • 
        
      • Automated browsers. This chapter's runs used Playwright to drive a headless Chromium: open the page, click, type, read the console. Real teams use the same kind of tool for end-to-end tests of their sites.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "JavaScript changes the HTML file." It changes the DOM in memory. Reload the page and the tree is rebuilt from the unchanged file.
        • 
        
      • "The DOM is part of JavaScript." It's a Web API that browsers provide. Node doesn't have it (Panel 2).
        • 
        
      • "querySelector returns all matches." Only the first. querySelectorAll returns all.
        • 
        
      • "A failed search throws an error." It returns null quietly; the error comes later, when you use the null.
        • 
        
      • "A NodeList is an array." It has length and forEach, but no map or filter.
        • 
        
      • "innerHTML is fine if I never insert a <script>." An <img onerror> is enough (Panel 13).
        • 
        
      • "getAttribute("value") tells me what's in the box." It tells you what the HTML said at the start. Use .value.
        • 
        
      • "defer works on any script." Only on scripts with src.
        • 
        
      • "addEventListener("click", ring()) wires up ring." It calls ring once, right away, and wires up its return value.
        • 
        
      • "Events go down to the children." Ordinary listeners hear events bubbling up from the target. Clicking a parent's empty space never reaches its children.
        • 
        
      • "this in a handler is always the element." Only in a regular function. Arrow functions keep the outer this.
        • 
        
      • "A div with a click listener is as good as a button." Not for keyboard or screen-reader users.

    Words from this chapter
    
      
      
      
        
      host
      The program that runs your JavaScript and adds its own objects: a browser (document, window) or Node (process).
      
        
      Web API
      An object or function the browser provides to scripts, such as the DOM or fetch.
      
        
      HTML element, tag, attribute
      An element is a piece of a page, written with an opening tag, content and a closing tag. Attributes such as id="title" sit in the opening tag.
      
        
      id / class
      An id is a name tag that one element wears; a class is a team badge that many can share.
      
        
      DOM
      Document Object Model: the tree of objects the browser builds from a page.
      
        
      node
      Any item in the DOM tree: the document, an element, a piece of text.
      
        
      element node / text node
      A node made from a tag / a node holding words. Text nodes have no children.
      
        
      parent, child, sibling, ancestor
      Family words for nodes one level up, one level down, side by side, and any number of levels up.
      
        
      DevTools
      The browser's built-in developer tools: Console, Elements and more.
      
        
      CSS selector
      A short pattern that describes elements: "li", "#title", ".lead", "#cast li".
      
        
      querySelector / querySelectorAll
      Return the first matching element (or null) / a NodeList of all matches.
      
        
      getElementById
      Returns the element with that id, or null; takes the id without #.
      
        
      NodeList
      A list of nodes with length and forEach, but not an array.
      
        
      textContent / innerHTML
      An element's text / its contents as HTML. Setting innerHTML builds new nodes from a string.
      
        
      XSS (cross-site scripting)
      An attack where text from a stranger ends up running as code on your page.
      
        
      attribute / property
      What the HTML says / a key on the element object. .value is a property.
      
        
      classList
      An element's classes, with add, remove, toggle and contains.
      
        
      createElement, append, remove
      Make a new element off stage, hang it in the tree as a last child, take it out of the tree.
      
        
      isConnected

      On a script with src: run it after the page has been read.

      local web server
      A small program that serves a folder to your own browser at an address like http://localhost:8000.
      
        
      event
      Something that happens on the page: a click, a key press, a form being sent.

      callback
      A function you hand to someone else to call later.
