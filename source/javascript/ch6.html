CHAPTER 6

SWITCHES AND LAPS

Picture: Kit, the stage manager in a pink hoodie with a headset and a clipboard, waves hello. On one side stands a signpost with two arms, true and false. On the other, a spinning wheel labelled lap.

Until now, every program ran straight down the page, every line exactly once. Today your programs learn to choose and to repeat. Railway switches send the train one way or the other (if, else, switch); gates let it through or stop it (&&, ||, ??); and a running track lets it go round and round (while, for, for...of) until the exit gate opens. About 100 minutes, with 32 hands-on checks.

  1. Forks in the track: if, else if and else
  2. Gates: &&, ||, ! and the ?? default
  3. Quick switches: the ternary and switch
  4. Laps: while, do...while and for
  5. Riding the list: for...of, break, continue and loops in loops
  6. Boss level and recap

PART 1 · FORKS IN THE TRACKif, else, else if, blocks and braces, and ifs inside ifs

1

Backstage, an hour before curtain-up. Kit's clipboard is full of cues that start with if and until.

Kit says: A real show isn't a straight list. If the seats are sold out, put up the sign. Run the scene again until it's right. Programs need exactly the same two powers.

Kit says: Choosing which lines run is called control flow. Two creatures help today: the signpost (a choice) and the wheel (a loop: lines that run again and again).

Picture: the signpost creature with arms labelled true and false, the wheel creature labelled loop, and the lamp creature switched on, labelled true.

2

Here's this chapter's first picture. Your program is a train running along the track, line by line. An if is a railway switch: a question decides which branch the train takes. Then the branches join up again.

  • The question sits in round brackets after if. Its answer is a boolean, true or false (Chapter 5's lamp). This question is called the condition.
  • true: the train takes the branch through the station: the lines inside the curly brackets run.
  • false: the train goes straight past. Those lines are skipped, not run at all.
  • Either way, the tracks join again and the next line after the } runs.

    PART 2 · GATES&&, || and !, short-circuits, defaults with || and ??, and which goes first
    

  
    
    12
    
    One question is often not enough. "Old enough and has a ticket." "A member or under 16." Three logical operators combine questions.
    
    and_or.js
    
    
    
    
    
      
      
    1. &&, said "and": true only when both sides are true. Line 5 is false because 15 isn't ≥ 18.
      2. 
      
    2. ||, said "or" (two vertical bars, usually Shift + \): true when at least one side is true. Line 6: not a member, but under 16, so true.
      3. 
      
    3. !, said "not": flips true and false. Line 7: !true is false.
      4. 
      
    4. Line 8: the usual place for them is inside an if.
      5. 
    
    
  
    

  
    
  

  
    
    13
    
    Now the second picture. Each side of && or || is a door. A truthy value (Chapter 5) is an open door, a falsy one is a closed door. The two operators walk the doors from left to right, but they stop for different reasons.
    
    
    
    
    
    
      
      
    Kit says: Learn it as a chant: && stops at the first NO. || stops at the first YES. And whichever door it stops at, that door's value is the answer. Not true or false: the value itself.
    
    
    
  
    

  
    
    14
    
    Does JavaScript really stop early? Put a console.log on the right of each gate. If the right side runs, we'll see it print.
    
    short_circuit.js
    
    
    
    
    
      
      
    1. Line 1: false && …: the first door is closed, so && stops. The right side never runs: no never printed.
      2. 
      
    2. Line 2: true || …: the first door is open, so || is done. Again the right side never runs.
      3. 
      
    3. Line 3: true && … must look at the right side. So the inner console.log runs and prints printed! first. A console.log call hands back undefined, and that's what && gives to the outer print: C: undefined.
      4. 
    
    
    
    Stopping as soon as the answer is known is called short-circuit evaluation. It's not a trick: it's guaranteed by the language, and real programs rely on it.
    
  
    

  
    
    15
    
    The || machine. Feed it pairs and watch which value comes out. Every answer is the real run of or_machine.js.
    
    
    
    
  
    

  
    
    16
    
    && works the other way round: it hands back the first falsy value, or the last value if every door is open.
    
    and_machine.js

      2. 
      
    2. Line 2: the empty string is a closed door, so the answer is the empty string. Printing an empty string prints an empty line: that gap in the terminal is real.
      3. 
      
    3. Line 3: "hi" is open, so && carries on and hands back the last value, y.
      4. 
      
    4. Line 5: three open doors in a row: the last one, 3.
      5.

        Four loops. Here's how to choose.
        
    
        
      
        for...of
        for (const x of list) { }
        You want each item of an array or string. Your first choice whenever it fits.
        
      
        for
        for (let i = 0; i < n; i++) { }
        You're counting: a known number of laps, or you need the bead numbers themselves.
        
      
        while
        while (condition) { }
        You don't know how many laps: "until the coins pass 100", "until the queue is empty".
        
      
        do...while
        do { } while (condition);
        Like while, but the first lap must always happen.
        
    
        
    
        Every one of them can use break and continue. And whichever you pick, run START IT, CHECK IT, CHANGE IT in your head before you run the code.

    Under the hood: how the switches and laps really work
    
        
      
        How if turns a value into yes or no
        
      
        The condition can be any expression. The engine works out its value, then applies the standard's ToBoolean rule: the eight falsy values from Chapter 5 (false, 0, -0, 0n, "", null, undefined, NaN) mean no; everything else means yes. while, do...while, the middle part of for, the ternary, !, && and || all use the same rule. Only ?? asks a different question: "is it null or undefined?"
        
      
        What && and || really return
        
      
        The ECMAScript standard defines a || b as: work out a; if ToBoolean of it is true, the answer is a itself, and b is never evaluated; otherwise the answer is b. a && b is the mirror image. That is why they return operands, why they short-circuit, and why nick && nick.length safely avoids reading a property of null. Chapter 11 adds ?., a shorter way to write exactly that guard, plus ||=, &&= and ??=.
        
      
        Why mixing ?? with || is a SyntaxError
        
      
        When ?? was added to the language (MDN says browsers have all had it since July 2020), its designers expected people to mix it up with ||. Rather than pick a precedence that half of readers would guess wrong, the grammar simply does not allow ?? to sit directly next to && or || without brackets. The Proofreader rejects it before anything runs.
        
      
        The exact rules of switch
        
      
          
        
        • The value in switch ( ) is worked out once. Each case expression is then worked out in order and compared with strict equality (===), until one matches.
          • 
        
        • Case labels can be any expression, not just literals, though literals are by far the most common.
          • 
        
        • After a match, every statement below runs until a break, the end of the switch, or a return (Chapter 7) or throw (Chapter 12).
          • 
        
        • default runs when nothing matched. It may be written anywhere in the list, but put it last so people can find it.
          • 
        
        • The whole switch is one block: a let or const declared in one case is visible (and clashes) in the others. Wrap a case's lines in their own { } if you need a private name.
          • 
      
        
      
        A fresh let for every lap
        
      
        In for (let i = 0; …; i++), the standard gives every lap its own copy of i, made from the previous lap's value just before the update runs. You can't see the difference yet. It matters when a function created inside the loop remembers i (closures, Chapter 17): each one remembers its own lap's value. Old var loops shared one variable, a famous source of bugs.
        
      
        What for...of asks for
        
      
        for...of asks the value for an iterator, an object with a next() method that hands out one item at a time. Arrays, strings, Maps and Sets have one built in; plain objects don't, hence is not iterable. Chapter 20 shows the protocol, and how to make your own things iterable. For strings, for...of goes by code points, so a simple emoji like a smiley is one lap (unlike s[i], which reads UTF-16 code units: Chapter 4's notebook). Emoji glued together from several parts still take several laps: Chapter 22.
        
      forof_emoji.js
      
        
      
        
      
        The smiley: one lap, though its length is 2. The family, built from three people and two invisible joiners (\u200D): five laps, one for each part.
        
      
        Labels: breaking out of two loops at once
        
      
        A plain break leaves only the innermost loop. Put a label (a name and a colon) before the outer loop, and break outer; leaves that one. It's legal, rarely needed, and often a sign the code would read better as a function with return.
        
      labels.js
      
        
      
        
    
        
  
        

  
        
    In real programs
    
        
      
          
        
        • Guard clauses everywhere. Professional code checks for bad input first and leaves early (with return in functions, continue in loops), keeping the main path flat and unindented.
          • 
        
        • Defaults with ??. Settings and options are filled in with ??, so that a deliberate 0, "" or false survives. Older code uses || for the same job and sometimes has exactly the volume bug.
          • 
        
        • switch on a "kind" or "action". A common pattern is a switch over a message type: case "add":, case "remove":, and a default that reports an unknown type. Many state-management libraries for web apps are built around this shape.
          • 
        
        • Fewer counting loops than you'd think. Once you meet array methods (Chapter 9), many for loops become map, filter or reduce. for...of stays common, especially with break or await inside.
          • 
        
        • Loops that wait. Servers, games and the browser itself sit in loops that wait for the next event. JavaScript's is called the event loop (Chapter 16): Kit's clipboard of cues, run one at a time.
          • 
        
        • Linters catch this chapter's bugs. ESLint has a rule for most of them: curly (always braces), no-cond-assign (= in a condition), no-fallthrough (missing break), default-case, for-direction (a counter moving the wrong way), no-constant-condition (while (true) by accident) and eqeqeq (== instead of ===).
          • 
        
        • Endless loops on purpose. while (true) { … } with a break inside is a real pattern ("keep going until something happens"). The break is the only way out, so it must be reachable.
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "Indentation decides what's inside the if." Only braces do. Without them, the if owns one statement.
          • 
        
        • "Every true branch of a ladder runs." Only the first true one. The rest are not even checked.
          • 
        
        • "&& and || always give true or false." They give back one of their operands. "Kit" || "guest" is "Kit".
          • 
        
        • "?? is just a newer ||." They differ exactly on the falsy values that aren't null or undefined (0, -0, 0n, "", false and NaN), which ?? keeps.
          • 
        
        • "if (x = 5) compares x with 5." It puts 5 into x, and the condition is then 5: truthy.
          • 
        
        • "switch stops after the matching case." Only at a break. Without one, it falls through.
          • 
        
        • "case 1: matches "1"." switch uses ===; kinds must match.
          • 
        
        • "A while loop stops the moment the condition becomes false." The condition is only checked at the top of each lap. A lap in progress always finishes (unless it hits break).
          • 
        
        • "for (let i = 0; i <= s.length; i++) visits every character." It visits one too many. Use <.
          • 
        
        • "const is always fine in a loop header." In for...of, yes (each lap gets a new one). In a counting for, no: i++ must change it.
          • 
        
        • "for...of works on anything." Only on iterables: arrays, strings, Maps, Sets… not plain objects or numbers.
          • 
        
        • "continue restarts the loop from the beginning." It ends only the current lap. In a for, the update (i++) still runs before the next check.
          •

    Words from this chapter
    
        
      
        
        
        control flow
        The order in which a program's lines run, including which lines are skipped or repeated.
        
        
        condition
        The expression in the brackets of an if, while or for, treated as true or false.
        
        
        block
        A group of statements in curly brackets { } that run together.
        
        
        else-if ladder
        A chain of if, else if … else; the first true check wins.
        
        
        nesting
        Putting one if or loop inside another.
        
        
        guard clause
        An early check that deals with a bad case first and gets it out of the way.
        
        
        logical operator
        && (and), || (or) and ! (not).
        
        
        short-circuit evaluation
        Stopping as soon as the answer is known, so the right side may never run.
        
        
        operand
        A value an operator works on: in a || b, a and b.
        
        
        default value
        A value used when none was given.
        
        
        nullish
        null or undefined.
        
        
        nullish coalescing (??)
        Gives the right side only when the left side is nullish.
        
        
        precedence
        Which operator goes first when several are mixed without brackets.
        
        
        token
        One "word" of code: a name, number, string or operator.
        
        
        ternary operator
        condition ? a : b: an expression that picks one of two values.
        
        
        switch / case / default
        Compares one value with a list of options using ===.
        
        
        fall-through
        Running on into the next case because a break is missing.
        
        
        loop
        A block that runs again and again while a condition holds.
        
        
        lap (iteration)
        One run of a loop's body.
        
        
        loop counter
        A variable that counts laps, like i.
        
        
        accumulator
        A variable that collects a running result, like sum.
        
        
        infinite loop
        A loop whose condition never becomes false. Stop it with Ctrl+C.
        
        
        do...while
        A loop that checks at the end, so its body runs at least once.
        
        
        for...of
        A loop that gives you each item of an iterable in turn.
        
        
        iterable
        A value for...of can go through: arrays, strings, Maps, Sets.
        
        
        array
        A list of values in square brackets (Chapter 9).
        
        
        object
        Named values in curly brackets, like { row: "B" } (Chapter 10).
        
        
        break / continue
        Leave the whole loop now / skip to the next lap.
        
        
        off-by-one
        One lap too many or too few, usually <= where < was meant.
        
        
        label
        A name before a loop, so break name; can leave an outer loop.
        
        
        keyword
        A word with a fixed meaning in JavaScript, like if, for or break.
