PART 1 · SENTENCES AND PHRASESStatements do things. Expressions produce values.

1

Back at the theatre. Kit has a new script to read.

Picture: Kit points at the clipboard of cues.

2

A JavaScript line is like a sentence. Inside it are phrases that each work out to a value.

STATEMENT A complete instruction, like a sentence. It does something: prints, decides, repeats. A program is a list of statements.

EXPRESSION A piece that produces a value, like a phrase that answers "what?". 40 + 2 works out to 42. "Seats:" is the text itself.

SEMICOLON ; The full stop at the end of a statement.

    PART 2 · FULL STOPS AND THE GREMLINSemicolons, automatic semicolon insertion, and spaces
    

  
    
    8
    
    A semicolon ends a statement, so two statements can even share a line. But look at line 2: it has no full stop.
    
    full_stops.js
    
    
    
    
    
    
      
      
    Kit says: Line 2 has no semicolon, and it still worked. Who put the full stop there?
    
    
    
  
    

  
    
    9
    
    
    Meet the gremlin who lives in the engine.
    
    
    
      
      
    
        
    The gremlin says: Heh heh. I'm the ASI gremlin. ASI stands for Automatic Semicolon Insertion. You forget a full stop at the end of a line? I pop one in for you!
    
        
    The gremlin says: Most of the time I'm helpful. Most of the time.
    
      
    
    
    
    
    Picture: a small green gremlin with pointy ears and a wide grin holds a giant black full stop over its head.
    
  
    

  
    
    10
    
    The gremlin follows three rules, written into the JavaScript standard.
    
    
      
      
    1. At the end of a line, if the next line can't continue the sentence, I insert a ;. That's what saved line 2 of full_stops.js: console.log can't continue console.log("Curtain").
      2. 
      
    2. At the end of the file, if the last statement has no full stop, I add one.
      3. 
      
    3. After a few special words, like return, a line break always gets a ;, even if the sentence wasn't finished. Watch out!
      4. 
    
    
    
    
      
      
    The gremlin says: And here's my secret: if the next line could continue the sentence, I stay home. Even when you wanted a full stop.
    
    
    
  
    

  
    
    11
    
    
    Rule 3 in action. This program builds a tiny mini-recipe called ticketPrice that should hand back 42.
    
    asi_return.js
    
    
    
    
    
    
      
    The gremlin says: Line 2 said return and then the line ended. Rule 3! I dropped a full stop right after it: return;. So it handed back nothing at all.
    
      
    
    
    
    function makes a reusable mini-recipe, and return hands a value back from it (Chapter 7 covers both). Here, all you need to know: the 42 on line 3 is never reached. No error, no warning, just undefined, JavaScript's word for "no value".
    
  
    

  
    
    12
    
    The fix: keep the value on the same line as return.
    
    asi_fixed.js
    
    
    
    
    
    
      
      
    Kit says: Same characters, one line break fewer. Now it prints 42. Line breaks can matter in JavaScript!
    
    
    
  
    

  
    
  

  
    
    13
    
    
    The opposite trap. Line 2 starts with a bracket, so it can continue line 1. The gremlin stays home.
    
    asi_paren.js
    
    
    
    
    
      
      
    1. Ready printed first. Then the crash.
      2. 
      
    2. With no full stop after line 1, the engine reads both lines as one sentence: console.log("Ready")(1 + 2). Brackets right after something mean "run it", so it tries to run whatever console.log("Ready") gave back.
      3. 
      
    3. TypeError: console.log(...) is not a function: that "something" can't be run. A TypeError means "this kind of value can't do that". The error points at line 2, column 1, where the joined sentence went wrong.
      4. 
    
    
  
    

  
    
    14

    asi_paren_fixed.js
    
    
    
    
    
    
      
      
    Kit says: This book's rule: write your own full stops. End every statement with a semicolon, and keep return and its value on one line. Then the gremlin has nothing to do.
    
    
    
    
    Line 2 is a statement that works out 1 + 2 and then throws the 3 away. Legal, but useless: it's only here to show the full stop doing its job.
    
  
    

  
    
  

  
    
    15
    
    What about spaces, tabs and blank lines? Between the words of a statement, JavaScript doesn't care how many you use.
    
    spacing.js
    
    
    
    
    
      
      
    1. Lines 1 and 2: many spaces or none around the commas, same result. (console.log always puts exactly one space between arguments.)
      2. 
      
    2. Line 3: indentation, the spaces at the start of a line, changes nothing. Programmers indent only to make code easier to read.
      3. 
      
    3. Lines 4 and 5: one statement split over two lines still works, because line 5 starts with a dot, which can continue line 4, so the gremlin stays home.
      4. 
      
    4. Line 6: inside quotes, every space is part of the text and is printed.

    Comments are notes for humans. The engine skips them completely. There are two kinds.

    BLOCK COMMENT/* ... */
    
        
    Everything between /* and */ is ignored, even across many lines, even in the middle of a line.
    
      
    
    
    
    comments.js

    nested_comment.js

    JavaScript has two rule books. The old one is forgiving, sometimes too forgiving. The newer one, strict mode, turns old traps into errors. Here's a trap: a number written with a leading zero.
    
    
    
      
    
        
    OLD FILEsloppy.cjs

    24
    
    Two guards, two moments. Knowing which one stopped you tells you a lot.
    
    
    
      
    
        
    
        
    THE PROOFREADERSyntaxError
    
        
    • When: before anything runs.
    • Checks: grammar. Brackets, quotes, word order.
    • Result: no line runs at all. The screen shows only the error.
    
      
    
      
    
        
    
        
    THE BOUNCERReferenceError, and friends
    
        
    • When: while the program runs, line by line.
    • Checks: names, as each line uses them.
    • Result: lines before the bad one already ran and printed.
    
      
    
    
    
    
    Picture: THE PROOFREADER card shows the Proofreader with a red pen; THE BOUNCER card shows the purple Bouncer.

    PART 5 · JARS ON THE SHELFValues, their types, and the label reader called typeof
    

  
    
    30
    
    Every value in JavaScript has a type: what kind of value it is. Picture a shelf. Seven small sealed jars, and one big box.
    
    
    
    
    
      
      
    Kit says: The seven are called primitives: simple, single values that can't be changed from the inside. Everything else is an object, a box that can hold many values. And see that sticker on the null jar? That's a famous mistake. Wait for it…
    
    
    
  
    

  
    
    31
    
    Writing a value straight into your code is called a literal. Here's at least one literal for most jars.
    
    literals.js
    
    
    
    
    
      
      
    1. Numbers: whole, decimal and negative numbers are all the same type, number.
      2. 
      
    2. Strings can use double quotes, single quotes or backticks. console.log prints just the text, never the quotes.
      3. 
      
    3. Booleans are exactly two values: true and false, written in small letters, no quotes.
      4. 
      
    4. undefined and null are values too, each the only value of its own type.
      5. 
      
    5. 10n: an n after a whole number makes a bigint, for huge whole numbers. It keeps its n when printed.
      6. 
    
    
  
    

  
    
    32
    
    In this book, each type has its own creature. Learn their faces: they'll keep turning up.
    
    
    
      
    BRICKnumberEvery number: 42, 3.14, -7. JavaScript has one number type for all of them.
    
      
    TRAINstringText: characters in a row, like carriages.
    
      
    LAMPbooleanOn or off: true or false.
    
      
    GHOSTundefined"Never set": nobody ever put a value here.
    
      
    EMPTY FRAMEnull"Empty on purpose": someone hung the frame and left it empty, deliberately.
    
      
    CABINETobjectA box of labelled drawers that holds many values (Chapter 10).
    
    
    
    
    Picture: six creatures. An orange brick labelled 3.14. A red train pulling three carriages, K, i, t. A glowing lamp labelled true. A white ghost labelled undefined.     The misprint, up close.
    
    null_bug.js
    
    
    
    
    
    
      
    
        
    The Professor says: In JavaScript's first version, written in 1995, every value carried a small type tag. The tag for objects was 0, and null was stored as zero too. So typeof null read the object tag and said object.
    
        
    The Professor says: A fix was proposed years later, and rejected: too many websites already depended on the old answer. So the misprint stays, forever.
    
      
    
      
    
    
    
    Line 3 asks "is typeof null exactly the text "object"?" with ===, the "exactly equal" check (Chapter 5). The answer is true. So typeof can't tell null apart from a real object. To check for null, compare with it directly, as in value === null.
    
  
    

  
    
  

  
    
    37
    
    Two more surprises from the big box: lists and functions.
    
    
    
      
    
        
    LISTSarrays.js
    
        
    
        
    
        
    An array (a list in square brackets, Chapter 9) is an object, so typeof says object. To ask "is this a list?", use Array.isArray(...): it answers true or false.
    
      
    
      
    
        
    FUNCTIONSfunctions_type.js
    
        
    
        
    
        
    console.log and Math.max are functions: things you can run with brackets. typeof gives them a special answer, function. Math and console themselves are boxes of tools: objects.

    UNDEFINEDnever set

    NULLempty on purpose
    
        
        
        
    Someone put a "kept empty" sign on this seat, deliberately. Programmers write null to say "no value here, and that's on purpose".

    Under the hood: from text to tokens to a tree
    
    
      
    Before anything runs, the engine (V8, inside Node) turns your file's text into something it can work with, in two steps.
    
      
      
        
    1. Tokenizing. The text is chopped into tokens, the "words" of code: names (console, log), punctuation (. ( ) , ;), literals ("Seats:", 40) and operators (+). Spaces and comments are thrown away at this point, which is why they never change meaning. An unfinished string can't even become a token, which is why that slip says Invalid or unexpected token.
      2. 
        
    2. Parsing. The tokens are fitted to the grammar, building a tree of statements and expressions (an abstract syntax tree). For console.log("Seats:", 40 + 2); the tree has one expression statement, holding a call, whose arguments are a string literal and an addition with two number literals. A token that doesn't fit is an Unexpected token; running out of tokens while something is open is an Unexpected end of input.
      3. 
      
    
      
    Only when the whole file has a tree does the first line run. That's the Proofreader. A ReferenceError or TypeError happens later, during the run, which is the Bouncer's moment.

    The exact ASI rules
    
      
    The ECMAScript standard lists when a semicolon is inserted: (1) before a token that the grammar doesn't allow, if a line break separates it from the previous token, or if it is }; (2) at the end of the file, if the program is otherwise incomplete; (3) at a line break in a "restricted production": after return, throw, break, continue and yield, before a postfix ++ or --, before => in an arrow function, and after async. No semicolon is inserted if the next line can legally continue the statement, which is why lines starting with (, [, a backtick, +, - or / can join the line above.
    
      
    How typeof decides
    
      
    typeof looks at a value's internal type: Undefined, Null, Boolean, Number, BigInt, String, Symbol or Object. Each gives its own lowercase name, with two special cases written into the standard: Null gives object (kept for compatibility, as in panel 36), and an object that can be called (a function) gives function. Those eight strings are the only answers typeof can ever give.
    
    
    
  
    

  
    
    In real programs: semicolon styles, checkers and type checks
    
    
      
      
        
    • Two semicolon styles. Most style guides and code formatters write every semicolon, as this book does. Some teams use a "no semicolons" style and rely on ASI on purpose; they then follow one extra rule: start any line that begins with (, [ or a backtick with a semicolon. Both work. Mixing them carelessly is what bites.
      • 
        
    • Formatters and linters. A formatter (for example Prettier) rewrites spacing, quotes and semicolons into one consistent style every time you save. A linter (for example ESLint) reads your code and warns about likely mistakes. ESLint has a rule for code like asi_paren.js (no-unexpected-multiline), one for return followed by unreachable code (no-unreachable), and one that catches misspelled typeof answers like "nul" (valid-typeof).
      • 
        
    • Grammar check without running. node --check file.js asks the Proofreader only: it checks the grammar and runs nothing. No output means the grammar is fine.
      • 
      
    
      
    
      
      
        
    • Type checks you'll see everywhere. typeof x === "string" and typeof x === "number" for primitives; x === null for null; Array.isArray(x) for lists; typeof x === "function" before calling something that might not be a function.
      • 
        
    • JSON, the data format used by most web services, has null but no undefined. When data travels as JSON, "empty on purpose" survives and "never set" usually disappears.
      • 
        
    • Strict mode is on in every ES module and every class. Most new code is written as modules, so most new code is strict without ever saying "use strict".

    Common wrong ideas
    
    
      
      
        
    • "Semicolons are optional, so they don't matter." ASI fills most gaps, but not all, and sometimes in the wrong place (return on its own line). Write them.
      • 
        
    • "A line break always ends a statement." Only when the next line can't continue it. console.log("Ready") followed by a line starting with ( becomes one statement.
      • 
        
    • "Indentation matters, like in Python." Not in JavaScript. It's only for readers. Line breaks matter in a few places; spaces at the start of a line never do.
      • 
        
    • "The error is always on the line it names." The line is where the engine noticed the problem. A missing ; or ) on the line above is a common real cause.
      • 
        
    • "If line 1 is correct, it will run even if line 10 has a typo." Not for grammar slips. A SyntaxError anywhere stops the whole file before line 1.
      • 
        
    • "typeof null is null." It is object, a mistake kept since 1995.
      • 
        
    • "typeof tells you if something is a list." Lists give object. Use Array.isArray.
      • 
        
    • "NaN is not a number, so its type isn't number." Its type is number. It means "a number result that went wrong".
      • 
        
    • "undefined and null are the same thing." Both mean "nothing", but undefined is "never set" and null is "empty on purpose", and typeof labels them differently.
      • 
        
    • "If it prints 5, it is the number 5." console.log prints 5 and "5" the same way. Ask typeof.
      • 
        
    • ""use strict" must be at the top of every file." Not in modules: they are strict already. It matters only in old-style scripts, like .cjs files.

    Words from this chapter
    
    
      
    
        
    statement
    A complete instruction, like a sentence. It does something.
    
        
    expression
    A piece of code that produces a value, like 40 + 2 or "hi".
    
        
    argument
    A value handed to a function inside its brackets, like each value given to console.log.
    
        
    semicolon
    The ; that ends a statement: JavaScript's full stop.
    
        
    ASI
    Automatic Semicolon Insertion: the rules by which the engine adds missing semicolons.
    
        
    whitespace
    Spaces, tabs and line breaks. Ignored between tokens, kept inside strings.
    
        
    indentation
    Spaces at the start of a line, used only for readability in JavaScript.
    
        
    case-sensitive
    Capital and small letters count as different: Console is not console.
    
        
    comment
    A note for humans that the engine skips: // … or /* … */.
    
        
    commenting out
    Turning code into a comment so it doesn't run.
    
        
    reserved word (keyword)
    A word with a fixed job in the language, like if or return.
    
        
    strict mode
    The stricter set of rules that turns old traps into errors. Modules and classes always use it.
    
        
    module
    A modern JavaScript file. In this book's folders, every .js file is one.
    
        
    SyntaxError
    A grammar slip found before the program runs. No line of the file runs.
    
        
    TypeError
    An error meaning "this kind of value can't do that", like running something that isn't a function.
    
        
    token
    One "word" of code: a name, a literal, an operator or a punctuation mark.
    
        
    parse
    To fit the tokens to the grammar and build a tree of the program.
    
        
    value
    A piece of data: a number, a string, true, null, an object…
    
        
    type
    What kind of value something is.
    
        
    primitive
    One of the seven simple types: number, string, boolean, undefined, null, bigint, symbol.
    
        
    object
    The one non-primitive type: a box that can hold many values. Arrays and functions are objects.
    
        
    literal
    A value written directly in the code, like 42, "hi" or true.
    
        
    number
    JavaScript's type for all ordinary numbers, whole or decimal.
    
        
    string
    Text, written in quotes or backticks.
    
        
    boolean
    The type with exactly two values, true and false.
    
        
    undefined
    The value meaning "never set".
    
        
    null
    The value meaning "empty on purpose".
    
        
    bigint
    A type for whole numbers of any size, written with an n: 10n.
    
        
    symbol
    A type for one-of-a-kind labels.
    
        
    NaN
    "Not a Number": a value of the number type that means a calculation made no sense.
    
        
    typeof
    An operator that gives a value's type name as a string.
    
        
    array
    A list of values in square brackets. Its type is object; check for one with Array.isArray.
    
        
    function
    A reusable mini-recipe you run with brackets. typeof says function.
