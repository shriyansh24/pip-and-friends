    PART 2 · GLUED TAGS AND GOOD NAMESconst, and the rules every name must follow
    

  
    
    10
    
    JavaScript has two keywords for making tags. The difference is how the string is attached.
    
    
    
      
    
        
    LETa tag on a clip
    
        
    
        
    Unclip it, clip it to another value. Use let for anything that changes: a score, the seats left, a countdown.
    
      
    
      
    
        
    CONSTa tag glued on for good
    
        
    
        
    Once tied, it can never be moved to another value. Use const for anything that stays: the theatre's name, the number of rows.

        Kit says: 0.1 + 0.2 is 0.30000000000000004, and it's not exactly 0.3? But 0.5 + 0.25 is exactly 0.75? Why do some decimals behave and others don't?
        
    
        
  
        

  
        
    37
    
        Picture the computer's numbers as a ruler. It doesn't have a mark for every decimal. Its marks are only at halves, quarters, eighths, sixteenths… (fractions made by halving again and again, called binary fractions).
        
    
        ZOOM 1 · the ruler from 0 to 1
        
    
    
        ZOOM 2 · from 1/16 (0.0625) to 1/8 (0.125), with finer marks
        
    
    
        ZOOM 3 · all the way in: the real marks next to 0.1
        
    
    
          
      
        • A 0.09999999999999999167
          • 
      
        • B 0.10000000000000000555: this is the "0.1" JavaScript really stores
          • 
      
        • C 0.10000000000000001943
          • 
    
        
    
    neighbours.js
    
        
    
        
    
        
      
        The Professor says: toFixed(20) shows 20 decimal places of the value really stored. gap is the distance between neighbouring marks near 0.1. The marks are so close that normally nobody notices, until a sum lands between two of them.
        
      
    
        
  
        

  
        
    38
    
        So here is the whole story of 0.1 + 0.2, with 20 decimal places of each value.
        
    ruler.js
    
        
    
        
    
          
      
        1. 0.5 and 0.75 sit exactly on marks (a half; a half plus a quarter), so their sum is exact.
          2. 
      
        2. 0.1 is stored a hair above 0.1, and 0.2 a hair above 0.2. Their sum lands on a mark just above 0.3…
          3. 
      
        3. …but the mark JavaScript uses for "0.3" is a hair below 0.3. Two different marks, so 0.1 + 0.2 === 0.3 is false. And console.log shows the shortest decimal that names the sum's mark: 0.30000000000000004.
          4. 
    
        
    
        
      
      
        Kit says: It's not a bug in JavaScript. It's the ruler. Decimals are nearly right, almost always. Never test two decimals for exact equality.
        
    
        
  
        

  
        
    39

    cents.js

    40

    Under the hood: tags, values and the 64-bit ruler
    
        
      
        Why tags and not boxes
        
      
        The ECMAScript rules describe a variable as a binding: a name connected to a value inside a record of names (an "environment record"). Numbers, strings and booleans are primitive values: they can never change. seats - 4 doesn't edit 120; it produces a different number, 116, and the assignment re-binds the name. Engines are free to store small numbers right next to the name for speed (V8 calls these "Smis", small integers), but the behaviour you can observe is exactly the tag picture. The picture matters most later, with objects: two tags on one object (Chapters 9 and 10) behave very differently from two boxes.
        
      
        let, const and "uninitialized"
        
      
        A let or const name exists from the start of its block, but it can't be used until its line has run. Using it too early gives a ReferenceError. That waiting period has a name, the temporal dead zone, and Chapter 8 explores it along with blocks, scope and the older keyword var.
        
      tdz.js
      
        
      
        
      
        The ruler is 64 bits
        
      
        Every JavaScript number is stored in the same format: a 64-bit IEEE 754 double. It keeps 53 binary digits of precision plus an exponent that slides the "decimal point" (really a binary point) left or right. That's why the marks near 0.1 are about 0.000000000000000014 apart, the marks near 1 are about 0.0000000000000002 apart, and past 253 they are 2 apart. The gap between marks grows with the size of the number. Chapter 23 draws the 64 bits.
        
      
        The same stored value explains (1.005).toFixed(2):
        
      
        
      
        What % really computes
        
      
        JavaScript's % divides, chops the quotient toward zero, and returns what's left: a % b is a - b * Math.trunc(a / b) (for normal finite numbers). Chopping toward zero is why the answer keeps the sign of a. Some languages use the floor instead, and give 2 for -7 % 3. If you need a remainder that's never negative, for example for clock arithmetic, use ((a % b) + b) % b. Lines 3 and 4 of halves.js, below, check both formulas for -7 % 3.
        
      
        Math.round and halves
        
      
        Math.round rounds a .5 toward plus infinity: 2.5 → 3, but -2.5 → -2. Many people expect "away from zero" (-3). toFixed works differently again: it rounds the exact stored value to the nearest, so a value sitting exactly on .5 rounds away from zero there. Lines 1 and 2 of halves.js show both, side by side:

    In real programs
    
        
      
          
        
        • const by default. Most modern style guides recommend it, and linters (tools that check code style) can enforce it: ESLint's prefer-const rule flags any let that is never reassigned.
          • 
        
        • Money. Shops and banks count in whole cents (or use special decimal libraries), and format with two places only for display. Chapter 23 shows Intl.NumberFormat, which adds currency signs and thousands separators for any country.
          • 
        
        • Pagination ("page 3 of 7") uses Math.ceil(items / perPage). Grids use Math.floor(i / columns) for the row and i % columns for the column.
          • 
        
        • Comparing decimals. Instead of a === b, check whether they're close enough: Math.abs(a - b) < 1e-9, with a tolerance that suits the job. Chapter 5 covers comparisons.
          • 
        
        • Random numbers. Math.random() is fine for games and dice, but not for passwords or security codes; for those, use crypto.getRandomValues(), which every host provides.
          • 
        
        • The one-line swap. Real code often swaps with destructuring, a trick from Chapter 11 that uses square brackets on both sides:

    Common wrong ideas
    
        
      
          
        
        • "= means equals." It means "tie the tag on the left to the value on the right". Asking "are these equal?" is === (Chapter 5).
          • 
        
        • "const means the value can never change." It means the tag can't move. A const tag on an object can still see the object change inside (panel 14).
          • 
        
        • "let is needed every time I change a variable." Only the first time. A second let for the same name is a SyntaxError.
          • 
        
        • "If I forget let, JavaScript makes the variable for me." Only in old non-module ("sloppy") code, where it silently creates a global variable, a classic source of bugs. In a module it's a ReferenceError. Compare:
          • 
      
        
      
        
        
        MODULEundeclared.js
        
        
        SLOPPYundeclared_sloppy.cjs
        
      
        
      
          
        
        • "7 / 2 is 3, like in some languages." It's 3.5. Use Math.floor or Math.trunc for a whole number.
          • 
        
        • "% means percent." It's the remainder. 50% of x is x * 0.5.
          • 
        
        • "% is always positive." It takes the sign of the left side: -7 % 3 is -1.
          • 
        
        • "Math.floor and Math.trunc are the same." Only for positive numbers.
          • 
        
        • "Dividing by zero crashes." In JavaScript it gives Infinity, -Infinity or NaN, silently. A NaN can travel a long way through a program before anyone notices.
          • 
        
        • "toFixed rounds a number." It formats one, returning a string.
          • 
        
        • "++ works on any number." Only on a tag. 5++ has no tag to move:
          •

    Words from this chapter
    
        
      
        
        
        variable
        A name that refers to a value. In this book: a name tag on a string.
        
        
        value
        A piece of data, like 120, "crown" or true.
        
        
        keyword
        A word with a fixed meaning in the language, like let, const or if.
        
        
        let
        Makes a tag that can be moved to another value later.
        
        
        const
        Makes a tag glued to one value for good. Must be given its value on the same line.
        
        
        declaration
        Making a new tag: let lives;
        
        
        assignment
        Tying a tag to a value with =: lives = 3;
        
        
        reassignment
        Moving an existing tag to a different value.
        
        
        initialization / initializer
        Declaring and assigning in one line; the = value part is the initializer.
        
        
        undefined
        The value of a tag that was declared but never tied: "never set".
        
        
        identifier
        The official word for a name you invent.
        
        
        reserved word
        A word the language keeps for itself, which can't be a name: class, new, let…
        
        
        camelCase
        Writing multi-word names with each new word capitalised: seatsPerRow.
        
        
        dynamic typing
        A tag can be tied to any kind of value, and the kind can change as the program runs.
        
        
        compound assignment
        Shortcuts like +=, -=, *=, /=: change the current value and move the tag.
        
        
        operator
        A symbol that takes values and produces a new one: + - * / % **.
        
        
        remainder (%)
        What's left over after dividing as many whole times as possible. Takes the sign of the left side.
        
        
        exponentiation (**)
        Raising to a power: 2 ** 3 is 2 × 2 × 2.
        
        
        precedence
        Which operator goes first when several share a line.
        
        
        unary minus
        A minus in front of a single value: -5.
        
        
        increment / decrement
        ++ adds 1 to a tag, -- takes 1 away.
        
        
        prefix / postfix
        ++a adds then gives the new value; a++ gives the old value then adds.
        
        
        Infinity
        A special number, bigger than any other; what dividing a non-zero number by 0 gives.
        
        
        NaN
        "Not a Number": a special number value meaning "no sensible answer", like 0 / 0.
        
        
        floating point
        The way computers store decimals: only values on the "ruler's marks" (binary fractions) are exact.
        
        
        binary fraction
        A fraction made by halving: 1/2, 1/4, 3/8, 5/16…
        
        
        Number.MAX_SAFE_INTEGER
        9007199254740991: the biggest whole number below which every whole number can be stored exactly.
        
        
        Math
        The built-in toolbox of number tools: round, floor, ceil, trunc, max, min, abs, random…
        
        
        toFixed
        Formats a number with a fixed number of decimal places, returning a string.
        
        
        TypeError
        An error meaning "this kind of thing can't do that", such as moving a const tag.
        
        
        RangeError
        An error meaning "a number outside the allowed range", such as toFixed(101).
        
        
        logic bug
        A mistake that gives a wrong answer with no error message, like the bad swap.
