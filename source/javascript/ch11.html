CHAPTER 11

SUITCASES AND SPEAKERS

Picture: Kit, the stage manager in a pink hoodie and headset, points at a suitcase with three numbered pockets, 0, 1 and 2, labelled [ a, b, c ], and at a microphone with a speech bubble saying "ME!".

A touring company has arrived with its suitcases, and today you learn to unpack them in one line, straight into labelled drawers. Then you meet three little dots that spread things out or scoop them up, a polite knock for doors where nobody might be home, and the trickiest word in JavaScript: this, the word "me", which changes with whoever is speaking. About 110 minutes, with 25 hands-on checks.

  1. Unpack by position
  2. Unpack by name
  3. Three dots: spread and rest
  4. The polite knock: ?. and ??
  5. Speakers: this
  6. Losing the speaker
  7. Boss level and recap

    PART 3 · THREE DOTSSpread things out, or scoop the rest up
    

  
    
    14
    
    Three dots, ..., do two opposite jobs. Which job depends on where they stand.
    
    
    
      
      
    
    
    
    
      
    SPREADwhere values are USED
    Inside [ ], { } or a call's ( ) on the right side: "tip this suitcase out here, item by item".
    
      
    RESTwhere names are MADE
    In a pattern or a parameter list: "everything left over goes into this one new array (or object)".
    
    
    
    
    THREE DOTS: SPREAD IT OUT, OR SCOOP IT UP.
    
  
    

  
    
    15
    
    Spread in action: joining lists, splitting a string into letters, and handing a list to a function that wants separate values.
    
    spread_arrays.js
    
    
    
    
    
      
      
    1. Line 3: [...act1, ...act2, "Kit"] builds a new array: act1's items, then act2's, then "Kit". Neither old array changes.
      2. 
      
    2. Line 5: a string is iterable too, so spreading it gives one item per character.
      3. 
      
    3. Line 7: Math.max wants separate numbers: Math.max(7, 9, 4). ...scores in the call's brackets tips the array out into exactly that.
      4. 
      
    4. Line 8: without the dots, Math.max gets one argument, an array, which isn't a number: NaN. No error, just a wrong answer. Forgetting the dots is a classic.
      5. 
    
    
  
    

  
    
    16

    spread_objects.js

      2.

      3. 
      
    3. This is the everyday way to say "the usual settings, but with these changes": defaults first, choices last.

    or_vs_nullish.js

    30
    
      Three shortcuts that combine a check with an =. Each one changes a drawer only in one situation.
      
    assign_ops.js
    
      
    
      
    
      
      
      ??=fill if nullish
      a ??= b is a ?? (a = b). The poster was null, so it's filled. Seats were 0, so they stay 0 (line 3).
      
      
      ||=fill if falsy
      a ||= b is a || (a = b). The title is kept, but the seats, 0, count as falsy and become 100 (line 6).
      
      
      &&=change if truthy
      a &&= b is a && (a = b). Only a value that's already there gets replaced: the sponsor becomes "ACME", and the poster is cleared (line 9).

    Under the hood: patterns, iterators, short-circuits and the call site
    
        
      
        A pattern is a list of reads
        
      
        const { name: n, role = "crew" } = actor; behaves like reading actor.name into n, then reading actor.role and using "crew" if the result is undefined. Defaults are checked with === undefined, not with falsiness, which is why a drawer holding null, 0 or false keeps its value. A default expression is only evaluated when it's needed, so { id = makeId() } = obj calls makeId only for objects without an id.
        
      
        Square brackets walk an iterator
        
      
        An array pattern doesn't index the value with [0], [1]. It asks the value for an iterator (a pocket-by-pocket walker, found under the special key Symbol.iterator) and takes items one at a time. That's why strings, Maps and Sets can be unpacked with brackets, why plain objects can't, and why the error says "iterable" and not "array" (Panel 13's lineup is not iterable). Chapter 20 builds iterators by hand.
        
      
        Rest and spread copy into new containers
        
      
        A rest element always makes a new array (or, for braces, a new plain object with the leftover own enumerable keys). Spread in a literal copies the source's own enumerable properties one by one, the same way as Object.assign({}, a, b), so later keys overwrite earlier ones, and nested objects are shared (shallow). Spreading null or undefined into an object literal is allowed and adds nothing; spreading them into an array or call is a TypeError, because they're not iterable.
        
      
        Optional chaining short-circuits the whole chain
        
      
        When a ?. finds null or undefined, the entire rest of that chain is skipped, including calls and index expressions with side effects: in user?.address.city, if user is nullish, .address.city is never evaluated. Wrapping part of the chain in brackets ends the chain: (user?.address).city crashes when user is null, while user?.address.city just gives undefined. A name that doesn't exist at all is still a ReferenceError: ?. protects against nullish values, not undeclared names.
        
      
        this belongs to the call, not the function
        
      
        When the engine evaluates obj.m(), the part before the brackets is a "reference" that remembers both the function and the object it was read from, and the call uses that object as this. const f = obj.m stores only the function, so f() has no object to pass. In strict code (every module and every class) a missing this stays undefined. In old sloppy-mode scripts it is replaced by the global object, which is why old tutorials show window.name appearing instead of a crash. Arrow functions have no this binding at all: the name this inside them is looked up outward through the rooms, exactly like a variable (Chapter 8).
        
      
        The top-level this
        
      
        An ES module's top-level code runs with this set to undefined. Node runs a CommonJS file inside a wrapper function and calls it with this set to module.exports, which starts as an empty object: the {} in Panel 41. Node's setTimeout calls your callback with this set to the Timeout object it returned; the HTML standard says a browser timer uses the window.
        
    
        
  
        

  
        
    In real programs
    
        
      
          
        
        • Options objects. Functions with many settings take one object and destructure it with defaults: function connect({ host = "localhost", port = 8080, retries = 3 } = {}). Callers name only what they change, in any order. You'll see this shape in almost every library's API.
          • 
        
        • Component props. UI libraries such as React pass each component a "props" object, and code usually unpacks it in the parameter list: function Button({ label, onClick }).
          • 
        
        • Returning several values. A function returns an array or object, and the caller unpacks it: const [value, setValue] = … or const { data, error } = ….
          • 
        
        • Immutable updates. Code that must not change the original builds a new one with spread: const next = { ...state, count: state.count + 1 }; or [...items, newItem]. Remember it's shallow: nested parts must be spread too, or copied with structuredClone.
          • 
        
        • Data from outside. Answers from web services often have optional parts, so response?.data?.items ?? [] is common. Validate the shape once at the edge of your program, and keep plain dots inside it, so typos still crash.
          • 
        
        • Caching. cache[key] ??= expensiveCompute(key); computes a value only the first time it's asked for.
          • 
        
        • Linters. ESLint has rules such as prefer-destructuring, prefer-spread, prefer-rest-params and prefer-object-spread. With TypeScript, the typescript-eslint rule no-unnecessary-condition reports ?. on values that can never be nullish, exactly the overuse of Panel 27.
          • 
        
        • this in the wild. Classes (Chapter 18) are built on methods and this, and passing obj.method as a callback is one of the most common bugs in event-handling code (Chapter 15). The usual fixes are an arrow wrapper or bind.
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "Destructuring changes or empties the array." It only reads. The trunk still holds everything afterwards.
          • 
        
        • "Too many names in a pattern is an error." Extra names get undefined (or their default).
          • 
        
        • "A default replaces any falsy value." Only undefined. { vip = false } keeps a real false, and also keeps null.
          • 
        
        • "In { name: n }, name is the new variable." The right side of the colon is the new name; the left is the drawer label.
          • 
        
        • "Spread makes a full copy." A shallow one: nested objects and arrays are shared.
          • 
        
        • "Rest and spread are the same thing." Same dots, opposite jobs: spread takes apart, rest gathers.
          • 
        
        • "?. makes code safer, so use it everywhere." It makes mistakes quieter. Use it where missing is normal.
          • 
        
        • "a?.b.c protects .c too." Only if a is nullish. If a.b is missing, .c still crashes.
          • 
        
        • "this is the object the function was written in." It's the object before the dot when the function is called.
          • 
        
        • "this inside a callback is the surrounding object." Only for arrow callbacks. A regular function callback gets whatever its caller gives it.
          • 
        
        • "Arrow functions are just shorter functions." They also have no own this (and no arguments), which makes them wrong for methods.
          • 
        
        • "A plain call gets the global object as this." Only in old sloppy-mode scripts. In modules, it's undefined.

    Words from this chapter
    
        
      
        
        
        destructuring
        Unpacking an array or object into separate names in one statement.
        
        
        pattern
        The shape on the left of the = (or in a parameter list) that says where each value goes: [a, b] or { name, role }.
        
        
        array destructuring
        Unpacking by position, with square brackets.
        
        
        object destructuring
        Unpacking by key, with curly braces.
        
        
        default value
        The value used in a pattern or parameter when the real value is undefined.
        
        
        renaming
        { key: newName }: unpacking a drawer into a variable with a different name.
        
        
        nested destructuring
        A pattern inside a pattern, to reach into inner objects or arrays.
        
        
        destructuring parameter
        A parameter written as a pattern, so the argument is unpacked as it arrives.
        
        
        iterable
        A value that can be walked through item by item: arrays, strings, Maps, Sets. Required by array patterns and array spread.
        
        
        spread syntax
        ...value where values are used: tips an array, string or object out into separate items, arguments or properties.
        
        
        rest element
        ...name at the end of a pattern: collects the leftover items or properties into a new array or object.
        
        
        rest parameter
        ...name at the end of a parameter list: collects all remaining arguments into a real array.
        
        
        arguments
        An old array-like object holding a regular function's arguments; replaced by rest parameters.
        
        
        shallow copy
        A copy of the outer container whose inner objects are shared with the original.
        
        
        optional chaining
        ?.: read, call or index only if the value before it is not null/undefined; otherwise give undefined and skip the rest of the chain.
        
        
        short-circuit
        Stopping an expression early because the answer is already known.
        
        
        nullish
        null or undefined.
        
        
        nullish coalescing
        a ?? b: a, unless it's nullish, then b.
        
        
        logical assignment
        ??=, ||=, &&=: assign only when the check says so.
        
        
        method
        A function stored as a property of an object.
        
        
        method shorthand
        name() { … } inside an object literal, short for name: function () { … }.
        
        
        this
        Inside a regular function: the object the function was called on (the one before the dot), decided at call time.
        
        
        call site
        The place in the code where a function is called; it decides this.
        
        
        detached method
        A method copied out of its object into a variable or passed as a callback, so it is called without its object.
        
        
        bind
        f.bind(obj) makes a new function whose this is always obj (Chapter 17).
        
        
        ES module / CommonJS
        Node's two module systems. In our folder, .js is an ES module (strict, top-level this is undefined); .cjs is CommonJS (top-level this is module.exports, an empty object at first).
