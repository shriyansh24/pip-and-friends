**How deep the best treatments go.** learncpp is in a different league from everything else: 307 lessons. It spends 3 lessons on `std::string` and `std::string_view` and 2 more on C strings, 15 on references and pointers, 3 on array decay and pointer arithmetic, 5 on manual allocation and 7 on move semantics and smart pointers. That is about 30 lessons on memory and indirection. It also spends 10 lessons on debugging and 12 on std::vector alone. Most other beginner sources give one page to each of these (W3Schools, Codecademy and freeCodeCamp give 1–2 units to pointers, and hackingcpp about 8 lessons spread out). Almost all of them skip four things:

- **Sanitizers.** Only hackingcpp has lessons on them. learncpp's UB lesson lists the symptoms of UB but names no tool.
- **Build systems and package managers.** Only roadmap.sh names them, and only CS106L has a "building projects" lecture.
- **std::print.** No source checked teaches it first. learncpp is still on C++17, and PPP3 and Tour3 use iostream with formatting.
- **Text encoding.** "A char is a byte, not a letter" is not taught anywhere for beginners.

**What that means for us.** Our "real runs only" rule turns UB into a teaching hazard: an out-of-range `v[3]` printed `0`, and an uninitialised `int` printed 32766 or 32764 on repeated runs of the same g++ binary, 0 under `-O2` and 32767 under clang. So the course must show the sanitizer view next to the "plausible garbage" view. It should also teach a short module on build tooling, which the other curricula leave out.

**Core Guidelines rules a beginner course should embody** (picked from the rule list; each one maps to a module below):

- **Variables and types:** ES.20 always initialize; ES.23 prefer `{}`; ES.25/Con.1 const by default; ES.45 no magic constants; ES.46 avoid narrowing; ES.47 nullptr; ES.48/ES.49 avoid casts, or use named casts.
- **Arithmetic and loops:** ES.71 prefer range-for; ES.78 no implicit fallthrough; ES.76 avoid goto; ES.100/ES.102/ES.106 signed arithmetic, don't mix signed and unsigned; ES.103/ES.105 don't overflow, don't divide by zero.
- **Strings, containers and I/O:** SL.con.1/SL.con.2 prefer vector or array to C arrays; SL.str.1/SL.str.2 string and string_view; SL.io.2 expect bad input; SL.io.50 avoid endl.
- **Functions and enums:** F.16 pass in-parameters cheaply; F.20/F.21 return values (or a struct) rather than out-parameters; F.43 never return a reference to a local; Enum.3 enum class.
- **Resources and classes:** R.1 RAII; R.11 avoid explicit new/delete; R.20/R.21/R.23 unique_ptr and make_unique; C.20/C.21 rule of zero/five; C.46 explicit single-argument constructors; C.49 initialise rather than assign; I.2 no non-const globals; P.8 don't leak.
- **Errors, files and performance:** E.2/E.15 throw to signal failure, catch by reference; SF.7/SF.8 header hygiene and guards; Per.6 measure before claiming speed.

**Where curricula disagree, and the choices made:**

- **Functions: early or late?** learncpp introduces functions in chapter 2, before any control flow, and PPP3 puts `vector` (3.6) beside functions (3.5). Codecademy, W3Schools and freeCodeCamp put functions after loops and arrays. We place functions (B13) after if/loops so example functions can do something real, but before vector, so that passing a vector by `const&` (B15–B16) has a reason.
- **std::vector and std::string first, or C arrays first?** Modern-first: learncpp (std::string 5.7, vector 16, C arrays 17.7), hackingcpp (vector lesson 5, C arrays lesson 70), PPP3 (vector ch. 3, arrays ch. 16), Codecademy (vectors only), CS106B and CS106L, MS Learn ("Don't use C-style arrays"), Core Guidelines SL.con.1. Arrays-first: W3Schools (arrays module 16, vectors module 29), freeCodeCamp (arrays ch. 7 before strings ch. 10), MIT 6.096 (lecture 4). **Choice:** vector and string in the beginner track; C arrays only in I14 as "how to read old code and C APIs".
- **References before pointers?** learncpp (12.3 before 12.7), W3Schools and CS106L teach references first. freeCodeCamp teaches pointers first. Exercism makes pointers depend on references. **Choice:** references first (B15). They give pass-by-reference without null or arithmetic, and pointers (B24) then arrive as "a reference you can reseat or leave empty".
- **Smart pointers or new/delete?** new/delete first: learncpp (19.1, then 22.5), PPP3 (free store ch. 15, then resource-management pointers 18.5), EECS 280, W3Schools (new/delete, no smart pointers listed), MIT 6.096. Smart pointers first or only: CS106L, MS Learn, Core Guidelines R.11/R.20, hackingcpp (unique ownership lesson 57 before manual memory 71), Exercism (smart-pointers right after pointers). **Choice:** unique_ptr in B25. Raw new/delete appears once there, under AddressSanitizer, to show the leak report and double-free abort it produces. It is fully treated only in I14.
- **iostream or std::print?** Every curriculum checked starts with `std::cout` (learncpp 1.5, PPP3 ch. 1–2, hackingcpp lesson 3, W3Schools, Codecademy). Tour3 adds formatting in 11.6. No source checked starts with std::print. On our toolchain `<print>` does not exist (g++ 13: `fatal error: print: No such file or directory`), while `<format>` works on both compilers. **Choice:** `std::cout << ... << '\n'` from B3, `std::format` from B9/B12 for neat output, and std::print as a flagged "C++23, needs GCC 14+" sidebar that cannot be run here.
- **Classes: early or late?** Exercism requires classes before references and functions. PPP3 has classes in ch. 8, learncpp in ch. 14. **Choice:** structs in B17 (plain data), classes in B23 after multi-file programs, because real classes use a header/source split.
- **Debugging and errors: early or late?** Early in learncpp (ch. 3) and PPP3 (ch. 4 "Errors!"); late in W3Schools (module 28). **Choice:** early. B4 covers reading errors and B20 covers the debugger, before any memory topic.
- **How curricula handle UB and sanitizers:**
  - learncpp defines UB in 1.6 with a list of symptoms, and later covers common semantic errors (9.3) and assert (9.6), but no sanitizer.
  - PPP3 avoids UB through checked containers in its support module and an early errors chapter.
  - EECS 280 contrasts "error handling vs undefined behavior".
  - roadmap.sh lists UB as a node.
  - hackingcpp is the only one with hands-on ASan and UBSan lessons.

  **Choice:** a dedicated B22 straight after debugging, plus a standing "safety-net build" (`-fsanitize=address,undefined -D_GLIBCXX_ASSERTIONS`) used in every later module that touches memory.

## 6. Facts for a "real runs only" course

**Current standard (verified 2026-11-07).**
- isocpp.org: "The current ISO C++ standard is C++23, formally known as ISO International Standard ISO/IEC 14882:2024(E)".
- C++26 is **not published**. WG21 finished technical work at the London (Croydon) meeting, which Wikipedia says shipped on 28 March 2026. The ISO DIS ballot then closed on 23 October 2026 as **"Disapproved"**, with Contracts as the main objection. Sources: Andreas Fertig's blog, plus Zeli/Hacker News coverage. A WG21 paper (P4238R0, 2026-07-30) had urged national bodies to vote No.
- The next WG21 meeting (16 Nov 2026 per Fertig; open-std.org lists a post-Búzios mailing deadline of 2026-12-15) must choose a path. Options include a revised DIS, back to CD, a TS or cancellation, and every option delays C++26.
- The latest working draft is N5046 (2026-05-12) per cppreference. iso.org could not be fetched (client error).
- isocpp.org's status page still says "C++26 work in progress".
- **Consequence:** write "C++23 is the current standard; C++26 is finished by the committee but not yet approved by ISO". Re-check before publishing.

**Latest compilers.**
- GCC 16.1 (2026-04-30) and 16.2 (2026-08-07). gcc.gnu.org says "C++20 mode is the default since GCC 16"; GCC 11–15 default to C++17.
- LLVM/Clang 23.1 was released 2026-08-25, with partial C++26 via `-std=c++2c`. Clang 16+ defaults to C++17.

**This machine's toolchain** (what captures will actually use):
- Compilers: g++ 13.3.0 and clang 18.1.3. Both default to C++17 (`__cplusplus` = 201703), so always pass `-std=`.
- `-std=c++23`:

- `-std=c++2c` / `-std=c++26`:

**Recommended baseline.**
- Teach C++20: `g++ -std=c++20 -Wall -Wextra -Wpedantic -g file.cpp -o file && ./file`.
- Safety-net build: add `-fsanitize=address,undefined -D_GLIBCXX_ASSERTIONS`.
- Flag C++23 items (print, expected, ranges::to) in a sidebar that states the minimum compiler. Only `std::expected` can be captured here, and only with g++.

**Things that make captured output nondeterministic or non-portable:**
- **Uninitialised reads and other UB.** Values changed between identical runs of one binary (g++: 32766, 32766, 32764; clang: 32767, 32764) and with optimisation level (0 at -O2). Never use UB output as an answer: show it as "varies" and pair it with the sanitizer report.
- **Addresses.** `&x` printed a different value each run because of ASLR. ASan reports also embed PIDs (`==14658==`), addresses and absolute paths.
- **Hash container order.** `unordered_map`/`unordered_set` order was stable across runs and across g++ and clang here (same libstdc++). It is unspecified, though, and differs on libc++ and MSVC. Sort before printing if the page is meant to be portable.
- **Random numbers.** The `std::mt19937` engine sequence is fully specified (seed 42 gave 1608637542 first). `uniform_int_distribution` results are implementation-specific (here `5 6 2 5 5`). `std::random_device` and time-based seeds are nondeterministic.
- **Threads.** The racy counter gave 400000 or 285017 on different runs. Any timing (`<chrono>`) output differs every run.
- **Buffered output and crashes.** Text written to `std::cout` without a flush was lost when the program crashed. Prefer `std::cerr` for diagnostic prints, and capture stdout and stderr separately (their interleaving is not reproducible when piped).
- **Link errors** contain random temporary object names (`/tmp/ccRBKfkH.o`, `/tmp/e5-6fc27f.o`). Normalise them or compile to named `.o` files first.
- **Locale.** In a UTF-8 locale g++ prints curly quotes (`‘x’`); in the C locale it prints straight quotes (`'x'`). Pin `LC_ALL` in the capture tool, and add `-fdiagnostics-color=never`.
- **Paths.** Diagnostics echo the path exactly as given on the command line. Compile with relative paths from the program folder.
- **Platform types.** `sizeof(long)` is 8 on Linux and 4 on Windows, and plain `char` signedness varies by platform. Present sizes as "on this machine".

**How errors look.**
- **g++ compile errors:**
  - An optional `file.cpp: In function 'int main()':` header comes first.
  - Then `file.cpp:LINE:COL: error: message`, then the source line in a numbered margin (`    4 |`), then a caret line and sometimes a fix-it line (e.g. `;` or `std::cout`).
  - `note:` lines follow, often pointing into `/usr/include/c++/13/...`.
  - Warnings end with the flag in brackets, e.g. `[-Wsign-compare]`.
- **clang compile errors:** the same core layout, with system headers shown as `/usr/bin/../lib/gcc/x86_64-linux-gnu/13/../../../../include/c++/13/...`, and a trailing `N error(s) generated.` / `N warning(s) generated.`.
- **Link errors** come from `ld`: `undefined reference to 'f(int)'` or `multiple definition of 'helper()'`, followed by `collect2: error: ld returned 1 exit status` (g++) or `clang++: error: linker command failed with exit code 1 (use -v to see invocation)`.
- **Runtime failures:**
  - Uncaught exceptions print `terminate called after throwing an instance of 'std::out_of_range'` and then `  what():  ...`.
  - `assert` prints `prog: file.cpp:3: int main(): Assertion 'expr' failed.` (the real output opens the expression with a backtick).
  - glibc detects double frees: `free(): double free detected in tcache 2`.
  - The words `Aborted`, `Segmentation fault` and `Floating point exception` are printed by the shell, not by the program. The exit codes are 134 (SIGABRT), 139 (SIGSEGV) and 136 (SIGFPE), i.e. 128 plus the signal number. The capture tool should record the exit code rather than shell text.

**Version-specific facts a beginner page must flag:**
- C++20 features: `.contains()` on maps and sets (`-std=c++17` gives `has no member named 'contains'`), designated initialisers, `std::format`, `std::erase`/`std::erase_if`, ranges and views, concepts, `<=>`, `std::span`, `std::jthread`, `std::ssize`, `consteval`.
- C++23 features: `std::print`, `std::expected`, `std::ranges::to`, `import std`, deducing `this`.
- learncpp says it "currently targets the C++17 standard". Exercism requires only C++14. PPP3 assumes C++20/23 with modules and ships `PPPheaders.h` as a fallback. A learner arriving from those sources will see older idioms.
- libstdc++ quirks:
  - `#include <string>` was not needed when `<iostream>` was included. Tell learners to include what they use anyway, because the code would not be portable.
  - g++ needs `-Wconversion` to flag `int x = 3.7;`, while clang flags it by default.
  - Neither compiler warned about `x == 1` or-ed with `2`.
  - g++ 13 `-Wall` did not warn about a `string_view` bound to a temporary `std::string`.
- Narrowing in brace initialisation is a hard error in g++ (`-Wnarrowing` reported as `error:`), not just a warning.
