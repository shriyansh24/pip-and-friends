Research as of 2026-11-07. Current stable Python is **3.15.2** (released 2026-10-25; 3.15.0 came out 2026-10-09). The course's capture tool currently runs **CPython 3.15.0b4** as the primary interpreter and **3.13.18** as the secondary one (from `tools/capture.py`). Every error message quoted below came from a real run of a two-line script on both of those interpreters in this sandbox. Where the two versions print different text, both are given.

**How deep the best treatments go.** Strings are the clearest example. Exercism gives them 4 concepts. Helsinki spreads them over 3 sections in parts 3–4 (operations and slicing, then formatting, then methods). ATBS gives them a full chapter (8), but only after lists and dictionaries. boot.dev's 168-lesson Learn Python has no chapter named for strings at all. References and mutability are the bigger gap. Only MIT (two lectures, L10–L11), Helsinki (one section, 5.2) and Fluent Python (chapter 6) teach "variables are names bound to objects" as its own topic. Most beginner books only show `b = a` changing a list as a surprise.

**What almost every course skips:**
- A drawn model of names versus objects.
- Why `0.1 + 0.2` is not `0.3`. Only the Tutorial's appendix and MIT L5 cover it.
- Reading a traceback as a skill. Only ATBS 5, CS50P's "Bugs", Real Python's bug-fixing course and Helsinki's debugger section teach it.
- Virtual environments.
- Text versus bytes.
- The iterator protocol behind `for`.

**What this means for us.** A 10-chapter beginner course will be shallow by default. A deeper version needs dedicated modules on references, reading errors, debugging and testing, and these should come early rather than in an appendix.

**Where curricula disagree, and the choice made here:**
- **Defining functions before or after loops.** CS50P defines functions in week 0. boot.dev puts Functions (ch 3) before Comparisons (7) and Loops (8). Think Python puts functions (3–4) before conditionals (5). Helsinki (3.4), ATBS (4), PCC (8) and py4e define functions after control flow. I chose *calling* built-ins from B3 and *defining* functions after loops (B15). A comic reader with no background needs something worth wrapping before `def` makes sense. Write the first function as a 3-line "recipe card" so the early-`def` approach can be adopted later without reordering.
- **Lists before conditionals.** PCC introduces lists in chapters 3–4, before `if` (5). Helsinki, ATBS and the Tutorial do conditionals first. I chose conditionals first, because looping over a list is what makes lists useful.
- **Exceptions early or late.** MIT teaches exceptions (L13) before dictionaries (L14). CS50P teaches them in week 3, before libraries and files. ATBS and PCC tie them to files. I put full exceptions at B25, but B9 shows the `ValueError` from `int("abc")` and B17 reads tracebacks, so error *reading* comes very early while error *handling* comes after functions.
- **Tuples before dictionaries.** The Tutorial and Exercism (`tuples` is a prerequisite of `dicts`) put tuples first. py4e and PCC do dictionaries first, and PCC has no tuple chapter. I chose tuples first, because `.items()` yields tuples.
- **Testing timing.** boot.dev teaches it at chapter 5 of 15, CS50P in week 5, PCC in chapter 11, and many courses never. I chose an `assert` taste in B15/B16 and a full module at B29, after packages so pytest can be installed for real.
- **Classes.** Helsinki defers OOP to the Advanced course (part 8). CS50P (week 8), PCC (9) and MIT (L17) treat it as beginner material. I chose a single "first look" (B31) at the end of the beginner track and the real depth in I9–I12.
- **Recursion.** Think Python puts it at chapter 5 and MIT at L15–16. Helsinki puts it in the advanced course (11.3). I chose intermediate (I8), after the debugger, because tracing the call stack needs the frames picture from B17.
- **Type hints.** boot.dev (ch 13) and CS50P (week 9) treat them as beginner material. I chose intermediate (I13). Hints add syntax without changing what runs, which is confusing in a "real runs only" book until the reader can run mypy.

**Toolchain commands a beginner page can show:**
- **Check the version:** `python3 --version` on macOS/Linux; `py --version` or `python --version` on Windows.
- **Run a script:** `python3 hello.py`. Start the REPL with `python3`; leave it with `exit` or Ctrl+D (Ctrl+Z then Enter on Windows).
- **Windows install:** the recommended route for 3.15 is the **Python install manager**, from python.org or the Microsoft Store. It provides `python`, `py` and `pymanager` (for example `py install 3.15`, `py list`, `py -V:3.15 script.py`). The traditional full installer is deprecated since 3.14, and none will be produced for 3.16. The legacy "Python launcher" is deprecated too and can take priority over the new `py`; the docs list "can't open file" as the symptom. `python3` exists on Windows only to catch POSIX habits and is not recommended there.
- **Virtual environments:** `python3 -m venv .venv`, then `source .venv/bin/activate` (macOS/Linux) or `.venv\Scripts\activate` (Windows). Install packages with `python -m pip install <pkg>`. The uv equivalents are `uv venv`, `uv add <pkg>`, `uv run script.py` and `uv python install 3.15`.
- **Testing and debugging:** `python -m pytest`, `python -m pdb script.py`, `python -m timeit "..."`, `python -m profiling.sampling` (3.15).

**Sources of nondeterminism observed in this sandbox (run the capture's two-seed check on every chapter):**
- **Set order.** The display and iteration order of sets of `str` or `bytes` depends on `PYTHONHASHSEED`. One four-element set printed four different orders across two seeds on two versions. Sets of small ints look stable but are not guaranteed. `hash("apple")` changes per process.
- **Dict order.** Dicts keep insertion order, guaranteed since 3.7, so they are safe.
- **Memory addresses.** They appear in default object reprs (`<__main__.A object at 0x7fedf4094980>`), in `id()`, in coroutine reprs, and in function and lambda reprs. All of them change every run.
- **Randomness and time.** `random` changes output unless you call `random.seed(n)` (the same seed gives the same sequence on the same version). `datetime.now()`, `time.time()`, `timeit` and profiler numbers change every run. `uuid4` and `secrets` are random by design.
- **Thread and process interleaving.** Our racy 4-thread counter printed the correct 400000 on both versions. Races are timing-dependent, and free-threaded builds (`3.15t`) make them far more likely to show. Never capture a race as "the" output; show it as one possible run.
- **File-system order.** `os.listdir`, `glob` and `Path.iterdir` return names in file-system order. Sort before printing.
- **Input echo.** With piped stdin, typed input is not echoed, and `input()` with no stdin raises `EOFError: EOF when reading a line`. The capture tool's pty mode handles this.
- **Colour.** The 3.13+ REPL, and many 3.15 CLIs and tracebacks, emit colour. Keep `NO_COLOR=1` and `PYTHON_COLORS=0`, as `capture.py` does.
- **Paths in tracebacks.** Tracebacks print the path exactly as it was given on the command line (absolute paths leak the author's folders). `capture.py` runs `cmd + [path.name]` from the file's folder, so only bare file names appear.
- **Recursion depth.** The count in "Previous line repeated 996 more times" depends on the recursion limit (1000) and the stack frames already in use. Capture it rather than predicting it.
- **Version-dependent numbers.** `sys.getsizeof` results and the caret/tilde patterns in tracebacks can differ between versions.

**How errors look:**
- **Compile-time `SyntaxError`/`IndentationError`/`TabError`.** No "Traceback (most recent call last):" header. You get `File "x.py", line N`, the source line, a caret line, then the error. Nothing in the file runs, including earlier `print` calls.
- **Runtime exceptions.** "Traceback (most recent call last):", then one `File ..., line N, in <function>` block per frame, outermost first. Since 3.11 there are `~~~^^^` markers under the failing sub-expression. Output printed before the crash appears on stdout, and the traceback goes to stderr. Exit status is 1.
- **Notes and exception groups.** A note added with `add_note()` prints on its own line after the message. `ExceptionGroup` prints a boxed tree (`+-+---------------- 1 ----------------`).
- **Warnings.** These are not errors and the program continues: `SyntaxWarning: "is" with 'int' literal. Did you mean "=="?` and `RuntimeWarning: coroutine '...' was never awaited`. They go to stderr with a `file:line:` prefix.

**Version differences captured between 3.13.18 and 3.15.0b4 (flag these on pages):**
- **SyntaxError wording.** `elif` after `else`: 3.15 says `'elif' block follows an 'else' block`, 3.13 just `invalid syntax`. Keyword typos: 3.15 adds `Did you mean 'while'?`, and 3.13 also puts the caret elsewhere.
- **AttributeError hints (new in 3.15).** `.push` on a list suggests `'.append'`. `.append` on a tuple suggests "Did you mean to use a 'list' object?".
- **Unhashable keys.** 3.15: `cannot use 'list' as a dict key (unhashable type: 'list')`. 3.13: `unhashable type: 'list'`.
- **Unpacking counts.** When the length is known (a list), 3.15 adds the count: `too many values to unpack (expected 2, got 3)`. 3.13 prints only `(expected 2)`.
- **Modulo by zero.** 3.15: `ZeroDivisionError: division by zero`. 3.13: `integer modulo by zero`.
- **math domain errors.** `math.sqrt(-1)`: 3.15 says `expected a nonnegative input, got -1.0`, 3.13 `math domain error`.
- **Syntax that only runs on newer versions.** On 3.13 each of these is a `SyntaxError`:
  - `except A, B:` without parentheses (3.14+)
  - t-strings `t"..."` (3.14+)
  - `lazy import` (3.15)
  - `*` unpacking inside comprehensions (3.15)
- **New builtins.** `frozendict` and `sentinel` exist only in 3.15. On 3.13 `frozendict` gives `NameError ... Did you mean: 'frozenset'?`.
- **UTF-8 default.** `open()` defaults to UTF-8 in 3.15 on every OS (PEP 686). On 3.13 the default is the locale encoding, which matters on Windows. In this Linux sandbox both report `utf-8`, because a C/POSIX locale already turns on UTF-8 mode.
- **Misleading circular-import message.** Circular imports produce `ImportError: cannot import name 'g' from 'b' (consider renaming '.../b.py' if it has the same name as a library you intended to import)` on both versions. A page about circular imports should say that the rename hint is a red herring here.
- **Isolated mode.** `-I` drops the script's folder from `sys.path`, so local imports fail with `ModuleNotFoundError`. `capture.py` does not use `-I`, which is correct for chapters with multiple files.
- **Behaviours a page must state precisely:**
  - `round()` uses banker's rounding (`round(2.5) == 2`).
  - `round(2.675, 2)` gives `2.67` because of float representation.
  - `//` floors toward negative infinity.
  - `int()` truncates toward zero.
  - int-to-str conversion is capped at 4300 digits.
  - `re.match` is soft-deprecated in 3.15 in favour of `re.prefixmatch`.
  - the `profile` module is deprecated in 3.15.
