# Rust: beginner + intermediate curriculum map

As of 2026-11-07. Current stable: Rust 1.99.1 (15 Oct 2026); edition 2024. All compiler and runtime messages quoted below were captured by actually compiling and running code with rustc/cargo 1.97.0 (edition 2024) on Linux. Wording can shift slightly between releases, so re-capture against the release you pin.

Abbreviations used in "Covered by" columns: **TRPL** = The Rust Programming Language (official book); **BRN** = Brown University interactive edition of TRPL; **RL** = Rustlings; **RBE** = Rust by Example; **CR** = Comprehensive Rust (Google); **100E** = 100 Exercises to Learn Rust; **EX** = Exercism Rust track; **RM** = roadmap.sh/rust; **MSL** = Microsoft Learn "Take your first steps with Rust"; **UPN** = UPenn CIS 1905; **CS110L** = Stanford CS110L; **TOR** = Tour of Rust; **ER** = Easy Rust; **R4R** = Rust for Rustaceans; **EFR** = Effective Rust; **RAL** = Rust Atomics and Locks; **AB** = the Async Book.

**How deep the best beginner treatments go.** The deepest free beginner treatments put 15–25% of their time into the ownership family. CR spends about 4 h 15 min of 18 h on references, memory management, borrowing and lifetimes. BRN adds two whole sections plus four recurring "Ownership Inventory" quizzes on top of TRPL's three ownership sections. RL has 5 move-semantics exercises, and TOR has 15 ownership lessons. Strings vary widely. TRPL has one section (8.2) plus the `&str` part of 4.3. RL has 4 exercises, and 100E has a single "String slices" section, used mainly to motivate `Deref`. TOR, at the other end, has a 14-lesson text chapter. Error handling gets one chapter almost everywhere (TRPL ch 9, RL 6 exercises, CR 55 min), but RBE splits it into 18 pages. Almost all of them skip or hand-wave four things. None teaches *reading a compiler error* as a skill. None teaches a *debugger*: only RM even names rust-gdb/lldb. None warns that output can be nondeterministic (HashMap order, thread order). Each assumes the reader already programs: TRPL, CR and 100E all say they assume another language. For our course, that means the zero-experience track has to add three things the sources lack. First, explicit "what is a variable, loop, function" scaffolding. Second, a drawn stack/heap model *before* ownership, as 100E and ER do. Third, a "the compiler is talking to you" module early, with a "fixing borrow errors" casebook (BRN's best idea) as a module of its own rather than a footnote.

**Where curricula disagree, and what I chose:**

- **When ownership comes.** TRPL/BRN/UPN put it at chapter 4 / week 2, right after basics and before structs. RL puts move semantics after vectors. 100E introduces it inside the struct project, after modules and visibility. CR introduces references on Day 1 but moves/Copy/Clone/Drop only on Day 3, after traits, generics, closures and std library types. TOR puts it after Option/Result/Vec. *Choice:* early (B13–B16), but preceded by a stack/heap picture module (as 100E, ER, CR's "Review of Program Memory" do). With no prior programming, the reader has no other model for "where data lives", and every later chapter (strings, vectors, structs) produces borrow errors that need this vocabulary.
- **Errors before or after collections.** TRPL: after collections (ch 9). TOR: ch 4, with Option. MSL: before memory. 100E: in the enum chapter. CR: last day. *Choice:* `Option` with enums (B20), basic `Result` + `?` at B24 (after collections, because realistic examples need `parse`, file reads and `HashMap::get`), and error *design* (custom types, `From`, thiserror/anyhow) at intermediate I8. That follows TRPL and 100E.
- **Strings.** TRPL splits them: `&str` in 4.3 Slices, `String` in 8.2. CR puts strings inside References on Day 1. TOR gives text its own chapter after ownership. *Choice:* split like TRPL (B17 light, B22 deep). Beginners meet `String`/`&str` mismatches in B12 already, so B12 gives a one-panel "just call `.to_string()` for now" promise that B22 pays off.
- **Lifetimes.** TRPL puts them with generics (10.3). CR puts them straight after borrowing. 100E introduces them when `iter()` needs one. RL has them after traits. *Choice:* intermediate (I4), after generics, because explicit annotations use generic syntax (`<'a>`). Beginners only need "a reference cannot outlive its owner", which they get at B15–B16 with error E0597/E0106.
- **Traits before enums?** 100E teaches traits (ch 4) before enums (ch 5). Everyone else does enums first. *Choice:* enums first. They extend `match`, which beginners already know from B9/B10, and `Option` is needed for vectors.
- **Testing timing.** 100E uses tests from exercise one. MSL and TRPL teach testing late (module 10 / ch 11). *Choice:* `assert_eq!` appears informally in exercises from B8, with a formal testing module at B26, and depth at I13.
- **Closures/iterators.** TRPL ch 13, after testing and a project. CR: closures Day 2, iterators Day 4. RL: iterators after tests. *Choice:* intermediate start (I5/I6), because adapters need closures and closures need traits for their signatures.

## 5. Beyond intermediate (one line each)

- Unsafe Rust: raw pointers, `unsafe` blocks/functions/traits, unions, `static mut`, safety invariants, Miri (TRPL 20.1, CR Unsafe day, R4R ch 9).
- FFI: `extern "C"`, `unsafe extern` blocks (2024), bindgen/cxx, C-variadic functions (stable in 1.99) (R4R ch 11, EFR items 34–35).

- Atomics and memory ordering (Relaxed/Acquire/Release/SeqCst), lock-free structures, building your own locks/channels/Arc (RAL ch 2–10).
- Advanced trait system: associated consts, GATs, higher-ranked trait bounds (`for<'a>`), blanket impl coherence, specialization (nightly), auto traits.

## 6. Facts for a "real runs only" course

**Versions (checked 2026-11-07).**
- Stable Rust: **1.99.1** (15 Oct 2026); 1.99.0 shipped 1 Oct 2026. Releases come every six weeks, so the next stable is due mid-November 2026. That date is inferred from the cadence, not announced on the pages I opened.
- rustup: **1.29.3** (3 Nov 2026).
- Edition: **2024**, stabilized in Rust 1.85.0 (Feb 2025). `cargo new` writes `edition = "2024"` (verified).
- The online TRPL assumes Rust 1.97.0+ with edition 2024. The print 3rd edition (March 2026) is "built on the Rust 2024 Edition".
- Rustlings published crate: 6.5.0, which requires Rust 1.88+.

**Toolchain commands to show.**
- Install: `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh` (Unix) or `rustup-init.exe` (Windows).
- Version checks and updates: `rustup update`, `rustc --version`, `cargo --version`.
- Project workflow: `cargo new hello`, `cargo run`, `cargo build --release`, `cargo check`, `cargo test`, `cargo fmt`, `cargo clippy`, `cargo doc --open`, `cargo add rand`.
- Help and offline docs: `rustc --explain E0382`, `rustup doc --book`, `rustup component add clippy rustfmt rust-analyzer`.
- Rustlings: `cargo install rustlings`, `rustlings init`, `cd rustlings`, `rustlings`.

**Big trap: bare `rustc` defaults to edition 2015.** Running `rustc main.rs` with no `--edition` flag compiles as Rust 2015. Verified results:
- `async fn` fails with `` `async fn` is not permitted in Rust 2015 ``.
- Let chains fail with `let chains are only allowed in Rust 2024 or later`.

Every captured run should use `cargo` (which reads `edition = "2024"`) or `rustc --edition 2024`.

**What a captured `cargo run` looks like.** Cargo's progress lines go to **stderr**; program output goes to stdout:
```
   Compiling hello v0.1.0 (/absolute/path/hello)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.16s
     Running `target/debug/hello`
Hello, world!
```
The absolute path and the timing (`0.16s`, then `0.01s` on a rerun) change from run to run. Either capture stdout only, or normalize these lines. A rerun with no changes skips the `Compiling` line entirely.

**Compile-error format (full, default).**
- `error[E0382]: borrow of moved value: \`s1\`` is followed by ` --> src/main.rs:L:C`.
- Then comes a source excerpt with a `|` gutter, `^^` under the primary span, `--` under secondary spans with labels ("value moved here"), and an optional `help:` block showing the suggested edit with `++++` markers.
- It ends with `error: aborting due to 1 previous error` and ``For more information about this error, try `rustc --explain E0382`.``
- Warnings (unused variables, unneeded `mut`) print in the same style and **will appear in captured output** unless the code is clean or allowed.
- `--error-format=short` gives one-line messages, which is handy for comic captions.
- Exit codes for a compile failure: bare `rustc` exits with 1. `cargo run`/`cargo build` exits with **101** (the same code as a runtime panic, so the exit code alone cannot tell the two apart) and adds a final line ``error: could not compile `hello` (bin "hello") due to 1 previous error``.

**Runtime panic format (Rust 1.91+).**
```
thread 'main' (6894) panicked at p.rs:8:52:
called `Option::unwrap()` on a `None` value
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```
Exit code is **101**. The number in parentheses is the **OS thread ID**, added in Rust 1.91 (per the rust-mode change log). **It differs on every run**, so it must be normalized or cropped out of comic panels. Material written before 1.91 shows `thread 'main' panicked at ...` without the ID.

If `RUST_BACKTRACE=1` is set in the environment, a multi-frame backtrace follows. It contains rustc commit hashes and std paths, so set or unset the variable explicitly when capturing. Panics are written to stderr.

Real messages captured:
- `index out of bounds: the len is 3 but the index is 10`
- `attempt to add with overflow`
- `attempt to divide by zero`
- `RefCell already borrowed`
- `end byte index 2 is not a char boundary; it is inside 'é' (bytes 1..3 of string)`
- `need a number: ParseIntError { kind: InvalidDigit }` (from `expect`)

**Test output format.**
- Header: `running 1 test`, then `test tests::adds ... FAILED`.
- Failure body: `` assertion `left == right` failed ``, then aligned `left: 5` / ` right: 4`.
- Summary: `test result: FAILED. 0 passed; 1 failed; ...; finished in 0.00s`.
- The test binary name carries a hash (`target/debug/deps/tt-23dd6ca62279c18c`), and a duration is printed. Both are nondeterministic.
- Tests run on parallel threads by default, so the order of `test ... ok` lines can vary. Use `-- --test-threads=1` for stable captures.

**Sources of nondeterminism to design around.**
- **HashMap/HashSet iteration order** is randomized per process. The same 5-key map printed in three different orders across three runs. For stable output, use `BTreeMap`/`BTreeSet`, sort before printing, or print lookups instead of the whole map.
- **Thread scheduling.** Four spawned threads printed `0 1 2 3` in two runs and `0 2 1 3` in another. Exercises should ask "which outputs are possible?" and the captured panel should be labelled "one possible run". The same applies to async tasks on a multithreaded runtime.
- **Panic thread IDs** (above), **timing lines** from cargo and tests, **absolute paths** in `Compiling` lines, and **test-binary hashes**.
- **Debug vs release behavior.** Integer overflow panics in debug (`cargo run`) but wraps silently in release (`cargo run --release`): the same program printed `2` in release. Always state which profile a panel used.
- **Time and randomness.** `Instant::now()`, `SystemTime`, and `rand` output. Seed RNGs (e.g. `StdRng::seed_from_u64`) or avoid printing them.
- **Pointer addresses** (`{:p}`) differ every run (ASLR).
- **Floating point.** Deterministic, but surprising for beginners: `0.1 + 0.2` prints `0.30000000000000004`, `1.0_f64` prints `1` with `{}` and `1.0` with `{:?}`.
- **Undefined behavior** can only arise inside `unsafe`. Safe beginner code has no UB, which is a real selling point to state in the book.
- **First build downloads crates** (network-dependent, with stderr progress lines). Commit `Cargo.lock` for reproducible dependency versions.
- **The Playground** may run a different version or channel than local captures.

**Version-specific facts a beginner page must flag.**
- Inline format args `{x}` need Rust 1.58+. Older tutorials use `{}` with positional args.
- `let ... else` needs 1.65+.
- **Let chains** (`if let Some(x) = a && x > 2`) need Rust 1.88+ **and** edition 2024.
- `async` closures have been stable since 1.85.
- Edition 2024 behavior changes:
  - `gen` is a reserved keyword (`let gen = 1;` fails with `expected identifier, found reserved keyword 'gen'`).
  - `std::env::set_var`/`remove_var` are `unsafe` (E0133).
  - `if let` and tail-expression temporaries drop earlier.
  - Return-position `impl Trait` captures all in-scope lifetimes.
  - References to `static mut` are denied.
  - `Box<[T]>` iterates by value.
  - The never-type fallback changed.
  - Cargo uses the MSRV-aware resolver (v3).
- Error wording has changed over time. Newer compilers say a trait "is not dyn compatible" (E0038), where older books say "object safe". Panic messages gained thread IDs in 1.91. `cargo add` has been built in since 1.62, and older guides tell you to edit `Cargo.toml` by hand.
- Compiler messages quoted in this file come from 1.97.0. Re-capture all panels with the pinned course version (1.99.x or later) using `rust-toolchain.toml` (`[toolchain] channel = "1.99.1"`) so every reader gets byte-identical messages.
