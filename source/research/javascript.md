# JavaScript: beginner + intermediate curriculum map

Research as of 2026-11-07. Every error message and output quoted below was captured from a real run on **Node.js v26.13.0 "Lithium" LTS** (V8 14.6.202.34), with a cross-check on v22.23.4. Browser-only messages are labeled as such and come from MDN's error reference.

Tags used in module names: **[Core]** = the ECMAScript language itself, the same in every host. **[Browser]** = DOM and Web APIs. **[Node]** = Node.js runtime APIs. **[Tool]** = toolchain. **[Think]** = how-to-think modules.

Abbreviations in "Covered by": JI = javascript.info; MDN = MDN Learn web development; MG = MDN JavaScript Guide; EJ = Eloquent JavaScript 4e; YDKJS = You Don't Know JS Yet 2e; FCC = freeCodeCamp JavaScript Certification (v9); TOP = The Odin Project (Foundations "JavaScript Basics" plus the Full Stack JavaScript "JavaScript" course); BD = boot.dev Learn JavaScript; EX = Exercism JavaScript track; RM = roadmap.sh/javascript; FSO = Full Stack Open; CS50W = Harvard CS50 Web, week 5; WD = web.dev Learn JavaScript; DG = JavaScript: The Definitive Guide 7e; NL = Node.js Learn.

**How deep the best beginner treatments go.** The deepest free treatments are deep in volume, not in the number of distinct topics. freeCodeCamp spends 6 lectures, 4 workshops and 2 labs on strings, and 18 labs plus 6 lectures on a "fundamentals review". javascript.info has 175 lessons, but strings and type conversion get one lesson each, while regex gets 17. MDN gives strings 2 lessons. boot.dev's 113 lessons have no strings chapter and no DOM. On coercion, the most complete treatment is a whole YDKJS book (still a rough draft). Among courses, only freeCodeCamp's "Debug type coercion errors" lab and Exercism's separate type-conversion and type-checking concepts make it an exercise topic.

**What almost all skip:**
- How to read a stack trace line by line. Only MDN, TOP and FCC have dedicated lessons.
- Why `'😀'.length` is 2. Only javascript.info, in Part 1's "miscellaneous" section.
- How Node's console output differs from the browser console.
- ESM vs CommonJS, and what decides which one a file is. Only DG, YDKJS and one FCC lecture cover it.
- The microtask vs timer order. Only JI, BD and NL.
- Time zones in `Date`.
- Nearly every API from ES2023–ES2026 (`toSorted`, `Object.groupBy`, Set methods, `Map.getOrInsert`) and Temporal. No course TOC reviewed has these as lessons. Only the MDN Guide has a `using` chapter.

**What this means for our course:** a comic course can beat all of these on breadth without being long, if it does four things:
- Give each trap its own page. The traps are coercion, `==`, `this`, TDZ, `var`, float, async order and Unicode length.
- Run everything in Node, so output can be captured.
- Treat the browser as two or three late modules.
- Teach reading errors as a skill from module 2, rather than as one late chapter.

**Where curricula disagree, and the choice made:**

- **Browser first or language first.** MDN, TOP Foundations, CS50W and FCC put DOM and events early. MDN teaches events (item 22) before objects (item 25), and CS50W's notes do events before variables. JI, EJ, YDKJS, BD, EX and WD teach the language first, and BD and WD never reach the DOM. **Chosen: language first in Node, browser at B28–B29.** Node output is plain text and can be captured, which a "real runs only" course needs. It also keeps host APIs (`document`, `alert`) from being mistaken for the language.
- **Arrays or objects first.** JI teaches objects (section 4) before arrays (section 5). MDN, EX and FCC teach arrays first. BD teaches objects in chapter 4 and arrays in chapter 8. **Chosen: arrays first.** A numbered row of boxes is simpler than named labels, and array methods are the natural first use of callbacks.
- **Functions or loops first.** BD puts functions (ch. 3) before loops (ch. 7). JI, MDN, EJ and FCC put loops first. **Chosen: loops first**, so functions can wrap loops in their first examples.
- **Prototypes or classes first.** JI, MDN Extensions, WD and YDKJS teach prototypes before classes. BD teaches classes (ch. 5) before prototypes (ch. 6), and TOP teaches constructors, then factories, then classes. **Chosen: prototypes first (I3), then classes (I4).** Losing methods, `instanceof` and "methods are shared" only make sense once the prototype chain has been drawn.
- **When `var` appears.** JI calls it "The old var" (in advanced functions). FCC puts `var` and hoisting in its fundamentals review. RM puts it in the first group. **Chosen: B15**, because learners meet it in every old Stack Overflow answer. It is taught as a legacy form, next to the TDZ.
- **Testing early or late.** JI teaches Mocha in Part 1 §3 and EX tests from exercise 1. TOP tests mid-course, and FCC has no testing module. **Chosen: B27.** It sits right after modules, because `node:test` needs `import`.
- **When errors are taught.** EJ (ch. 9), BD (ch. 9) and JI (§10) teach errors after objects or classes. MDN and TOP put "what went wrong" in the first few lessons. **Chosen: first contact in B3, a full module at B22–B23.** Learners see errors from their first typo.
- **Async at the end of beginner, or intermediate only.** CS50W and MDN Core put fetch and JSON in the beginner set. BD, JI and FCC put async late. **Chosen: a gentle B30 (timers, ordering, `await fetch`), with full depth in I14–I15.** Async ordering is a top beginner trap, and learners meet `Promise { <pending> }` early.

## 6. Facts for a "real runs only" course

**Current versions (checked 2026-11-07):**

- **ECMAScript 2026 (17th edition)** is the current standard. Ecma International approved it on 2026-06-30, and it was published in July 2026. Its new features:
  - `Array.fromAsync`
  - `Error.isError`
  - `Math.sumPrecise`
  - Uint8Array base64/hex: `toBase64`, `fromBase64`, `toHex`, `fromHex`
  - Iterator sequencing: `Iterator.concat`
  - JSON.parse source text access: `JSON.rawJSON`
  - Upsert: `Map`/`WeakMap` `getOrInsert` and `getOrInsertComputed`
- **The live spec draft is ES2027 (18th edition).** Its finished proposals so far are Temporal, Explicit Resource Management (`using`), iterator chunking, Iterator includes, Iterator join, `Atomics.pause` and joint iteration.
- **Node.js 26.x "Lithium" is the Active LTS.** Its first LTS release was v26.13.0 on 2026-10-28. It ships V8 14.6.202.34 and npm 11.20.0, and reaches EOL on 2029-04-30.
- **Older and newer Node lines:**
  - 24.x "Krypton": Maintenance LTS since 2026-10-20, EOL 2028-04-30.
  - 22.x "Jod": Maintenance LTS, EOL 2027-04-30.
  - 25.x and 20.x: end-of-life.
  - 27.x: Alpha.
- **Node's release model is changing.** Starting with Node 27 there is one major release a year: Alpha from October, Current from April, LTS from October. Every line becomes LTS, with 36 months from first Current release to end-of-life. **Pin the book to Node 26 LTS.**

**Feature availability in the pinned runtime (real feature detection, Node 26.13.0):**

- **Present in Node 26.13.0:** Temporal (on by default), `Map.getOrInsert`, `Error.isError`, `Array.fromAsync`, `Iterator.concat`, `Uint8Array.toBase64`, `JSON.rawJSON`, `RegExp.escape`, `Promise.try`, iterator helpers, Set methods, `Float16Array`, `Object.groupBy`, `Promise.withResolvers`, `toSorted`, and `using`/`DisposableStack`.
- **Missing from Node 26.13.0: `Math.sumPrecise`.** It is part of ES2026, but calling it gives `TypeError: Math.sumPrecise is not a function`. A beginner page must not claim "every ES2026 feature works in Node".
- **Missing from Node 22.23.4:** Temporal, `getOrInsert`, `sumPrecise`, `Error.isError`, `Iterator.concat`, `toBase64`, `RegExp.escape`, `Promise.try`, `Float16Array`, `using`. Pages using these must say "Node 26+".
- **Temporal in browsers:** MDN marks it "Limited availability" (not Baseline). Browser-facing pages must feature-detect it.

**Toolchain commands (all verified on 26.13.0):**

- Check versions: `node --version`, `npm --version`.
- Run a file: `node file.js`. Re-run on save: `node --watch file.js`.
- REPL: `node`, then `.help` and `.exit`. It prints the `Welcome to Node.js v26.13.0.` banner.
- Syntax-check without running: `node --check file.js`.
- Run tests: `node --test`. Add coverage with `node --test --experimental-test-coverage`.
- Run a package.json script: `node --run <script>` or `npm run <script>`.
- Packages: `npm init -y`, `npm install <pkg>`, `npm install -D <pkg>`, `npx <tool>`.
- Debugging: `node inspect file.js` or `node --inspect-brk file.js`, then open chrome://inspect.
- TypeScript: `node file.ts` runs it directly, with types stripped and not checked. `enum` and other non-erasable syntax fail with `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`.
- Environment file: `node --env-file=.env file.js`.

**How errors look (V8/Node; capture these verbatim):**

- **Uncaught runtime error in a CommonJS file**, in this order:
  1. The absolute path and line number: `/path/crash.js:2`
  2. The offending source line
  3. A caret `^` under the failing column
  4. A blank line
  5. `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`
  6. Stack frames such as `at greet (/path/crash.js:2:15)`, followed by Node-internal frames such as `at Module._compile (node:internal/modules/cjs/loader:1968:14)`
  7. A blank line, then `Node.js v26.13.0`

  The exit code is 1.
- **ESM files** show `file:///...` URLs instead of plain paths.
- **SyntaxErrors** show the caret at the unexpected token, then only loader frames (`at wrapSafe ...`). None of the user's code ran.
- **Unhandled promise rejection:** same layout, exit code 1. Code before the crash has already printed (for example "after call").
- **Top-level await on a promise that never settles:** `Warning: Detected unsettled top-level await at file:///...`, exit code 13.
- **Node-specific errors carry codes:** `Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'lodash' imported from ...`, followed by a `code: 'ERR_MODULE_NOT_FOUND'` property dump.
- **Warnings include the process ID,** e.g. `(node:17516) Warning: Failed to load the ES module ...`. Strip or normalize the PID.
- **Assertion failures** print `AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:`, followed by `+ actual - expected` diff lines.

**Things that make captured output nondeterministic or machine-specific (normalize or avoid):**

- **Paths and versions in traces.** Stack traces contain absolute paths and Node-internal line numbers that change between Node versions: the same frame is `loader:1781` on 22.23.4 and `loader:1968` on 26.13.0. Capture in a fixed folder and pin the Node version. For beginner pages, show only the first 5–6 lines of a trace.
- **Randomness and clocks:** `Math.random()` (cannot be seeded), `crypto.randomUUID()`, `Date.now()`, `new Date()`, `performance.now()`, `console.time`.
- **Test runner timings:** durations such as `✔ adds numbers (1.220084ms)` and `duration_ms` change every run.
- **Time zone:** `new Date(2026, 0, 31).toString()` printed `GMT-0600 (Central Standard Time)` under `TZ=America/Chicago`. `new Date("2026-11-07").getDate()` was 6 in Chicago and 7 in Tokyo. Set `TZ=UTC` for every capture.
- **Locale:** `(1234567.891).toLocaleString()` printed `1,234,567.891` under one locale and `1.234.567,891` with `LANG=de_DE.UTF-8`. The time-zone name in `Date#toString` was also localized ("Japanische Normalzeit"). Set `LANG=C.UTF-8` or `en_US.UTF-8`, or always pass an explicit locale to `Intl`.
- **Timer order:** `setTimeout(f, 0)` vs `setImmediate(g)` in the main module has non-deterministic order (the Node docs say so explicitly). Inside an I/O callback, immediate always runs first. Do not capture the main-module version as a single "answer".
- **Order that is deterministic, and can be captured:**
  - sync code, then `process.nextTick`, then promise microtasks, then `setTimeout(0)` (real run). Avoid mixing in `setImmediate`.
  - Object key order (integer-like keys ascending, then string keys in insertion order).
  - Map and Set insertion order.
  - `Array.prototype.sort` stability (guaranteed since ES2019).
  - JS has no hash-order randomization (unlike Python sets or Go maps).
- **Real I/O:** network `fetch` results, and `Promise.all` completion timing. The result array order is stable, but side-effect logs inside the callbacks can interleave.
- **GC-dependent behavior** (`WeakRef`, `FinalizationRegistry`) is non-deterministic by design. Never capture it.
- **stdout vs stderr:** `console.error` goes to stderr. If both streams are captured into one transcript, interleaving can vary. Capture them separately.
- **Console formatting:**
  - `console.log` output in Node is `util.inspect` formatting. Nested objects past depth 2 print as `[Object]`.
  - Long arrays wrap into columns. 30 numbers printed as 4 rows of up to 9.
  - Holes print as `<1 empty item>`, and `-0` prints as `-0`.
  - Colors appear only on a TTY. Piped capture has no ANSI codes, but set `NO_COLOR=1` to be safe.
  - Browser consoles render all of this differently, so never present Node output as "what the browser shows".
- **Error message wording:**
  - It differs between engines. The same mistake reads `Cannot read properties of undefined (reading 'x')` in V8, `"x" is undefined` in Firefox, and `undefined is not an object (evaluating 'obj.x')` in Safari, per MDN. Label engine-specific messages.
  - It can also change between V8 versions: `new Intl.NumberFormat('xx-invalid-!!')` throws `Incorrect locale information provided` on Node 22 but `Invalid language tag: xx-invalid-!!` on Node 26.
- **Math functions** such as `Math.sin` and `Math.exp` are "implementation-approximated" in the spec, so results may differ in the last digit across engines. Basic `+ - * /` on numbers is fully deterministic IEEE 754.
- **Module format of a `.js` file** depends on the nearest `package.json` `"type"`. With no `"type"`, Node uses syntax detection (on by default since 22.7). Give every captured chapter folder its own `package.json` with `"type": "module"`, so `this`, `require` and `__dirname` behave the same on every run. Top-level `this` was `{}` in a `.cjs` file and `undefined` in a `.mjs` file (real run).
- **Timer callbacks:** in Node, `this` inside a regular-function `setTimeout` callback is a `Timeout` object. In browsers it is `window`. Host-specific.

**Version-specific facts a beginner page must flag:**

- Temporal and `using` need Node 26+. They are not in Node 24 or 22.
- `Math.sumPrecise` is in ES2026 but not in Node 26.13.
- `RegExp.escape` and `Promise.try` are missing from Node 22.23.4 and present in 26.13.0 (verified). They are expected from Node 24 (V8 13.6), but that was not run.
- `require(esm)` and ESM syntax detection are on by default in 22.x and later.
- Native TypeScript stripping is unflagged in Node 22.18+ and 23.6+. It worked without flags on 22.23.4 and 26.13.0 in our runs.
- Node 26 removed `--experimental-transform-types`.
- `toSorted` and the other change-array-by-copy methods are ES2023. `Object.groupBy` is ES2024. Set methods are ES2025.
- Global `fetch` is available on all supported LTS lines.
- Browser pages must say which browsers were used for screenshots, because console output and error wording are engine-specific.
