CHAPTER 20 · INTERMEDIATE

CUTTERS AND GUMBALLS

Picture: Scoot, the bike courier in a red cap and green jacket, waves hello.

Last chapter, small interfaces snapped together like pipes. This chapter has two new tools. First, a cookie cutter with an adjustable slot: one function or type that works for ints, floats, strings and your own types, without copying it out three times. That's generics. Then a gumball machine you crank: a function that hands out values one at a time to a for range loop, and stops the moment you walk away. That's an iterator. About 130 minutes, with 24 hands-on checks.

  1. The cookie cutter: your first generic functions
  2. Shaping the slot: constraints, unions and the tilde
  3. Generic types: one Stack design, any parcel
  4. Generics in the toolbox, and when not to use them
  5. The gumball machine: writing iterators with yield
  6. Ready-made gumballs: Seq2, slices, maps and laziness
  7. Boss level and recap

Imagine one cutter with an adjustable slot on top. Before you cut, you slide a dough type into the slot: int, float, string. A little gauge on the slot checks that the dough can do what the cutter needs. Go 1.18 added exactly this, and called it generics.

    

    
    
      
  1. 1The slot is a type parameter, usually called T: a stand-in for a type, filled in later.
    2. 
      
  2. 2The gauge is the constraint: what any type must be able to do to fit the slot.
    3. 
      
  3. 3Each dough is a real type argument. A type that fails the gauge is refused by the Compiler.
    4. 
      
  4. 4Each cut is an instantiation: Max[int], Max[float64]... one cutter, many cookies.
    5. 
    

    

      
      
Scoot says: Catchphrase: one cutter, many doughs. You write the shape once, and the slot says which doughs it accepts.

PART 2 · SHAPING THE SLOTConstraints are interfaces: comparable, unions and the tilde


  

    8
    
Here's the secret: every gauge is an interface (chapter 14). In a constraint, an interface describes a set of types: the doughs that fit. The tighter the set, the more the function may do with them.

    

    
    
      
  • any and comparable are built into Go. cmp.Ordered lives in package cmp.
    • 
      
  • Number is one you write, in panel 10. Its | means "or", and its ~ means "or any type made of it".
    • 
      
  • A slice, a map or a function is never comparable: Go doesn't let you ask whether two slices are ==, and they can't be map keys (chapter 12).
    • 
      
  • Every Number type is also inside cmp.Ordered's set; the picture draws them side by side only to keep it readable.
    • 
    

  


  

    9
    
"Is this value in the slice?" needs ==. The gauge for that is comparable. In any_eq.go, the same function with any.

any_eq.go

    

    
    
      
  1. comparable.go: Contains[T comparable] (line 7)
    Works for strings, ints, and even the Point struct, because a struct whose fields are all comparable is comparable too: true false true.
    2. 
      
  2. any_eq.go: incomparable types in type set
    The "type set" is the set of doughs the gauge lets in (panel 8). any's set includes slices and maps, which can't be compared, so == is refused on line 7.
    3. 
    

  


  

    10
    
Adding needs +, and strings use + to glue text, which isn't what a Sum means. So write your own gauge: an interface that lists the types you accept.

    number.go
    

    

    
    
      
  1. type Number interface { ~int | ~float64 } (lines 5 to 7)
    An interface with a list of types instead of methods. | makes a union: "int or float64". Every type in it supports +, so Sum may use += on line 12.
    2. 
      
  2. The ~ (tilde)
    ~float64 means "float64, or any type whose underlying type is float64" (chapter 18's cups). That's why []Celsius works on line 23: 41.5.
    3. 
      
  3. var total T (line 10)
    Every type has a zero value, so a T starts at zero: 0 for ints, 0 for floats, a zero Celsius for Celsius.
    4. 
      
  4. %T of Sum(temps) (line 24)
    main.Celsius: the result is still in the Celsius cup. Generics keep your types; they never pour them into a plain float64.
    5. 
    

    

      
      
Scoot says: Catchphrase: a tilde lets the cousins in. ~float64 welcomes float64 and every cup made of float64.

    PART 5 · THE GUMBALL MACHINEIterators: range over a function, yield, and break
    

  
    
    19
    
    Outside the bakery stands a gumball machine. Turn the crank: one gumball drops. Turn again: another. Walk away, and the machine just stops. It never pours out the whole globe at once.
    
    
    
    
    
      
      
    
        
    Scoot says: Since Go 1.23, a for range loop can crank a function. The function is the machine. Each time it wants to hand out a value, it calls a function named yield, and that runs your loop body once.
    
        
    Scoot says: A function you can range over like that is called an iterator. When the loop body says break, the machine gets told to stop.
    
      
    
    
    
    
    Picture: Scoot points at the gumball machine, smiling.
    
  
    

  
    
    20
    
    A first machine: it hands out 3, 2, 1.
    
    countdown.go
    
    
    
    
    
      
      
    1. func Countdown(n int) iter.Seq[int] (line 8)
      Countdown doesn't count. It builds the machine and hands it back. iter.Seq[int], from package iter, is a generic type: "a sequence of ints". It's just a name for the function type func(yield func(int) bool).
      2. 
      
    2. return func(yield func(int) bool) { ... } (line 9)
      The machine itself: a function literal (chapter 17) that takes one argument, yield. yield takes one int and answers with a bool.
      3. 
      
    3. if !yield(i) { return } (lines 11 to 13)
      Hand over i. If yield answers false, the loop said "stop", so the machine returns. This one line is the heart of every iterator.
      4. 
      
    4. for v := range Countdown(3) (line 19)
      Go calls the machine with a yield it makes from your loop body. Each yield(i) runs the body once with v = i: 3, 2, 1. When the machine's function returns, the loop is over: liftoff!.
      5. 
    
    
    
    
      
      
    Scoot says: Catchphrase: every crank is a yield; walking away is a false.

    Under the hood: type sets, instantiation, and how range-over-func is built
    
      
      
      
        
        
      The Professor says: Both features are mostly the Compiler's work. The program that runs is ordinary Go.
      
      
      
      
      Interfaces describe type sets
      
      
      Since Go 1.18 the spec defines every interface by its type set. A method interface such as fmt.Stringer has the set of all types with a String() string method. An interface may also list type terms: int (exactly int), ~int (every type whose underlying type is int), joined into a union with |. A type satisfies a constraint when it is in the set. Interfaces with type terms, or that embed comparable, may only be used as constraints, never as the type of an ordinary variable: var n Number is a compile error.
      
      
      Which operations are allowed
      
      
      Inside a generic function, an operation on a T is allowed only if it is allowed for every type in the constraint's type set. With ~int | ~float64 that includes +, -, *, / and <, but not %, because % doesn't work on floats. With any, the set includes types with no operators at all, so only assignment and passing values around remain. comparable is special: it is a built-in interface whose set holds exactly the strictly comparable types.
      
      
      Type inference
      
      
      Go infers type arguments from the types of the ordinary arguments (and, since Go 1.21, also from the type a generic function is assigned to). Untyped constants get their default type only if nothing else decides: that's why Max(3, 2.5) becomes float64 but Max(n, 2.5) with n int fails. Inference never looks at the result type alone, so a function like func Zero[T any]() T must always be called as Zero[int]().
      
      
      How generic code is compiled
      
      
      The Go toolchain doesn't make a full copy of the function for every type, nor one fully shared version. It groups types by their memory shape (a "GC shape": for example, all pointer types share one), compiles one copy per shape, and passes a hidden dictionary with the details of the exact type. That's why generics are usually about as fast as interfaces, and sometimes faster, but not always as fast as a hand-written copy. Performance is a reason to measure, not a reason to use generics.
      
      
      What range-over-func turns into
      
      
      For for v := range seq { body }, the Compiler rewrites the loop body into a hidden function, roughly func(v int) bool { body; return true }, where break becomes return false, and calls seq(thatFunction). That hidden function is the main.main-range1 in panel 23's trace. It also adds a guard: once the body has returned false (or the loop exited by return, goto or a panic), calling it again panics with the message you saw. A return inside the loop body returns from the enclosing function; the Compiler arranges that too.
      
      
      iter.Pull
      
      
      Turning a push iterator into a pull one needs the iterator to pause in the middle of its own loop. iter.Pull runs the iterator on a coroutine, a special lightweight goroutine that hands control back and forth with the caller, which is cheaper than a goroutine plus channels. That is also why stop matters: an iterator abandoned half-way would otherwise sit paused for ever.
      
    
      
  
      

  
      
    In real programs: where generics and iterators show up
    
      
      
        
        
      • The slices and maps packages (Go 1.21) are the biggest users: slices.Sort, SortFunc, BinarySearch, Compact, Equal, maps.Clone, maps.Copy. Before generics, code used sort.Ints, sort.Strings and sort.Slice with an any argument.
        • 
        
      • Built-in min and max (Go 1.21) do what this chapter's Max does, for any number of ordered arguments. Our Max was a lesson, not something to keep.
        • 
        
      • sync.OnceValue and atomic.Pointer[T] use type parameters so callers get back their own type without assertions (chapter 25). context.WithValue itself is not generic (chapter 26), but people often write small generic helpers around it for the same reason.
        • 
        
      • Data structures: sets, ordered maps, caches, trees and queues are the classic case: Set[T comparable] built on map[T]struct{}.
        • 
        
      • Iterators in the standard library: strings.Lines, strings.SplitSeq and strings.FieldsSeq (Go 1.24), bytes.Lines, maps.All, slices.Chunk. Containers by convention offer an All() method returning an iterator, like Boss 4's Stack.
        • 
        
      • Database rows, file lines, paginated web results: anything that arrives a piece at a time and might be very long fits an iterator. Chapter 21's bufio.Scanner is the older, pre-iterator way of reading lines.

    Common wrong ideas
    
      
      
        
        
      • "[T any] is the same as an any parameter." An any parameter gives you a box you must open with an assertion. A type parameter keeps the real type: First(nums) returns an int.
        • 
        
      • "With any I can do anything to a T." The opposite: any allows the fewest operations. A wide gauge means a small toolbox.
        • 
        
      • "The error is where the Compiler points." For T cannot use operator, the fix is in the constraint on the function's first line, not on the line with the operator.
        • 
        
      • "int | float64 accepts my type Score int." Only ~int does.
        • 
        
      • "Generics make code faster." Sometimes; often not. Use them to remove duplication.
        • 
        
      • "Every function should be generic, just in case." Write plain code first; generalise when the second copy appears.
        • 
        
      • "Methods can never have type parameters." True before Go 1.27. Now they can, but interface methods still can't.
        • 
        
      • "An iterator function runs the loop." It's the other way round: the iterator calls yield, and yield runs your loop body. The iterator is in charge, and it pauses inside each yield call.
        • 
        
      • "break stops the iterator straight away." break only makes yield return false. The iterator has to notice and return; if it doesn't, Go panics.
        • 
        
      • "maps.Keys gives the keys in order." In no particular order. Use slices.Sorted(maps.Keys(m)).
        • 
        
      • "An iterator remembers where it stopped." An iter.Seq made by a function like Countdown starts again from the beginning every time you range over it.

    Words from this chapter
    
      
      
      
        
      generics
      Writing a function or type once with type parameters, so it works for many types.
      
        
      type parameter
      A stand-in for a type, declared in square brackets: the T in [T any].
      
        
      type parameter list
      The square brackets after a function or type name, listing type parameters and their constraints.
      
        
      type argument
      The real type that fills a type parameter, such as int in Max[int].
      
        
      instantiation
      Filling the type parameters with type arguments, making a real function or type: Stack[string].
      
        
      type inference
      Go working out the type arguments from the ordinary arguments, so you can write Max(3, 7).
      
        
      constraint
      The interface after a type parameter, saying which types may fill it and so what the code may do with them.
      
        
      type set
      The set of types an interface describes; a type satisfies a constraint when it is in the set.
      
        
      satisfy
      To pass a constraint's check.
      
        
      comparable
      The built-in constraint for types that == and != work on.
      
        
      cmp.Ordered
      The constraint for types that < and > work on: integers, floats and strings.
      
        
      union
      Type terms joined with | in a constraint, meaning "any one of these".
      
        
      tilde ~
      In a constraint, ~T means T and every type whose underlying type is T.
      
        
      generic type
      A type with type parameters, such as Stack[T any].
      
        
      generic method
      A method with type parameters of its own (Go 1.27 and later).
      
        
      duplication
      The same code written more than once.
      
        
      iterator
      A function you can range over, which hands out values one at a time by calling yield.
      
        
      yield
      The function an iterator calls with each value. It runs the loop body and returns false if the loop wants to stop.
      
        
      iter.Seq[V], iter.Seq2[K, V]
      Generic names for iterator function types that hand out one value, or a pair, each time.
      
        
      push iterator, pull iterator
      Push: the iterator calls your code with each value (for range). Pull: you ask for the next value yourself (iter.Pull).
      
        
      lazy, eager
      Lazy: values are made only when asked for. Eager: all values are made up front.
