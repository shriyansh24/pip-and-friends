CHAPTER 11

BEADS ON A NECKLACE

Picture: Scoot, the bike courier in a red cap and green jacket, cheers with both arms up.

Names on parcels, street addresses, messages, emoji: most of what programs handle is text. In Go, a string is a necklace of beads (bytes), and some letters need two, three or four beads. This chapter shows why len("héllo") is 6, how range hands you whole letters, how to change text when strings can't be changed, and the strings toolbox for searching, splitting, cutting and building. About 100 minutes, with 25 hands-on checks.

  1. The necklace: bytes, UTF-8 and len
  2. One bead or one letter: s[i], byte, rune and range
  3. Converting, quoting, and why strings never change
  4. The strings toolbox
  5. Building and comparing strings
  6. Boss level and recap

    4
    
Why beads? A computer can only store numbers. Text is stored by turning every letter into numbers, using a code book that the whole world shares. Go uses the most common one, UTF-8.

    

      
h1 BEAD
English letters, digits, spaces, punctuation

      
é2 BEADS
accented letters, Greek, Cyrillic, Hebrew, Arabic

      
日3 BEADS
Chinese, Japanese and Korean, the € sign

      
👋4 BEADS
emoji and rarer symbols

    

    

      

        
        
For plain English text, one letter is one bead, so counting beads and counting letters give the same answer. That's why chapter 7's word counter never noticed.

      

      

        
UTF-8the code book

        
Every letter in every language, plus emoji, has its own number, called a code point. UTF-8 writes each code point as 1 to 4 beads. Go source files are UTF-8, so "héllo" in your code really is those 6 beads.

    21
    
      Go has three kinds of quotes. Two make strings, one makes a rune.
      
    
      
      
      DOUBLE QUOTES"a\tb"
      An interpreted string. A backslash starts an escape: \n new line, \t tab, \" a quote, \\ a backslash.
      
      
      BACKTICKS`a\tb`
      A raw string. Every character means itself: a backslash is just a backslash. It may even run over several lines.
      
      
      SINGLE QUOTES'é'
      A rune: exactly one letter. Escapes work here too: '\n' is the new-line rune.
      
    
      
    
      
      
      
      Scoot says: The backtick lives on the key left of 1 on most keyboards. Raw strings are perfect for Windows paths and anything full of backslashes.

    Under the hood: string headers, UTF-8 bit patterns, and what conversions cost
    
        
      
        A string is two words
        
      
        A Go string value is a small header: a pointer to its bytes and a length. No capacity, because a string never grows. On a 64-bit computer that's 16 bytes, however long the text. Assigning a string (t := s) or passing it to a function copies the header, not the bytes. That's safe precisely because the bytes can never change: nobody can paint through one name and surprise the other, which is the chapter 10 problem strings simply don't have.
        
      
        How UTF-8 lays out the beads
        
      
        UTF-8 marks every bead so a program can tell where letters start:
        
      
          
        
        • Code points 0 to 127 (plain English, digits, punctuation) use one byte that starts with a 0 bit: 0xxxxxxx. These are the same numbers as the old ASCII code.
          • 
        
        • A two-byte letter starts 110xxxxx, a three-byte one 1110xxxx, a four-byte one 11110xxx.
          • 
        
        • Every following byte starts 10xxxxxx. Those are the dashed beads in panel 6, and they are always 128 to 191. That's why é's second bead, 169, can never be mistaken for the start of a letter.
          • 
      
        
      
        é is code point 233, binary 11101001. Split over two beads: 110+00011 = 195 and 10+101001 = 169. Exactly the beads your programs printed.
        
      
        What range does with broken beads
        
      
        The Go specification says that when range meets bytes that aren't valid UTF-8, it hands out the rune 0xFFFD (the "replacement character", often drawn as a question mark in a diamond) and moves on by one byte. So ranging over the broken result of panel 19 never crashes; it just yields replacement characters for the two stray beads. utf8.ValidString(s) tells you in advance whether a string is valid.
        
      
        Conversions copy
        
      
        []byte(s), []rune(s) and string(b) normally allocate new memory and copy, which is what panel 18's tracer showed: a []byte can change, so it must not share bytes with a string that promises never to change. The compiler skips the copy in some safe cases, for example for i, b := range []byte(s) or a string(b) used only as a map key. []rune(s) uses 4 bytes per letter, so it's up to four times bigger than the string.
        
      
        copy from a string
        
      
        The built-in copy from chapter 10 also takes a string as its source when the destination is a []byte. It copies beads, as many as the destination has room for, even if that cuts a letter in half:
        
      copy_string.go
      
        
      
        
      
        Three beads fit: h and both halves of é, so n is 3 and %q shows "hé". With room for only two, the second bead of é would have been left behind.
        
      
        Substrings share
        
      
        s[2:5] on a string makes a new header pointing into the same bytes, with no copying, like slicing a slice. A tiny substring can therefore keep a huge string alive in memory. strings.Clone(sub) makes an independent copy when that matters.
        
      
        Inside strings.Builder
        
      
        A Builder keeps a growing []byte, using append from chapter 9, and String() hands that memory over as a string without copying it again. The documentation warns: do not copy a Builder after you've started writing to it. If you know the final size, sb.Grow(n) reserves the room up front. Chapter 28 measures the difference against +=.
        
    
        
  
        

  
        
    In real programs: where strings, bytes and runes show up
    
        
      
          
        
        • Files and networks speak bytes. Reading a file gives a []byte; so does an HTTP request body. Many programs convert with string(data) once, then use the strings toolbox. The bytes package has the same tools (bytes.Contains, bytes.Split, bytes.CutLast…) for working on []byte directly, without converting.
          • 
        
        • Parsing lines. strings.Cut(line, "=") for settings files, strings.Fields(line) for words, strings.Split(line, ",") for simple comma-separated data. (Real CSV with quoted fields needs encoding/csv.)
          • 
        
        • File names. CutLast(name, ".") gets an extension; the path/filepath package has filepath.Ext for real paths.
          • 
        
        • Cleaning input. strings.TrimSpace on everything a person types: chapter 7's typed input could carry stray spaces round the number.
          • 
        
        • Showing text to people. Counting letters for a limit (a username of at most 20 letters) uses utf8.RuneCountInString, not len. Storing a size limit in a database column usually means bytes, so len. Know which one you mean.
          • 
        
        • Building output. Report generators and template engines build text on a strings.Builder or write straight into a file.
          • 
        
        • Case-insensitive checks. strings.EqualFold(answer, "yes") accepts YES, Yes and yes.
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "len(s) is the number of letters." It's the number of bytes. They agree only for plain English text.
          • 
        
        • "s[i] is the i-th letter." It's the i-th byte, a uint8. For letters, use []rune(s)[i] or range.
          • 
        
        • "In for i, r := range s, i counts letters." i is the byte offset where each letter starts: 0, 1, 3, 4, 5 for "héllo".
          • 
        
        • "A rune is a character." A rune is one code point. Most of the time that's one visible letter, but panel 36's e-plus-accent is two runes that look like one letter, and some emoji are built from several code points too.
          • 
        
        • "Strings are arrays of chars, so I can change one." Go strings are immutable. Every change makes a new string.
          • 
        
        • "strings.ToUpper(s) makes s uppercase." It returns a new string. Catch it: s = strings.ToUpper(s).
          • 
        
        • "string(65) is "65"." It's "A". Use strconv.Itoa. go vet flags it.
          • 
        
        • "Single and double quotes are the same." Single quotes make a rune; double quotes and backticks make strings.
          • 
        
        • "s += x in a loop is free." Each one copies the whole string so far. Use a strings.Builder for big loops.
          • 
        
        • "< on strings sorts like a dictionary." It compares byte values: capitals before small letters, and "10" before "9".
          • 
        
        • "Two strings that look the same are ==." Not if their bytes differ, as panel 36 showed. What to do: normalise both strings to the same form first, usually NFC ("Unicode Normalization Form C", where é is the one-letter version), with the golang.org/x/text/unicode/norm package, then compare: norm.NFC.String(a) == norm.NFC.String(b). That package lives outside the standard library, so this page didn't run it; the Go Blog's "Text normalization in Go" (in Go deeper) walks through it.
          • 
        
        • "Go strings must be valid UTF-8." A string can hold any bytes. Literals in your source code are UTF-8, but bytes read from a file might not be.

    Words from this chapter
    
        
      
        
        
        byte
        A small number from 0 to 255, stored in 8 bits: one bead. In Go, byte is another name for uint8.
        
        
        bit
        A single 0 or 1. Eight bits make a byte.
        
        
        UTF-8
        The way of writing every letter as 1 to 4 bytes that Go (and most of the web) uses.
        
        
        Unicode
        The shared code book that gives every letter, symbol and emoji in every language its own number.
        
        
        code point
        A letter's number in Unicode, such as 233 for é, written U+00E9.
        
        
        rune
        Go's type for one code point; another name for int32. Written in single quotes: 'é'.
        
        
        rune literal
        A rune written in code: one letter between single quotes.
        
        
        ASCII
        An old code for 128 English letters, digits and symbols; they are the one-byte letters in UTF-8.
        
        
        immutable
        Can't be changed after it's made. Go strings are immutable.
        
        
        byte offset
        The position of a byte in a string, counted from 0. range gives each letter's starting byte offset.
        
        
        utf8.RuneCountInString
        Counts the runes (letters) in a string.
        
        
        conversion
        Turning a value into another type: []byte(s), []rune(s), string(r).
        
        
        interpreted string literal
        A string in double quotes, where backslash escapes like \n are turned into special characters.
        
        
        raw string literal
        A string in backticks, where every character means itself and line breaks are allowed.
        
        
        escape sequence
        A backslash and a code inside quotes that stands for a hard-to-type character: \n, \t, \", \\, \u00e9, \xc3.
        
        
        hexadecimal
        Writing numbers in base 16 with digits 0–9 and a–f: a9 is 169.
        
        
        strings package
        Go's standard toolbox of functions for searching, changing, splitting and building strings.
        
        
        separator
        The text you split at or join with, like "," in strings.Split(s, ",").
        
        
        strings.Builder
        A workbench that collects bytes efficiently and makes one string at the end.
        
        
        method
        A function that belongs to a value and is called with a dot, like sb.WriteString. Chapter 13 explains them.
        
        
        lexical (byte-wise) order
        How < compares strings: byte by byte from the left, and a shorter string first if it runs out.
        
        
        replacement character
        U+FFFD, what range hands out for bytes that aren't valid UTF-8.
