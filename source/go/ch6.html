Picture: Scoot, the bike courier in a red cap and green jacket, cheers with both arms up.

Computers never get bored. Tell Go to do something five times, or five million, and it will: that's a loop. Run laps with Go's one loop word, for, in four styles. Skip a lap with continue, leave the stadium with break, and nest loops inside loops. Then pack values into arrays: egg cartons with the size printed on the lid. About 85 minutes, with 26 hands-on checks.

      PART 2 · FOUR WAYS TO LOOPOne word, four shapes: three-part, while-style, forever, range
      

  
      
    10
    
      Other languages have several loop words (while, do, repeat…). Go has only for, in four shapes.
      
    
      
      
      
        
      THREE-PARTfor i := 0; i < n; i++
      
        
        
      A counter with a start, a check and a step. Laps you can count.
      
        
      When you know how many laps.
      
      
      
      
      
        
      CHECK ONLYfor fuel > 0
      
        
        
      Just the check. Keep going while it's true. Other languages call this a while loop.
      
        
      When you don't know how many laps, only when to stop.
      
      
      
      
      
        
      FOREVERfor { … break … }
      
        
        
      No check at all. Spins until a break inside says "out".
      
        
      When the exit is decided in the middle of a lap.
      
      
      
      
      
        
      RANGEfor i := range 5
      
        
        
      Go counts 0, 1, 2, … up to just below the number for you. New in Go 1.22.
      
        
      The tidiest way to say "5 times".

      PART 3 · SKIP A LAP, LEAVE THE STADIUMcontinue, break, labels and loops inside loops
      

  
      
    16
    
      Two words change a lap halfway through.
      
    
    
      
      
      continueskip the rest of this lap
      Jump straight to the end of the lap. The POST still runs (the counter ticks), then the check, then the next lap.
      
      
      breakleave the stadium
      Leave the loop right now. No more laps, no POST, no check. The run carries on after the loop's }.

    40
    
        What you learned in Chapter 6
        
    
          
      
        • ONE WORD, FOUR SHAPESfor with three parts, with only a check, with nothing (forever, until break), or with range n. Go has no while: the check-only for is it.
          • 
      
        • START ONCE, CHECK BEFORE, POST AFTERSTART runs once. The check runs before every lap and ends the loop when false. POST runs after every lap.
          • 
      
        • CHECK THE FIRST LAP AND THE LAST LAPStart at 0 with <, or at 1 with <=. Off by one is quiet in a count and a panic in a carton.
          • 
      
        • CONTINUE SKIPS A LAP. BREAK LEAVES THE STADIUM.continue jumps to POST; break leaves the innermost loop or switch. A label (break shelves) says which one.
          • 
      
        • THE SIZE IS ON THE LID[3]int holds exactly 3 ints, indexed 0 to 2; the size is part of the type. Wrong constant index: compile error. Wrong variable index: panic.
          •

    Under the hood: what a loop becomes, and where a carton lives
    
        
      
        A loop is a jump backwards
        
      
        The processor has no idea what a "loop" is. It runs instructions one after another, and it has a jump instruction that says "continue from that address instead". The Compiler turns for i := 0; i < 3; i++ { body } into roughly: set i to 0; top: if i < 3 is false, jump to end; run the body; add 1 to i; jump to top; end:. The map in panel 19 is that picture: continue is a jump to the POST instructions, break is a jump to end.
        
      
        What the specification says about the three parts
        
      
        The Go specification calls the three parts the init statement, the condition and the post statement. The init may be a short variable declaration (i := 0); the post may not (you can't write := there). Any part may be left out: for ; i < 3; { is legal, and gofmt tidies it to for i < 3 {. A missing condition means true, which is how for { spins for ever.
        
      
        One fresh counter per lap (Go 1.22 and later)
        
      
        Since Go 1.22, each lap of a three-part loop has its own copy of the variable declared in the init statement. Before the POST runs, Go makes a new variable for the next lap and copies the current value into it; then POST changes the new one. For the loops in this chapter you can't see any difference. You will when a lap hands its counter to something that runs later (chapter 17, closures, and chapter 24, goroutines). The go line in go.mod picks the behaviour: 1.22 or later gets fresh variables.
        
      
        Range over an integer
        
      
        for i := range n needs n to be an integer; it gives 0 to n-1, and if n is 0 or negative the body never runs. The value of n is worked out once, before the first lap. i gets the same type as n (an untyped constant like 3 gives an int).
        
      
        An array is its elements, side by side
        
      
        A [3]int is exactly three ints next to each other in memory: 24 bytes on a 64-bit computer, nothing else. No hidden length field: the length is in the type, so the Compiler always knows it. eggs[i] means "start of the carton plus i times the size of one element". That is why indexes start at 0: index 0 is "step past zero elements". Before every index with a variable, Go adds a quick check that i is between 0 and len - 1; if not, it panics instead of reading neighbouring memory. When the Compiler can prove an index is always safe (as inside for i := range eggs), it leaves the check out.
        
      
        Why is assignment a full copy?
        
      
        Because the carton is the value, the same as an int is its number. b := a copies all the bytes. For a [1000000]int that is 8 megabytes copied by one innocent-looking line, which is one reason Go code passes slices (chapter 9) or pointers (chapter 13) around instead of big arrays.
        
    
        
  
        

  
        
    In real programs: where you'll see these every day
    
        
      
          
        
        • for i := range n and for _, v := range things are the most common loops in modern Go. The three-part form shows up when the step isn't 1 (i += 2), when counting down, or when two counters move together: for i, j := 0, len(a)-1; i < j; i, j = i+1, j-1 (that's the swap from chapter 3, used to reverse a carton).
          • 
        
        • The check-only loop reads "keep going while…": retrying a network request while it fails, reading a file while there is more to read, or for scanner.Scan() (chapter 7), which reads input line by line until it runs out.
          • 
        
        • for { … } is everywhere in servers: "wait for the next request, handle it, repeat for ever". Programs like that are meant never to stop.
          • 
        
        • Labels are rare but respected: searching a grid, or leaving a loop from inside a switch or select. Go also has goto; you will almost never need it.
          • 
        
        • Arrays appear where the size is truly fixed: a 3 × 3 matrix, the 4 bytes of an IPv4 address, the 32 bytes of a SHA-256 hash (Go's crypto/sha256 returns a [32]byte, and that type name contains the size). Because arrays can be compared with ==, they can also be keys in a map (chapter 12).
          • 
        
        • Most "lists" are slices. When you read Go code and see []string with empty brackets, that's a slice; [5]string or [...]string is an array.
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "Go has a while loop." It doesn't. for condition { } does the same job, and while is not even a keyword.
          • 
        
        • "The check runs after each lap." It runs before each lap, including the first. A loop whose check starts false runs zero times.
          • 
        
        • "for i := range 5 gives 1 to 5." It gives 0 to 4.
          • 
        
        • "i++ can be used inside an expression." In Go it is a statement on its own. x := i++ and ++i are both errors.
          • 
        
        • "continue restarts the loop from the beginning." It skips to POST and the next check. The START part never runs again.
          • 
        
        • "break stops the program." It leaves one loop (or one switch). The lines after it still run.
          • 
        
        • "break inside a switch leaves the loop around it." It leaves only the switch (panel 21). Use a label.
          • 
        
        • "The counter still exists after the loop." A counter built in the START part lives only inside the loop. Using i after the closing brace is undefined: i.
          • 
        
        • "An array of 5 has indexes 1 to 5." 0 to 4. The last index is always len - 1.
          • 
        
        • "b := a makes b another name for the same array." It copies the whole array. (Slices, in chapter 9, behave differently; that's a big reason to learn arrays first.)
          • 
        
        • "[3]int and [4]int are the same type, just different sizes." They are different types. You can't assign or compare one with the other.
          • 
        
        • "An index out of range is always a compile error." Only when the index is a constant the Compiler can check. A variable index panics at run time.

    Words from this chapter
    
        
      
        
        
        loop
        Code that runs the same lines again and again.
        
        
        lap / iteration
        One time through a loop's body.
        
        
        for
        Go's only loop keyword, in four shapes.
        
        
        body
        The lines between a loop's braces, run once per lap.
        
        
        init statement (START)
        The first part of a three-part for. Runs once, before the first check.
        
        
        condition (CHECK)
        The middle part. Checked before every lap; false ends the loop.
        
        
        post statement (POST)
        The last part. Runs after every lap, usually i++.
        
        
        counter
        A variable that counts the laps, often called i.
        
        
        ++ / --
        Add 1 to / take 1 from a variable. Statements, not values.
        
        
        +=
        x += 5 is short for x = x + 5.
        
        
        statement
        A complete instruction, like x = 5 or i++. It does something but isn't a value.
        
        
        off by one
        A loop that runs one lap too many or too few, or an index one too big or too small.
        
        
        while loop
        Other languages' name for a loop with only a check. In Go: for condition { }.
        
        
        infinite loop
        A loop that never ends. Stop it with Ctrl+C.
        
        
        range
        Hands out values one per lap: 0 to n-1 for a number, index and element for an array.
        
        
        continue
        Skip the rest of this lap; go to POST and the next check.
        
        
        break
        Leave the innermost loop (or switch) right now.
        
        
        label
        A name for a loop, written name: before it, so break name or continue name can say which loop.
        
        
        nested loop
        A loop inside another loop's body.
        
        
        FizzBuzz
        A classic counting puzzle: Fizz for multiples of 3, Buzz for 5, FizzBuzz for both.
        
        
        array
        A fixed number of values of one type, side by side: [3]int.
        
        
        element
        One value inside an array: one cup of the carton.
        
        
        index
        An element's position, counted from 0.
        
        
        len
        Built-in function that gives an array's length (its number of elements).
        
        
        array literal
        Writing an array's values directly: [3]int{1, 2, 3}.
        
        
        [...]
        In an array literal: "Compiler, count the values for me".
        
        
        panic
        A run-time crash. Go prints panic:, the reason and where it happened, and exits with status 2.
        
        
        run time
        While the program is running (in the kitchen), as opposed to compile time (at the desk).
        
        
        multi-dimensional array
        An array of arrays, like [3][3]string: rows and columns.
        
        
        slice
        A growable list built on an array, written []int. Chapter 9.
        
        
        language version
        The go line in go.mod. It decides which features (like range 3) your code may use.
