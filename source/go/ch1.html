    8
    
Every Go program lives through two moments. Learn their names: you'll hear them all the time.

    

      

        
COMPILE TIMEthe translator's desk

        

        
The Compiler checks the whole program and translates it. Mistakes caught here are compile errors. Nothing has run yet, not one line.

      

      

        
RUN TIMEthe kitchen

        

        
The binary runs, one step after another. Trouble here is called a panic: the program stops in the middle. Earlier steps already happened.

      

    

    

      
      
Scoot says: That's why Go is called a compiled language: translate everything first, run second.

    

    
Pictures: on the compile-time card, the Compiler at its desk, beacon red; on the run-time card, the cook in the kitchen.

    Under the hood: what go run really does
    
        
      
        go run is a shortcut for three jobs. It compiles your package (the Compiler proper turns Go text into machine code), links it (the linker joins your code with the parts of Go every program needs, called the runtime, into one executable file), then runs that file. The file is written to a temporary folder and thrown away afterwards. go build does the first two jobs and leaves the file next to your code.
        
      
        That is why the missing-main error looked so different: it comes from the linker. The runtime's start-up code wants to call main.main (the function main in package main); when nothing by that name exists, the linker has no line to point at, so it names the missing symbol instead: runtime.main_main·f.
        
      
        
        
        nomain.go
        
        
        No file:line:column: the problem is something missing, not something written wrong.
        
      
        
      
        Named after the folder, or the module?
        
      
        In panel 22 the folder and the last part of the module path were both hello, so you couldn't tell which one named the binary. Here the folder is called proj, and the module is still example/hello:
        
      
        
      
        How this run was really made: one shell, in a folder of the book's program collection labelled ~/proj here. Before go mod init, it walked in, copied main.go there and deleted any old go.mod and binary. ls ran as ls -C -T 0.
        
      
        The binary is hello: go build names it after the last part of the module path, not after the folder.
        
      
        Invisible semicolons, exactly
        
      
        The Go specification says a semicolon is inserted after a line's final token if that token is a name (an identifier), a literal such as a number or a quoted string, one of the keywords break, continue, fallthrough or return, or one of ++ -- ) ] }. func main() ends in ), so it gets one, and a { on the next line is cut off from its function. Lines ending in { or , never get one.
        
      
        Why does Go reject unused imports?
        
      
        The Go designers made it a compile error on purpose. Unused imports make a program slower to build and harder to read, and in big projects they pile up. Chapter 2's tools can add and remove imports for you when you save.
        
      
        What's in a binary?
        
      
        A Go binary carries everything it needs: your code, the parts of the standard library it uses, and the runtime. That makes it bigger than you might expect for Hello World, but easy to share: copy one file to a computer with the same operating system and chip, and it runs. Building for another system is one setting away (GOOS and GOARCH, the two words go env showed you).
        
    
        
  
        

  
        
    In real programs: streams, exit codes and the go tool
    
        
      
        Programs talk to the world through standard output and standard error. Keeping them apart lets you save results to a file while still seeing complaints on screen: > results.txt after a command sends only stdout into the file:
        
      
        
      
        The standard-error line still reached the screen, and the file holds only the standard-output line. Line 10 of streams.go uses fmt.Fprintln(os.Stderr, ...) to write to the error stream; you will use it in real tools later.
        
      
        
      
        The exit code is how scripts and build systems know whether a step worked: 0 means success, anything else means failure. A compile error makes go run exit with 1. A panicking program exits with 2, which go run reports as exit status 2 before ending with 1 itself.
        
      
        Notice that go mod init printed its friendly messages on the error stream (they were red in panel 20) yet exited with 0. Many command-line tools do this: stdout is kept for results, and chatter goes to stderr. Trust the exit code, not the colour.
        
      
        The go command is a whole toolbox. You met version, env, help, mod init, run and build. Coming later: fmt and vet (chapter 2), test, get and install. go help build explains any one of them.
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "Double-clicking main.go runs it." It opens the text. The Compiler must translate it first.
          • 
        
        • "The computer will understand what I meant." It does exactly what is written, in order. Shoes before socks, if you say so.
          • 
        
        • "No output means it failed." For mkdir, cd and go build, silence means success. Errors always print something.
          • 
        
        • "Red text means failure." Red here means "on the error stream". go mod init writes red tips and succeeds. Check the exit code.
          • 
        
        • "The $ or the prompt is part of the command." Tutorials show $ go version; type only go version.
          • 
        
        • "Putting the brace on the next line is just style." In Go it is a compile error, because of invisible semicolons.
          • 
        
        • "An unused import is harmless." Go refuses to build. Delete it.
          • 
        
        • "'Hello' and "Hello" are the same." Single quotes hold one character (a rune). Text needs double quotes.
          • 
        
        • "I need go mod init for every file." Once per project (per folder tree). Every .go file in that folder belongs to it.
          • 
        
        • "The Playground is the same as my computer." It runs on Go's servers, with limits: no files of your own, no keyboard input.

    Lab: run it yourself (Windows, macOS, Linux)
    
        
      
        1. Install Go
        
      
          
        
        • Windows: download the .msi from go.dev/dl and run it. It installs into Program Files and adds Go to your PATH. Open a new Terminal (PowerShell) window afterwards.
          • 
        
        • macOS: download the .pkg for your chip (Apple silicon: arm64; older Intel Macs: amd64) and run it. Go goes into /usr/local/go. Reopen Terminal.
          • 
        
        • Linux: download the .tar.gz, then (with sudo if needed) remove any old copy and unpack the new one: rm -rf /usr/local/go && tar -C /usr/local -xzf go1.27.3.linux-amd64.tar.gz. Add export PATH=$PATH:/usr/local/go/bin to ~/.profile, then log out and in (or run source ~/.profile). Never unpack over an existing /usr/local/go.
          • 
      
        
      
        Check: go version should print a version line like the one in panel 13.
        
      
        2. Make the project
        
      
          
        
        1. Go home: cd (macOS, Linux) or cd $HOME (PowerShell) or cd %HOMEPATH% (Windows cmd).
          2. 
        
        2. mkdir hello, then cd hello.
          3. 
        
        3. go mod init example/hello. Expect go: creating new go.mod: module example/hello.
          4. 
        
        4. In a code editor, create main.go in that folder with the Hello World program from panel 24. (Any plain-text editor works; chapter 2 sets up VS Code.)
          5. 
        
        5. go run . should print Hello, World!
          6. 
        
        6. go build, then ls (PowerShell or macOS/Linux) or dir (cmd). Run the binary: ./hello (macOS, Linux) or .\hello.exe (Windows).
          7. 
      
        
      
        3. Break it on purpose
        
      
          
        
        1. Move the { to its own line. Run. Find the address. Put it back.
          2. 
        
        2. Add "os" to the imports without using it. Meet "imported and not used".
          3. 
        
        3. Rename main to Main. Meet the linker.
          4. 
        
        4. Change the double quotes to single quotes. Meet the rune literal message.
          5. 
        
        5. Add panic("stop") between two Println lines. See which lines still print.
          6. 
      
        
      
        4. No install? Use the Playground
        
      
        Open go.dev/play, paste the program, press Run. Every example in this chapter except the terminal commands works there.

    Words from this chapter
    
        
      
        
        
        computer
        A machine that takes input, follows instructions, and gives output.
        
        
        CPU
        The part of a computer that carries out instructions, one tiny step at a time.
        
        
        program
        A list of instructions a computer runs in order.
        
        
        source code
        A program written as text, like the contents of a .go file.
        
        
        machine code
        The 0s and 1s a CPU understands directly.
        
        
        compiler
        A program that checks source code and translates it into machine code.
        
        
        binary / executable
        A file of machine code that the computer can run by itself.
        
        
        compiled language
        A language, like Go, whose programs are fully translated before they run.
        
        
        compile time
        The moment the compiler checks and translates. Compile errors happen here.
        
        
        run time
        The moment the program runs. Panics happen here.
        
        
        compile error
        A mistake the compiler finds. No binary is made and nothing runs.
        
        
        panic
        A run-time stop: the program halts in the middle and reports what went wrong.
        
        
        output
        What a program shows or writes.
        
        
        stdout / stderr
        Standard output (normal results) and standard error (problems and messages): a program's two output streams.
        
        
        exit code
        The number a program ends with: 0 for success, anything else for failure.
        
        
        terminal
        A window where you type commands.
        
        
        shell
        The program inside the terminal that reads your commands (bash, zsh, PowerShell).
        
        
        prompt
        The text that means "your turn", like you@laptop:~$.
        
        
        PATH
        The list of folders the shell searches for command names.
        
        
        folder / directory
        A place that holds files and other folders.
        
        
        current directory
        The folder the terminal is standing in.
        
        
        home folder ~
        Your own folder, where the terminal usually starts.
        
        
        cd / mkdir / ls
        Change directory, make directory, list files (dir in Windows cmd).
        
        
        module
        A collection of Go code that belongs together, described by a go.mod file.
        
        
        go.mod
        The module's label: its module path and Go version.
        
        
        module path
        The module's name, like example/hello.
        
        
        package
        A named group of Go code. Every file starts with its package line.
        
        
        package main
        The package that makes a runnable program.
        
        
        import
        Brings another package's tools into your file, like "fmt".
        
        
        function
        A named group of instructions, like main or Println.
        
        
        func main
        The function where every Go program starts running.
        
        
        call
        Using a function, with parentheses: fmt.Println(...).
        
        
        statement
        One instruction inside a function.
        
        
        braces
        { }, which hold a function's body.
        
        
        string literal
        Text written in double quotes, like "Hello, World!".
        
        
        rune literal
        One character in single quotes, like 'H' (chapter 11).
        
        
        comment
        A note for humans: // to the end of the line or /* between the marks */.
        
        
        semicolon insertion
        Go adding invisible ; at the ends of certain lines.
        
        
        declaration
        Something that introduces a name, like package, import or func. Only declarations may sit outside functions.
        
        
        linker
        The last step of building, which joins everything into one binary.
        
        
        Go Playground
        A web page (go.dev/play) that runs Go programs without installing anything.
        
        
        GOTOOLCHAIN
        A setting that lets the go command fetch a newer Go when a project asks for one.
