The detective's routine for any pile of Go errors.

    
    
      
  1. Who's talking? A line starting with vet:, or a bare main.go after go vet, means vet. A # header plus ./file.go after go build or go run means the Compiler. A bare file name after gofmt means Tidy. panic: means a running program.
    2. 
      
  2. First error first. Read the top message only.
    3. 
      
  3. Address. File, line, column. Go to the exact door.
    4. 
      
  4. Message. What did it expect? What did it find?
    5. 
      
  5. Fix one thing, run again. New messages after a fix are often progress.
    6. 
    

    

      
The Professor says: A long list of errors is not a long list of problems. Usually it's one problem, explained several ways.

    Under the hood: how gofmt, vet and the Compiler read your code
    
    
      
    All three start the same way. They parse your text: chop it into tokens (names, numbers, strings, symbols) and build a tree of what belongs to what. In 2 + 3*4, the tree has + at the top, with 2 on one branch and the smaller tree 3*4 on the other. Precedence is simply the shape of that tree.
    
      
      
        
    • gofmt parses the file, throws away your spacing, and prints the tree again in the one official layout. Because it reprints the tree, it cannot change what the program means, and it cannot work on a file that doesn't parse (panel 11). Its spacing of 2 + 3*4 is the tree drawn in spaces.
      • 
        
    • go vet parses the file and works out every type, then runs a set of analyzers: small checkers for common mistakes. The printf analyzer compares each % verb with the value it gets. Vet and gopls use the parser from Go's standard library (go/parser); the Compiler has its own, which is why panel 21 shows two wordings for one mistake.
      • 
        
    • The Compiler checks grammar for the whole file first. If the grammar is broken it stops there, which is why the division by zero in panel 19 only showed up after the comma was fixed. Then it checks types and meaning, then translates.
      • 
      
    
      
    Sums made of literals are done at compile time
    
      
    In this chapter every sum was made only of literals, like 7/2. Go calls such a sum a constant expression and works it out while compiling, with exact arithmetic. That is why 7 / 0 is a compile error rather than a crash: the Compiler has already tried to compute it. The running program just prints a ready-made answer.
    
      
    Literals are untyped until they need a type. 7.0 / 2 mixes an untyped float and an untyped integer, which is allowed for constants; the result is a float. In chapter 4, once values have fixed types, mixing an int and a float64 becomes an error and you'll convert on purpose.
    
      
    The exact rules (from the Go specification)
    
      
      
        
    • Integer division truncates toward zero: the fraction is dropped. For whole numbers q = x / y and r = x % y, the rule x == q*y + r always holds, and r is smaller than y in size, with the sign of x.
      • 
        
    • Go has five precedence levels. The two you met: * / % (and some you'll meet later, like << and &) above + - (and |, ^). Below them come comparisons (chapter 5), then &&, then ||. Operators on the same level work left to right.
      • 
        
    • A constant divisor must not be zero. A divisor that is only known at run time can be zero, and then the program panics (chapter 4 shows one).
      • 
        
    • % is defined for integers only. Go's math package has a function for float remainders, for the rare times you need one.
      • 
      
    
      
    
        
    precedence.go
    
        
    
      
    
    
    
  
    

  
    
    In real programs: formatting, vetting, and division everywhere
    
    
      
    Every Go project uses gofmt. Go code looks the same everywhere, so you can read anyone's code without adjusting to their style, and nobody argues about spaces. Many teams make their automatic checks fail if gofmt -l . prints anything. go fmt ./... runs gofmt over every package in a module (it prints the names of the files it changed).
    
      
    go vet runs more often than you think. go test (chapter 15) automatically runs a small set of vet's checks, the Printf check among them, before running tests. Many editors and teams also run go vet ./... on every change.
    
      
    Integer division and remainders are everywhere:
    
      
      
        
    • Splitting seconds: 125 seconds is 125/60 minutes and 125%60 seconds.
      • 
        
    • Even or odd: a number is even when n%2 is 0.
      • 
        
    • Pages: with 10 results per page, result 37 is on page 37/10 (counting pages from 0).
      • 
        
    • Going round in circles: clock hours, days of the week and turns in a game all wrap around with %.
      • 
      
    
      
    Watch the sign rule in those last cases: a negative number gives a negative remainder in Go, not the "wrapped round" number you might want for a clock. When a value might be negative, code often adds the divisor back before taking the remainder.
    
    
    
  
    

  
    
    Common wrong ideas
    
    
      
      
        
    • "7 / 2 is 3.5." Not for two whole numbers: it's 3. Write 7.0 / 2 for 3.5.
      • 
        
    • "Integer division rounds." It chops. 3.9 becomes 3, and -3.5 becomes -3 (toward zero, not down).
      • 
        
    • "-7 % 3 is 2." Some languages say so. Go says -1: the remainder has the sign of the left side.
      • 
        
    • "% is percent." It's the remainder. Nothing to do with percentages.
      • 
        
    • "6.0 / 2 printed 3, so it's an integer." It's a float; Println just doesn't show a .0.
      • 
        
    • ""Age: " + 36 should just work." Go never mixes a string and a number by itself. Use a comma in Println.
      • 
        
    • "2 + 3 * 4 is 20, reading left to right." * goes first: 14.
      • 
        
    • "gofmt might break my program." It only moves spaces and line breaks. The program does exactly the same thing.
      • 
        
    • "No squiggles, so it's correct." No squiggles means no mistakes the helpers recognise. Your logic can still be wrong: Go happily computes the wrong sum if you typed the wrong sum.
      • 
        
    • "Fix every error message from the bottom up." First error first. Then run again.
      • 
        
    • "The column is counted in spaces." It's counted in characters. A tab is one.
      • 
      
    
    
    
  
    

  
    
    Lab: run it yourself (Windows, macOS, Linux)
    
    
      
    1. Set up VS Code
    
      
      
        
    1. Download VS Code from code.visualstudio.com. Windows: run the installer. macOS: drag it into Applications. Linux: use the .deb or .rpm package, or your distribution's software store.
      2. 
        
    2. Open the Extensions panel (the four-squares icon), search Go, and install the one published by the Go team at Google.
      3. 
        
    3. Open any .go file. When the extension offers to install tools such as gopls, accept. If you missed it: open the Command Palette (Ctrl+Shift+P, or Cmd+Shift+P on a Mac) and run Go: Install/Update Tools.
      4. 
        
    4. Settings (Ctrl+, or Cmd+,): search format on save and make sure it's ticked.
      5. 
        
    5. Open your project folder (File, Open Folder), the one with go.mod, not just a single file. gopls works best that way.
      6. 
      
    
      
    2. Try the tools in a terminal
    
      
    VS Code has one built in: Terminal, New Terminal. In your project folder:
    
      
      
        
    1. gofmt -l . lists untidy files. gofmt -d main.go shows the changes. gofmt -w main.go makes them. (gofmt comes with Go: it's in the same folder as go, so if go version works, gofmt does too.)
      2. 
        
    2. go fmt ./... tidies every package in the module.
      3. 
        
    3. go vet checks the package in this folder; go vet ./... checks them all. Silence and exit code 0 mean nothing suspicious.
      4. 
        
    4. Seeing exit codes: on macOS and Linux type echo $? right after a command; in PowerShell type $LASTEXITCODE.
      5. 
      
    
      
    3. Break it on purpose
    
      
      
        
    1. Remove a comma between two values in a Println. Watch the squiggle appear, hover it, then compare with go run.
      2. 
        
    2. Mess up the spacing badly, then save. Watch Tidy fix it. Now add a missing comma and save again: nothing gets tidied until you fix it.
      3. 
        
    3. Delete import "fmt" and count the undefined: fmt messages. Then save: VS Code may put the import back for you.
      4. 
        
    4. Try fmt.Println(7 / 0) and fmt.Println(7.5 % 2). Read both addresses.
      5. 
        
    5. Predict, then check: fmt.Println(-7 / 2, -7 % 2, 7 / -2, 7 % -2).
      6. 
      
    
      
    4. No install? Use the Playground
    
      
    go.dev/play runs every program in this chapter. Its Format button runs gofmt for you.
    
      
    Different output? Error wording can change a little between Go versions. For example, Go 1.24 printed vet's messages with # header lines and pointed at a different column of the Printf line, and its gofmt -d ended with exit code 0 instead of 1. The idea, read the address and the message, stays the same.
    
    
    
  
    

  
    
    Words from this chapter
    
    
      
    
        
    code editor
    A text editor made for programs, like VS Code.
    
        
    extension
    An add-on for an editor. The Go extension adds Go support to VS Code.
    
        
    gopls
    Go's language server, said "go please". It reads your code as you type and powers squiggles, hover help and autocomplete.
    
        
    language server
    A helper program that understands a language and tells the editor what it finds.
    
        
    squiggle
    A red wavy underline marking a mistake in the editor.
    
        
    format on save
    An editor setting that tidies the file every time you save.
    
        
    gofmt
    Go's official formatter. -l lists untidy files, -d shows the changes, -w writes them.
    
        
    diff
    A list of differences between two versions: - lines go, + lines come.
    
        
    go vet
    A checker for code that compiles but is probably wrong.
    
        
    analyzer
    One of vet's small checkers, each looking for one kind of mistake.
    
        
    header line
    The # … line before compile errors, naming the package being built.
    
        
    address
    file:line:column: where an error is. Street, house, door.
    
        
    column
    A character position in a line, counted from 1. A tab counts as one.
    
        
    undefined
    A name Go doesn't know, like fmt without its import.
    
        
    value
    One piece of data, like 42, 3.5, "Go!" or true.
    
        
    literal
    A value written directly in the code.
    
        
    integer / int
    A whole number (Brick). int is Go's main integer type.
    
        
    float
    A number with a fractional part (Jelly).
    
        
    string
    Text, written in double quotes (Train).
    
        
    boolean
    true or false (Lamp).
    
        
    type
    The kind of a value: integer, float, string, boolean, and more later.
    
        
    untyped constant
    A literal that hasn't been pinned to an exact type yet.
    
        
    concatenation
    Joining strings end to end with +.
    
        
    escape sequence
    A backslash pair inside a string: \n new line, \t tab, \" quote, \\ backslash.
    
        
    scientific notation
    1e3 means 1 × 10³ = 1000.
    
        
    operator
    A symbol that works on values, like + or %.
    
        
    integer division
    / on two integers: the fraction is chopped off, toward zero.
    
        
    float division
    / when either side is a float: keeps the fraction.
    
        
    remainder
    %: what's left over after integer division. Its sign follows the left side.
    
        
    dividend / divisor
    In 7 / 2, 7 is the dividend (what's shared) and 2 the divisor (how many ways).
    
        
    truncate
    To chop off the fraction without rounding.
    
        
    precedence
    Which operators go first: * / % before + -.
    
        
    parentheses
    ( ), which make their contents go first.
    
        
    constant expression
    A sum made only of constants, worked out by the Compiler.
