    24
    
        The mode is a sign on the door. Pick the right one!
        
    
          
      
        • "r" read
          The default. Read what's there. Missing file? FileNotFoundError. Writing is refused.
          • 
      
        • "w" write ⚠
          Creates the file, or wipes it empty first if it exists. Then you write from scratch.
          • 
      
        • "a" append
          Adds to the end and keeps what was there. Creates the file if needed.
          • 
    
        
    
        
      
      
        Pip says: "w" wipes first. And f.write() never adds a newline by itself: you write the \n.
        
    
        
    
        Picture: three door signs. r for read, w for write with a warning sign and a dashed pink border, a for append.

    Under the hood: what with, buffers and file objects really do
    
          
      
          with is a promise to close
          
      
          A file object talks to the operating system on your behalf. with open(...) as f: guarantees f.close() runs when the block ends, even if an exception escapes from inside it. It is shorter and safer than calling close() yourself, and it is what the official tutorial recommends.
          
      
          Buffers: why closing matters
          
      
          Writing to a disk is slow, so a file object collects small writes in a buffer and sends them in bigger batches. Until the buffer is flushed (when it fills up, when you call f.flush(), or when the file closes) the text may not be in the file yet. Boss exercise 2, run for real:
          
      
          
      
          Append mode, run for real
          
      
          Mode "a" opens a file for adding: every write goes after what is already there, and nothing is wiped. This program writes Monday with "w" (a fresh file), then opens it again with "a" to add Tuesday:
          
      
          
      
          A file object remembers its place
          
      
          Reading moves a position forward through the file. After f.read() the position is at the end, so a second read gets nothing. Open the file again (or f.seek(0)) to start over.
          
      
          
      
          Where does "note.txt" go?
          
      
          A plain file name is a relative path: it is looked up in the current working directory, the folder your terminal was in when you started Python. That is not always the folder the script lives in. If you run python3 python-ch10/book_v7.py from your home folder, Python looks for recipes.txt in your home folder.
          
      
          
      
          Text mode, newlines and encodings
          
      
          In text mode, Python turns the operating system's line endings (Windows uses \r\n) into a plain \n when reading, and back again when writing, so your code can always use \n. Characters are stored as bytes using an encoding. Python 3.15 uses UTF-8 by default for open() (PEP 686). Python 3.14 and older use the computer's "locale" encoding, which on many Windows machines is not UTF-8, so a file with crème brûlée in it can come out garbled or crash. Writing encoding="utf-8" works the same on every version:
          
      
          
    
          
  
          

  
          
    In real programs: csv, json, and safer saves
    
          
      
          Our name,item,amount format is a home-made CSV (comma-separated values). It breaks the day a recipe is called mac, cheese: split(",") would cut it in two. The standard library's csv module puts quotes around values that contain commas, and reads them back correctly:
          
      
          
      
          For nested data like our dict of dicts, JSON is even simpler: json.dump writes the whole structure, and json.load rebuilds it, keeping ints as ints.
          
      
          
      
            
        
          • pathlib gives tidy paths: Path("recipes.txt").read_text(encoding="utf-8") reads a whole file in one call.
            • 
        
          • Safer saves. Real apps write to a temporary file first and then rename it over the old one, so a crash halfway through a save can never leave half a file.
            • 
        
          • Validation everywhere. Files are typed by people too. Real loaders report the line number of a bad line instead of crashing.

    Common wrong ideas
    
          
      
            
        
          • "Mode "w" adds to the file." It wipes it first. Adding is "a".
            • 
        
          • "write() starts a new line." It writes exactly what you give it. You add \n.
            • 
        
          • "print(line) is fine." Each line keeps its \n; print adds another, so you get double spacing. Strip first.
            • 
        
          • "split() and split(",") are the same." No arguments means "cut at any whitespace". split(",") cuts only at commas.
            • 
        
          • "Numbers read from a file are numbers." Everything read from a text file is text. Convert with int() or float().
            • 
        
          • "The file is found next to my script." It is found in the current working directory. See "Under the hood".
            • 
        
          • "The line in the traceback is where the bug is." It is where the program noticed. In the v4 spot exercise the mistake was three lines earlier.
            • 
        
          • "Reading a file twice works." The second read() starts at the end and returns ''.
            • 
        
          • "int(" 12 ") fails because of the spaces." int() ignores spaces at the ends. It fails on words and on decimal points.

    Words from this chapter
    
          
      
          
        
          version
          One working state of a program as it grows. Each version is run and checked before the next.
          
        
          diff
          A list of the lines added (+) and removed (−) between two versions of a file.
          
        
          constant
          A name for a value that should never change, written in CAPITALS by habit, like SERVES.
          
        
          file
          Named storage on a disk that keeps its contents after programs end.
          
        
          text file
          A file of characters, readable in any editor. .txt, .py and .csv files are text files.
          
        
          open()
          The built-in function that connects your program to a file and gives back a file object.
          
        
          file object
          What open() returns: you write with f.write(), read with f.read() or for line in f.
          
        
          mode
          How a file is opened: "r" read (default), "w" write from empty, "a" append.
          
        
          with block
          Code that runs while the file is open. The file closes when the block ends.
          
        
          newline, \n
          The character that ends a line in a text file.
          
        
          whitespace
          Spaces, tabs and newlines.
          
        
          .strip()
          Returns a copy of a string with whitespace removed from both ends.
          
        
          .split(",")
          Cuts a string at each comma and returns a list of the pieces.
          
        
          repr()
          Shows a value the way you'd type it in code, making hidden characters visible.
          
        
          buffer
          A waiting area where small writes collect before going to the disk.
          
        
          working directory
          The folder a plain file name is looked up in: where you started Python.
          
        
          encoding
          The rule for storing characters as bytes. UTF-8 handles every language.
          
        
          validation
          Checking input before using it, and asking again if it's wrong.
          
        
          FileNotFoundError
          Raised when you open a file for reading that does not exist.
          
        
          io.UnsupportedOperation
          Raised when you, for example, write to a file opened for reading.
          
        
          KeyError
          Raised when a dict has no such key.
