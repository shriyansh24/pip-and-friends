    Under the hood: names, objects and references
    
              
      
              In Python, a name never holds a value directly. It holds a reference: Python's way of saying "that object over there". Assignment just makes a name refer to an object. That's why we draw tags and arrows, and it's the same picture Python Tutor draws.
              
      
              Same object, or just equal?
              
      
              is asks "are these two tags on the very same object?" and id() gives each object a number that is unique while it lives. Both confirm that sidekick = hero made no copy:
              
      
              
      
              (==, which asks "do these look equal?", is a different question. It arrives with comparisons in Chapter 4.)
              
      
              When does a tag-less object really disappear?
              
      
              CPython, the standard Python, counts how many references each object has. When the count drops to zero, the memory is usually freed straight away. Two honest footnotes: text and numbers written directly in your code are also held by the program itself while it runs, and CPython keeps small whole numbers (roughly −5 to 256) alive permanently as a speed trick. So in the tracer, "faded" means "your program can no longer reach it", not "erased this very instant". You can never tell the difference from inside your program.
              
      
              How does a, b = b, a really work?
              
      
              The language rule: the whole right side is worked out first, left to right, and then the names on the left are assigned, left to right. You can watch CPython do it with the dis module, which lists the tiny instructions Python actually runs:
              
      
              
      
              Two LOAD_NAMEs fetch both objects, SWAP trades them, two STORE_NAMEs tie the tags. No spare tag needed. (The end differs between versions: 3.15 finishes with two instructions, LOAD_COMMON_CONSTANT and RETURN_VALUE, and 3.13 does the same job with one instruction, RETURN_CONST. That's an internal detail that changes between releases, so never rely on it.)
              
    
              
  
              

  
              
    In real programs: names, constants and input
    
              
      
                
        
              • Naming style is official. Python's style guide, PEP 8, asks for snake_case for variables and UPPER_CASE for constants, and says to avoid single-letter names l, O and I, which look like the digits 1 and 0 in some fonts.
                • 
        
              • Need a name that clashes with a keyword? PEP 8 suggests a trailing underscore: class_. Many programmers prefer a clearer word, like course.
                • 
        
              • Constants live at the top of a file, so anyone can find and change them in one place: prices, limits, file names.
                • 
        
              • Shadowed a built-in by accident? Deleting your tag with del uncovers the built-in again, because Python goes back to looking in its own tags:
                • 
      
              
      
              
      
                
        
              • Real programs rarely trust input() blindly. People type spaces, capital letters or nothing at all. You'll learn to clean and check input in later chapters.
                • 
        
              • f-strings are everywhere: messages, file names, web pages. They arrived in Python 3.6 (What's New in Python 3.6: formatted string literals), so every modern Python has them.
                • 
      
              
    
              
  
              

  
              
    Common wrong ideas
    
              
      
                
        
              • "A variable is a box that holds a value." Boxes break as soon as two names share one object. A tag picture explains everything a box does, and more.
                • 
        
              • "b = a makes a copy." It ties a second tag to the same object. (This matters a lot when objects can change: lists in Chapter 7.)
                • 
        
              • "After b = a, changing a changes b." Reassigning a moves only a's tag. Tags are tied to objects, never to each other.
                • 
        
              • "= means equals, so x = x + 1 is nonsense." = is an instruction: work out the right side, then tie the tag.
                • 
        
              • "If I type digits, input() gives me a number." It always gives a str.
                • 
        
              • "Constants can't be changed." Python doesn't enforce it. CAPS are a promise between people.
                • 
        
              • "print("name") prints my name." Quotes mean literal text. print(name) follows the tag.
                • 
        
              • "The line in the traceback is always the broken line." With shadowing, the damage shows up later than the mistake.
                •

    Python's reserved words (and a version difference)
    
              
      
              Python's own keyword module lists the reserved words. Run on CPython 3.15:
              
      
              
      
              
      
              The 35 hard keywords can never be names. Soft keywords are only special in certain places, so they still work as ordinary names. That's why type, match and case are legal variable names. This list really differs by version: CPython 3.13 prints no 'lazy'.     Words from this chapter
    
              
      
              
        
              variable
              A name tied to an object. This book draws it as a name tag.
              
        
              object
              A thing Python keeps in memory: a piece of text, a number, and later lists and more.
              
        
              value
              What an object stands for, like 'pizza' or 7.
              
        
              reference
              The arrow: how a name (or a container) points at an object.
              
        
              assignment
              A line like name = value: work out the right side, then tie the name to it.
              
        
              reassignment
              Assigning to a name that already exists. The tag moves.
              
        
              augmented assignment
              The shortcuts += and -=: x += 1 means x = x + 1.
              
        
              literal
              A value typed straight into the code, like "pizza" or 3.
              
        
              keyword
              A word Python reserves for itself, like class or if. Not usable as a name.
              
        
              case-sensitive
              Capitals matter: Pip and pip are different names.
              
        
              snake_case
              Lowercase words joined with underscores: Python's naming style.
              
        
              constant
              A name in ALL CAPS whose object should never be replaced. Python doesn't enforce it.
              
        
              shadowing
              Making your own name that hides a built-in one, like print.
              
        
              swap
              Making two names trade objects: a spare tag, or a, b = b, a.
              
        
              input()
              Shows a prompt, waits for Enter, hands back the typing as a str.
              
        
              prompt
              The question text input() shows before waiting.
              
        
              empty string
              Text with nothing in it: ''.
              
        
              concatenate
              Glue strings together with +.
              
        
              f-string
              A string with f in front whose { } holes are filled with values.
              
        
              TypeError
              An error meaning the wrong kinds of things met, like text + number. More in Chapter 3.
