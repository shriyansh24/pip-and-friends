Chapter 6's notebook gave you the short version. Here is the whole rule. When code uses a name, Python looks in up to four places, from the inside out, and stops at the first hit. People call it LEGB.

    

      

        
B BUILT-IN Python's own: len, print, max

        

          
G GLOBAL names made at the top of the file

          

            
E ENCLOSING names of the function around this one (and around that one…)

            

              
L LOCAL names made inside the function that is running

            

          

        

      

    

    
L→E→G→B→NameError

    

      
      
Pip says: Inside out, first hit wins. The new box this chapter is E. Only nested functions have one. If all four boxes say no, the Bouncer steps in.

    Under the hood: cells, free variables, and what @ compiles to
    
          
      
      
          Decided when the function is compiled
          
      
          Python sorts every name in a function body into a kind before the function ever runs. A name that is assigned in the body (and not declared global or nonlocal) is local. A name that an inner function uses from this function is a cell variable here, and a free variable in the inner function. That's why UnboundLocalError can happen on the very first line of a body: the decision was already made. You can see the sorting on a function's code object: co_varnames (locals), co_cellvars (cells it shares out) and co_freevars (cells it receives).

          Closures instead of globals
          
      
          A closure is a light way to give a function private memory: a counter, a running total, a "last value seen". The data can't be reached or changed from outside, except through the function.     Common wrong ideas
    
          
      
            
        
          • "A closure takes a copy of the value." It holds the variable (the cell). Later changes are seen (Panel 11), which is the root of late binding (Panel 17).
            • 
        
          • "Late binding only happens with lambda." A def inside a loop behaves exactly the same. It's about when names are looked up, not about lambda.
            • 
        
          • "I need nonlocal to use an outer variable." Only to assign to it. Reading, or changing a list in place, needs nothing (Panel 15).
            • 
        
          • "global and nonlocal are the same." global goes straight to the file's top level; nonlocal goes to the nearest enclosing function (Panel 16).
            • 
        
          • "The decorator runs every time I call the function." The decorator runs once, at decoration time. The wrapper is what runs every call (Panels 25 and 26).
            • 
        
          • "@deco changes the original function." The original is untouched; the name is moved to a new function, the wrapper.
            • 
        
          • "Stacked decorators apply from the top down." The one nearest the def wraps first (Panel 33). At call time, the top one's code runs first, from the outside in.
            • 
        
          • "@repeat and @repeat(3) are the same." With brackets, repeat(3) runs first and its result is the decorator. Without brackets, repeat itself is used as the decorator (Boss level, check 4).
            • 
        
          • "@cache makes any function faster." Only repeat calls with the same, hashable arguments; and it's only safe for pure functions.

    Version notes: what is new, and since when
    
          
      
            
        
          • nonlocal (PEP 3104): since Python 3.0.
            • 
        
          • Decorators for functions (PEP 318): since 2.4; for classes (PEP 3129): since 3.0.
            • 
        
          • Any expression after @ (PEP 614): since 3.9.
            • 
        
          • functools.cache: since 3.9. lru_cache: since 3.2; bare @lru_cache without brackets: since 3.8.
            • 
        
          • functools.wraps sets __wrapped__ since 3.2 and also copies __type_params__ since 3.12.
            • 
        
          • Inlined comprehensions (PEP 709): since 3.12. The loop variable still has its own scope, and late binding still happens: Panel 17 gives [2, 2, 2] on both 3.15 and 3.13.
            • 
        
          • UnboundLocalError's wording "cannot access local variable … where it is not associated with a value" is word for word the same on 3.15 and 3.13 (both captured). Older Pythons, and many web pages, use a different wording, "local variable … referenced before assignment"; that version was not run for this book.

    Words from this chapter
    
          
      
          
        
          nested function
          A function defined inside another function's body.
          
        
          enclosing function
          The function around a nested function. Its names are the E in LEGB.
          
        
          LEGB
          The order Python searches for a name: Local, Enclosing, Global, Built-in.
          
        
          closure
          A function together with the variables it carries from the function where it was built: a machine with a backpack.
          
        
          free variable
          A name a function uses but doesn't own or receive as a parameter, found in an enclosing function. Listed in __code__.co_freevars.
          
        
          cell
          The little shared box Python keeps a captured variable in. __closure__ is a tuple of cells.
          
        
          factory function
          A function whose job is to build and return a new function (or object).
          
        
          nonlocal
          A statement that lets a nested function assign to a variable of its enclosing function.
          
        
          global
          A statement that lets a function assign to a variable at the top level of the file.
          
        
          UnboundLocalError
          A local name was read before it got a value. Common when you assign to an outer name without nonlocal or global.
          
        
          late binding
          Looking up a name's value when the function runs, not when it is built.
          
        
          early binding
          Fixing a value when the function is built, for example with a default (i=i).
          
        
          currying
          Turning a function of several arguments into a chain of one-argument functions.
          
        
          decorator
          A function that takes a function (or class) and returns a replacement, usually a wrapper.
          
        
          wrapper
          The function a decorator returns: it runs extra steps around the original.
          
        
          @ syntax
          @deco above a def or class: shorthand for name = deco(name).
          
        
          decoration time
          When the decorator itself runs: once, when the def runs.
          
        
          call time
          When the decorated function is called: the wrapper runs.
          
        
          functools.wraps
          A decorator for wrappers that copies the original's name, docstring and other labels, and sets __wrapped__.
          
        
          metadata
          Information about a thing rather than the thing itself: a function's name, docstring, module.
          
        
          decorator factory
          A function that takes settings and returns a decorator: repeat(3).
          
        
          stacking
          Several decorators on one function. The one nearest the def applies first.
          
        
          memoization
          Saving a function's answers so a repeat call can skip the work. @cache does it.
          
        
          cache hit / miss
          A hit is an answer found in the cache; a miss means the function had to run.
          
        
          LRU
          "Least recently used": the entry lru_cache drops when it is full.
          
        
          class decorator
          A decorator placed above a class: Cat = register(Cat).
