CHAPTER 25

STENCILS AND CODEBOOKS

Picture: a smiling plastic stencil with the pattern \d+ cut into it; the string train spelling café; and a row of five byte boxes, 63 61 66 c3 a9, the same word as raw bytes.

Pip has a page full of dates, prices and phone numbers to pick out, and a file of words that comes out as gibberish. Two new tools fix both: a stencil you slide along the text until it fits, and a codebook that turns letters into bytes and back. About 100 minutes, with 33 hands-on checks.

Part 1 · The stencila pattern that describes a kind of text, and the search that slides it along

1

Pip's bakery gets order emails all day. Pip has to copy out every delivery date. Today there are two hundred emails.

Pip says: The dates are always different! find("2026-11-08") only finds that one date. I need "four digits, a dash, two digits, a dash, two digits"… wherever they are.

The Professor says: Then you need a stencil: a card with the shape of a date cut out of it. Slide it along the text, and wherever it fits, there's a date. In Python that stencil is a regular expression, regex for short: a little pattern that describes a kind of text.

2

Regex builds on three things you already have. If one feels shaky, its chapter has the full story.

  1. String methods (Chapter 11): find, in, split, replace, startswith, isdigit. For one exact piece of text they are simpler than any pattern. Try them first.
  2. Raw strings (Chapter 11): r"..." switches off the backslash's magic. Every pattern in this chapter wears an r, and Panel 10 shows why.
  3. Code points (Chapter 11): every character is a number in the Unicode table. ord("é") is 233. Parts 5 to 7 build on that.

    15
    
    With a range like {2,4}, how many does the stencil take? As many as it's allowed. Quantifiers are greedy: they grab the most they can.

    The Professor says: Computers can only store and send bytes: numbers from 0 to 255. A Python str is the message itself, a row of characters (code points). To save or send text, it must be turned into bytes with a codebook, called an encoding. UTF-8 is the codebook almost the whole world uses today.
    
      
    
    
    
    
      
      
    Pip says: So my friend's laptop read my dots with a different codebook! My rule: TEXT IS THE MESSAGE, BYTES ARE THE WIRE, AND THE ENCODING IS THE CODEBOOK.
    
    
    
  
    

  
    
    34

    1. 4 characters, 5 bytes. c, a and f are one byte each; é takes two.
      2. 
      
    2. b'caf\xc3\xa9': the b means bytes. Python shows bytes that happen to be ASCII letters as letters, and every other byte as \x plus two hexadecimal digits (base 16: c3 is 195).
      3. 
      
    3. list(data) shows the truth: a bytes object is just numbers.
      4.

    An old program saved "café" with the Latin-1 codebook, an older encoding for Western European languages where every character is one byte. Pip reads it back as UTF-8.
    
    
    
      decode_error.py
    
      
    
    
    
    
    Read it like a detective. This last line packs four clues:
    
    
      
      
    1. 'utf-8' codec: which codebook was used. A codec is Python's word for an encoding (coder-decoder).
      2. 
      
    2. can't decode byte 0xe9: the byte that made no sense, in hex. 0xe9 is 233.
      3.

      4.

    Under the hood: how the stencil really slides, and how UTF-8 packs its bits
    
      
      
      
      Backtracking: the stencil can bend
      
      
      Python's re module is a backtracking engine. At each starting position it works through the pattern piece by piece. When a greedy quantifier like .* has grabbed too much for the rest of the pattern to fit, the engine backs up: it gives back one character at a time and tries again. That's how <.*> in Panel 25 could still end on a >. Patterns with many nested, overlapping choices can make the engine back up an enormous number of times, which is why a badly built regex can be slow on some inputs. (Python 3.11 added possessive quantifiers such as *+ and atomic groups (?>...), which never give back; they are an advanced tool.)
      
      
      Empty matches
      
      
      A stencil that can fit nothing (zero characters) fits at every position. That surprises people:
      
      
      
      
      a* fits nothing before the b, all of aaa, and nothing at the very end. x* fits nothing between every pair of letters, so sub puts a dash in each gap. If a pattern returns empty strings you didn't expect, look for a * or ? that lets everything be optional.
      
      
      How UTF-8 lays out its bits
      
      
      The first byte says how long the character is. Continuation bytes always start with the bits 10, so a program that lands in the middle of a character can tell, and skip ahead:
      
      
        
        
      • U+0000 to U+007F (ASCII): 0xxxxxxx, one byte
        • 
        
      • U+0080 to U+07FF (é, ß, Greek, Arabic…): 110xxxxx 10xxxxxx
        • 
        
      • U+0800 to U+FFFF (€, 日, most other scripts): 1110xxxx 10xxxxxx 10xxxxxx
        • 
        
      • U+10000 to U+10FFFF (emoji, rare scripts): 11110xxx and three continuation bytes
        • 
      
      
      
      That's why \xe9 alone failed in Panel 39: e9 is 11101001, the start of a three-byte character, and no continuation bytes followed.
      
      
      More byte tools
      
      
      
      
      hex() and bytes.fromhex() convert between bytes and hex text. int.from_bytes reads bytes as one number; "big" and "little" say which byte comes first (endianness), which matters in file formats and network protocols. UTF-16 is another Unicode codebook, using two or four bytes per character; it starts with a byte order mark (BOM), \xff\xfe, to say which order its bytes are in.
      
      
      The UTF-8 BOM
      
      
      Some Windows programs put three bytes, \xef\xbb\xbf, at the start of UTF-8 files. Decoded as plain UTF-8 they become an invisible character, U+FEFF, which can break the first column name of a CSV file. The codec "utf-8-sig" removes it:
      
      
      
    
      
  
      

  
      
    Regex and Unicode: what \w and \d really mean
    
      
      
      For str patterns, Python's classes are Unicode-aware: \w matches letters in every alphabet, and \d matches any decimal digit, including Arabic-Indic digits like ٣ (three). The flag re.ASCII limits them to English letters and 0 to 9:
      
      
      
      
      So \d isn't always the same as [0-9]. When validating something that must be ASCII digits, such as a PIN for a bank's old system, write [0-9] or use re.ASCII. Patterns can be bytes too (rb"\d+"), and then they only search bytes; mixing a str pattern with bytes text raises a TypeError.
      
      
      Normalization matters for regex as well: r"café" won't find an NFD "café" in the text. Normalize the text first.
      
    
      
  
      

  
      
    In real programs: where stencils and codebooks show up
    
      
      
      Regular expressions
      
      
        
        
      • Log files. Pulling the time, level and message out of millions of lines, exactly like Panel 20.
        • 
        
      • Validation. Postcodes, order numbers and dates in forms, always with fullmatch. (For email addresses, most projects only check for an @ and then send a confirmation email: the full rules are too complicated for a sensible regex.)
        • 
        
      • Cleaning data. re.sub(r"\s+", " ", text) squashes runs of spaces; data-science libraries such as pandas accept regex in their string tools.
        • 
        
      • Web frameworks. Some web frameworks route addresses like /orders/4471 to code using patterns.
        • 
        
      • Editors and the command line. Find-and-replace in code editors, and tools such as grep, speak a regex dialect very close to Python's.
        • 
      
      
      
      Bytes and encodings
      
      
        
        
      • Networks. Everything sent over the internet is bytes. Libraries decode web pages using the encoding the server announces.
        • 
        
      • Files you don't control. Old CSV exports in cp1252, files with a BOM, mixed encodings: open with the right encoding=, and use errors="replace" only when losing a character is acceptable.
        • 
        
      • Binary formats. Pictures, zip files and sound are read with "rb". The struct module turns bytes into numbers for file formats.
        • 
        
      • Search and usernames. Sites normalize (often to NFC or NFKC) and casefold names, so "Zoë" can't be registered twice with two different ë's.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "re.match checks the whole string." It only pins the start. That confusion is exactly why 3.15 added prefixmatch. Use fullmatch to check everything (Panel 28).
        • 
        
      • "re.search returns the text it found." It returns a Match object, or None. Call .group(), after checking (Panel 7).
        • 
        
      • "The r is optional." Sometimes a pattern works without it, by luck. \b silently breaks, and other escapes warn (Panel 10).
        • 
        
      • ". means a dot." It means any character. A real dot is \. (Panel 31).
        • 
        
      • "Regex can parse anything." Nested formats such as HTML need a real parser.
        • 
        
      • "A string is stored as UTF-8." A Python str holds code points; how CPython keeps them in memory is its own business. Bytes appear only when you encode.
        • 
        
      • "len() counts what I see." It counts code points: an emoji can be 5, an é can be 2 (Panels 48 and 49).
        • 
        
      • "If no error appears, the encoding was right." Latin-1 and cp1252 decode almost any bytes without complaint and give mojibake (Panel 40).
        • 
        
      • "b"abc"[0] is b"a"." It's 97. One byte is a number.
        • 
        
      • "Python 3.15 means I can drop encoding=." Your code may run on older Pythons, or with PYTHONUTF8=0. Naming the encoding is never wrong.
        • 
      
      
    
      
  
      

  
      
    Version notes: what is new, and since when
    
      
      
        
        
      • re.prefixmatch() and Pattern.prefixmatch(): new in Python 3.15, with re.match() soft-deprecated (no warning, no planned removal). On 3.13.18 they're an AttributeError, which is why stencil_walk.py, prefix_surprise.py and pred_prefix.py fail there (Panel 26 shows one).
        • 
        
      • re.PatternError: the new name, since 3.13, of the exception once called re.error, which remains as an alias. bad_pattern.py gave the same error on both versions; only the paths and line numbers inside the re module differ.
        • 
        
      • Invalid escape sequences such as "\d" have given a SyntaxWarning since 3.12 (a quieter DeprecationWarning before that). 3.15.2 words it more helpfully and suggests a raw string; 3.13.18 says only invalid escape sequence '\d' (Panel 11).
        • 
        
      • UTF-8 mode on by default (PEP 686): new in 3.15. sys.flags.utf8_mode is 1 on 3.15.2 and 0 on 3.13.18 here (Panel 51). Switch it off with PYTHONUTF8=0 or python -X utf8=0; switch it on in older versions with PYTHONUTF8=1.
        • 
        
      • Possessive quantifiers and atomic groups in re: since 3.11.
        • 
        
      • Unicode data: each Python version ships a newer Unicode table in unicodedata, so very new emoji may have no name in older versions.
        •

    Words from this chapter
    
      
      
      
        
      regular expression (regex)
      A small pattern that describes a kind of text, used to find, check, split or replace it. The stencil.
      
        
      pattern
      The regex itself, written as a (raw) string.
      
        
      match
      A piece of text where the pattern fits.
      
        
      Match object
      What search, prefixmatch, fullmatch and finditer give for a fit: group(), span(), groups() and more.
      
        
      character class
      A set of characters, any one of which fits: \d, \w, \s, [aeiou], [^0-9].
      
        
      quantifier
      Says how many times the thing before it may repeat: ?, *, +, {n}, {n,m}.
      
        
      greedy / lazy
      A greedy quantifier takes as much as it can; a lazy one (with an extra ?) takes as little as it can.
      
        
      anchor
      A piece of pattern that matches a position, not a character: ^, $, \b.
      
        
      word boundary
      \b: the edge between a word character and anything else.
      
        
      group
      A part of the pattern in parentheses, whose text can be read back separately. A named group (?P<name>...) has a label; a non-capturing group (?:...) only groups.
      
        
      alternation
      a|b: either side may fit.
      
        
      flag
      An option for the whole pattern, such as re.IGNORECASE or re.VERBOSE.
      
        
      compiled pattern
      A Pattern object made by re.compile, with the same methods as the module.
      
        
      escape
      A backslash before a special character so that it means itself, as in \..
      
        
      validation
      Checking that input has the right shape before using it.
      
        
      soft deprecation
      The docs recommend something else, but the old name keeps working, with no warning and no removal planned.
      
        
      byte
      The unit computers store and send: a number from 0 to 255.
      
        
      bytes
      Python's frozen row of bytes, written b"...". bytearray is the changeable version.
      
        
      encoding (codec)
      A codebook for turning characters into bytes and back: UTF-8, ASCII, Latin-1, cp1252, UTF-16.
      
        
      encode / decode
      Text to bytes / bytes to text, using an encoding.
      
        
      UTF-8
      The encoding that can write every Unicode character, in 1 to 4 bytes, and matches ASCII for English letters.
      
        
      ASCII
      The oldest common encoding: 128 characters, codes 0 to 127.
      
        
      hexadecimal (hex)
      Writing numbers in base 16 with the digits 0 to 9 and a to f; one byte is two hex digits.
      
        
      mojibake
      Garbled text from decoding bytes with the wrong encoding, like cafÃ©.
      
        
      combining character
      A code point, such as an accent, that attaches to the character before it.
      
        
      normalization (NFC, NFD)
      Rewriting a string in one standard form: composed (NFC) or decomposed (NFD).
      
        
      zero-width joiner (ZWJ)
      An invisible code point, U+200D, that glues emoji together into one symbol.
      
        
      binary mode
      Opening a file with "rb" or "wb", so it reads and writes bytes, with no encoding.
      
        
      locale
      A computer's regional settings, including its default encoding.
      
        
      UTF-8 mode
      A Python setting that makes UTF-8 the default encoding regardless of the locale. On by default since 3.15.
