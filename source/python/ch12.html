BOXES INSIDE BOXES

Picture: Pip waves next to a filing cabinet with drawers labelled math and art, and a row of crates whose boxes hold more boxes: a list, a dict and another list.

          What you learned in Chapter 12
          
    
            
      
          • ZIP STOPS AT THE SHORTEST.zip(a, b) pairs items up. Add strict=True to turn uneven rows into a ValueError instead of a silent loss.
            • 
      
          • WHAT AM I HOLDING?Read index paths left to right. A dict wants a key, a list wants a number. KeyError 0 and TypeError mean you used the wrong one.
            • 
      
          • ASK FOR PAIRS WITH .items().A loop over a dict hands out keys only. Without .items() it crashes, or quietly lies.
            • 
      
          • FIRST TIME? EMPTY LIST. THEN APPEND.The grouping pattern builds a dict of lists, just as the counting pattern builds a dict of numbers.
            • 
      
          • * 3 COPIES THE ARROW, NOT THE ROW.[[0] * 3] * 3 is one row with three arrows. .copy() is shallow; copy.deepcopy() copies all the way down.
            • 
      
          • JSON FOR BOXES, CSV FOR TABLES.JSON keys come back as strings; CSV values are always strings. Convert what you load.

    Under the hood: containers hold arrows, not boxes
    
          
      
          Every tracer in this chapter draws an arrow from a list box to an inner list. That arrow is the truth: a Python list or dict never holds another object inside it. It holds references, arrows to objects that live on their own. Nesting is really arrows pointing to more arrows.
          
      
          That one fact explains the whole copy trap:
          
      
            
        
          • [row] * 3 repeats the arrow it was given. It never calls [0] * 3 again, so there is nothing new to point at.
            • 
        
          • .copy() (and list(a), and a[:]) builds a new outer box and copies the arrows into it: a shallow copy.
            • 
        
          • copy.deepcopy(a) follows every arrow, copies whatever it finds, and keeps going: a deep copy. It remembers what it has already copied, so two arrows to one inner list in the original become two arrows to one copied list, not two separate copies.
            • 
      
          
      
          Dicts behave exactly the same way. Watch a shallow and a deep copy of a dict of lists:
          
      nb_dict_copy.py
          
      
          backup sees Ada's new 85, because that list is shared. But it has no 'Cy': adding a drawer changes only book's own outer cabinet. safe sees neither change.
          
      
          zip is lazy
          
      
          zip() doesn't build a list. It hands back a zip object that makes each pair only when asked, and can be walked through only once:
          
      zip_lazy.py
          
      
          The second list(pairs) is empty because the first one used every pair up. That laziness is also why strict=True only notices a short row when it gets there (you saw that in the ex_strict.py exercise). Chapter 16 shows how these one-pass objects, called iterators, work. strict itself arrived in Python 3.10 (PEP 618).

    In real programs
    
          
      
            
        
          • Web services speak JSON. Weather, maps, games: when a program asks a server for data, the answer is usually JSON text, which json.loads turns into nested dicts and lists. Then it's index paths all the way: data["forecast"][0]["temp"].
            • 
        
          • Settings files. Many tools keep their settings in a JSON file: editors, game saves, project configs. (Python's own project files use a similar format called TOML.)
            • 
        
          • Spreadsheets. Every spreadsheet program can save and open CSV, so CSV is how tables move between people and programs. DictReader turns them into a list of dicts in one line.
            • 
        
          • Grids everywhere. Game boards, seating plans, pixel images: lists of lists, built with a loop, never with [[...]] * n.
            • 
        
          • Writing CSV. csv.DictWriter writes a list of dicts back out, quoting anything that needs it:
            • 
      
          
      csv_write.py
          
      
          The writer quoted mac, cheese for you. It also ends each line with the two characters \r\n (the CSV standard's line ending), which is one more reason for newline="" when you open the file for writing. Reading it back without newline="", as the last line does, turns those endings into ordinary newlines for printing.
          
    
          
  
          

  
          
    Common wrong ideas
    
          
      
            
        
          • "[[0] * 3] * 3 makes three rows." It makes one row and three arrows to it. Build rows in a loop.
            • 
        
          • ".copy() copies everything." It copies the outer box only. Inner lists and dicts are shared.
            • 
        
          • "zip complains if the lists differ in length." Plain zip stays silent and drops the extras. Only strict=True complains.
            • 
        
          • "for k, v in d: gives keys and values." It gives keys only. Ask for d.items().
            • 
        
          • "JSON is just Python." Close, but not the same: double quotes only, true/false/null, no tuples, no trailing commas, and keys are always strings. Python-style text makes json.loads raise JSONDecodeError.
            • 
        
          • "DictReader gives me numbers." It gives strings. Convert with int() or float().
            • 
        
          • "A deeper path is fine if it runs." Deep paths fail silently when they pick the wrong but existing box, like pets[0] when you meant pets[1]. Print the intermediate steps, as path_walk.py does, when you're unsure.

    Words from this chapter
    
          
      
          
        
          zip
          Pairs up items from two (or more) rows by position, stopping at the shortest. strict=True raises ValueError if the lengths differ.
          
        
          pair
          A two-item tuple, like ("Ada", 91).
          
        
          star
          unpacking
          first, *rest = items: the starred name collects all leftover items into a list.
          
        
          nesting
          Putting containers inside containers: a list of dicts, a dict of lists, and so on.
          
        
          record
          Everything about one thing, often stored as a dict of fields, like one pet's name, kind and age.
          
        
          field
          One named part of a record: a key of that dict, such as "name".
          
        
          list of dicts
          A collection of records. What a CSV file becomes with DictReader.
          
        
          dict of lists
          Groups: each key holds a list of items, such as the names of each kind of pet.
          
        
          dict of dicts
          Records you look up by an id key.
          
        
          grid
          A list of lists, read as grid[row][column].
          
        
          index path
          A chain of brackets like data["pip"]["scores"][1]. Each bracket works on what the previous one handed back.
          
        
          grouping
          pattern
          First time you see a key, store an empty list; then append. Builds a dict of lists.
          
        
          setdefault
          d.setdefault(key, default) returns the value for key, first storing default if the key is missing.
          
        
          reference
          The arrow from a name or a container to an object.
          
        
          shallow copy
          A new outer container holding the same references: a.copy(), list(a), a[:].
          
        
          deep copy
          A copy of the container and everything inside it, all the way down: copy.deepcopy(a).
          
        
          JSON
          JavaScript Object Notation: a text format for nested data, with objects, arrays, strings, numbers, true, false and null.
          
        
          serialize
          To turn data in memory into text or bytes that can be saved or sent. json.dumps serializes; json.loads turns the text back into data.
          
        
          JSONDecodeError
          Raised when text isn't valid JSON. A kind of ValueError.
          
        
          CSV
          Comma-separated values: a table as text, one row per line, with a header line naming the columns.
          
        
          DictReader
          Reads a CSV file as a list of dicts keyed by the header. Every value is a string.
          
        
          Path
          A pathlib object for a file location: join parts with /, check exists(), use read_text and write_text.
