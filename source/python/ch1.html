A program is a list of instructions, written in a file. Like a recipe card. Each instruction is called a statement.

  2. print("Python runs one line at a time")
  3. print("Top to bottom")

So what is "Python"? Two things that share one name.

THE LANGUAGEPython: the rules for writing

The words and grammar you write in: print, quotes, brackets, and where each one goes. Python has a rule checker that knows every rule: the Proofreader. You'll meet him in Part 5.

THE INTERPRETERpython3: the program that runs it

A program on your computer that reads your .py file and carries it out, line by line. That's me!

The Professor says: Deep down, a CPU only understands machine code: long patterns of 0s and 1s. You write Python; the interpreter does the translating.

    Under the hood: what happens when you run a file
    
        
      
        Running a file has two phases. First Python reads the whole file and turns it into bytecode, a compact list of simple steps (the Proofreader's job: this is where SyntaxError and IndentationError come from). Only then does it run that bytecode, top to bottom (Pip's job). Both programs below have a problem on line 2:
        
      
        
        
        syntax_first.py
        Line 1 never ran. The missing quote was found while reading.
        
        
        name_later.py
        Line 1 ran and printed one. The unknown name was only found at line 2.
        
      
        
      
        The program called python3 on most computers is CPython, the reference interpreter, itself written in the C language. Other interpreters exist (PyPy, MicroPython for tiny boards), but they all read the same Python language.
        
      
        IndentationError is a kind of SyntaxError
        
      
        Python's error types form a family tree. IndentationError is a child of SyntaxError, which is why both come from the Proofreader and both stop the run before line 1. A third member, TabError, is a child of IndentationError. issubclass asks Python "is this kind a child of that one?":
        
      
        
      
        print is a function
        
      
        A function is a named piece of code you call with brackets. A call also hands back a result. print shows its arguments and hands back None, Python's word for "no value". So printing what print hands back shows the text, then None:
        
      
        
      
        The full signature is print(*objects, sep=' ', end='\n', file=None, flush=False). The star means "any number of values". file and flush come much later.
        
    
        
  
        

  
        
    In real programs: output streams, exit codes, comments
    
        
      
        A running program has two output streams. Normal output goes to standard output (stdout); error messages go to standard error (stderr). The red text in the terminals came from stderr.
        
      
        Every program also ends with an exit code: 0 means success, anything else means failure. Scripts and test tools read it to decide what to do next.
        
      
        
      
        Professional code uses comments sparingly: to explain why something odd is done, to credit a source, or to mark a to-do (# TODO: ...). Many teams also start a file with a comment saying what it is for. Clear code plus a few "why" comments beats a comment on every line.
        
      
        Professionals keep a >>> prompt open all day as a scratchpad: to check how something behaves before writing it into a file.
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "The quotes get printed." They don't. print("Hi") shows Hi.
          • 
        
        • "Python will understand what I meant." It won't. Print and print are different names.
          • 
        
        • "An error means I broke something." Nothing is damaged. Read the last line first, then the line number.
          • 
        
        • "A # anywhere starts a comment." Not inside quotes: "#1 fan" is text.
          • 
        
        • "I should type the >>> too." No. It's the prompt Python shows. Code copied from a tutorial with >>> in front fails in a file:
          
          • 
        
        • "The 'Did you mean' hint is always right." It's a guess. Panel 35 and Boss 6 show two wrong guesses.
          • 
        
        • "Curly quotes are fine." Word processors and some chat apps turn " into curly quotes. Python only accepts straight ones:
          
          
          Write code in a code editor, not a word processor.
          • 
        
        • "The line number is always where the mistake is." It is where Python noticed. Usually that is the line, but check the line above too, especially for brackets.
          •

        3. Leave with exit(), or Ctrl+D (macOS, Linux) or Ctrl+Z then Enter (Windows).
          4. 
      
        
      
        Since Python 3.13 the prompt is coloured and has extras, such as editing several lines at once (What's New in Python 3.13: a better interactive interpreter). Older versions look plainer. The >>> works the same way in all of them.
        
    
        
  
        

  
        
    How to ask for help: the long version
    
        
      
          
        
        • Search first, smartly. Paste the last line of the error into a search engine. Remove anything that is only yours: file paths, your own names, your text in quotes.
          • 
        
        • Make it small. Delete lines until the error disappears; the last line you deleted is a strong suspect. The smallest program that still shows the problem is called a minimal reproducible example.
          • 
        
        • Explain it to a rubber duck. Describe your program, line by line, out loud, to anyone or anything. Programmers really do this; saying what each line should do often reveals the one that doesn't.
          • 
        
        • Paste text, formatted as code. On most forums, put three backticks ``` on the line before and after your code so spaces at the start of lines survive.
          • 
        
        • Be kind and follow up. Say what fixed it. The next learner with the same error will find your answer.

    Words from this chapter
    
        
      
        
        
        computer
        A machine that takes input, follows instructions, and gives output.
        
        
        CPU
        The part of a computer that carries out instructions, one tiny step at a time.
        
        
        memory
        Where a running program and its data are kept while it works.
        
        
        program
        A file of instructions Python follows from top to bottom.
        
        
        machine code
        The patterns of 0s and 1s a CPU understands directly.
        
        
        Python
        A programming language; also, loosely, the program that runs it.
        
        
        interpreter
        A program that reads code and carries it out. python3 (CPython) is one.
        
        
        terminal
        A window where you type commands, like python3 hello.py.
        
        
        script
        A Python program saved in a .py file and run as a whole.
        
        
        >>> prompt
        Python's interactive mode (also called the REPL: read, evaluate, print, loop). It runs one line at a time and shows each value.
        
        
        statement
        One instruction, usually one line.
        
        
        function
        A named piece of code you call with brackets, like print(...).
        
        
        argument
        A value you hand to a function inside its brackets.
        
        
        sep / end
        Settings of print: the glue between values (default one space) and what comes after the last value (default a new line).
        
        
        string
        Text in quotes, like "Hello, world!" or 'Hi'.
        
        
        escape sequence
        A backslash plus a character that means something special, like \n (new line) or \'.
        
        
        comment
        Text after a # (outside quotes). Python ignores it.
        
        
        indentation
        Spaces at the start of a line. In Python they have meaning.
        
        
        SyntaxError
        The code is not written in a form Python can read. Nothing runs.
        
        
        IndentationError
        A kind of SyntaxError: a line is indented where it shouldn't be (or not where it should). Nothing runs.
        
        
        NameError
        The program used a name Python does not know.
        
        
        traceback
        The report Python prints when an error happens: where it was, and what went wrong.
        
        
        caret
        The ^ marks under a copied line, pointing at the trouble.
        
        
        exit code
        A number a program ends with: 0 for success, anything else for failure.
