CHAPTER 20

SOCKETS AND STAMPED FORMS

Two pictures. First: the back of a blue appliance with the name plate Bag. Two cables, len() and for, are plugged into sockets named __len__ and __iter__. A third cable, +, hangs loose above a crossed-out, dashed socket named __add__. Second: a pre-printed form titled Point, with printed rows x: int and y: int = 0, filled in by hand with 3 and 4, and a red stamp reading @dataclass, __init__ __repr__ __eq__.

Why does len() work on a list but not on your own object? Every piece of Python syntax is a cable looking for a socket, and you can build the sockets. Then a rubber stamp that writes the boring methods for you. About 75 minutes, with 29 hands-on checks.

  1. Sockets on the back: syntax calls special methods
  2. Same, equal, and in order: ==, hashing, sorting
  3. Plus signs and polite refusals: +, NotImplemented, calling
  4. The stamped form: @dataclass
  5. Ready-made shapes: named tuples, enums, frozendict
  6. Which box for which data?
  7. Boss level and recap

    13
    
    Why would Python do that? Picture a set as a wall of lockers. To store a thing, Python works out a number from it, its hash, and that number picks the locker. To ask "is it in here?", Python computes the hash again and opens only that one locker. That's why sets and dict keys are so fast.
    
    
    
      
    0(8, 'clubs')
    
      
    1
    
      
    2 ✓(7, 'hearts')
    
      
    3(2, 'spades')
    
      
    An equal card asks: "hash me" → 2 → open locker 2 → compare with == → found. If two equal cards could get different numbers, Python would open the wrong locker and say "not here".
    
    
    
    
    
      
    The Professor says: The rule: things that are equal must have equal hashes. The built-in hash goes by identity, which only matched the old ==. Once you change what "equal" means, that hash would break the rule. So Python sets __hash__ to None rather than let your sets quietly go wrong.

    26
    
    Wall sockets come in standard shapes, so any lamp fits any wall. Python's sockets come in standard sets too, called protocols. A protocol is an agreement: "have these methods, and these tools will work with you". Nobody signs anything. Just having the methods is enough: Chapter 19's duck typing.
    
    
    
      
    Sized
    has __len__
    works with len(), and with if
    
      
    Iterable
    has __iter__
    works with for, list(), sorted(), in, max()…
    
      
    Container
    has __contains__
    a fast in
    
      
    Sequence
    has __len__ and __getitem__ with 0, 1, 2…
    indexing, slicing, and looping
    
      
    Hashable
    has a working __hash__ that agrees with __eq__
    set elements, dict keys
    
      
    Callable
    has __call__
    use it with round brackets
    
    
    
    
    
      
    The Professor says: The module collections.abc has a class for each of these names. You can inherit from them, and they'll even write some methods for you. The notebook has a taste. Chapter 21 shows how to write a protocol down so a checker can test it.

    Under the hood: where Python looks for sockets, and what the stamp writes
    
      
      
      
      Sockets live on the class, not the object
      
      
      When syntax uses a special method, Python looks it up on the object's class (its type), skipping the object's own attributes. So sticking a __len__ onto one object does nothing for len(), even though calling it by hand works. This is also part of why special methods are fast: the interpreter can find them without searching the object's dict.
      
      
      
      
      The oldest socket: __getitem__ alone
      
      
      Before __iter__ existed, Python looped over objects by calling __getitem__(0), __getitem__(1), … until one raised IndexError. That back-up plan still works, for for and for in:
      
      
      
      
      += falls back to +
      
      
      a += b first tries a.__iadd__(b), "add in place". If there is none, Python runs a = a + b: a new object, and the name moves to it. Lists have __iadd__ and change in place (Chapter 7's aliasing surprise); Money doesn't, so same still sees the old wallet:
      
      
      
      
      NotImplemented is not a truth value
      
      
      Since Python 3.14, using NotImplemented in an if is a TypeError. In 3.13 it only printed a DeprecationWarning and counted as true, which hid bugs:
      
      
      
      
      CPython 3.13.18:
      
      
      
      
      What the stamp really did
      
      
      @dataclass reads the class's annotations in order, builds the source code of __init__, __repr__ and __eq__ as text, and runs it, which is why a frozen dataclass's traceback mentions File "<string>". The methods are then real methods in the class's dict. fields() lists what it found, and it also sets __match_args__, which Chapter 21's match uses:
      
      
      
      
      The rules for __hash__ in a dataclass: eq=True (the default) with frozen=False sets it to None; eq=True, frozen=True writes one from the fields; unsafe_hash=True forces one even for a changeable class (the name is the warning).
      
    
      
  
      

  
      
    In real programs: validation, operators, and records everywhere
    
      
      
      Checking values as the form is filled in
      
      
      The stamp's __init__ calls a method named __post_init__ at the end, if you write one. It's the place to check values, or to work out a field from the others (field(init=False) keeps it out of the call):
      
      
      
      
      Operators you already use
      
      
        
        
      • pathlib joins paths with /: Path("data") / "scores.txt". That's __truediv__.
        • 
        
      • decimal.Decimal and fractions.Fraction do exact money and fraction maths with ordinary + and *, and mix with ints thanks to reflected methods.
        • 
        
      • datetime: subtracting two dates gives a timedelta (__sub__).
        • 
        
      • Data libraries such as NumPy and pandas overload almost every operator, so prices * 1.2 works on a whole column at once.
        • 
      
      
      
      Records in the wild
      
      
        
        
      • Dataclasses hold settings, rows read from files, and messages passed between parts of a program.
        • 
        
      • os.stat() and time.localtime() return named-tuple-like objects; csv rows are often turned into NamedTuples or dataclasses.
        • 
        
      • Enums name states and options: http.HTTPStatus.NOT_FOUND is an IntEnum whose value is 404; re.IGNORECASE is a Flag.
        • 
        
      • Libraries like attrs and Pydantic grew from the same idea as dataclasses; Pydantic also checks the labels at runtime.
        • 
      
      
      
      Building on collections.abc
      
      
      Inherit from collections.abc.Sequence, write only __len__ and __getitem__, and you get __contains__, __iter__, __reversed__, index and count for free. MutableMapping does the same for dict-like classes. If you forget a required method, you get the "Can't instantiate abstract class" error from Chapter 19.
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "Dunder methods are private." They're public hooks with reserved names. A single leading underscore (Chapter 19) is the "internal" hint; dunders mean "Python calls this".
        • 
        
      • "I should call obj.__len__() myself." Write len(obj). The built-in also checks the result (a whole number, 0 or more) and works on every type.
        • 
        
      • "I can make up my own dunder names." Names like __score__ mean nothing to Python, and a future version might claim them. Only use the documented ones.
        • 
        
      • "Defining __eq__ is harmless." It switches hashing off (Panel 12). Add __hash__, or use a frozen dataclass.
        • 
        
      • "Returning False from __add__ means no." It's an answer. Return NotImplemented to let the other side try (Panel 23).
        • 
        
      • "__radd__ runs when the left side has no __add__ at all." Also when its __add__ returns NotImplemented, like 0 + Money inside sum(). And not when both sides are the same type.
        • 
        
      • "Field types in a dataclass are checked." They're labels (Panel 29). Use __post_init__ or a checker (Chapter 21).
        • 
        
      • "A frozen dataclass is deeply frozen." Only its fields can't be re-pointed. A list inside can still be changed, and then the object can't be hashed.
        • 
        
      • "An enum member equals its value." Not for plain Enum: Light.RED == 1 is False. Use .value. (IntEnum is the exception.)
        •

      • frozendict (PEP 814): a new built-in in Python 3.15. Earlier versions give NameError (Panel 41).

    Words from this chapter
    
      
      
      
        
      special method (dunder method)
      A method with a name like __len__ that Python calls for you when it sees matching syntax.
      
        
      data model
      Python's rulebook of which special methods exist and what syntax uses each one.
      
        
      truthiness
      Whether a value counts as true or false in an if or while. Objects choose with __bool__, or __len__.
      
        
      iterator
      The dispenser from Chapter 16: an object with __next__. __iter__ must return one.
      
        
      hash
      A whole number worked out from a value, used to find it quickly in a set or dict. Equal values must have equal hashes.
      
        
      hashable / unhashable
      Has a working __hash__ (can be a set element or dict key) / doesn't.
      
        
      rich comparison
      The six comparison sockets: __eq__, __ne__, __lt__, __le__, __gt__, __ge__.
      
        
      total_ordering
      A class decorator in functools that fills in the missing comparison methods from __eq__ and one other.
      
        
      operand
      A value on either side of an operator: in a + b, a and b.
      
        
      operator overloading
      Giving an operator like + a meaning for your own class.
      
        
      NotImplemented
      A special value a socket returns to say "I don't handle this; ask the other side".
      
        
      reflected method
      The right-hand-side version of an operator socket, such as __radd__, tried when the left side refuses.
      
        
      callable
      Anything you can call with round brackets: functions, classes, and objects with __call__.
      
        
      protocol
      An informal agreement: "have these methods, and these tools will work with you".
      
        
      dataclass
      A class made with @dataclass, which writes __init__, __repr__ and __eq__ from its fields.
      
        
      field
      One row of a dataclass: a name, an annotation, and maybe a default.
      
        
      annotation
      A label after a colon, like : int. Stored, but not checked by Python.
      
        
      default_factory
      A zero-argument function a dataclass calls to make a fresh default for each object, like list.
      
        
      mutable default
      A changeable default value, such as a list, that would be shared by every object.
      
        
      frozen
      A dataclass whose fields can't be reassigned after creation; it raises FrozenInstanceError.
      
        
      slots
      A fixed list of attribute names (__slots__); the object has no __dict__, so new attributes can't be added.
      
        
      named tuple
      A tuple whose positions also have names: typing.NamedTuple or collections.namedtuple.
      
        
      enum, member
      A class whose instances are a fixed menu of choices; each choice is a member, with a name and a value.
      
        
      IntEnum, Flag
      Enums whose members are ints / can be combined with |.
      
        
      frozendict
      A built-in dict that can't change, new in Python 3.15.
      
        
      sum type
      A value that is exactly one of several shapes, each with its own fields.
