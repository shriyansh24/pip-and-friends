RUST · CHAPTER 5

LAPS AND EGG CARTONS

Picture: Mabel the librarian waves. Beside her, a yellow wheel creature labelled loop spins round and round, and an egg carton holds six eggs labelled 3, 1, 4, 1, 5 and 9, with the cups numbered 0 to 5.

Doing something again and again, without writing it again and again. Laps that end at a whistle, laps that check a sign, laps that count cones. Then two ways to keep several values together: the lunchbox (a tuple) and the egg carton (an array). About 90 minutes, with 27 hands-on checks.

  1. Laps until the whistle: loop and break
  2. Check the sign first: while
  3. Count the cones: for, ranges, .rev() and continue
  4. Loops inside loops, and labels
  5. Lunchboxes: tuples
  6. Egg cartons: arrays
  7. Boss level and recap

PART 1 · LAPS UNTIL THE WHISTLEloop, break, a stuck loop and Ctrl-C, and break with a value

1

Mabel has 300 returned books to stamp. One stamp per book.

Mabel says: Write stamp(); 300 times? My wrist hurts already. And next week there might be 412.

Mabel says: What I want is: "stamp a book, then go round again, until the pile is empty." That's a loop: a piece of code that runs again and again. Each time round is called a lap (programmers also say an iteration).

Picture: Mabel looks at a tall pile of books with a worried face, holding her rubber stamp.

2

Rust has three loops. Picture a running track, with three different coaches.

LOOPloop { ... }

Runs laps for ever, until the coach blows the whistle: break.

WHILEwhile n > 0 { ... }

Reads a sign before every lap. "Yes" means one more lap; "no" means leave the track.

FORfor i in 0..5 { ... }

Counts numbered cones, one lap per cone, then stops by itself.

Three drawings. Loop: an oval running track with a yellow whistle in the middle. While: an oval track with a yellow sign at the start line asking "n greater than 0?". For: a straight track with five orange cones numbered 0 to 4.

    PART 2 · CHECK THE SIGN FIRSTwhile loops, and loops that run zero times
    

  
    
    8
    
    while puts a sign at the start line. The sign is a condition: a bool, exactly like an if's.
    
    
    
      
      
    • Before every lap, even the very first one, the sign is read. true: run the body once more. false: skip the body and carry on after the loop.
      • 
      
    • Something inside must change the answer, or the sign says "yes" for ever (an infinite loop).
      • 
      
    • It can run zero times: if the sign says "no" right at the start, the body never runs at all.

      PART 5 · LUNCHBOXESTuples: mixed kinds in one value, .0 .1 .2, destructuring, and the empty tuple ()
      

  
      
    24
    
      Loops repeat. Now: keeping several values together under one name. Rust has two simple containers, and they are not the same.
      
    
      
      
      
        
      LUNCHBOX · TUPLE(500, 6.4, 'z')
      
        
      
        
      • Different kinds in each compartment: a whole number, a decimal, a char.
      • Compartments are opened by position: .0, .1, .2.
      • A fixed set: no compartments added later.
      
      
      
      
      
        
      EGG CARTON · ARRAY[52, 61, 58, 49, 63, 55]
      
        
      
        
      • The same kind in every cup: here, six whole numbers (egg weights in grams).
      • Cups are numbered from 0: eggs[0], eggs[1]…
      • A fixed number of cups, for ever.
      
      
      
    
      
    
      Catchphrase: a lunchbox mixes, an egg carton matches.

        PART 6 · EGG CARTONSArrays: fixed size, one kind, indexing from 0, usize indexes, out-of-bounds panics, loops over arrays, grids
        

  
        
    29
    
        An array is an egg carton. Its type says what goes in each cup, and how many cups: [i32; 6].
        
    
        
    
          
      
        1. One kind in every cup: i32, the part before the semicolon. A carton of eggs never holds a sock.
          2. 
      
        2. A fixed number of cups: 6, the part after the semicolon. The size is part of the type, so a [i32; 6] and a [i32; 5] are different types.
          3. 
      
        3. Cups are numbered from 0. The number is the index. Six cups means indexes 0 to 5: the last index is always one less than the length.
          4. 
    
        
    
        Picture: an egg carton with a tag reading [i32; 6]. Six eggs labelled 52, 61, 58, 49, 63 and 55 sit in cups numbered 0, 1, 2, 3, 4 and 5.
        
  
        

  
        
    30

    arrays.rs
    
        
    
        
    
          
      
        1. Line 4: eggs[2] is the third egg, 58, because counting starts at 0.
          2. 
      
        2. Line 5: .len() counts the cups: 6. It's a usize, the type Rust uses for sizes and positions (Chapter 3).
          3. 
      
        3. Line 6: eggs[eggs.len() - 1] is the usual way to reach the last cup, index 5.
          4. 
      
        4. Line 7: [0; 4] is the repeat form: "the value 0, four times". Its type is written the same way, [u8; 4].
          5. 
    
        
  
        

  
        
    31

          What you learned in Chapter 5
          
    
            
      
          • LOOP RUNS TILL THE WHISTLEloop repeats for ever until break. break value makes the loop hand back a value: let x = loop { … break 6; };. Stuck? Ctrl+C.
            • 
      
          • WHILE READS THE SIGN FIRSTwhile cond { } checks before every lap, so it can run zero times. Something inside must change the answer.
            • 
      
          • THE FINISH CONE IS NOT A LAPfor i in a..b stops before b; a..=b includes it. 1..10 is nine laps. Count down with (1..=5).rev(); skip a lap with continue.
            • 
      
          • LABEL THE LOOP YOU MEAN TO LEAVEInner loops run fully for every outer lap. A plain break leaves only the innermost loop; 'outer: for … and break 'outer leave both.
            • 
      
          • A LUNCHBOX MIXES, A CARTON MATCHESTuples hold different kinds: t.0, let (a, b) = t;, and () is the empty one. Arrays hold one kind, a fixed number of times: [i32; 6], [0; 5].
            •

    Under the hood: how for really works, and what cartons look like in memory
    
          
      
          A range is a value
          
      
          1..4 isn't special loop syntax: it's an ordinary value of type Range<i32>, which you can store in a box and print. A for loop works with anything that is an iterator, something that can be asked "next one, please?" until it answers "no more". Each lap of for x in thing asks thing for its next value; when there isn't one, the loop ends. That's why a range of floats was refused in panel 13: there's no sensible "next float".
          
      
          Arrays sit side by side
          
      
          An array's cups are stored one after another in memory, with nothing in between. So [i32; 6] takes 6 × 4 = 24 bytes, and the computer finds cup i by jumping i × 4 bytes from the start. That's why indexes start at 0: cup 0 is "zero jumps from the start". Tuples can contain padding: the computer likes a 4-byte u32 to start at a position divisible by 4, so (u8, u32) takes 8 bytes, not 5.
          
      sizes.rs
          
      
          () really takes 0 bytes: an empty lunchbox costs nothing.
          
      
          The bounds check
          
      
          Every eggs[i] that the Compiler can't prove safe gets a hidden check: "is i less than the length? If not, panic." It's very cheap, and the optimizer removes it when it can prove the index is always fine. A for egg in eggs loop never needs the check at all, which is one more reason to prefer it over index loops.
          
      
          A loop that never ends has a type too
          
      
          A loop with no break can never finish, so it never produces a value. Rust gives it the special type !, called "never". Later chapters come back to it.
          
      
          Why loop and while true are not the same to the Compiler
          
      
          The warning's stated reason is clarity: loop says "for ever, until break" directly, so a reader doesn't have to check that the condition really is always true. There's also a practical difference: the Compiler treats while true like any other while, so it can't hand back a value. Only loop can break with one:
          
      while_value.rs
          
      
          The run shows the while_true warning (with its help: use `loop`) and then error E0571, the same code as panel 23's knock-on error: a while loop can't break with a value.
          
    
          
  
          

  
          
    In real programs: game loops, step_by, enumerate and when to use arrays
    
          
      
            
        
          • Game loops and servers are loops: draw the screen, read the keys, update the world, repeat until the player quits. A web server loops "wait for a visitor, answer them" for as long as it runs.
            • 
        
          • Retry loops: try something (connect to a network, read a file) up to 3 times, with break as soon as it works.
            • 
        
          • Prefer for x in array over index loops. No off-by-one, no panic, no bounds checks. Reach for indexes only when you really need the position.
            • 
        
          • Need the position and the value? .iter().enumerate() hands you both at once. It's a preview of the iterator tools in Chapter 20:
            • 
      
          
      extras.rs
          
      
            
        
          • .step_by(5) counts in fives. (0..=20).step_by(5) gives 0, 5, 10, 15, 20.
            • 
        
          • A range can be stored and asked questions: r.len() says how many numbers it holds, without looping.
            • 
        
          • Arrays in real code hold things whose count never changes: the 7 days of the week, the 12 months, the 3 colour channels of a pixel, a 3 × 3 board for noughts and crosses, or a fixed-size buffer. Anything that grows (a shopping list, the lines of a file) is a Vec (Chapter 11).
            • 
        
          • Tuples in real code are small and short-lived: a function returning two things at once, like a minimum and a maximum, or a point (x, y). When the fields deserve names, a struct is better (Chapter 10).

    Common wrong ideas
    
          
      
            
        
          • "1..10 includes 10." It stops at 9. Use 1..=10.
            • 
        
          • "10..1 counts down." It's an empty range: the loop body never runs, with no error. Use (1..=10).rev().
            • 
        
          • "A while loop always runs at least once." It checks first, so it can run zero times. A loop body always runs at least once.
            • 
        
          • "break leaves all the loops." Only the innermost one. Use a label to leave an outer one.
            • 
        
          • "continue ends the loop." It ends the current lap and starts the next.
            • 
        
          • "A loop label is a variable." Labels start with an apostrophe and can only be used with break and continue. Without the apostrophe you get E0425.
            • 
        
          • "The first egg is eggs[1]." It's eggs[0]. The last is eggs[eggs.len() - 1].
            • 
        
          • "Any integer can be an index." Only usize. Convert on purpose with as usize if you have to, or better, make the box a usize from the start.
            • 
        
          • "An out-of-bounds index reads garbage, like in C." Rust always checks: a compile error if it can see it coming, a panic if not.
            • 
        
          • "An array can grow if I make it mut." mut lets you change the eggs, never the number of cups. Growing lists are Vecs.
            • 
        
          • "A tuple is a small array." A tuple's compartments can all be different types, and you open them with .0, never with [0]. You can't loop over a tuple with for.
            • 
        
          • "The error is always on the line the arrow points at." The arrow shows where the problem was noticed. In spot_index.rs the cause was two lines earlier.

    Words from this chapter
    
          
      
          
        
          loop
          Code that runs again and again. Also the Rust keyword loop, which repeats until break.
          
        
          lap / iteration
          One time round a loop.
          
        
          body
          The code between a loop's braces.
          
        
          break
          Leave the loop now. break value also hands a value out of a loop.
          
        
          continue
          Skip the rest of this lap and start the next one.
          
        
          infinite loop
          A loop that never stops. Stop a stuck program with Ctrl+C.
          
        
          while
          A loop that checks a bool condition before every lap.
          
        
          for
          A loop that runs once for each item of a range or a collection.
          
        
          range
          a..b (from a, stopping before b) or a..=b (including b).
          
        
          iterator
          Something that can hand out "the next value" until there are none left. Ranges and arrays can be walked as iterators.
          
        
          .rev()
          Walk a range backwards.
          
        
          off-by-one
          A bug where something happens one time too many or too few, often from .. versus ..=, or < versus <=.
          
        
          nested loop
          A loop inside another loop's body.
          
        
          loop label
          A name like 'outer: in front of a loop, so break 'outer or continue 'outer can target it.
          
        
          warning
          A message from the Compiler that doesn't stop the build, like while_true.
          
        
          tuple
          A fixed group of values of possibly different types: (500, 6.4, 'z').
          
        
          field
          One compartment of a tuple, opened with .0, .1…
          
        
          destructuring
          Unpacking a tuple (or more) into names with a pattern: let (a, b) = pair;.
          
        
          pattern
          The shape on the left of a destructuring let.
          
        
          unit, ()
          The empty tuple: "nothing to hand back". 0 bytes.
          
        
          array
          A fixed number of values of one type, side by side: [i32; 6].
          
        
          repeat form
          [value; n]: n copies of the value.
          
        
          index
          A cup's number, from 0. Must be a usize.
          
        
          out of bounds
          An index that's too big for the array: a compile error or a run-time panic.
          
        
          panic
          Rust stopping a program on purpose because something impossible was asked. Exit code 101.
          
        
          slice
          A view of some of an array's cups. Mentioned in an error message here; Chapter 9.
          
        
          Vec
          Rust's growable list, the accordion folder of Chapter 11.
