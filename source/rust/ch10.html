RUST · CHAPTER 10

FORMS AND REMOTE CONTROLS

Picture: Mabel points at a clipboard holding a filled-in library card form, with boxes for name (Ana), age (12) and books (3). Beside it stands a remote control with three buttons: an eye, a dial and a wrench.

So far every value has been a single thing: a number, a String, a tuple. Today Mabel designs her own kind of value: a form with labelled boxes, called a struct. Then she clips a remote control to it: buttons, called methods, that look at the form, change it, or take it apart. About 110 minutes, with 25 hands-on checks.

  1. The blank form: defining a struct and filling it in
  2. Shortcuts on the form: shorthand and ..other
  3. Numbered boxes, blank tags, and printing a form
  4. The remote control: impl and &self
  5. Three kinds of buttons, and the factory button ::new
  6. Compile or not? Detective drills
  7. Boss level and recap

STRUCTthe blank form
A struct (short for "structure") is a new type you design yourself. It lists named fields, each with its own type. Nothing is stored yet: it's a design.

      
INSTANCEa filled-in form
An instance is one real value of that type, with a value in every field. card, ana, ben: all instances of the same Card struct.

    23
    
      A method is a function that belongs to a type, like a button on that type's remote. Every button gets the device itself as its first input, called self. There are three kinds of buttons, depending on how they get the device.
      
    
      
    
        
      
      • LOOK&selfBorrows the device to read it. Most buttons are this kind.
        • 
      
      • CHANGE&mut selfBorrows the device to change its settings. Then hands it back.
        • 
      
      • TAKE APARTselfTakes ownership of the device. It's gone afterwards; maybe you keep a part.
        • 
    
      
  
      

  
      
    24
    
      The same job, three ways: a loose function, a method, and the method called "the long way".
      
    fn_vs_method.rs
    
      
    
      
    
        
      
      1. Line 6: a loose function, as in Chapter 8: it borrows a &Rect to read it.
        2. 
      
      2. Line 10: impl Rect { opens an implementation block: "here are the buttons for Rect". Everything inside belongs to Rect.
        3. 
      
      3. Line 11: fn area(&self). The first parameter is the device itself. &self is short for self: &Self, and inside an impl Rect block, Self means Rect. So it's exactly line 6's &Rect, with a standard name.
        4. 
      
      4. Line 19: rug.area(). You don't write &rug: the dot lends rug to the method by itself. This is automatic referencing.
        5. 
      
      5. Line 20: proof. Rect::area(&rug) is what the dot really does. Same answer, 12.
        6.

        One more kind of function in an impl block: one with no self at all. It isn't a button on a radio; it's the factory that makes radios.
        
    assoc_new.rs

    Under the hood: how big a struct is, and what a method really is
    
        
      
        
        
        
        The Professor says: A struct costs nothing extra: its fields, side by side, plus a little padding. A method costs nothing extra either: it's an ordinary function with a nicer way to call it.
        
      
        
      
        Fields side by side
        
      
        A struct's fields are stored next to each other, in one block, wherever the struct lives: on a plate of the stack for a local variable, or inside another struct. There is no hidden header and no pointer to the struct. A String field is the 24-byte ticket (pointer, length, capacity); its letters are on the heap, as panel 5 showed.
        
      sizes.rs
        
      
        Card is 24 + 4 = 28 bytes of fields, but takes 32. Radio is 24 + 1 = 25, and also takes 32. The extra bytes are padding: the computer reads 8-byte values fastest at addresses that are multiples of 8, so the whole struct is rounded up to a multiple of 8. Rust may also reorder fields in memory to waste less space; the order you write is the order you read in code, not necessarily the order in memory. A tuple struct is laid out the same way, and a unit struct takes no space at all. (These sizes are for this 64-bit Linux machine.)
        
      
        A method is a function with self first
        
      
        radio.louder() and Radio::louder(&mut radio) compile to exactly the same thing (Card E in Part 6). When you write the dot, the Compiler looks up louder among Radio's methods, sees its receiver is &mut self, and adds the &mut for you. If the receiver were a reference already, it would add * instead. That's automatic referencing and dereferencing, and it's why Rust has no separate -> operator as C and C++ do.
        
      
        Two loans of two different fields
        
      
        The borrow checker tracks fields separately, as Chapter 9 showed for tuples: &mut card.name and &card.age may exist at the same time.
        
      field_loans.rs
        
      
        That's also why a partial move (panels 12 and 13, Card C) is allowed: Rust knows exactly which box is empty. A method, though, borrows the whole self. While radio.station()'s returned &str is still in use, you can't press a CHANGE button on that radio: E0502, Chapter 8's reader-and-writer rule.
        
      station_loan.rs
        
      
        What derive writes
        
      
        #[derive(Debug)] runs a small program at compile time (a derive macro) that writes the Debug printing code for your struct: print the name, then each field's name and its Debug form. That's why every field's type must itself be Debug. You'll meet more derivable abilities, such as Clone, PartialEq and Default, in Chapter 18.
        
    
        
  
        

  
        
    In real programs: how professionals use structs and methods
    
        
      
          
        
        • One struct per idea. A point, a user, a settings file, a game character. Functions that would take five loose arguments take one struct instead, and swapped arguments (panel 2) disappear.
          • 
        
        • Methods that take another instance. A LOOK button often borrows a second value of the same type to compare with or measure against:
          • 
      
        
      in_real.rs
        
      
          
        
        • new is a convention. Rust has no special constructor. Types often have several factories with clear names: Point::origin() above, String::with_capacity(10), Vec::new(). Big structs with many optional settings often use a builder (Chapter 28).
          • 
        
        • Newtypes everywhere. struct Meters(f64);, struct UserId(u32);: wrappers that cost nothing at run time and turn mix-ups into compile errors. A space probe was famously lost to a units mix-up between two teams' software; newtypes are one defence against that kind of bug.
          • 
        
        • Derive Debug on almost everything. It makes {:?} and the dbg! macro work, which are the first tools for "what's in this value right now?". dbg!(&card) prints the file, line, expression and value to the error stream (the error-style lines below). It was only handed a loan, &card, so card is still yours afterwards:
          • 
      
        
      dbg_card.rs
        
      
          
        
        • Validate once, at the door. Like the thermostat, a type whose constructor checks its input can be trusted everywhere else. With Chapter 14's privacy, the constructor becomes the only door.
          • 
      
        
    
        
  
        

  
        
    Common wrong ideas
    
        
      
          
        
        • "Fields must be filled in the order they were declared." They're matched by name; any order works (Exercise after panel 4).
          • 
        
        • "I can make just one field mut." Mutability belongs to the binding: let mut card covers every field.
          • 
        
        • "..other copies the other struct." It moves non-Copy fields out of it. Copy fields are copied; everything else changes owner.
          • 
        
        • "A partly moved struct is completely unusable." The fields that weren't moved can still be read (panel 13). Only the whole value, and the moved fields, are off limits.
          • 
        
        • "#[derive(Debug)] makes {} work." It makes {:?} work. {} needs Display (Boss 6).
          • 
        
        • "A struct field should be &str because function parameters are." Parameters borrow for the length of a call; a struct field would have to borrow for the struct's whole life. That needs lifetimes (Chapter 19). Use String.
          • 
        
        • "self is a keyword that means the current object, like this." It's the name of the first parameter, and its type is spelled out by &self, &mut self or self. There is no hidden object.
          • 
        
        • "new is special." It's an ordinary associated function. You could call it make; please don't.
          • 
        
        • "Type.method() works like in other languages." The dot needs a value. On a type, use :: (E0423). And an associated function can't be pressed on a value either (E0599).
          • 
        
        • "A &self method needs let mut." Only &mut self does (Card A).
          • 
        
        • "Methods slow the program down compared with functions." They are functions; the dot is just spelling.

    Words from this chapter
    
        
      
        
        
        struct
        A type you design, made of named fields (or numbered ones, or none).
        
        
        field
        One named box of a struct, with its own type: age: u32.
        
        
        instance
        One real value of a struct type, with every field filled in.
        
        
        initializer
        The Card { ... } expression that fills one in.
        
        
        UpperCamelCase
        The naming style for types: LibraryCard.
        
        
        field init shorthand
        Card { name } for Card { name: name }.
        
        
        struct update syntax
        ..other at the end of an initializer: take the remaining fields from other (copying Copy fields, moving the rest).
        
        
        partial move
        Moving one field out of a struct; the other fields stay usable.
        
        
        tuple struct
        A struct with numbered fields: struct Shelf(u32, u32);.
        
        
        newtype
        A one-field tuple struct that gives an existing type a new name and meaning, like Celsius(f64).
        
        
        unit struct
        A struct with no fields: struct Closed;. Takes no space.
        
        
        attribute
        A #[...] note to the Compiler about the item below it.
        
        
        derive
        Ask the Compiler to write an ability for you: #[derive(Debug)].
        
        
        Debug / Display
        Two printing styles: {:?} for programmers (derivable), {} for people (written by hand, Chapter 18).
        
        
        method
        A function in an impl block whose first parameter is self. Called with a dot.
        
        
        impl block
        "Implementation": the block that holds a type's methods and associated functions. A type may have several.
        
        
        receiver, self
        The value a method is called on, in front of the dot. Taken as &self, &mut self or self.
        
        
        Self
        Inside an impl block, the name of the type itself.
        
        
        associated function
        A function in an impl block with no self. Called on the type with ::, like Radio::new.
        
        
        constructor
        An associated function that makes a new instance, usually called new.
        
        
        automatic referencing
        The dot adds & or &mut (or *) to fit the method's receiver.
        
        
        getter / setter
        Methods that read a field, or change it (often checking the new value).
        
        
        path separator, ::
        Joins a type (or module) to a name inside it.
        
        
        padding
        Unused bytes added so a struct's size is a convenient multiple for the computer.
        
        
        E0063 / E0594 / E0609
        A missing field; assigning to a field of a non-mut form; no field with that name.
        
        
        E0423 / E0599
        A type used where a value belongs (Radio.new); no method with that name on this value (including an associated function pressed with a dot).
