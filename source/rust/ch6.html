RUST · CHAPTER 6

THE GUESSING GAME

Picture: Mabel the librarian waves. Beside her, an envelope with the number 42 on it slides in, and a yellow card shows a big question mark and the range 1 to 100.

Your first real program: a game that listens. The player types guesses, the program reads them, opens them up, and says too small, too big or you win. Along the way you borrow code from strangers (a crate) and learn to shrug off typos. About 90 minutes, with 25 hands-on checks.

  1. The mail slot: reading what the player types
  2. Opening the envelope: trim, parse and the Result parcel
  3. A secret number: crates, cargo add and Cargo.lock
  4. Too small, too big: cmp, Ordering and match
  5. Round and round: the game loop and bad input
  6. Boss level and recap

PART 1 · THE MAIL SLOTReading what the player types

1

Closing time at the library. The shelves are tidy, and Mabel has an idea.

Mabel says: Let's play a game. I'm thinking of a number from 1 to 100. You guess, and I'll say "too small" or "too big".

Mabel says: Every program so far only talked. This one has to listen too. Let's build it together, one small step at a time.

Picture: Mabel points at the reader, holding her ledger.

2

Real programmers don't write a whole game in one go. They build a tiny piece, run it, and climb one step higher. Here's our staircase.

  1. READa line the player types.
  2. OPEN ITand read the number written inside.
  3. PICKa secret number, with code borrowed from a stranger.
  4. COMPAREtoo small, too big, or a win?
  5. REPEATuntil the player wins.
  6. SHRUG OFFtypos instead of crashing.
3

Think of the keyboard as the library's mail slot. Whatever the player types arrives as a letter.

  1. THE SLOTRust calls it standard input, or stdin: where typing arrives.
  2. THE LETTERThe typing comes in as text, a String. Even "42" arrives as two characters, not as a number.
  3. THE EDGEPressing Enter adds an invisible newline, written \n, to the end of the letter.
  4. OPEN IT.trim() cuts off the edge.
  5. READ IT.parse() reads the number written inside.
  6. SCRIBBLESIf the letter says "abc", there's no number to read. parse reports a problem.
4

Step 1: read one line and say it back. In the terminal, the 42 after the question is what the player typed.

show_newline.rs

    11
    
trim works like scissors at both ends of the envelope. It never cuts the middle.

    
    
    
      
  • Both ends. Spaces, tabs and newlines at the start and the end go (a dot · stands for a space in the picture).
    • 
      
  • Never the middle. "4 2" keeps its space, so it still isn't a number.
    • 
      
  • Windows too. On Windows, Enter sends two characters, \r\n. trim removes both, so the same code works everywhere.

    21
    
    
    Step 3: the secret number. It has to be different every game, so it must be random.
    
    
    
      
      
    
        
    Mabel says: Rust's standard library has no dice! It's kept small on purpose.
    
        
    Mabel says: But this is a library's favourite trick: if we don't have a book, we borrow it from another library. In Rust, a shared package of code is called a crate, and the big public shelf of crates is crates.io.
    
      
    
    
    
    
    The crate everybody uses for random numbers is called rand. Cargo, Rust's project helper from Chapter 1, fetches it for you.
    
    
    Picture: Mabel shrugs in surprise. A burst says HUH.
    
  
    

  
    
    22
    
    A fresh project, then one command: cargo add rand. Then a peek at the two files it changed.
    
    
    
    
    How this run was really made: every command shown ran for real, one after another in one shell. The only extra step is before the first one: the capture first moved into a fresh, empty temporary folder (cd "$(mktemp -d -p /home/you/rust-ch6/.tmp)"), so cargo new had somewhere clean to work. The prompt shows that folder as ~.
    
    
      
      
    1. cargo new guessing_game makes a project folder; cd steps into it (Chapter 1).
      2. 
      
    2. Adding rand v0.10.3 to dependencies: cargo looked on crates.io and chose the newest version. A dependency is a crate your project depends on.
      3. 
      
    3. Features: are optional parts of a crate, switched on (+) or off (-). The defaults are fine; you can ignore this list.
      4. 
      
    4. cat Cargo.toml shows the new line under [dependencies]: rand = "0.10.3". That's all cargo add really does: it writes this line for you.
      5. 
      
    5. Locking 8 packages and grep '^name' Cargo.lock: you asked for one crate, but rand needs helper crates of its own (rand_core, getrandom, chacha20…). Each one gets a line in Cargo.lock, plus your own project.
      6. 
    
    
    
    cargo add has been built into cargo since Rust 1.62 (June 2022, according to the Rust 1.62.0 release announcement on blog.rust-lang.org). Older guides tell you to type the dependency line into Cargo.toml by hand. The result is exactly the same. (Your version number may be newer than 0.10.3 if you try this later.)
    
  
    

  
    
    23
    
    Two files, two jobs. Think of an order form and a receipt.
    
    
    
      
    
        
    CARGO.TOMLthe order form (you edit it)
    
        
        
    Says what you want: rand, version 0.10.3 or any newer 0.10 release that's meant to be compatible. Short, and written for people.
    
      
    
      
    
        
    CARGO.LOCKthe receipt (cargo writes it)
    
        
        
    Records what you got: the exact version of every crate, helpers included. Next week, next year, on a friend's laptop: the same versions, so the program builds the same way.
    
      
    
    
    
    
    
      
      
    The Professor says: Keep both files with your project. The first cargo build after adding a crate downloads it and compiles it, which takes a moment; after that it's quick, and only your own code is rebuilt. Want newer versions? cargo update rewrites the receipt.

    PART 4 · TOO SMALL, TOO BIGcmp, Ordering and match
    

  
    
    26
    
    Step 4: compare the guess with the secret. Rust's way is a balance scale: guess.cmp(&secret). The guess goes on the left pan, the secret on the right, and the scale gives exactly one of three answers.
    
    
    
      
    
        
    LESSguess 30, secret 42
    
        
        
    Ordering::Less: the guess is too small.
    
      
    
      
    
        
    GREATERguess 50, secret 42
    
        
        
    Ordering::Greater: the guess is too big.
    
      
    
      
    
        
    EQUALguess 42, secret 42
    
        
        
    Ordering::Equal: a win!
    
      
    
    
    
    
    The & in &secret means "look at it, don't take it", as in Chapter 5's for x in &arr. The answer's type is called Ordering, and it lives in std::cmp (cmp is short for compare), so the program starts with use std::cmp::Ordering;.

    compare.rs
    
      
    
    
    
    
      
      
    1. match guess.cmp(&secret_number) { … } (line 14)

      2.

      4.

      Three ways a game loop goes wrong. Each one compiles without a single complaint.
      
    
        
      
      1. No break in the win arm. The player wins, and the game asks again. And again. Forever. Stop a runaway program with Ctrl+C (Chapter 5).
        2. 
      
      2. break instead of continue for scribbles. One typo and the game quietly ends, with no message at all. Try the exercise below.
        3.

    Under the hood: the mail slot, the parcel and the dice
    
      
      
      Why the program sees nothing until you press Enter
      
      
      While you type, your keys go to the terminal, not to the program. The terminal shows them (that's the echo you see in every run) and lets you fix mistakes with Backspace. Only when you press Enter does it hand the whole line, newline included, to the program's standard input. read_line sits waiting until that line arrives.
      
      
      read_line adds; it never replaces
      
      
      The official docs say it plainly: the line is appended to the buffer, and the previous content is kept. Here are two reads into the same notepad, then clear(), which empties it:
      
      
      
      
      That's Boss 2's bug. Two cures: make a fresh String::new() on every lap (the game's way), or call guess.clear() before each read.
      
      
      When there's nothing left to read
      
      
      If the input ends (the player presses Ctrl+D on macOS or Linux, or Ctrl+Z then Enter on Windows, or a file of input runs out), read_line doesn't fail. It returns Ok(0): zero bytes read, notepad untouched. The number inside the parcel is how many bytes arrived. This run was given no input at all:
      
      
      
      
      Careful: our finished game would treat an empty notepad as scribbles and continue forever if the input ended. Real programs check for that 0 and stop.
      
      
      Shadowing doesn't throw the text away
      
      
      After let guess: u32 = …, the old String is still in memory until the end of the block; only its name is hidden (the tracer in panel 13 kept it on screen). Chapter 7 explains exactly when values are cleared away.
      
      
      Where the random numbers come from
      
      
      rand::random_range uses a generator that rand keeps for each running thread, started from randomness supplied by the operating system (that's the job of the getrandom helper in the lock file). The numbers come from a calculation, so you can also start a generator from a fixed number, a seed, and get the same "random" numbers every time. Tests and games with replays use this:
      
      
      
      
      This program prints the same three numbers on every run. use rand::prelude::*; brings in the handful of names most rand users need at once, including StdRng, SeedableRng and the random_range method. The official Rust book's guessing game uses the same prelude, with rand::rng().random_range(1..=100), which gives the same kind of result as our rand::random_range(1..=100).
      
    
      
  
      

  
      
    In real programs: input, prompts and crates
    
      
      
        
        
      • Prompts on the same line. Many programs print a prompt with print! (no newline) so the typing appears right after it. Rust's output waits for a newline before it shows up, so such programs call io::stdout().flush() before reading. This chapter used println! to keep things simple.
        • 
        
      • Input from files and other programs. Standard input isn't only the keyboard. In a terminal, echo 42 | cargo run -q pipes the text "42" into the program as if typed. This book's runs were captured in a similar way: a script supplied the typing, and a pseudo-terminal recorded the screen exactly as you'd see it.
        • 
        
      • expect messages say what you expected. A good message reads like "what should have been true": .expect("Please type a number!"), not .expect("error"). Chapter 13 shows how real programs handle errors without panicking.
        • 
        
      • Arguments instead of questions. Command-line tools usually take their input as words typed after the command (cargo add rand is one!). Rust reads those with std::env::args, and the popular clap crate builds whole command-line interfaces.
        • 
        
      • Choosing crates. crates.io shows each crate's downloads, documentation (on docs.rs), and how recently it was updated. Teams prefer well-known crates with good docs, and they keep Cargo.lock in version control for programs.
        • 
        
      • Testable randomness. Fixing the secret while building (panel 28) and seeding generators (previous page) are everyday tricks for making random programs repeatable.
        • 
        
      • A smart strategy. Boss 4's player halves the range every time. That's called binary search, and it finds any number from 1 to 100 in at most 7 guesses, because halving 100 seven times gets below 1.
        • 
      
      
    
      
  
      

  
      
    Common wrong ideas
    
      
      
        
        
      • "Typing 42 gives the program the number 42." It gives text: "42\n". You open it with trim and read it with parse.
        • 
        
      • "read_line replaces what's in the String." It adds to the end. Make a fresh String or clear() it.
        • 
        
      • "trim removes all the spaces." Only at the two ends. "4 2" stays "4 2".
        • 
        
      • "parse knows what number I want." It must be told: let n: u32 or parse::<u32>() (otherwise E0284).
        • 
        
      • "parse gives a number." It gives a Result parcel holding a number or an error (otherwise E0308).
        • 
        
      • "expect handles the error." It stops the program with your message. That's fine while learning, but a match that recovers (like continue) is kinder to users.
        • 
        
      • "use downloads things." use only shortens names. cargo add and the next build do the downloading.
        • 
        
      • "rand = \"0.10.3\" means exactly 0.10.3." In Cargo.toml it means "0.10.3 or a newer compatible 0.10 release". The exact version lives in Cargo.lock.
        • 
        
      • "All the match arms run." Exactly one runs: the first whose pattern fits.
        • 
        
      • "The first help: is always the fix." Panel 6's first two helps suggested cargo add io and i8. Read them all, and use your head.
        •

    Words from this chapter
    
      
      
      
        
      standard input (stdin)
      Where a program's input arrives: usually the keyboard, through the terminal.
      
        
      standard library (std)
      The tools that come with every Rust installation.
      
        
      module
      A named drawer of tools inside a library, such as std::io or std::cmp.
      
        
      use
      Brings a name within reach so you can write it short: use std::io;.
      
        
      path
      A name's full address, biggest part first: std::io::stdin.
      
        
      String
      Rust's growable text that you own. String::new() makes an empty one.
      
        
      &str
      A fixed piece of text, such as "Mabel". .to_string() makes a String from it.
      
        
      read_line
      Waits for a line of input and adds it, newline included, to a String.
      
        
      &mut
      Lending a value so it can be changed ("borrow as mutable"). Explained in Chapter 8.
      
        
      newline, \n
      The invisible character that ends a line. Enter adds one (Windows: \r\n).
      
        
      debug format, {:?}
      Prints a value as a programmer would write it, showing quotes and hidden characters.
      
        
      trim
      Gives the text without spaces, tabs and newlines at its two ends.
      
        
      parse
      Reads a value, such as a number, from text. Returns a Result.
      
        
      turbofish, ::<>
      Writing a type on a function call: parse::<u32>().
      
        
      Result
      A parcel that holds either Ok(value) or Err(error).
      
        
      .expect("msg")
      Opens a Result: gives the value inside Ok, or panics with your message for Err.
      
        
      panic
      The program stopping on purpose because something went wrong. Exit code 101.
      
        
      ParseIntError
      The error inside the parcel when text isn't a valid whole number (InvalidDigit, Empty, PosOverflow…).
      
        
      thread id
      The number in thread 'main' (1): a number the system gives the running thread. It differs between machines.
      
        
      crate
      A package of Rust code. Your own project is one, and so is rand.
      
        
      crates.io
      The public website where Rust crates are shared.
      
        
      dependency
      A crate your project uses, listed under [dependencies].
      
        
      cargo add
      Adds a dependency line to Cargo.toml (built into cargo since Rust 1.62).
      
        
      Cargo.toml
      The project's order form: its name, edition and the dependencies you want.
      
        
      Cargo.lock
      The receipt: the exact version of every crate used, written by cargo.
      
        
      feature
      An optional part of a crate that can be switched on or off.
      
        
      seed
      A starting number for a random generator. The same seed gives the same numbers.
      
        
      cmp
      Compares two values and returns an Ordering.
      
        
      Ordering
      A type with three values: Less, Greater, Equal.
      
        
      match
      Checks a value against patterns, top to bottom, and runs the first arm that fits.
      
        
      arm / pattern
      One case of a match: a pattern, =>, and the code to run.
      
        
      _
      A pattern that fits anything and doesn't name it: "I don't care what's here".
      
        
      binary search
      Finding a value by halving the range every time.
      
        
      E0284, E0308, E0433, E0596
      Type annotations needed; mismatched types; name or crate not found; can't borrow as mutable (missing mut).
