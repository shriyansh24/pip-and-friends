PLATE STACKS, HOUSE KEYS

Picture: Mabel the librarian waves. Next to her, a smiling golden key with a paper tag that says owner.

Where do your values actually live while a program runs? First we draw memory: a stack of plates for the functions that are running, and a coat-check room for things that grow. Then we meet Rust's big idea, the one that makes it different from almost every other language: ownership. Every value has exactly one owner, like a house with exactly one key. PART 1 · WHERE DO VALUES LIVE?Memory as numbered cells, and the stack: one plate per running function

1

Six chapters of lines like let age = 36;. Mabel has a question that most courses skip.

Mabel says: When you write let age = 36;, the 36 has to be kept somewhere while the program runs. Where, exactly?

Mabel says: The answer is the computer's memory (also called RAM). Today we draw it. Once you can picture it, Rust's strictest rules stop feeling strange and start making sense.

Picture: Mabel points at her ledger, looking thoughtful.

2

Picture memory as a very long wall of tiny pigeonholes, like the mail cubbies behind a library desk. Each cell holds one byte (a small number from 0 to 255), and each cell has a number painted on it: its address.

  • A value can take several cells. An i32 takes 4 bytes side by side; a bool takes 1. The value's address is the number of its first cell.
  • A name is a label for some cells. Your program says age; the computer thinks "the 4 cells starting at 1000".
  • The real row goes on for billions of cells, and the addresses here are made up. Real ones are huge numbers and change every run, so this book draws memory instead of printing real addresses.
3

A running program keeps its everyday values in a part of memory called the stack. Think of the spring-loaded plate stack in a cafeteria.

ONE PLATE PER CALL

Each time a function is called, a fresh plate goes on top: its frame, holding that call's parameters and local variables. Putting it on is called a push.

LAST IN, FIRST OUT

Only the top plate is in use. When that function returns, its plate comes off (a pop) and everything on it is gone. The plate that went on last always comes off first.

    PART 2 · THE COAT-CHECK ROOMThe heap, pointers, what a String really is, capacity, and Box
    

  
    
    7
    
    A problem: some things grow while the program runs. A guest list. A text you keep typing into.
    
    
    
      
      
    
        
    Mabel says: A plate's size is fixed before the program starts. So where do I put a String that might hold 2 letters now and 2,000 later?
    
        
    Mabel says: In the other part of memory: the heap. It's a big open room where a program can ask, while it runs, "please give me room for 5 bytes", and later "actually, make that 8".
    
      
    
    
    
    
    Picture: Mabel shrugs, puzzled.
    
  
    

  
    
    8
    
    The heap works like a coat-check room. You hand over a big, bulky coat and get back a small numbered ticket. The coat stays in the back room; the ticket goes in your pocket.
    
    
    
      
      
    • The ticket is a pointer. A pointer is a value that holds an address: "your coat is on hook #1". It's small and always the same size (8 bytes here), so it fits on a plate.
      • 
      
    • The coat is the heap data. It can be any size, and it can be swapped for a bigger one.
      • 
      
    • Fetching takes a walk. To use the coat you first read the ticket, then go to the back room. That's why heap data is a little slower to reach than plate data.
      •

          PART 3 · ONE KEY, ONE OWNEROwnership's three rules, scope, and the drop at the closing brace
          

  
          
    17
    
    
          Rust's answer to "who gives the coat back?" is a rule you already know from real life.
          
    
          
      
      
          
        
          Mabel says: Every heap value in Rust is like a house with exactly one key. Whoever holds the key is the value's owner.
          
        
          Mabel says: The owner is responsible for the house. When the owner leaves for good, the house is cleaned up and handed back. One key means exactly one owner, so the house is never cleaned up twice, and never forgotten. One key, one owner.
          
      
          
    
          
    
          
      
      
    
          
    
          Picture: Mabel points at a smiling golden key with a tag that says name, next to a little pink house with a door. A burst says CLICK.
          
  
          

  
          
    18
    
          The three ownership rules. Everything else in this chapter, and the next two, follows from them.
          
    
            
      
          1. Each value has an owner.The owner is a variable (or a parameter): the name holding the key.
            2. 
      
          2. There is only one owner at a time.Keys can be handed over, but never shared. Two names can't own the same heap block.
            3. 
      
          3. When the owner goes out of scope, the value is dropped."Dropped" means cleaned up: Rust frees its heap memory, automatically, right there.
            4. 
    
          
    
          
      
      
          Mabel says: In my library: every book has exactly one owner. When the owner leaves, the library takes the book back. The next panel shows what "out of scope" means.

    23
    
              Every language has to give heap memory back somehow. There are three main ways to do it.
              
    
              
      
              
        
              THE JANITORa garbage collector
              
        
              
        
              Go, JavaScript and Java have a helper that walks around while your program runs, finds coats nobody holds a ticket for, and hands them back. (Python mostly counts tickets instead, and keeps a janitor for the leftovers.) Easy for you, but it costs time, and you can't be sure exactly when it happens.
              
      
              
      
              
        
              DO IT YOURSELFmanual freeing, as in C
              
        
              
        
              You write "give it back" yourself. Forget, and memory leaks away. Do it twice (a double free), or use a coat after giving it back, and the program can crash or be attacked. These bugs are famous for causing security holes.
              
      
              
      
              
        
              THE OWNERRust
              
        
              
        
              The Compiler knows who owns each value and where its scope ends, so it puts the clean-up at that closing brace for you. No janitor wandering about, nothing to forget, never twice. The rules are checked before the program runs.
              
      
              
    
              
    
              Three cards. The janitor: a cleaner with a broom and a question mark. Do it yourself: two sticky notes that both say free(x), and the word TWICE. The owner: the smiling key with an owner tag.

    28
    
                Why is Rust so strict? Picture what would happen if s1 kept working.
                
    
                
    
                  
      
                • Two owners would mean two clean-ups. When both left scope, both would free block #1: a double free, one of the worst bugs a program can have.
                  • 
      
                • Copying the heap bytes instead would fix that, but could be very slow for a big String, and would happen silently on every =. Rust never copies heap data behind your back.
                  • 
      
                • So Rust moves. Cheap (only 24 bytes), and safe: the old name simply stops working. Catchphrase: give away the key, and the door stays shut.

                  PART 5 · FLYERS AND LOCKSMITHSCopy types are copied, .clone() makes a deep copy on purpose, and partial moves
                  

  
                  
    35
    
                  But wait: with numbers, let b = a; leaves a working (copy.rs in the next panel shows it). Three different things can happen when you hand a value over.
                  
    
                  
      
                  
        
                  GIVE THE KEYmove
                  
        
                  
        
                  For String, Box, vec!… anything that owns heap memory. Cheap, and a stops working.
                  
      
                  
      
                  
        
                  PHOTOCOPYCopy
                  
        
                  
        
                  For small plate-only values: numbers, bool, char. Copying a few bytes is as cheap as moving them, and there's no heap to free twice, so both names keep working.
                  
      
                  
      
                  
        
                  CUT A NEW KEY.clone()
                  
        
                  
        
                  You ask the locksmith on purpose: a.clone() builds a second, separate heap value. Both keys work, but cutting takes time.
                  
      
                  
    
                  
    
                  Three cards. Give the key: a golden key tagged b. Photocopy: a sheet of paper with a key printed on it and a COPY stamp. Cut a new key: a shiny silver key with sparkle lines, tagged spare.
                  
  
                  

  
                  
    36
    
                  Values that live entirely on the plate are marked Copy. For them, = makes a copy, and the original stays usable.
                  
    copy.rs
    
                  
    
                  
    
                  
      
      
      
      
    
                  
    
                    
      
                  • Copy: every integer type (i32, u8, usize…), f32 and f64, bool, char, and tuples and arrays whose parts are all Copy, like (i32, bool) or [i32; 3].
                    • 
      
                  • Not Copy: anything that owns heap memory: String, Box, vectors, and any tuple or array that contains one of those.
                    • 
      
                  • How to tell: when a move error says does not implement the `Copy` trait, the type is a give-the-key type. (A trait is a named ability a type can have; Chapter 17 explains them.)
                    • 
    
                  
    
                  Creatures: the orange brick holding 7 for integers, the green jelly holding 2.5 for floats, the lit lamp for bool, and the photocopied key flyer for char and Copy tuples and arrays.

                    • PLATES STACK UP: LAST IN, FIRST OUTEach function call pushes a frame onto the stack, holding its parameters and local variables; returning pops it. Everything on the stack has a size known at compile time (size_of).

    Under the hood: real stacks, real heaps, and what a move compiles to
    
                    
      
                    
        
        
                    The Professor says: The plates and the coat-check room are good pictures. Here's what they stand for.
                    
      
                    
      
                    The stack is one block of memory and a pointer
                    
      
                    Each thread gets one stretch of memory for its stack, plus a register (a tiny storage slot inside the processor) called the stack pointer, which marks the top. A call "pushes a plate" by moving the stack pointer by the frame's size, which the Compiler worked out in advance; a return moves it back. That's why the stack is so fast: no searching, just one addition. It's also why every local variable needs a size known at compile time. The stack is not huge: a Rust program's main thread usually gets the operating system's default (often 8 MB on Linux), and threads you start yourself get 2 MB unless you ask for more. A function that calls itself forever runs out of plates, and the program is stopped: a stack overflow (not run in this chapter).
                    
      
                    The heap is managed by an allocator
                    
      
                    Asking for heap memory ("allocating") goes through the allocator, a part of the standard library that keeps track of which blocks are in use and finds a free one of the right size. Freeing gives the block back to it. That bookkeeping is why the heap is slower than the stack, and why programs that allocate in a tight loop can be sped up by allocating once and reusing.
                    
      
                    A String is a vector of bytes
                    
      
                    Inside the standard library, String is a wrapper around a Vec<u8>: a vector of bytes that Rust promises is valid UTF-8 text (Chapter 12). The vector holds the pointer, the capacity and the length: three 8-byte numbers on a 64-bit machine, so 24 bytes. Rust doesn't promise the order of those three fields in memory, and you never need it. When the String needs more room it usually at least doubles its capacity, which keeps a long run of push_str calls fast overall. Those exact growth numbers are an internal detail and can change between versions.
                    
      
                    A move is a byte copy, then a rule
                    
      
                    At the machine level, let s2 = s1; copies the 24-byte record from one stack slot to another, the same as copying an integer, and the optimizer often removes even that. The "move" part exists only in the Compiler's bookkeeping: it notes that s1 may no longer be used and must not be dropped. When a value is moved on only some paths (say, inside an if), Rust keeps a small hidden drop flag so that the closing brace drops it only if it's still there.
                    
      
                    The capacities in the steppers, measured
                    
      
                    The steppers draw each String's cap. Those numbers aren't guesses: this program makes the same Strings the same way and asks each one for its capacity(). (grow.rs in panel 12 shows the same growth rule.)

    In real programs: where moves, clones and boxes show up
    
                    
      
                      
        
                    • Functions that keep what you give them take ownership. A function that stores a name in a list, or sends a message to another thread, takes a String by value, because it needs the value to outlive the call. Functions that only look at a value borrow it instead (Chapter 8).
                      • 
        
                    • Builders pass ownership along a chain. Many libraries let you write thing.with_size(3).with_colour(red): each method takes the value by move and hands it back, exactly like stamp in give_back.rs.
                      • 
        
                    • Clone while learning, then tidy up. Experienced Rust programmers also reach for .clone() when a design isn't settled. Clone small things freely; think twice about cloning big things in loops.
                      • 
        
                    • Box is for size and indirection. A big array is moved cheaply if it's boxed (8 bytes instead of all its contents); and a type that contains itself, like a tree node, needs a box to have a known size (Chapter 23).
                      • 
        
                    • Drop is how Rust closes things. Files, network connections and locks are also owned values. When their owner goes out of scope, they're closed or released automatically. This pattern has a name: RAII (Resource Acquisition Is Initialization). Chapter 18 shows how to write your own clean-up code.
                      • 
        
                    • The same three rules make threads safe. Because a value has one owner, handing it to another thread is a move, and the first thread can't touch it any more. Chapter 26 builds on exactly this.
                      • 
      
                    
    
                    
  
                    

  
                    
    Common wrong ideas
    
                    
      
                      
        
                    • "A String variable contains its text." It contains a pointer, a length and a capacity. The text is on the heap.
                      • 
        
                    • "let b = a; copies everything." For a String it copies only the 24-byte record, and moves ownership. Heap data is never copied unless you call .clone().
                      • 
        
                    • "After a move, the data is deleted." The data is untouched; the new owner uses it. Only the old name stops working.
                      • 
        
                    • "A moved variable is dropped at the move." Nothing is dropped at a move. The value is dropped later, when its new owner goes out of scope.
                      • 
        
                    • "The error is where the carets are." For E0382 the carets show where the moved value was used. The cause is under the dashes: value moved here.
                      • 
        
                    • "Integers move too, so I need .clone() on numbers." Integers, floats, bool and char are Copy. .clone() on them works but does nothing extra.
                      • 
        
                    • "mut lets me use a value after moving it." mut is about changing a value, not about who owns it. A let mut String still moves.
                      • 
        
                    • "Rust has a garbage collector that frees things at the end." There's no collector. Each value is freed at the closing brace of its owner's scope, often long before the program ends.
                      • 
        
                    • "Stack variables are faster, so I should avoid Strings." Use the type that fits the job. The heap costs a little; a correct, readable program matters far more.
                      • 
        
                    • "A for loop just reads the vector." for x in v moves v into the loop. To keep the vector, loop over &v (Chapter 8).

    Words from this chapter
    
                    
      
                    
        
                    memory (RAM)
                    Where a running program keeps its values: a long row of numbered cells.
                    
        
                    byte
                    One memory cell: a number from 0 to 255. An i32 takes 4 bytes.
                    
        
                    address
                    The number of a memory cell. A value's address is the number of its first cell.
                    
        
                    stack
                    The part of memory for function calls, used last in, first out, like a pile of plates.
                    
        
                    frame
                    One function call's plate on the stack: its parameters and local variables.
                    
        
                    push / pop
                    Putting a frame on top of the stack (a call) / taking it off (a return).
                    
        
                    last in, first out (LIFO)
                    The thing that went on most recently comes off first.
                    
        
                    known at compile time
                    Decided before the program runs. Every stack value's size must be.
                    
        
                    heap
                    The part of memory where a program can ask for blocks of any size while it runs.
                    
        
                    allocate / free
                    Ask the heap for a block / give it back.
                    
        
                    pointer
                    A value holding an address: the ticket saying where the coat is.
                    
        
                    length (len)
                    How many bytes a String is using.
                    
        
                    capacity (cap)
                    How many bytes of room its heap block has. Always at least the length.
                    
        
                    Box
                    A pointer that owns one value on the heap: Box::new(5).
                    
        
                    vector, vec![...]
                    A growable list whose items live on the heap. Chapter 11.
                    
        
                    scope
                    Where a name can be used: from its let to the closing brace of its block.
                    
        
                    block
                    Code between a pair of braces: a room for names.
                    
        
                    binding
                    The Compiler's word for a name made by let (or a parameter).
                    
        
                    owner, ownership
                    The one name responsible for a value. The three rules: one owner; one at a time; dropped when the owner goes out of scope.
                    
        
                    drop
                    Clean a value up when its owner goes out of scope, freeing its heap memory.
                    
        
                    move
                    Hand ownership to another name or function. The old name can't be used afterwards.
                    
        
                    E0382
                    "borrow of / use of moved value": a name used after its value moved away.
                    
        
                    E0425
                    "cannot find value in this scope": a name used where it doesn't exist (for example, outside its block).
                    
        
                    double free
                    Freeing the same heap block twice: a serious bug that ownership rules out.
                    
        
                    garbage collector
                    A helper in some languages that finds and frees unused heap memory while the program runs. Rust doesn't have one.
                    
        
                    Copy
                    Types copied by = instead of moved: integers, floats, bool, char, and tuples and arrays of them.
                    
        
                    trait
                    A named ability a type can have, like Copy. Chapter 17.
                    
        
                    .clone(), deep copy
                    Make a separate copy of a value, heap data included.
                    
        
                    partial move
                    Moving one part out of a tuple (or struct), leaving the rest.
                    
        
                    size_of
                    std::mem::size_of::<T>(): the number of bytes a type takes.
