PART 1 · BOXES OF DIFFERENT SHAPESenum: a type whose value is exactly one of a list of named kinds, with or without something inside

1

Every evening Mabel sorts the returns. Each book goes back to exactly one place: the Fiction shelf, the Science shelf, or the History shelf. Never two places, never "somewhere else".

Mabel says: I could write the shelf on each book as text, "fiction". But then somebody writes "Fiction", or "fictoin", and the book is lost forever.

The Professor says: Then don't use text. Make a type that can only be one of those three. In Rust, that's an enum, short for "enumeration": a list you write out in full.

Picture: Mabel shrugs at a pile of returned books. The Professor answers her.

2

Think of an enum as a set of box shapes. The type lists every shape there is. A value is always exactly one box, of one shape.

ENUMthe list of shapes

An enum is a type you define by listing every possible value. enum Shelf { Fiction, Science, History } has exactly three.

VARIANTone shape on the list

Each item on the list is a variant. You name one with the type in front and two colons: Shelf::Fiction.

    PART 2 · THE SORTING MACHINEmatch: one arm per shape, arms are expressions, nothing forgotten (E0004), the _ wildcard, and taking the contents out
    

  
    
    9
    
    Remember Chapter 6's sorting machine for Ordering? It works for any enum. Mabel's late fees come in coins: a value drops into the hopper, and exactly one chute catches it. And here's the rule that makes it safe: the machine refuses to start if any shape has no chute.

    coin_match.rs

      2.

    PART 3 · THE GIFT BOXOption<T>: Some(value) or None, instead of "nothing"; match, if let, let else, matches!, and why unwrap is dangerous
    

  
    
    18
    
    A reader asks: "Which seat in the reading room is free?" Sometimes the answer is "seat 2". Sometimes the answer is "none of them". How does a function say no answer?
    
    
    
      
      
    The Professor says: Many languages have a special value meaning "nothing here": null, nil, None. Any value might secretly be that nothing, and if you forget to check, the program crashes at the worst moment. The man who added null to a language in 1965, Tony Hoare, later called it his "billion-dollar mistake".
    
    
    
    
    
      
    Mabel says: Rust has no null. Instead, a "maybe" answer comes in a gift box. You can see from the outside that it's a box, and you have to open it before you can use what's inside.
    
      
    
    
    
    Picture: the Professor explains null; Mabel answers him.
    
  
    

  
    
    19
    
    Meet the gift box. It's either got exactly one thing in it, or it's empty. Never two things, and never a surprise.
    
    
    
      
      
      
    
    
    
    Picture: first, a gift box with its lid open and a card saying 2 popping out, labelled Some of 2. Next, an open, empty gift box with a surprised face, labelled None. Last, the ghost character, labelled: nothing here.
    
    
    It's not magic: Option is an ordinary enum from the standard library.
    enum Option<T> {
    None,
    Some(T),
}
    
    
    
      
    OPTION<T>a box for one T, or nothing
    The <T> means "of some type T": Option<u8> may hold a u8, Option<String> may hold a String. (Making your own types with <T> is Chapter 17.)
    
      
    ALWAYS IN REACHno use, no ::
    Option, Some and None are so common that Rust lets you write them without Option:: in front.
    
    
    
  
    

  
    
    20
    
    You've already met the box: in Chapter 3, checked_add answered with Some(253) or None. And you can return one from your own functions.
    
    checked.rs
    
    first_free.rs
    
    
      
      
    1. checked.rs: 250 + 3 fits in a u8, so Some(253); 250 + 10 doesn't, so None. Both have the type Option<u8>.
      2. 
      
    2. first_free.rs, line 1: -> Option<usize>. The signature itself warns every caller: "you might get nothing back". true means a seat is taken.
      3. 
      
    3. Line 4: found a free seat? Return it, wrapped: Some(i). Line 7: the loop finished with no luck, so the answer is None.
      4. 
    
    
  
    

  
    
    21
    
    
    Mabel wants to show seat numbers starting from 1, so she adds 1 to the answer.
    
    option_add.rs
    
    
    
    
    
      
      
    1. error[E0369]: cannot add `{integer}` to `Option<usize>`
      What: you can't do arithmetic on a gift box. seat isn't a number; it's a box that might hold one.
      2. 
      
    2. The labels under line 13 name both sides: Option<usize> on the left of +, {integer} (some whole number) on the right.
      3. 
      
    3. note: `Option<usize>` does not implement `Add<{integer}>`
      "There is no adding for boxes." The long /rustc/… path points into Rust's own library files and names the exact compiler build, so it differs on your machine. Skip it.
      4. 
    
    
    
    
      
      
    The Compiler says: What's None + 1? Nobody knows, so I won't guess. Open the box first, and decide what to do if it's empty. Catchphrase: open the box before you use what's inside.
    
    
    
  
    

  
    
  

  
    
    22
    
    The first way to open the box: the sorting machine. An Option has two shapes, so two arms.
    
    option_match.rs
    
    
    
    
    
      
      
    1. Line 15: Some(i) => … If the box holds something, the name i gets it: a plain usize, ready for arithmetic.
      2. 
      
    2. Line 16: None => … The empty case. Forget it, and it's E0004: pattern `None` not covered. The Compiler makes you think about "no answer".
      3. 
    
    
  
    

  
    
    23
    
    When you only care about one shape, a whole match is a lot of typing. if let is a match with one arm.
    
    if_let.rs
    
    
    
    
    
      
      
    1. Line 3: if let Some(total) = space.checked_add(3) { … } Read it as: "if the box on the right fits the pattern Some(total), let total be what's inside, and run the block." Note the single =: this is a pattern, not a comparison.
      2. 
      
    2. Line 6: the box is None, so the block is skipped, and the else on line 8 runs instead.
      3. 
    
    
    
    
      
    matchevery shape
    Use it when every shape needs handling. The Compiler checks you covered them all.
    
      
    if letone shape
    Shorter, but the Compiler can't warn you about shapes you forgot: everything else is silently skipped (or goes to the else).
    
    
    
  
    

  
    
    24
    
    A third way, for when "no answer" means "give up now": let … else. Unpack the box, or leave.
    
    let_else.rs
    
    
    
    
    
      
      
    1. Line 11: let Some(i) = first_free(seats) else { … }; If the box fits Some(i), i gets the seat, and it stays usable for the rest of the function, not just inside a block.
      2. 
      
    2. Lines 12–13: if it doesn't fit, the else block runs, and it must leave: return here. (In a loop, break or continue also work.)
      3. 
      
    3. Line 15: the "happy path", the code for the normal case, stays flat and easy to read. let … else needs Rust 1.65 or newer; older tutorials won't have it.
      4. 
    
    
    
    What if the else block doesn't leave?
      let_else_err.rs
    
      
    Without the return, line 14 would use i, but there is no i when the box was empty. The Compiler says the else "does not diverge" (go somewhere else). expected `!` is its way of saying "I needed a block that never finishes normally". Both help: lines are good fixes.
    
    
    
  
    

  
    
  

  
    
  

  
    
    25
    
    Sometimes you don't want what's inside; you only want to know "is it this shape?". matches! answers with a bool.
    
    matches.rs
    
    
    
    
    
      
      
    1. Line 12: matches!(coin, Coin::Penny) is true if coin fits the pattern. The ! means it's a macro, like println!. It works on any enum, not just Option.
      2. 
      
    2. Line 18: Some(_) means "a Some, with anything inside": the wildcard works inside patterns too.
      3. 
    
    
  
    

  
    
  

  
    
    26
    
    
    There's a shortcut: .unwrap() rips the box open and hands you what's inside. "I'm sure there's something in it." And if there isn't?
    
    unwrap_panic.rs
    
    
    
    
    
      
      
    1. seat 2: line 13's box held Some(2), so unwrap gave back 2.
      2. 
      
    2. thread 'main' (1) panicked at src/main.rs:14:42:
      A run-time stop, a panic, on line 14, column 42: the .unwrap(). The (1) is the thread's id number; on your computer it will be a different number.
      3. 
      
    3. called `Option::unwrap()` on a `None` value
      What: the box was empty, and unwrap has no answer to give, so it stops the whole program. Exit code 101.
      4. 
    
    
    
    
      
      
    The gift box says: The Compiler checks a match, but unwrap is you promising "it's never empty". If the promise is wrong, the program crashes. Catchphrase: unwrap is a promise. Break it, and the program stops.
    
    
    
    
    A kinder crash: expect
      expect_panic.rs
    
      
    .expect("…") works like unwrap, but the panic prints your message. If you're sure a box can't be empty, expect with a message that explains why is the polite way to say so.

    PART 4 · THE ACCORDION FOLDERVec<T>: Vec::new and vec!, push and pop, v[i] versus v.get(i), insert, remove, sort and dedup
    

  
    
    28
    
    You've used vectors a little since Chapter 7. Now properly. A vector, Vec<T>, is an accordion folder: a row of numbered pockets that can grow and shrink while the program runs. Every pocket holds the same type of thing.
    
    
    
    
    
      
    VEC<T>a growable list
    Items of one type T, side by side, on the heap. Vec<i32> holds i32s.
    
      
    LENpockets in use
    v.len(): how many items it holds right now. Pockets are numbered 0 to len - 1.
    
      
    CAPACITYroom before growing
    How many pockets it has room for before it must find a bigger folder. Part 6 is all about that move.
    
    
    
  
    

  
    
    29

    vec_basics.rs
    
    
    
    
    
      
      
    1. Line 2: Vec::new() makes an empty folder. It must be let mut to grow, and the : Vec<i32> says what it will hold.
      2. 
      
    2. Lines 3–5: push adds an item at the end.
      3. 
      
    3. Line 7: vec![4, 8, 15] makes a vector with items already in it. The type is worked out from the items. vec! is a macro, hence the !.
      4. 
      
    4. Lines 9–10: is_empty() asks "len is 0?"; contains(&20) searches for 20. It wants a reference, &20, because it only looks.
      5.

    PART 5 · WALKING THROUGH THE FOLDERfor x in &v (look), for x in &mut v (change, with *x), for x in v (take), and a folder of gift boxes
    

  
    
    35
    
    Three ways to walk through the folder with for. They're the three permissions you know from Chapters 7 and 8: look, change, own.
    
    
    
      
    for x in &vlook
    Each x is a reading pass, &T. The folder is untouched and still yours afterwards. The usual choice.
    
      
    for x in &mut vchange
    Each x is a writing pass, &mut T. Write *x to change the item in its pocket. Needs let mut v.
    
      
    for x in vtake
    The loop takes the whole folder. Each x is an owned item. Afterwards, v is gone (moved).

    2. Line 5: *f follows the pass to the number (Chapter 8's star). Line 7 can still print fines: we only looked.
      3.

      What you learned in Chapter 11
      
    
        
      
      • ONE OF A FEW, AND THE COMPILER KNOWS THEM ALLAn enum lists every shape a value can take. Variants can be empty, tuple-like Move(i32, i32) or struct-like Write { text: String }, and enums get methods in impl blocks.
        • 
      
      • EVERY SHAPE GETS A CHUTEmatch runs the first arm that fits, is an expression with a value, and must cover every shape (E0004). _ catches the rest; patterns with names unpack the contents.
        • 
      
      • OPEN THE BOX BEFORE YOU USE WHAT'S INSIDEOption<T> is Some(value) or None: Rust's answer to null. You can't do arithmetic on the box (E0369). Open it with match, if let or let … else; ask about it with matches!.
        •

    Under the hood: tags, payloads, free gift boxes and growing by doubling
    
      
      
      
        
        
      The Professor says: Let's weigh some boxes.
      
      
      
      sizes.rs
      
      
      (Sizes measured on this 64-bit Linux machine; size_of::<T>() reports how many bytes one value of type T takes. Line 10 builds each variant once so the Compiler doesn't warn that some are never used.)
      
      
      An enum value is a tag plus a payload
      
      
      In memory, an enum value is a small number saying which variant it is (the tag, or discriminant), followed by room for the largest variant's data (the payload). Shelf has three variants and no data, so one byte is plenty. Option<u32> needs a tag and 4 bytes of payload; with padding to keep the u32 lined up, that's 8 bytes. A match is mostly "read the tag, jump to the right arm", which is very fast.
      
      
      Some gift boxes are free
      
      
      Look at &u32 and Option<&u32>: both 8 bytes. A Rust reference can never be the address 0, so the Compiler uses address 0 to mean None. No tag needed. This is called the null-pointer optimisation: you get null's speed with none of its danger, because you still can't use the box without opening it.
      
      
      A Vec is three numbers
      
      
      The Vec<i32> itself is 24 bytes: a pointer to the heap block, the length and the capacity, exactly the ticket in panel 41. The items live on the heap. When a push finds len == capacity, the vector asks for a bigger block (today: twice as big, starting at 4 for items like i32; the first size depends on how big each item is, as the run below shows), copies the items over, and frees the old block. Because the size doubles, the copying averages out to a small, fixed cost per push. Programmers call that amortised constant time.
      
      first_room.rs
      
      
      A one-byte item starts with room for 8, an i32 with room for 4, and a huge 2000-byte item with room for just 1. And vec![10, 20, 30] asks for exactly the room it needs: capacity 3, already full, so its very next push needs a bigger block (panel 43).
      
      
      Asking for room up front
      
      
      If you know how many items are coming, Vec::with_capacity(n) reserves room for at least n at once, so the folder never has to move while you fill it:
      
      with_capacity.rs
      
      
      match on a reference
      
      
      In panels 17 and 39, a &Action or &Item was matched with patterns written for the value itself. Rust's "default binding modes" make that work: when the value is a reference, the names in the pattern become references too (title: &String). That's why nothing was moved out of the vector, and why the arms wrote *days to get at the number.
      
    
      
  
      

  
      
    In real programs: where you'll see enums, Option and Vec
    
      
      
        
        
      • Option is everywhere in the standard library. v.get(i), v.pop(), v.first(), v.last(), checked_add, and many more answer with an Option whenever "no answer" is possible. Chapter 13's HashMap::get does too.
        • 
        
      • Result is Option's sibling. When "no answer" needs a reason, Rust uses Result, which is Ok(value) or Err(reason): Chapter 6's parcel from parse. It's the same idea, another enum, and it gets its own chapter (13).
        • 
        
      • Enums model "one of a few states". A download is waiting, running or done; a chess square is empty or holds a piece; a message is text, an image or a file. With an enum, an impossible state (a "done" download with no file) can't even be written down.
        • 
        
      • Vec is the most used collection in Rust programs. When in doubt, start with a Vec.
        • 
        
      • A Vec of an enum is a classic: an event log, a list of drawing commands, the tokens of a calculator.

    Common wrong ideas
    
      
      
        
        
      • "An enum is just a list of named numbers." In some languages, yes. In Rust each variant can carry its own data, of its own types.
        • 
        
      • "I'll add a _ arm to every match, to be safe." It compiles, but it switches off the Compiler's best help: when a new variant is added, a _ swallows it silently. Prefer listing every variant when there are only a few.
        • 
        
      • "if let is just a shorter match." It's shorter, but it isn't checked for missing shapes.
        • 
        
      • "Some(5) is a 5." It's a box with a 5 in it. You must open it before you can add, compare or print it as a number (E0369).
        • 
        
      • "None is like null, so it can crash my program." A None can only crash the program if you unwrap it. The type Option warns you, and the Compiler makes you handle it.
        • 
        
      • "unwrap is fine; it's what the examples do." Short examples use it to stay short. In real code, ask: what should happen if it's empty? Then write that.
        • 
        
      • "v[i] returns None when i is too big." Only v.get(i) does. v[i] panics.
        • 
        
      • "dedup removes all duplicates." Only neighbours. Sort first.
        • 
        
      • "for x in v and for x in &v are the same." The first takes the vector; you can't use it afterwards.
        • 
        
      • "push doesn't touch pocket 0, so a reference to pocket 0 is safe." A push may move every pocket. That's E0502.
        • 
        
      • "Capacity is always a power of two." It is in today's runs from Vec::new(), but with_capacity(100) gave exactly 100 and vec![10, 20, 30] gave 3, and the growth rule is an implementation detail that could change.

    Words from this chapter
    
      
      
      
        
      enum (enumeration)
      A type defined by listing every possible variant. A value is exactly one variant.
      
        
      variant
      One of an enum's choices, named with Type::Name. It may carry no data, tuple-like data or struct-like data.
      
        
      match
      Compares a value against patterns, top to bottom, and runs the first arm that fits. It is an expression.
      
        
      arm
      One pattern => code line of a match.
      
        
      pattern
      A shape a value can fit, like Coin::Dime, Some(i), 6 | 7 or _.
      
        
      exhaustive
      Covering every possible value. A match must be (E0004).
      
        
      wildcard, _
      A pattern that fits anything, used as a catch-all last arm.
      
        
      binding
      Giving a name to a value inside a pattern, like x and y in Action::Move(x, y).
      
        
      todo!()
      A placeholder that compiles but panics if it runs: "write this later".
      
        
      Option<T>
      The standard enum Some(T) or None: a value that may be missing. Rust's replacement for null.
      
        
      null
      In other languages, a special "nothing here" value any reference might secretly be. Rust has none.
      
        
      if let
      Runs a block only if a value fits one pattern, binding its contents.
      
        
      let … else
      Binds a pattern for the rest of the function, or runs an else block that must leave (diverge).
      
        
      diverge
      Never finish normally: return, break, continue or a panic.
      
        
      matches!
      A macro answering true or false: does this value fit this pattern?
      
        
      unwrap / expect
      Take the value out of a Some, or panic on None (expect with your own message).
      
        
      vector, Vec<T>
      A growable list of items of one type, stored side by side on the heap.
      
        
      vec![…]
      A macro that makes a vector with items already in it.
      
        
      push / pop
      Add an item at the end; take the last item off (returns an Option).
      
        
      get(i)
      Read pocket i safely: Some(&item), or None past the end.
      
        
      index out of bounds
      The panic from v[i] when i is not less than len.
      
        
      capacity
      How many items a vector has room for before it must move to a bigger block.
      
        
      dereference, *x
      Follow a reference to the value it points at.
      
        
      stack (the data structure)
      A pile where you add and remove only at the top: push and pop.
      
        
      E0004 / E0369 / E0282 / E0368 / E0599
      Non-exhaustive match; an operator used on an Option; a type the Compiler can't work out; += on a reference; a variant that doesn't exist.
